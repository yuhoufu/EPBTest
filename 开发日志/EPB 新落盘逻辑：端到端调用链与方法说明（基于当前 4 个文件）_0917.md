# EPB 新落盘逻辑：端到端调用链与方法说明（基于当前 4 个文件）

> 涵盖文件：`EpbDiskWriter.cs`、`TwoDeviceAiAcquirer.cs`、`EpbManager.cs`、`FrmEpbMainMonitor.cs`
>  目的：把“只保留电流与压力字段、圈号与卡钳动作强关联、支持 Free-Run(圈号0) 和停止时留存最近 N 圈”的新落盘逻辑，完整串联起来，说明每个方法**做什么、在何处被调用、先后顺序**。

------

## 1）总体架构与数据流（谁→谁）

```
NI 采集硬件 → TwoDeviceAiAcquirer（批处理滤波）
    └─ 触发 OnDiskBatch(device, tsUtc[], currentsByEpb, P1[], P2[])
         └─ FrmEpbMainMonitor 订阅 OnDiskBatch：
              按 EPB1..12 选择对应压力数组 → _diskWriter.WriteBatch(epbId, ts[], I[], P[])
EpbManager（控制周期/圈）
    ├─ 周期开始：Recorder.BeginCycle(ch, cycleNo, utcNow)
    ├─ 周期结束：Recorder.GetCurrentCycleSampleCount(ch) → Recorder.CompleteCycle(...)
    └─ 停止通道：Recorder.FlushRecent(ch, N)    // 留存最近 N 圈
EpbDiskWriter（真正执行写盘）
    ├─ WriteBatch/WriteSample → 内存映射 .dat（Curr、Pressure 两字段）+ 进度索引(SQLite)
    ├─ Begin/CompleteCycle → 建立/完结圈级索引；按策略触发留存
    └─ PersistLatestCyclesNow/Export → “archive” 或 “delete”
```

------

## 2）集成点（初始化到运行的“先后关系链”）

1. **窗体加载**（`FrmEpbMainMonitor_Load`）
   - 完成 DAQ/映射/曲线/UI 初始化。
   - **创建落盘策略与写盘器**，并用适配器包装成 `IEpbCycleRecorder`，随后**注入到 EpbManager**：`_epb.Recorder = recorder` 。
   - **订阅采集器的 OnDiskBatch 事件**，把每个 EPB 的电流与对应组压力批量喂给 `_diskWriter.WriteBatch` 。
2. **TwoDeviceAiAcquirer 采集循环**
   - 每到一批滤波完成的数据，**构造时间戳数组**，**按 EPB1..12 组装电流数组**，**提取两组压力**，最后**触发 OnDiskBatch**（供 UI/写盘订阅）  。
3. **EpbManager 驱动“圈”**
   - 每次周期开始：**调用 `Recorder.BeginCycle`**；
   - 每次周期结束：先取 **`Recorder.GetCurrentCycleSampleCount`**，再 **`Recorder.CompleteCycle`**；
   - 停止某通道：**`Recorder.FlushRecent(channel, 10)`**（把最近 N 圈正式数据落盘/归档）  。
4. **EpbDiskWriter 负责真正写盘**
   - `WriteBatch/WriteSample` 把（UTC 时间戳、圈号、样本序号、电流、组压）**写入内存映射文件**；**圈内**同时更新 SQLite 进度；**未开圈时若启用 Free-Run 则写入圈号0**   。
   - `CompleteCycle` 完结圈、清状态，并按停止触发策略在**圈末**执行业务留存（`PersistLatestCyclesNow`） 。
   - 留存时，会查询应清理的圈并“archive（导出 CSV 后删索引）/delete（仅删索引）” 。

------

## 3）逐文件 / 逐方法说明

### A. `FrmEpbMainMonitor.cs`（UI/集成层）

**核心字段**

- `_diskWriter`、`_recorder`：落盘器与其接口包装体，用于与 `EpbManager` 解耦 。

**Load 关键片段**

- **创建策略与写盘器**：设置数据根目录、单文件容量、`RetainLatestCycles`、`CleanupMode`；然后 new `EpbDiskWriter(policy)`。
   再 new `DiskWriterRecorderAdapter(_diskWriter)`，**注入** `_epb.Recorder` 。
- **订阅 OnDiskBatch**：把 EPB1..6 用 P1，EPB7..12 用 P2，长度一致时调用 `_diskWriter.WriteBatch`（批量落盘） 。

> 你在窗体里做的这三步，构成“**采集 → 批量事件 → 落盘**”链路的**入口**。

------

### B. `TwoDeviceAiAcquirer.cs`（采集/批处理层）

**OnDiskBatch 事件**

- 由采集器在每批**滤波后的工程值**产出时触发：
   1）**时间戳序列**按采样率回推生成；
   2）把当前设备的工程值矩阵**分拣出 EPB1..12 的电流向量**；
   3）**提取两组压力**（多名称兜底）；
   4）**触发事件** `OnDiskBatch(device, tsUtc, currentsByEpb, pressure1, pressure2)`  。

**被谁用？**

- `FrmEpbMainMonitor_Load` 中订阅该事件，**直接调用 `_diskWriter.WriteBatch`** 完成落盘（见上文）。

------

### C. `EpbManager.cs`（试验流程/圈调度）

**Begin/Complete/Flush 的调用点**

- **周期开始**：`Recorder?.BeginCycle(channel, i, DateTime.UtcNow)`；
- **周期结束**：先 `Recorder?.GetCurrentCycleSampleCount(channel)`，再 `Recorder?.CompleteCycle(..., finalN, ...)`；
- **停止通道**：`Recorder?.FlushRecent(channel, 10)`（可根据 UI 参数改 N）  。

> 这三处是**圈级“钩子”**，把业务周期与落盘“圈号”牢靠对齐。

------

### D. `EpbDiskWriter.cs`（真正的数据落盘实现）

**对外接口（通过 `IEpbCycleRecorder` 暴露）**

- `BeginCycle(epbId, cycleNo, startUtc)`：开启正式圈（圈号>0）；建立/更新圈索引起点。

- `WriteBatch(epbId, tsUtc[], currents[], pressures[])`：批量写入（内部逐点 `WriteSample`，确保并发与索引一致） 。

- `GetCurrentCycleSampleCount(epbId)`：返回当前圈已写样本数（给 `EpbManager` 作为 `finalN`）。

- `CompleteCycle(epbId, cycleNo, finalN, endUtc)`：完结圈，必要时触发**圈末留存**（见下） 。

- `FlushRecent(epbId, lastN)`：在**停止时**把“最近 N 圈”正式数据归档/清理（适配器里调用 `PersistLatestCyclesNow`） 。

  > 这些方法由 **`DiskWriterRecorderAdapter`** 直接映射到 `EpbDiskWriter` 实现，`EpbManager` 只依赖接口，不关心细节 。

**批量/单点写入逻辑**

- `WriteSample` 会根据当前状态选择圈号：
  - 若 `CurrentCycle` 有值 → 使用该圈号；
  - 否则若开启 **Free-Run** → 使用圈号 **0**；
  - 两种情况都会写入 `TimestampBinary/Cycle/SampleIndex/EpbCurrent/GroupPressure` 五个字段到内存映射文件，并在**正式圈**内**更新 SQLite 进度**（`sample_count` 与 `end_time`）  。
- `WriteBatch` 只是长度校验后循环调用 `WriteSample`，逻辑一致 。

**圈末策略（与“停止时最近 N 圈”一致）**

- 在 `CompleteCycle` 里，如果停止触发为 **EndOfCurrentCycle**，则**圈结束即执行业务留存**；`AfterKMoreCycles` 则倒计数至 0 时执行 。
- 留存动作 `PersistLatestCyclesNow`：依据 `keepLatestN` 计算需清理的历史圈集合，按 `action=archive/delete` 进行导出 CSV + 删索引或仅删索引（示例 SQL 见文件） 。

## 4）常见使用场景与调用顺序

### 场景 A：**正式试验**（有圈号）

1. `EpbManager` 开始某圈 → `Recorder.BeginCycle(...)`（圈号 > 0） 
2. `TwoDeviceAiAcquirer` 持续产出批次 → `OnDiskBatch` → `_diskWriter.WriteBatch(...)`（圈内样本落盘）  
3. `EpbManager` 该圈结束：取 `GetCurrentCycleSampleCount` → `CompleteCycle(...)`（圈完结、必要时圈末留存） 。

### 场景 B：**Free-Run 记录**（未开圈号）

1. 上层调用 `_diskWriter.StartFreeRun(epbId)`（或按你约定）
2. 采集批次到来 → `WriteBatch`；因无 `CurrentCycle`，**自动以圈号0** 写入（仅用于区分临时数据）。
3. 可在任意时刻 `ExportFreeRunBySamples(epbId, lastSamples, path)` 导出最近窗口（如需要）。

### 场景 C：**停止卡钳，留存最近 N 圈**

- `EpbManager.StopChannel(ch)` → `Recorder.FlushRecent(ch, 10)`（可改 N） → `PersistLatestCyclesNow` 执行清理/归档（仅**正式圈**，不含圈0） 。

## 6）你需要记住的“契约”

1. **圈号来源**由 `EpbManager` 决定：`BeginCycle/CompleteCycle` 的圈号和实际动作一一对应。
2. **批次写入只需要电流与压力**：`WriteBatch` 的数组长度必须一致；EPB1..6 用 `P1[]`，EPB7..12 用 `P2[]`（窗体层已处理） 。
3. **Free-Run(圈0)**：未开圈但启用 Free-Run 时也允许写盘，圈号恒为 0（与正式圈区分） 。
4. **停止即留存**：`StopChannel` 必须调用 `FlushRecent(ch, N)` 来确保“最新 N 圈”正式数据被归档/清理（默认 10） 。
5. **索引与数据分离**：圈级索引用 SQLite 管（`sample_count/end_time/status` 等），数据本体在固定大小 `.dat`（内存映射）里，循环覆盖。

------

## 7）运行环境与依赖（易错点）

- `System.Data.SQLite` 需要**匹配位数**的 **SQLite.Interop.dll** 在输出目录（`x86/x64`）可加载，否则会出现“无法加载 DLL ‘SQLite.Interop.dll’”的初始化错误。确保 NuGet 包 `System.Data.SQLite.Core` 已安装，并把相应的 native 目录复制到可执行文件同级（或使用包自带的 build 逻辑自动拷贝）。
- `.dat` 文件大小、留存数量、清理模式等来自 `DataRetentionPolicy`（窗体示例已演示如何设置） 。
