# EPB测试系统 - 内存映射数据落盘方案设计文档

## 方案概述

采用内存映射文件 + 滑动窗口的方式实现EPB测试数据的存储，解决原有方案中"保留最新N组数据"的需求。

## 技术方案

### 1. 核心设计理念

- **内存映射文件（Memory-Mapped File）**：利用操作系统的虚拟内存机制，将文件映射到内存地址空间
- **滑动窗口（Circular Buffer）**：固定大小的循环缓冲区，自动覆盖最旧的数据
- **零拷贝**：数据直接写入内存映射区域，操作系统负责持久化

### 2. 数据存储结构

#### 2.1 文件组织
```
DataStore/
├── EPB1_sliding.dat    (384MB, 固定大小，二进制格式)
├── EPB2_sliding.dat    (384MB, 固定大小，二进制格式)
├── ...
├── EPB12_sliding.dat   (384MB, 固定大小，二进制格式)
└── index.db           (SQLite索引文件，约10MB，存储元数据)
```

#### 2.2 原始数据存储格式 (.dat文件)

**存储格式**：内存映射二进制文件
- **文件大小**：384MB (固定)
- **数据容量**：10个循环 × 30万采样点 × 128字节/点
- **存储方式**：循环覆盖，最新数据自动替换最旧数据

**单个记录的二进制结构** (128字节)：
```csharp
struct SampleRecord  // 优化后的结构，基于AIConfig.xml通道配置
{
    long Timestamp;         // 8字节  - 时间戳 (DateTime.ToBinary())
    int CycleNumber;        // 4字节  - 循环编号
    int SampleIndex;        // 4字节  - 样本索引
    double EpbCurrent;      // 8字节  - EPB电流值 (已应用工程变换)
    double GroupPressure;   // 8字节  - 对应组的压力值 (EPB1-6用Pressure_1, EPB7-12用Pressure_2)
    double Reserved1;       // 8字节  - 预留字段1
    double Reserved2;       // 8字节  - 预留字段2
    byte[88] Reserved;      // 88字节 - 预留字段，便于扩展
}

// 二进制布局
[Offset 0-7]   : long Timestamp        (时间戳)
[Offset 8-11]  : int CycleNumber       (循环编号)
[Offset 12-15] : int SampleIndex       (样本索引)
[Offset 16-23] : double EpbCurrent     (EPB电流，已工程化)
[Offset 24-31] : double GroupPressure  (对应组压力，已工程化)
[Offset 32-39] : double Reserved1      (预留字段1)
[Offset 40-47] : double Reserved2      (预留字段2)
[Offset 48-127]: byte[88] Reserved     (88字节预留扩展)
```

**重要优化**：
- **去除夹紧力字段**：Force仅用于实时监控，不存储到文件
- **简化压力处理**：每个EPB只存储对应组的压力值，减少数据冗余
- **增加预留空间**：从72字节增加到96字节，便于未来扩展

**文件内容示例**：
```
EPB1_sliding.dat 文件内容（二进制格式）：
[Record 0]: [时间戳][循环1][样本0][电流值][压力1][压力2][力值][预留...]
[Record 1]: [时间戳][循环1][样本1][电流值][压力1][压力2][力值][预留...]
[Record 2]: [时间戳][循环1][样本2][电流值][压力1][压力2][力值][预留...]
...
[Record N]: [时间戳][循环10][样本M][电流值][压力1][压力2][力值][预留...]
```

#### 2.3 SQLite数据库作用和结构

**重要说明**：SQLite **不存储原始采样数据**，而是作为**元数据索引库**。

**主要作用**：
1. **循环信息索引**：记录每个循环的起始位置、样本数、时间范围
2. **快速查询支持**：按循环号、时间范围快速定位数据在.dat文件中的位置
3. **配置管理**：存储系统配置参数
4. **统计信息**：提供数据统计和监控信息

**数据库表结构**：
```sql
-- 循环信息表
CREATE TABLE epb_cycles (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    epb_id INTEGER NOT NULL,           -- EPB编号 (1-12)
    cycle_number INTEGER NOT NULL,     -- 循环编号
    start_time DATETIME NOT NULL,      -- 循环开始时间
    end_time DATETIME,                 -- 循环结束时间
    start_position INTEGER NOT NULL,   -- 在.dat文件中的起始位置
    sample_count INTEGER DEFAULT 0,    -- 该循环的样本数
    status TEXT DEFAULT 'running',     -- running/completed/stopped
    created_at DATETIME DEFAULT CURRENT_TIMESTAMP,
    UNIQUE(epb_id, cycle_number)
);

-- 配置表
CREATE TABLE epb_config (
    key TEXT PRIMARY KEY,              -- 配置键
    value TEXT NOT NULL,               -- 配置值
    updated_at DATETIME DEFAULT CURRENT_TIMESTAMP
);

-- 示例配置数据
INSERT INTO epb_config VALUES ('retain_cycles', '10', '2025-09-15 10:30:00');
INSERT INTO epb_config VALUES ('samples_per_cycle', '300000', '2025-09-15 10:30:00');
```

#### 2.4 数据存储工作流程

**数据写入过程**：
```
1. 接收采样数据 (double values)
   ↓
2. 创建SampleRecord结构体 (128字节)
   ↓
3. 计算循环缓冲区位置 (position % capacity)
   ↓
4. 直接写入内存映射文件 (零拷贝，极高性能)
   ↓
5. 更新SQLite循环信息 (异步，批量更新)
```

**数据读取过程**：
```
1. 查询SQLite获取循环信息和位置
   ↓
2. 计算在.dat文件中的精确位置范围
   ↓
3. 直接从内存映射区域读取二进制数据
   ↓
4. 反序列化为SampleRecord结构体
   ↓
5. 返回查询结果给应用程序
```

#### 2.5 存储架构对比

| 组件 | 存储内容 | 格式 | 大小 | 主要作用 | 性能特点 |
|------|---------|------|------|---------|----------|
| `.dat文件` | **原始采样数据** | 二进制 | 384MB×12 | 高性能数据存储 | 写入>100万/秒 |
| `SQLite` | **元数据索引** | SQL | ~10MB | 数据查询和管理 | 复杂查询支持 |

**设计优势**：
- **为什么不用SQLite存储原始数据？**
  - 性能考虑：1kHz采样 = 每秒15000条记录，SQLite INSERT会成为瓶颈
  - 内存映射优势：零拷贝，操作系统级优化，性能极致

- **为什么需要SQLite索引？**
  - 快速查询：按循环号、时间范围快速定位数据位置
  - 元数据管理：循环统计、配置管理、状态跟踪
  - 数据完整性：事务支持，确保索引一致性

- **混合架构的优势**：
  ```
  高频写入 → 内存映射文件 (极致性能)
  复杂查询 → SQLite索引 (SQL便利性)
  数据分析 → 二进制+索引结合 (最佳体验)
  ```

#### 3.2 关键算法

**写入算法**：
1. 计算循环写入位置：`position = _writePosition % _capacity`
2. 计算文件偏移：`offset = position * RECORD_SIZE`
3. 直接写入内存映射区域
4. 更新写入位置：`_writePosition++`

**读取算法**：
1. 根据循环编号计算数据范围
2. 使用内存映射直接访问数据
3. 支持按时间范围、循环范围查询

### 5. 性能预期

#### 5.1 内存占用
- **映射内存**：12 × 384MB = 4.6GB
- **实际物理内存**：操作系统按需加载，约500MB-1GB
- **索引内存**：约10MB（SQLite缓存）

#### 5.2 性能指标
- **写入性能**：>1,000,000 样本/秒（直接内存操作）
- **查询性能**：毫秒级响应（内存映射 + 索引）
- **启动时间**：<2秒（文件映射初始化）
- **数据安全**：系统崩溃时数据自动持久化

### 6. 优势分析

#### 6.1 技术优势
- **性能极致**：零拷贝，直接内存操作
