# 我对“新的数据落盘逻辑”的完整理解（供确认）

下面把你刚才强调的两点（只存电流/压力；循环数跟真实卡钳动作绑定）落到现有代码与方案上，给出我对改造范围、对接点、数据结构与时序的整体理解。

## 1) 现状里与“落盘”相关的入口/对接点

- **采数入口**：`TwoDeviceAiAcquirer` 启动后维护电流/压力的快照读取接口（`ReadCurrent* / ReadPressure*`），供控制与落盘使用。压力是按**组**（1/2）读取。 
- **试验循环驱动**：`EpbManager` 给每个通道创建高精度定时器并在回调里执行一圈动作，回调参数 `i` 即“第几圈”。这就是**权威的循环编号**来源与绑定点。
   同时，`hydId = (channel<=6 ? 1 : 2)`，可据此把该通道样本关联到对应压力传感器（P1 或 P2）。
- **旧落盘应用位置**：窗体 `FrmEpbMainMonitor` 里按设备（Dev1/Dev2）初始化 `DaqAIContext` 并挂**定时器**做批量 flush（“数据落盘相关”区域与 `InitDaqLogTimer`）。新逻辑将替换/收敛到新的写入器。 

## 2) 你要的“记录格式”与字段裁剪

- **核心要求**：去掉所有“预留字段”，实际**数据字段只保留：电流 + 压力**；其余仅保留必要**元信息**（时间戳、循环号、样本序）。
- 结合你之前给的“内存映射+滑动窗口”设计文档，原提案里一条记录包含 `Timestamp/CycleNumber/SampleIndex/EpbCurrent/GroupPressure` 及若干 Reserved。新方案**删除所有 Reserved**，仅保留上述 5 项（若你同意，也可把 `SampleIndex` 下沉为每圈块级元信息）。
- 压力字段按组取值：EPB1–6→`Pressure_1`；EPB7–12→`Pressure_2`（由 `hydId` 推断）。读取接口沿用 `TwoDeviceAiAcquirer.ReadPressure`。 

> 小结：**最终单点记录** = `Timestamp` + `CycleNumber` + `SampleIndex` + `EpbCurrent` + `GroupPressure`。**不再**存任何预留字段与其他测量（如夹紧力/调试量）。

## 3) 循环号如何与“真实动作”绑定

- 以 `EpbManager.StartChannel` 内部的定时器回调为**唯一循环边界**：在 `timer.StartAsync(... async (i, token) => { ... })` 回调中，`i` 即第 i 圈，我们在该圈动作开始前/结束后分别发出“圈开始/圈结束”信号给新落盘器，用它来给期间到来的采样打上 `CycleNumber=i`。
- 每个通道独立定时器 → 各通道“圈号”天然**互不干扰**，契合你“各卡钳独立进度/仅保留各自最新 N 圈”的需求。数据保留策略仍按你提供的**滑动窗口**与**索引**方案实现（见下）。

## 4) 存储与保留策略（沿用你给的方案，但裁剪字段）

- **介质与结构**：每个 EPB 一个固定大小 `.dat`（内存映射，循环覆盖最新 N 圈）；SQLite 仅存**索引/元数据**，不存原始点。我们只需把记录结构更新为“无预留字段”的精简版即可。 
- **滑动窗口写入**：按记录条数取模定位，零拷贝写入内存映射区；超出容量自动覆盖最旧数据，满足“只保留最新 N 圈”。
- **查询/回放**：通过索引里的“圈起/圈止位置、样本数、时间范围”直接定位。

## 5) 改造边界与对接方式（不改外部行为）

- **替换点**：用一个新的 `EpbDiskWriter`（内存映射实现）取代 `DaqAIContext` 的写盘职责；窗体层仍在“数据落盘相关”区域完成初始化，但**不再**维护“原生通道大数组 + 预留字段”的旧格式。 
- **数据流**：
   `TwoDeviceAiAcquirer`（批）→ **新写盘器.Enqueue(batch)**（仅提取该通道对应的“电流+组压力”，补齐 `Timestamp / CycleNumber / SampleIndex`）→ **内存映射写入**。压力读值与组别由 `hydId` 与 `ReadPressure` 决定。 
- **循环边界**：在 `EpbManager` 的每圈回调中调用 `writer.BeginCycle(channel, i, hydId)` 与 `writer.EndCycle(...)`，由写盘器将圈号传导到区间内的样本。
