# EPB 数据落盘与报警 - 快速验证指南（现行口径）

> 说明：本仓库当前的落盘实现以 `DataOperation/EpbDiskWriter.cs` 为准（内存映射环形数据 + SQLite 圈级索引）。
> 旧文档中出现的 `EpbMemoryMappedStorage` / `DataRetentionPolicy.xml(128B/384MB)` 等内容与现行实现不一致，请不要按旧方案联调。

## 你应该验证的 4 件事

### 1) 正常运行：圈能封为 completed

- 启动测试后，让任意通道正常跑完至少 2 圈。
- 在“停止该通道”后，确认导出的“最近 N 圈”目录中存在对应 CSV/BIN 文件。

### 2) 报警联动：报警灯/蜂鸣器与快照导出

- 触发任意一条 EPB 报警：
    - 对应通道报警灯点亮；
    - （若启用）蜂鸣器拉响；
    - 导出报警快照：包含报警通道与所有正在运行通道。

快照目录规则见：
- [开发日志/报警系统（泓格M-7055D_RS-485）设计与联调.md](开发日志/报警系统（泓格M-7055D_RS-485）设计与联调.md)

### 3) 报警停机：该路立即停止且不影响其他通道液压

- 触发报警后，确认：
    - 报警通道停止进入下一圈（计时器停止）；
    - 其它通道仍能继续跑且不会被“等待报警通道到释放点”卡住。

### 4) 计数一致性：报警中断圈也要计数

- 报警发生在圈内时：
    - 该圈会以 `status='alarm'` 封圈（避免遗留 `running` 悬挂圈）；
    - UI 侧该通道的圈数计数会与落盘圈次数保持一致。

### 5) 实时曲线：全通道流畅 + 前后台切换不阶梯

- 全通道勾选（EPB1..12 + P1/P2/F），让系统连续运行 1~2 分钟。
- 反复做“前台→后台→前台”的窗口切换（可用 Alt+Tab），观察是否出现明显的“阶梯/平台”。
- 验证 FastLine 是否生效：
    - 日志中应出现一次性记录（只打一次）：
        - `ZedGraph 快速渲染设置已应用：AntiAlias=OFF, Smooth=OFF, IsFastLine=ON/N/A, Curves=...`
    - `IsFastLine=ON` 表示当前 ZedGraph 版本支持并已启用；`N/A` 表示版本无该属性，但仍会关闭 AntiAlias/Smooth。

可调参数（仅影响显示层，不影响控制/落盘）：

- `MTTfTest/FrmEpbMainMonitor.cs`：
    - `UI_TARGET_FPS`：控制统一重绘频率（建议 5~15）。
    - `UiMaxPlotHz`：显示层抽稀上限（建议 80~150）。
    - `MaxPendingEngBatchesPerDev` / `MaxEngBatchesPerUiRun`：UI 侧小队列缓冲与单次处理上限（用于减少“丢批次导致阶梯”）。

更完整的背景/参数解释/排查套路见：

- `开发日志/UI实时曲线性能联调说明.md`

## 常用定位点

- 报警配置：`MTTfTest/Config/AlarmConfig.xml`
- 报警快照目录：`StoreDir\TestName\AlarmSnapshots\...`
- UI 日志导出：当前运行目录下 `RunLog.txt` / `WarnLog.txt` / `ErrorLog.txt`

## 常见构建问题：无法复制 MTTFTest.exe（文件被占用）

现象：编译阶段通过，但输出复制到 `MTTfTest/bin/Debug/MTTFTest.exe` 时失败，提示被占用（常见占用者：`MTTFTest` 进程或 VS 远程调试器 `msvsmon`）。

处理：

- 先关闭正在运行的程序窗口；若仍不行，任务管理器结束 `MTTFTest.exe`。
- 若提示被 `msvsmon` 占用，结束 `msvsmon.exe` 后再重新编译。
