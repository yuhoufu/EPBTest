# 两个数采卡曲线不同步问题修复总结

## 问题描述

15个采集通道分布在2个NI数采卡（Dev1/Dev2）上，长时间运行后，监控界面显示的两个卡的通道曲线逐渐不同步。

## 根本原因

系统之前为每个设备维护**独立的时钟**（`DevClock`），包含：
- `T0`：本设备参考起点
- `Last`：本设备上一次时间戳  
- `Samples`：累计样本数

虽然每个设备内部有轻微纠偏机制（5ms阈值），但**两个设备之间没有互相同步**，导致：
1. 各自按采样率推进时间时，微小的差异会长时间累积
2. 即使都与主机时钟纠偏，两个独立的纠偏动作不协调
3. UI曲线使用各设备独立的时间戳，造成X轴逐渐分离

## 解决方案

### 修改内容

在 [TwoDeviceAiAcquirer.cs](IO.NI/TwoDeviceAiAcquirer.cs) 中实施以下修改：

#### 1. 字段定义（第88-91行）

**修改前：**
```csharp
private sealed class DevClock
{
    public DateTime T0;
    public DateTime Last;
    public long Samples;
}
private readonly ConcurrentDictionary<string, DevClock> _devClocks = new();
```

**修改后：**
```csharp
// —— 统一时间基准（不再按设备分开，避免长时间漂移）—— //
private DateTime _globalLast = DateTime.Now; // 全局最后一次时间戳（两设备共用）
private readonly object _globalLastLock = new object(); // 保护 _globalLast 的并发写入
```

#### 2. Start() 方法（第639-656行）

**修改前：**
```csharp
// 为每个实际启用的设备放入独立的时钟
if (_dev1Channels.Length > 0)
    _devClocks["Dev1"] = new DevClock { T0 = _t0, Last = _t0, Samples = 0 };

if (_dev2Channels.Length > 0)
    _devClocks["Dev2"] = new DevClock { T0 = _t0, Last = _t0, Samples = 0 };
```

**修改后：**
```csharp
if (!_sw.IsRunning)
{
    _t0 = DateTime.Now;
    _sw.Start();
    _ts0 = _sw.ElapsedMilliseconds;
    lock (_globalLastLock)
    {
        _globalLast = _t0; // 统一初始化全局时间基准
    }
}
```

#### 3. OnAiBatch() 回调中的时间戳计算（第740-757行）

**修改前：**
```csharp
// ② 取本设备的时钟状态
if (!_devClocks.TryGetValue(device, out var clk))
{
    clk = new DevClock { T0 = _t0, Last = _t0, Samples = 0 };
    _devClocks[device] = clk;
}

var last = clk.Last;
var hostNow = _t0.AddMilliseconds(_sw.ElapsedMilliseconds - _ts0);
var idealNow = last.AddSeconds(n / _sampleRate);
var driftMs = (hostNow - idealNow).TotalMilliseconds;
var current = Math.Abs(driftMs) > 5 ? hostNow : idealNow;
```

**修改后：**
```csharp
// ② 使用全局统一的时间基准（两设备共用，避免漂移）
DateTime last, current;
double driftMs;
lock (_globalLastLock)
{
    last = _globalLast;
    
    // 两种时间：主机"实测" + 按采样率推进的"理想"
    var hostNow = _t0.AddMilliseconds(_sw.ElapsedMilliseconds - _ts0);
    var idealNow = last.AddSeconds(n / _sampleRate);

    // ③ 轻微纠偏（例如 >5ms 时用主机时间，否则用理想时间，避免长期漂移）
    driftMs = (hostNow - idealNow).TotalMilliseconds;
    current = Math.Abs(driftMs) > 5 ? hostNow : idealNow;
    
    // ④ 原子更新全局时间基准（两设备共享，确保同步）
    _globalLast = current;
}
```

## 关键改进

1. **全局统一时间轴**：两个设备不再各自维护时间戳，而是共享同一个 `_globalLast`
2. **原子更新**：通过 `lock (_globalLastLock)` 确保两个设备的回调线程安全地更新全局时间
3. **协调纠偏**：两个设备的纠偏动作基于相同的全局状态，避免独立漂移
4. **保持推进逻辑**：仍然保留"理想时间"（按采样率推进）+ "5ms纠偏"机制，但基准统一

## 预期效果

1. ✅ 两个数采卡的曲线始终在同一X轴时间基准上
2. ✅ 长时间运行后（数小时/数天）曲线保持同步
3. ✅ 不影响现有的低延迟控制逻辑（fast分支）
4. ✅ 不影响现有的滤波/UI更新逻辑

## 验证方法

1. **短期验证**（5-10分钟）：
   - 启动采集，观察两个卡的通道曲线是否对齐
   - 查看UI曲线的时间戳是否一致

2. **长期验证**（数小时）：
   - 运行3-6小时，定期检查曲线同步性
   - 对比同一事件（如启动/断电）在两个卡的通道上的时间戳

3. **日志验证**：
   - 检查 `ErrorLog` 中是否有异常的 DAQ 回调节拍（通过 `TryLogDaqCallbackTiming`）
   - 两个设备的 `drift` 应该基本一致

## 注意事项

1. 修改后仍保留5ms纠偏阈值，防止长期累积漂移
2. 两个设备的回调可能不会完全同时到达（有几ms差异是正常的）
3. UI曲线的"批次间gap补偿"逻辑（`ApplyEngBatchToCurves`）仍然有效
