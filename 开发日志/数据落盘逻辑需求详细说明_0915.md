# EPB测试系统 - 数据落盘逻辑需求详细说明

## 系统概述

万向EPB测试系统控制12个EPB卡钳进行疲劳测试：
- **卡钳分组**：12个卡钳分为两组，每组6个
- **压力监控**：每组有一个压力传感器
- **夹紧力监控**：所有卡钳的夹紧力数据通过数采2采集

## 当前数据存储需求

### 1. 数据保留策略（新增需求）

**核心要求**：每次停止试验时，每个卡钳只保留最新的N组数据（默认10组）

**详细说明**：
- **可配置参数**：保留数据的组数应当可配置
  - 默认值：10组（即最新10次计数的数据）
  - 配置方式：通过配置文件或界面设置
  - 特殊选项：支持设置为"全部保留"（保持原有逻辑）

- **数据组定义**：
  - 一组数据 = 一次完整的EPB循环测试数据
  - 包含该次循环的所有采集数据（电流、压力、夹紧力等）

- **保留逻辑**：
  - 保留最新的N组数据（按计数序号倒序）
  - 删除或归档更早的数据
  - 例如：保留10组，卡钳完成5000次测试，则保留第4991-5000次的数据

### 2. 卡钳独立进度处理（重要需求）

**场景描述**：每个卡钳的测试进度可能不同，需要独立处理数据保留

**具体示例**：
- **预设目标**：所有卡钳计划完成10000次测试
- **实际情况**：
  - 卡钳1：在5000次时提前停止 → 保留第4991-5000次数据（最新10组）
  - 卡钳2-6：完成全部10000次 → 保留第9991-10000次数据（最新10组）

**处理原则**：
- 每个卡钳独立计算其最新的N组数据
- 不受其他卡钳进度影响
- 按各自的实际完成次数确定保留范围

### 3. 数据存储格式和结构

**推测的数据结构**（基于现有系统）：
- **文件组织**：每个卡钳独立的数据文件或数据库表
- **数据格式**：.raw文件 + 索引文件
- **数据内容**：
  - 循环计数序号
  - 电流数据（来自AI采集）
  - 压力数据（按组共享）
  - 夹紧力数据（来自数采2）
  - 时间戳
  - 测试状态标记

### 4. 数据清理和归档策略

**清理时机**：
- 试验正常停止时
- 试验异常终止时（可选）
- 手动触发清理

**清理方式**：
- **删除模式**：直接删除旧数据，节省存储空间
- **归档模式**：将旧数据移动到归档目录，保留完整历史

**安全措施**：
- 数据清理前进行完整性检查
- 提供数据清理确认机制
- 记录清理操作日志

## 技术实现考虑

### 配置参数设计
```xml
<!-- TestConfig.xml 中的新配置项 -->
<DataRetentionPolicy>
  <RetainLatestCycles>10</RetainLatestCycles> <!-- 保留最新N组数据 -->
  <RetainAllData>false</RetainAllData>        <!-- 是否保留所有数据 -->
  <CleanupMode>delete</CleanupMode>           <!-- delete/archive -->
</DataRetentionPolicy>
```

### 实现要点
1. **独立处理**：每个卡钳的数据保留逻辑独立实现
2. **异步操作**：数据清理使用异步方式，避免阻塞主线程
3. **原子操作**：确保数据清理过程的原子性
4. **日志记录**：详细记录数据清理过程和结果

### 兼容性保证
- **向后兼容**：默认配置下保持原有的"全部保留"行为
- **渐进迁移**：支持逐步启用新的数据保留策略

## 用户界面考虑

- 在测试设置界面添加数据保留策略配置
- 提供预设选项（保留10组、50组、100组、全部）

**监控界面**：
- 显示每个卡钳当前保留的数据范围
- 显示最后一次数据清理的时间和结果
