  项目中有两个类实现了FlushRawToDiskAsync方法，用于异步批量写入原始数据到磁盘：

  1. ClsDaqAIContext.FlushRawToDiskAsync (第175-275行)

  功能： DAQ数据采集卡的原始数据落盘

  核心特性：
  - 数据格式： 每个样本记录包含 int SaveRawCounter(4B) + long TimeFile(8B) + double[Channels] (8*Channels B)
  - 时间戳插值： 为批内每个样本生成独立时间戳，使用线性插值避免时间重复
  - 文件切换： 根据StoreTimeMinutes自动切换文件名
  - 缓冲预估： Lens * SamplesPerChannel * (4 + 8 + 8 * Channels) 字节

  关键实现：
  // 时间戳精确插值 (第217-229行)

      ? spanTicks / (double)recvSamples
      : TimeSpan.FromMilliseconds(1).Ticks; // 1kHz兜底

  // 关键：用(j+1)确保首样本时间>last，避免跨批重复
  var tsTicks = lastTicks + (long)Math.Round(stepTicks * (j + 1));

  异步写入优化：
  - 使用FileOptions.WriteThrough | FileOptions.Asynchronous
  - Buffer.BlockCopy进行高效内存拷贝
  - SemaphoreSlim rawFileLock确保线程安全

  2. ClsDeviceContext.FlushRawToDiskAsync (第141-228行)

  功能： CAN设备原始数据落盘

  核心特性：
  - 数据格式： int SaveCounter(4B) + long TimeFile(8B) + byte[RecvDataLens]
  - 设备标识： 按DeviceId区分不同CAN设备
  - 文件命名： EMB_CAN{DeviceId+1}_Raw_{FileCounter}.bin
  - 缓冲大小： Lens * (12 + RecvDataLens) 字节

  关键实现：
  // 简单的顺序写入 (第180-195行)
  for (int i=0; i<Lens; i++) {
      if(rawData.TryDequeue(out CanData canData)) {
          // 写入序号、时间戳、原始数据
          Buffer.BlockCopy(noBytes, 0, buffer, offset, 4);
          Buffer.BlockCopy(timeBytes, 0, buffer, offset, 8);
          Buffer.BlockCopy(canData.Data, 0, buffer, offset, RecvDataLens);
      }
  }

  共同设计模式

  1. 跳过首次写入： 两个方法都跳过第一次调用（SaveRawCounter <= 1），避免数据不完整

  2. 异常处理： 统一的错误日志写入模式，记录到专用log文件

  3. 资源管理： finally块确保锁释放和文件流释放

  4. 并发控制： 使用SemaphoreSlim保证单线程写入

  5. 性能优化：
  - 预分配缓冲区避免频繁内存分配
  - 批量写入减少I/O次数
  - 异步操作提高并发性能

  这两个方法体现了EPB测试系统中DAQ采集数据和CAN通信数据的不同落盘策略，DAQ侧重精确时间戳处理，CAN侧重设备数据完整性
  保存。

  SaveRawCounter的设计意图

  1. 文件完整性保护： 第一次调用时数据可能不完整，跳过保存避免脏数据
  2. 序号连续性： 写入文件时使用 Counter-1，确保从0开始的连续序号
  3. 数据同步标识： 每个数据块都有唯一序号，便于数据回放和校验

  文件中的数据结构：
  [序号:4字节] [时间戳:8字节] [数据:N字节]

  这个计数器机制确保了数据落盘的可靠性和可追溯性。
