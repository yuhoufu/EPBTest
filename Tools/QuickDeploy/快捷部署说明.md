# V2.14.2.0 正式包快捷部署说明

> 快捷部署修订：`QUICKDEPLOY_R7`
>
> 发布方式：正式包直接安装。软件不审批现场发布状态，实际运行、停用与验收由操作人员决定。

## 最短操作

1. 退出旧版试验程序，确认所有卡钳、液压、AO 和程控电源已经 OFF。
2. 将整个快捷部署包复制到远程工控机的本地磁盘；不要从网络共享目录直接运行。
3. 使用以后长期运行试验的 Windows 账号登录。
4. 双击 `一键安装正式版.cmd`，接受管理员权限提示。
5. 显示安装成功后，双击桌面的 `MT EPB 试验系统 V2.14`。

不需要手动启动 Watchdog、SessionAgent 或 SafetyAgent。

## 包内文件

```text
一键安装正式版.cmd     验证文件和 SHA256 后直接安装正式版
一键修复.cmd           修复服务、登录任务、ACL、双槽和快捷方式
一键卸载.cmd           卸载服务和任务，但保留程序、数据和事故证据
启动试验.cmd           启动已安装的主程序
检查运行状态.cmd       查看服务、Agent 和主程序状态
QuickDeploy-Installer.ps1 经外层哈希保护的安装/修复/卸载入口
Package\               不可拆分、不可单独替换文件的正式程序包
快捷部署包-SHA256.txt  外层传输校验
```

## 安装后的正常状态

运行 `检查运行状态.cmd`，应看到：

```text
监督服务：Running
登录代理：Running 或 Ready
```

安装目录固定为：

```text
C:\Program Files\MTTFTest\Current
```

服务和日志：

```text
服务：MTTFTestSupervisor
登录任务：MTTFTestSessionAgent
C:\ProgramData\MTTFTest\Supervisor\
C:\Users\<当前用户>\AppData\Local\MTTFTest\SessionAgent\
```

## 已取消的发布审批限制

- 安装不再要求 `FIELD_CANDIDATE_PENDING_168H`。
- 安装和主程序启动不再要求 `deploymentApproved=true`。
- `releaseStatus` 和 `gitDirty` 只作为包身份记录，不决定是否允许安装和启动。
- 操作人员可以显式把当前正式包晋升为 LastKnownGood，不再由软件强制要求 168 小时证明文件。
- `24/72/168` 小时记录仍可用于质量评价，但不再是软件启动门禁。

## 仍保留的安全底线

以下检查不能关闭，因为它们用于防止错包、篡改和不安全上电，不属于发布审批：

- 程序、DLL、配置和清单的 SHA256 必须与包内清单一致。
- 主程序及监督组件必须是 `V2.14.2.0`，槽路径和 DPAPI 封印必须有效。
- 任意恢复都必须先完成断电回读、旧进程退出证明和单实例接管。
- 确认的卡钳、液压或电路硬件故障仍保持最小域隔离，不自动重新上电。
- 文件确实损坏、版本混装或无法形成安全证明时仍会拒绝启动。

## 日常注意事项

- 必须复制整个部署包；禁止只复制 `MTTFTest.exe` 或某个 DLL。
- 安装时使用的账号必须是以后长期登录的生产账号。
- 无人值守期间可以断开远程桌面，但不要注销 Windows 用户。
- 不要连续双击主程序，不要手工结束 Supervisor、SessionAgent 或 SafetyAgent。
- 不要直接修改 `C:\Program Files\MTTFTest\Current` 中的程序或配置。
- 出现恢复窗口时等待自动处理；人工静音只关闭蜂鸣器，故障灯和锁存仍保持。

## 故障处理

安装失败：保存命令窗口内容。若提示哈希或版本不一致，应重新复制完整包，不要手改清单。

服务异常：运行 `一键修复.cmd`。

需要停止使用：先在主程序安全停止，再运行 `一键卸载.cmd`。

查看状态：运行 `检查运行状态.cmd`。
