# V4.1 受控文件修复入口实施记录

本次把一键包 `Repair` 接到文件安装器的实际修复流程；该入口代码已实现，**完整安装场景尚未验收，不能据此交付现场包**。

## 流程

1. 校验完整包、受保护的安装目录与逐文件原安装记录，修复包必须是同版本、同构建、同文件清单。
2. 从包内加载协议程序集，不依赖可能损坏的已安装 DLL；当前 PowerShell 已加载其他位置的同名协议时拒绝，要求新安装器进程。
3. 读取受保护注册文件，核验主程序/SafetyAgent 的规范安装路径、项目运行意图及已停止条件。保存维护状态并撤销旧启动凭证；活动批次及未完成安全收尾不能进入替换。
4. 按安装 ID、命令路径和 SYSTEM 身份核验独立服务，停止后限时确认；取得独立执行器租约，再次检查主程序与登记的旧会话辅助进程均已退出。
5. 执行已验证的文件替换事务。配置目录、数据库和未知文件类型不从包默认值恢复。
6. 用正常完整校验重新读取注册，修复服务/任务注册及快捷方式。服务保持维护停止状态，不自动恢复试验。明确启用与业务恢复验证仍为独立步骤。

## 损坏组件时的维护身份读取

新增 `IndependentExecutorRegistration.LoadTrustedForMaintenance`。仅跳过主程序和 SafetyAgent 的文件摘要验证，以允许修复这两个损坏文件；保留受保护路径、注册结构、状态目录身份、全部安全配置摘要、读取期间注册文件未变化的校验。它不授予启动许可。

原 `LoadTrusted` 的运行时完整校验保持不变。安装修复后的注册读取仍使用该完整入口。不能把维护读取成功当成设备可运行。
