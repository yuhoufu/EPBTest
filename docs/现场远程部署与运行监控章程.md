## 1. 目标、职责与授权边界

目标是安全完成跨版本原项目续测，保留真实业务进度和原始数据，捕捉自然发生的退出、停滞、保存及恢复异常，为后续版本修复提供可追溯证据。

- Codex 负责远程只读核查、准备备份和回退方案、经停机授权后的切换、只读监控、异常通知及记录。
- 用户确认停机窗口；现场安全状态无法通过可信遥测确认时，由现场人员核实断能、卸压等条件。急停必须人工复位。
- 现场 Supervisor 负责即时自动恢复。远程每五分钟检查不替代现场监督，不主动重启、强杀、挂起程序或注入硬件故障；故障注入测试须另行明确授权。
- 人工停止、正常退出、试验完成不自动续测。异常恢复必须满足安全、数据保存、运行身份及恢复许可条件；不得降低门槛以促使恢复。
- 未确认停机窗口前，不停止试验、不替换程序、不改现场配置、服务或任务。只读检查及在线备份也必须控制负载，发现影响采集或写盘时停止相关采集操作并记录。

## 3. 停机前只读核查与准备

### 3.1 建立现场基线

记录采集时间（带时区）、现场时钟偏差、主机名、主程序完整路径、文件版本及摘要、PID 和启动时间；同时记录 Supervisor、SessionAgent、sidecar、健康任务的实际路径、身份、状态和最近结果。任务成功退出不等于业务健康。

从项目配置、运行状态和持久化证据交叉核实项目标识、运行标识、各启用通道的目标次数、完成圈数、剩余次数、当前控制步骤、采样推进以及数据根目录、最新提交位置。界面计数与落盘计数分开记录，有差异先解释，不手工修改。

采集最近异常退出前后主程序日志、监督交接与恢复记录、相关 Windows 应用程序/服务/任务事件，核对退出意图、PID 变更及恢复结果。单凭任务事件或窗口消失不能判定根因；无法取得的证据明确列为缺项。

### 3.2 续测兼容性与备份

核对配置字段与现场参数、数据库或文件格式、圈数及检查点语义、恢复状态、监督 schema 和组件身份。发布记录中格式保持不变只是核对依据，不能替代 V2.14.2.11 到 V2.17.3.0 的实际兼容检查。

使用隔离副本验证可验证的读取和恢复条件；隔离环境不得连接真实硬件、注册现场监督实例或写入原项目。无法安全离线验证的项列为切换验收门槛。

备份旧程序完整目录、实际配置、项目数据及关联文件、Supervisor 配置和状态、服务与计划任务定义，记录各自原路径、备份路径、大小、时间及摘要。确认空间、备份可读性和恢复工具可用。在线复制的活动数据库不直接认定为一致备份；优先采用已有一致性机制，停机保存完成后补齐最终一致备份并校验。

回退步骤必须在停机前具体化到命令或操作入口、程序路径、服务/任务恢复方式和数据选择规则。监督持久状态可能包含过期许可，禁止直接回放旧运行许可；按匹配版本的受支持流程恢复组件。不得只写“换回旧版”。

### 3.3 提交停机窗口申请

准备完成后向用户提交：实际包身份、兼容结论及缺项、备份与回退路径、逐通道进度基线、切换步骤、预计停机时间范围和回退触发条件。停机估算包括正常停止与保存、最终备份、安装、恢复验证和回退预留；依据现场数据量及已验证操作耗时估算，不用测试机恢复秒数代替。

必须取得明确停机窗口确认并记录允许起止时间。窗口不足或条件变化时暂停切换并报告；无法确认断能、卸压或保存完成时不得继续部署。

## 4. 切换与回退

1. 复核主机、项目、安装包身份和授权窗口，记录切换前最后业务及持久化基线。
2. 通过正常操作入口停止试验，等待保存完成；确认安全断能、卸压及控制资源释放。保存失败或超时保持阻塞，不强制退出绕过保存。
3. 补齐最终一致备份，按已验证安装流程协调维护状态和监督组件，防止旧新实例同时接管。安装程序行为及覆盖范围必须提前核实。
4. 部署已核验的包，恢复经核对的现场配置；核验安装后的完整路径、版本、组件摘要、服务及任务身份。
5. 打开原项目并通过受支持入口续测。按各通道核对正式圈数、剩余次数、采样、控制步骤和持久化提交持续推进，解释合法的重新学习阶段及任何计数差异。
6. 至少取得连续两次有效业务提交证据，并覆盖一次当前合法步骤推进；记录恢复前后提交位置与圈数。窗口打开、进程存在或许可批准均不算恢复成功。
7. 对账成功后记录监控起点 T0，启动第 5 节规定的 24 小时观察。

无法正确续测、计数不明、数据保存失败或安全条件不满足时，立即停止继续变更，保持安全状态，保存新版运行与错误证据，执行已准备且适用的回退方案。

回退恢复旧程序及匹配配置、服务和任务；新版已产生的数据必须单独保留。若旧版不能安全读取最新状态，不把旧备份覆盖回原数据目录，也不回退计数后重测掩盖差异，应保持安全停止并通知用户。回退后仍须重新核实身份、安全条件和业务对账；不满足条件不得续测。禁止擅自清零圈数、重建项目或跳过安全检查。

## 5. 每五分钟只读监控与异常取证

### 5.1 周期与判断

从 T0 起每五分钟检查一次，持续至 T0+24 小时。记录任务标识、实际首次触发及预计结束时间，检查有界超时，避免检查重叠。创建失败、调度中断或连接失败必须报告监控不可用；不得声称持续值守或保证五分钟内一定发现异常。

| 对象 | 每次检查证据 |
| --- | --- |
| 主程序 | 路径、版本、PID、启动时间、退出意图、是否存在重复实例 |
| Supervisor / sidecar / SessionAgent | 精确进程身份、健康响应、监督循环进度、恢复阶段与结果 |
| 健康任务 | 注册状态、最近触发与结果、维护抑制及失败原因 |
| 业务 | 项目和运行标识、逐通道圈数、剩余次数、控制步骤、采样推进 |
| 保存 | 实际持久化路径、提交位置或检查点、队列积压、保存错误及可用空间 |

停滞阈值在部署前按项目配置和现场基线填写：当前步骤最大合法等待时间、采样最大允许无进展时间、保存提交最大允许间隔、恢复阶段允许预算及判断来源。缺少阈值时标记判断受限，不宣称业务正常。单次圈数未变、文件时间改变或文件增大都不能单独判定停滞或保存成功。

正常时静默，仅保存轻量检查快照。人工停止、正常退出和试验完成记录为明确终态，不自动续测，也不误报为异常退出；监督异常和监控不可用仍独立判断。

### 5.2 告警与恢复记录

异常退出、超过对应预算的进度停滞、保存失败、恢复失败或监控失联时，在当前 Codex 任务通知用户。通知包含异常编号、首次发现和最后正常时间、主机与项目、版本和运行身份、进度差异、现有安全证据、Supervisor 恢复阶段及证据位置。区分已证实事实、推断和待核实原因。

同一异常首次通知后，仅在状态变化、恢复成功、恢复失败或需要人工处理时追加通知，避免每五分钟重复相同告警。若检查间隔中曾退出但已恢复，仍依据日志记录并通知该异常及恢复结果。

远程常规检查保持只读；Supervisor 自恢复失败后，按第7节的用户追加授权进行有条件介入。只有采样、控制和持久化重新推进且进度对账通过，才记录恢复成功。人工意图或急停阻断时保持阻断，不视为必须消除的错误。

### 5.3 证据保全与结束

异常时增量采集相关时间窗口的日志、监督状态和 Windows 事件；关联主机、项目、RunId、通道、PID 与启动时间，保留原始错误和恢复结果。记录文件来源、大小、采集时间、范围/偏移、摘要和截断标记；不把尾部片段当作完整日志。对活动文件采用兼容写入和替换的共享读取方式，限制读取量和时长，不锁住生产数据。

文档记录放在 `docs/02_Issues/`，建议使用日期、主机和项目组成文件名；截图放在记录旁的 `截图/` 中并用相对链接。大体积原始日志和数据留在已记录的证据目录，不提交仓库。无法取得桌面截图时记录限制，不据此伪造界面状态。

到 T0+24 小时停止本轮定时任务，提交观察报告，列出实际成功检查次数、缺测区间、自然异常、恢复结果与未验收项。未解决异常明确交接，不自行无限延期监控。
