# V4.1.0.0 候选包安装、升级、回退与验收说明

## 使用边界与源码身份

这是独立 SYSTEM 执行器候选包。本轮用于 jxcq 隔离验证，不自动部署 WJ-EPB。真实主程序从启动预检、自学习到正式动作恢复的整链验收及真实硬件验收尚未全部完成。

版本、二进制源码提交和安装脚本提交以 `automatic-bundle.json` 为准；`candidateTag` 表示候选标识，`candidateTagExistsAtPackaging` 明确打包时是否已经存在对应 Git 标签。标签存在时必须指向二进制构建源码。压缩包 SHA-256 在同目录 `.sha256.txt` 中，完整解压后再操作。

本轮新增修复包括：监控完整初始化后才进入恢复；单通道人工暂停同步到独立恢复目标；主程序 AO 安全归零直接写入 0 V。对应分析文档随包提供。不能据这些修复宣称 NI 底层采样中断已消除。

## 文件与组件

保留 Base、automatic-bundle.json、Install-AutomaticRecoveryBundle.ps1、RecoveryGuard-Acceptance.ps1 和原有中文 cmd。FallbackGuard 与 Tools 保存独立执行器及维护脚本；新增检查升级、升级、继续收尾、恢复中断事务和回退 cmd。

独立服务使用 SYSTEM，负责监督、持久事务及精确接管；交互启动任务负责以指定登录账户拉起主程序窗口。安装、修复、升级成功不等于恢复成功，维护结束后须显式启用监督。

## 操作前准备

1. 保留原构建完整安装包、原安装路径及项目封盘；不要覆盖原包。
2. 将新包解压到本机独立目录。校验压缩包哈希并执行 ValidatePackage；该检查不启动试验，也不验证真实硬件。
3. 有运行试验时先人工停止，等待安全收尾并退出旧控制程序。安装器不会通过忽略原协议或猜测身份来覆盖正在运行的会话。
4. 准备真实项目目录、受保护的安装目录和交互用户 SID。SID 可由目标登录账户执行 `whoami /user` 查看。不得直接复制文档占位值。

以下示例均在解压目录的管理员 PowerShell 中执行。命令里的路径仅为占位示例；项目数据库、计数、配置不应人为修改。

```powershell
.\Install-AutomaticRecoveryBundle.ps1 -Mode ValidatePackage
```

## 首次安装

InstallRoot 必须不存在，父目录需受保护。不能拿首次安装覆盖旧安装。

```powershell
.\Install-AutomaticRecoveryBundle.ps1 -Mode Install -InstallRoot 'C:\Program Files (x86)\MTTFTest' -ProjectDirectory 'D:\实际项目目录' -InteractiveUserSid '实际交互账户SID'
.\Install-AutomaticRecoveryBundle.ps1 -Mode Status -InstallRoot 'C:\Program Files (x86)\MTTFTest'
```

Install 注册服务、任务和快捷方式后保持维护停止。确认安装状态无错误后显式启用监督，再打开主程序：

```powershell
.\Install-AutomaticRecoveryBundle.ps1 -Mode Restore -InstallRoot 'C:\Program Files (x86)\MTTFTest'
.\Install-AutomaticRecoveryBundle.ps1 -Mode Launch -InstallRoot 'C:\Program Files (x86)\MTTFTest'
```

Restore 不清除人工停止/暂停意图。首次 Launch 打开主程序，不自动替操作员选择通道或点击开始；明确选择目标并开始后才建立持久运行意图。自动故障接管使用独立一次性凭证启动，不能通过普通 Launch 绕过活动恢复事务。

## 已安装版本升级

保留旧完整包，使用新版包执行；同版本修复使用 Repair，不冒充版本升级。

```powershell
.\Install-AutomaticRecoveryBundle.ps1 -Mode ValidateUpgrade -InstallRoot 'C:\Program Files (x86)\MTTFTest' -PreviousBundleDirectory 'D:\旧构建完整包'
.\Install-AutomaticRecoveryBundle.ps1 -Mode Upgrade -InstallRoot 'C:\Program Files (x86)\MTTFTest' -PreviousBundleDirectory 'D:\旧构建完整包'
```

核对 Upgrade 目录下 result.json 的阶段，只有 Completed 才表示该升级事务完成。核对主程序版本、组件摘要及快捷方式版本。仍保持维护停止，需要试验时按前节显式 Restore、Launch，再明确开始。

若阶段为 FinalizationFailed，保留证据后使用本次 Upgrade 目录的32位事务ID继续收尾：

```powershell
.\Install-AutomaticRecoveryBundle.ps1 -Mode FinalizeUpgrade -InstallRoot 'C:\Program Files (x86)\MTTFTest' -TransactionId 'Upgrade目录中的32位事务ID'
```

## 修复与文件事务中断

同构建包 Repair 可修复组件、服务、任务和快捷方式，保留项目与配置，完成后仍维护停止。

```powershell
.\Install-AutomaticRecoveryBundle.ps1 -Mode Repair -InstallRoot 'C:\Program Files (x86)\MTTFTest'
```

文件事务中断时，先核对 Repair 目录 transaction.json；RecoverFiles 使用 **Repair 文件事务ID**，与 Upgrade 事务ID不同。只用于已记录、可验证的中断事务，不能猜 ID，也不能把它当作撤销成功升级。

```powershell
.\Install-AutomaticRecoveryBundle.ps1 -Mode RecoverFiles -InstallRoot 'C:\Program Files (x86)\MTTFTest' -TransactionId 'Repair目录中的32位事务ID'
```

## 回退旧版

从本次新版完整包执行，提供升级时的旧包和 Upgrade 事务ID。只恢复经摘要与备份验证的组件及注册，不回退项目数据库或试验计数。

```powershell
.\Install-AutomaticRecoveryBundle.ps1 -Mode RollbackUpgrade -InstallRoot 'C:\Program Files (x86)\MTTFTest' -PreviousBundleDirectory 'D:\原构建完整包' -TransactionId 'Upgrade目录中的32位事务ID'
```

核对 RolledBack、实际主程序版本及旧快捷方式；仍维护停止。重复同一回退事务应幂等；失败时保留事务记录及日志，不手工替换数据库或删掉授权文件。

## 停止、采证和卸载

```powershell
.\Install-AutomaticRecoveryBundle.ps1 -Mode Stop -InstallRoot 'C:\Program Files (x86)\MTTFTest'
.\Install-AutomaticRecoveryBundle.ps1 -Mode Status -InstallRoot 'C:\Program Files (x86)\MTTFTest'
.\Install-AutomaticRecoveryBundle.ps1 -Mode Evidence -InstallRoot 'C:\Program Files (x86)\MTTFTest'
.\Install-AutomaticRecoveryBundle.ps1 -Mode Uninstall -InstallRoot 'C:\Program Files (x86)\MTTFTest'
```

Stop 的“受理”不代表安全收尾已完成；核对 SafetyCleanupPending、阶段和错误。Uninstall 仅删除该安装有记录且摘要匹配的组件，注销其服务、任务和快捷方式，保留项目、配置及必要维护证据。它不是版本回退，也不会递归清空安装或项目目录。未知修改会保留并报错。

中文 cmd 可在具备参数时双击使用；首次安装、升级和事务恢复所需参数不能靠双击猜出，应按上述 PowerShell 命令传入。不要在压缩包内部执行 cmd。

## 验收与未完成项

安装层检查：版本/快捷方式一致、服务和任务正确注册、维护停止可控、卸载/修复/回退可重复，测试资源可精确清理。

业务恢复必须同时满足：唯一新进程、正确目标集合、旧授权失效、新监督绑定、动作恢复、机械计数推进、每个目标至少三个正式周期落盘。人工暂停/取消勾选/已完成/永久隔离通道不应被自动恢复。进程存活、服务启动、心跳正常和安装退出码 0 均不能替代该验收。

jxcq 已有模拟硬件下的独立重启、单/部分/全部停滞、单通道人工暂停及安装升级回退证据。真实主程序操作与硬件闭环、实物电源/DO/AO/压力和长时耐久仍须后续验收，不能将这些模拟结果当作真实台架通过。本轮不打断 WJ-EPB 当前试验，不检测 CAN，不重置计数，不绕过安全联锁。
