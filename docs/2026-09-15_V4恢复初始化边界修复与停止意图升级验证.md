# V4 恢复初始化边界修复与停止意图升级验证

## 结论与适用范围

本轮发现并修复主程序恢复入口的初始化判定缺口：控制器对象非空不代表监控初始化成功。此项是代码审查确认的缺陷，不是已由现场线程栈证明的 I0016/I0017/I0018 停机根因。不能据此宣布 DEV 未回调问题已消除，也不能宣布整个独立续测链路已完成验收。

## 缺陷及修复

`FrmEpbMainMonitor_Load` 在创建 `_epb` 后，仍需绑定记录器、应用配置、启动采集并注册独立恢复回调；这些步骤可能失败。旧恢复入口只轮询 `_epb` 和 `_cfg` 是否非空，原 Watchdog 就绪方法同样可能用对象存在判定成功。`OnShown` 原先又在 Raw 管线和无人值守恢复订阅之前发布就绪。

改为每个窗体独立的 `MonitorInitializationGate`：Load 全部必要步骤完成以及 Shown 全部订阅完成，两项都满足才放行。失败或关闭永久撤销该窗体就绪结果，晚到完成信号不能复活它；等待超时只结束该次等待，不破坏后续正常初始化。Load 提前返回也进入初始化失败状态。

独立恢复、原 Watchdog 恢复、安全空闲重启及检查点恢复统一等待该结果。采用既有 Watchdog 就绪等待默认值 30 秒；该异步等待不声称能中断卡死的 UI 或硬件调用，外部执行器的阶段期限仍负责此类故障。
