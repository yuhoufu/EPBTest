# 10243-028 液压管路故障组隔离修复实施及验收记录

## 1. 事件与目标

- 软件版本：V2.13.0.44，事件编号 I0012。
- 数据封盘：`D:\EPB_Data\Backups\10243-028_V2.13.0.44_I0012_0901_1030`。
- 现场最终结论：卡钳 11 机械损坏漏液，导致液压 2 不能建压/保压。
- 软件证据的可靠诊断边界是“液压 2 共享管路低压”；程序不得仅凭共享压力推断具体漏液卡钳。

修复目标是把可证明已断能的局部液压故障限制在配置所属组。液压 2 故障时，EPB7–EPB12 中本次启用成员停止并报警，液压 1 保持原 RunId、定时器、采集和正式圈节律继续运行；只有物理断能不可证明、全局 DAQ 连续性不可证明或进程控制权丢失时才升级到全局 StopAll/Watchdog。

## 2. 旧故障链

```text
卡钳11漏液 → 液压2新鲜低压 → 启动组内软件恢复
→ EPB11旧圈错误使用新DAQ代次封口 → Persistence=False
→ 正式槽全局撤权/StopAll → Watchdog接管
→ Safety Agent无法确认电源OFF → 自动恢复已阻断
```

旧逻辑把已经完成 `MotorOff=True`、`HydraulicReleased=True` 的局部数据封口问题传播为全局安全边界失败，使健康液压组被一并停止，并用上层 `UnhandledSoftwareStartup` 遮蔽了首发液压原因。

## 3. 已实施状态机

1. 液压低压必须来自新鲜压力样本。第一次、第二次独立代次失败均立即冻结故障组，撤销组内执行权，执行 EPB DO OFF、液压 DO OFF、AO 置零并确认释压；只启动组内有界恢复，不发布全局故障。
2. 一次合格建压并完成有效保压/释压代次后，连续失败计数按现有协调器规则清零。
3. 第三次新鲜低压失败由现有 `HardwareConfirmed` 分类锁存为组级 `AlarmStopped`，停止该组自动恢复并持续报警。配置全成员和本次启用成员均写入诊断；健康组继续运行。
4. 故障原因明确提示共享管路不能自动唯一定位具体卡钳，要求检查组内成员。
5. 组级安全隔离成功后，正式槽的数据终态交由液压恢复事务处理；只要电机 OFF 或液压释压任一不可证明，仍保持原全局接管边界。

## 4. 数据口径与跨代次封口

- 圈开始时冻结 DAQ 设备、DAQ 代次和起始序号，不再在故障恢复换代后用新代次封旧圈。
- 液压恢复冻结时，对组内在途圈完成已有样本的有界落盘，并提交独立终态 `AbortedByHydraulicGroupFault`。
- 作废圈不增加正式完成圈数、机械完成数和自适应有效样本；维修恢复后从剩余目标继续。
- 正式槽仅在“液压恢复拥有该通道且电机 OFF、液压已释放”时把持久化责任委托给组内事务，防止 `CycleWindowUnsealed` 误触发全局 StopAll。
- 健康组不切换 DAQ 代次、不冻结持久化管线、不关闭其程控电源。

## 5. 操作员界面与恢复行为

- 主窗体保持打开，组内通道显示液压硬件故障和 `AlarmStopped`；诊断包含液压组、配置成员、启用成员、压力证据及共享管路排查提示。
- “暂停→继续试验”不增加确认框。健康组先按既有流程恢复，随后 `ResumeInfrastructureAlarmGroupsAsync` 对报警液压组整组执行 DAQ、电源、建压、两轮保压/释压资格复核。
- 复核通过：清除本次运行的组级锁存和报警，整组按下一公共正式槽重新加入。
- 复核失败：故障组再次强制释压、断电并保持报警；失败被限制在该组，健康组继续运行。
- “停止→重新开始”继续使用既有完整预检。历史报警证据保留，但本次运行锁存不是永久配置禁用；维修后成功预检即可解除。
