# 10358-029 V2.11.0.16 彻底整改实施记录

## 1. 结论

- 现场异常版本：V2.11.0.13。
- 代码整改基线：V2.11.0.15。
- 修复发布版本：**V2.11.0.16**。
- 原始分析：[10358-029 V2.11.0.13 运行异常日志分析](../01_Inboxes/2026-08-08_10358-029_V2.11.0.13运行异常日志分析.md)。

本次整改没有放宽电流峰值偏差、压力容差或连续确认次数，而是消除了以下软件缺陷：

1. DAQ“已恢复”事件能够抢在整组截止清理完成前进入验证和共同重入。
2. 旧恢复代的迟到清理能够删除新恢复代的液压参与状态或压力租约。
3. 同液压组成员不是原子重入，存在 EPB4 已公开、EPB5 尚未公开的中间状态。
4. 恢复完成状态早于共同槽重入提交，人工停止可能与恢复提交互相覆盖。
5. 快速峰值与完整峰值使用了不同的证据时间窗，断电后的迟到样本可能被误计为硬偏差。
6. 人工停止取消自动恢复后，界面仍可能保留“自动恢复失败/启动受阻”。

现场分别暂停和开始 EPB4、EPB5 后恢复正常，是因为该操作重建了两通道的定时器和液压参与状态；V2.11.0.16 将这一临时人工恢复过程固化为自动、原子、可校验的恢复事务。

## 2. 恢复状态机整改

DAQ 恢复现在只能单向经过以下阶段：

`Created → CutoffStarted → CutoffCompleted → ValidationReady → Validating → Rejoining → RejoinCompleted → Committed`

失败或人工停止进入 `Terminal`，不能再回到前一阶段。

### 2.1 整组截止屏障

恢复开始时先冻结受影响通道的液压参与版本，随后等待每个通道完成：

- 定时器暂停和当前周期取消；
- 高优先级断电；
- 旧参与状态按版本移除；
- 旧压力租约释放；
- 安全去能确认；
- 采样时间线重新同步。

所有异步释放任务都完成后才提交 `CutoffCompleted`。即使 DAQ 恢复通知先到，也只能等待，不能越过屏障。

DAQ 无需重建时，截止完成后开放验证；DAQ 需要重建时，只有 `RecoverDevice` 成功并接受新采集代次后才进入 `ValidationReady`。这避免了使用旧任务或半重建任务完成验证。

### 2.2 恢复代和迟到清理防护

每次加入液压参与集合都会生成单调递增的 participant version。旧清理只有在“当前版本仍等于它启动时捕获的版本”时才允许移除成员。

压力租约释放也从“按键删除”改成“按键值对精确删除”：迟到的旧租约释放不能删除相同键下的新租约。

因此以下原异常顺序已被阻断：

`共同重入 [4,5] → EPB5 旧清理迟到 → EPB5 被移出参与集合`

### 2.3 同组原子重入和提交

共同重入在液压组锁内完成：

1. 删除全部旧定时器；
2. 为全部成员计算同一未来正式槽；
3. 在启动任一定时器前，先登记全部成员的液压参与状态；
4. 启动全部新定时器；
5. 校验参与快照包含全部预期成员，并记录 `Invariant=Passed`；
6. 完成 `RejoinCompleted` 后，才提交恢复完成和 Running 状态。

任一步失败都会回滚本次新定时器和新参与状态，不向调度器公开部分恢复结果。

共同重入与终态提交使用同一提交锁；人工停止取消也使用该锁。结果只有两种：完整恢复提交，或人工停止提交，不再出现两者交错覆盖。

## 3. 图一整改

### 3.1 EPB8 峰值证据时间窗

快速控制路径现在保存它实际已经观察到的证据截止时刻。完整数据收尾只用于排空截止前已在途样本，不再把断电后的 100 ms 扩展成新的峰值采集窗口。

只有完整峰值的时间戳落在快速决策证据窗内，才允许比较两者并累加硬偏差连续次数。晚到且超出决策窗的峰值记录为 `PeakEvidenceLagWarning`，不会推进 `PeakEvidenceMismatch` 硬故障计数。

原有 1.000 A 容差和连续 3 次确认策略保持不变，真实同窗峰值偏差仍会正常报警。

### 3.2 人工停止分类

- `ManualUi` 触发的恢复取消明确记录为 `ManualCancelled`。
- 通道终态发布为 `ManualStopped`，允许覆盖上一轮锁存的 `StartBlocked`。
- 界面显示“已由人工停止取消/人工停止”，不再将预期的 `OperationCanceledException` 显示为新硬件启动失败。
- 历史原因和关联号仍保留在日志中，未丢失审计信息。

## 4. DAQ 积压可观测性

`BackgroundQueueFull` 日志新增：

- 实际队列深度；
- 队列容量；
- 最老批次年龄。

这些指标用于区分瞬时生产峰值、消费者变慢和磁盘/证据处理阻塞。队列容量未盲目扩大，避免只延后样本陈旧和安全联锁。

## 7. 现场发布验收

V2.11.0.16 上线后需要保留一轮现场故障注入或等效台架验证，满足以下条件才结束观察：

1. 模拟 Dev1 队列积压/DAQ 重建，日志必须先出现整组截止完成，再出现验证和共同重入。
2. 共同重入日志包含 `Members=[4,5]`、相同正式槽和 `Invariant=Passed`。
3. 不得再出现共同重入完成后，同恢复代对 EPB4/5 执行旧参与状态移除。
4. EPB4/5 连续 100 个周期每个 15 s 周期只建立一次 H1 压力。
5. EPB4/5 动作间隔保持 800 ms 附近，建议验收带 700～900 ms，不出现持续 2～3 s 偏差。
6. 自动恢复中点击“停止全部”，界面应显示人工停止，不出现虚假的自动恢复失败或启动受阻。
7. EPB8 若再出现硬峰值偏差，必须能证明快速峰值与完整峰值属于同一证据时间窗；迟到窗外峰值只记录证据延迟预警。

## 8. 发布与回退说明

- 发布版本：V2.11.0.16。
- 不需要修改项目安全参数或现场液压配置。
- 若现场发现新的安全回归，应整组安全停止并回退到上一已验证版本；不要通过扩大峰值容差、压力容差或队列容量规避故障。
- V2.11.0.13 的“同组分别暂停后再开始”仍可作为旧版本临时处置，但 V2.11.0.16 正常情况下不应再依赖人工重建共同节拍。

---

**整改结论：** V2.11.0.16 已在代码层关闭 DAQ 恢复早到、旧代清理迟到、同组非原子重入、人工取消误分类和峰值跨窗误比较五条故障链。EPB4/5 恢复后只会以同一液压成员快照和同一未来正式槽对外提交，避免再次形成两个压力代次。
