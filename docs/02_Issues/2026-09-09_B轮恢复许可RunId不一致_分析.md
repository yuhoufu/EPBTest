## 代码路径

WatchdogHost.ApproveRelaunchPermit：优先_journal.RunId，为空时退到LastCheckpointMirror.RunId。StopCompleted后日志RunId为空，旧检查点仍为初始Run；独立RecoveryControl意图已更新到重建后的2d6867…，形成不同来源不一致。现场事件未直接记录函数最终传入参数，最终入参需通过回放测试确认，不能只凭事件顶层空RunId断言函数实际传入空串。

StrictHostRelaunchOrchestrator.RegisterFailure → WithLegacyPermitAdmission → RecoveryControlStore.RunLegacyRecoveryAuthorityMutation。最后一层同时要求Session一致、SameRolloverRun为真；不满足则抛出已记录的原因。Main的ArmApplicationExitDeadline等待Approved许可2秒，取不到则拒绝退出，属于下游保护行为。

## 修复与验证方向

1. 回放“学习重建改变Run → StopCompleted清空活动Run → 旧检查点未更新 → 审批许可”顺序，明确许可申请身份来源。
2. 在受控恢复事务中保留并使用可验证的当前运行身份；不要默认从旧检查点、任意最后Run或当前授权中不加核验补值。
3. 保持人工停止、不同会话、不同PID/启动时间、不同授权及Guard已接管时拒绝旧许可。
4. 增加上述正向回放和拒绝用例，在JXCQ运行匹配组件后才重新打包；没有修正前不再次现场安装同一包。

持久化积压是更早触发因素，尚未唯一定位底层原因；低C盘空间、落盘延迟、DAQ恢复和Run传递需要分别分析。I0050液压发布一致性仍为第二步，不在本轮推断中强行合并。
