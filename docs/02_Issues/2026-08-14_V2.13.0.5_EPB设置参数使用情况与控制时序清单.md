# V2.13.0.5 EPB 设置参数使用情况与控制时序清单

> 核查日期：2026-08-14  
> 核查对象：当前工作区源码，程序集版本 `2.13.0.5`  
> 当前正式控制模式：`AdaptiveCurrent`，12 路全部启用，`AdaptiveShadowMode=false`  
> 主要配置样本：`D:\EPB_Data\10358-029\Config\TestConfig.xml`

## 1. 结论

### 1.1 EPB 设置表格中的参数没有全部用于当前控制

当前界面实际创建 13 列：`通道`、`名称`、`目标次数`，以及 10 个每通道 EPB 参数。当前正式试验强制使用 `AdaptiveCurrent`，因此不能按旧的 `LegacyFixedTiming` 路径判断字段是否有效。

结论如下：

| 分类 | 字段 | 当前 V2.13.0.5 结论 |
|---|---|---|
| 当前直接或条件生效 | `Channel`、`TargetTotalCount`、`ForwardA`、`SafetyMarginA`、`HoldMs`、`RevDecayLimitA`、`RevDecayRigidMaxMs`、`PreReleaseKeepMs`、`PreReleaseDetectTimeoutMs`、`PeakIgnoreMs` | 保留并使用；部分字段只在首次学习、无稳定模型或启动定位阶段生效 |
| 当前控制冗余 | `FwdOnLimitMs` | `AdaptiveCurrent` 正式圈不使用；启动定位只记录为审计值，不作为上电上限。仅旧控制路径使用 |
| 当前控制冗余 | `RevEmptyFixedMs` | `AdaptiveCurrent` 正式圈不执行固定反向空行程延时。仅旧控制路径使用 |
| 仅标识、不参与控制 | `Name` | 用于界面/XML 标识，不参与电流、方向或时序决策 |

因此，如果软件继续强制全部通道使用 `AdaptiveCurrent`，建议从 EPB 设置表中删除或明确标灰：

1. `正上限时长(ms)` / `FwdOnLimitMs`；
2. `反向固定空行程(ms)` / `RevEmptyFixedMs`；
3. `名称`可以保留，但应注明“仅显示标识，不参与控制”。

### 1.2 存在未在 EPB 设置界面展示、但实际生效的参数

最重要的是以下四组：

1. `TestConfig.xml/Basic/LearnCycle`：学习圈数，当前项目为 10；界面没有编辑控件，但批量启动实际使用。
2. `TestConfig.xml/ElectricalGroups/Group/StaggerMs`：组内上电错峰，当前为 800 ms；界面没有展示。
3. `TestConfig.xml/Hydraulics/Hydraulic`：除启用和目标压力外，还有建压、稳压、释压、超时、同步屏障等大量控制参数未展示。
4. `MTTfTest/App.config` 中 12 个程序级 EPB 安全参数：正式自适应控制实际读取它们，界面没有展示。

### 1.3 配置模型中还存在 8 个“旧项目兼容影子字段”

`EpbCycleRunnerConfig.Record` 和 `EpbRow` 仍定义：

- `ForwardProgressConfirmMs`
- `ForwardMinimumRiseSlopeAperMs`
- `ForwardProgressDeadlineMs`
- `ReverseProgressConfirmMs`
- `ReverseMinimumDecaySlopeAperMs`
- `ReverseProgressDeadlineMs`
- `OffCurrentClearThresholdA`
- `OffCurrentClearTimeoutMs`

它们不建表格列，用户看不到。加载器会兼容读取旧项目值，界面保存时也会在内存中重新组装这些字段；但是 `ConfigLoader.SaveTest` 明确不再把它们写回项目 XML，当前 Runner 也不使用项目中的这些值，而是使用 EXE 同名 `App.config` 的程序级值。

这 8 个字段属于容易误导维护人员的兼容残留，不应再当成可用的项目参数。

## 3. 界面中全部参数逐项说明

## 3.1 基础信息区

| 界面名称 | 配置字段 | 是否使用 | 详细作用 |
|---|---|---:|---|
| 试验名称 | `TestName` | 是 | 项目身份、项目路径选择、日志/检查点/报告标识，不直接改变卡钳动作 |
| 周期 | `TestCycle` / `TestPeriod` | 是，核心 | 单位为秒；转换为 `PeriodMs` 后决定相邻计划圈的时间轴，并参与自适应正、反向绝对上电上限计算 |
| 目标次数 | `TestTarget` | 是 | `all` 勾选时作为 12 路统一目标；也是每通道目标为空时的回退值 |
| all | `IsSameCycleForAllEpb` | 是 | 决定是否用全局 `TestTarget` 覆盖/补足每通道 `TotalCount` |
| 负责人 | `Owner` | 是，但不控制动作 | 保存项目责任人，供日志/报告使用 |
| 存储路径 | `StoreDir` | 是，但不控制动作 | 决定项目和试验数据保存根目录 |
| 描述信息 | `Description` | 是，但不控制动作 | 项目备注，不参与运行判定 |

### 周期的实际含义

`PeriodMs = round(TestCycle × 1000)`。周期不是“正向上电时间”，而是正式圈的计划启动间隔。当前 `TestCycle=15 s`，所以 `PeriodMs=15000 ms`。

在当前自适应模式下，它还派生两个硬上限：

```text
正向绝对上电上限 = min(10000, max(6000, ceil(PeriodMs × 0.60)))
反向绝对上电上限 = min( 5000, max(2000, ceil(PeriodMs × 0.35)))
```

当前 15 s 周期得到：正向 9000 ms，反向 5000 ms。

## 3.2 EPB 设置表格

| 界面列 | 字段 | 当前是否用于控制 | 生效阶段与规则 | 当前项目磁盘值 |
|---|---|---:|---|---:|
| 通道 | `Channel` | 是 | 1..12 的主键；决定 DO、DAQ、电源组、液压组和自适应画像的映射 | 1..12 |
| 名称 | `Name` | 否（控制） | 仅作为 `EPB1` 等界面/XML 标识；当前运行链不读取 `rcfg.Name` 做控制 | EPB1..EPB12 |
| 目标次数 | `TargetTotalCount` → `EpbRecords.TotalCount` | 是 | 每路剩余正式圈数=`TotalCount-RunCount`；成功完整圈才扣减/计数 | 100000 |
| 夹紧目标(A) | `ForwardA` | 是，核心 | 正向目标电流；用于预测断电、合格下限、过冲/欠冲判断 | 15 A |
| 首次提前量(A) | `SafetyMarginA` | 是，但属种子值 | 尚无断电预测模型时，预测提前时间约为 `SafetyMarginA/上升斜率`，且最多 100 ms；有稳定断电预测后改用画像中的提前时间 | 2 A |
| 正上限时长(ms) | `FwdOnLimitMs` | **当前冗余** | 自适应正式圈不使用；启动定位明确只记作 `ProjectForwardLimitMs(audit-only)`；旧固定时序路径才用它限制正向等待 | 5000 ms |
| 夹紧保持(ms) | `HoldMs` | 是，核心 | 正向终态断电后、反向上电前的保持时间；配置 `<=0` 时 Runner 创建阶段强制回退为 1000 ms，所以无法通过填 0 真正取消保持 | 1000 ms |
| 反向衰减限(A) | `RevDecayLimitA` | 是，核心 | 自适应反向释放的项目阈值；下限在运行时钳制到 0.1 A；同时参与启动定位释放判定 | 3 A |
| 反衰限制时长(ms) | `RevDecayRigidMaxMs` | 条件生效 | 正式圈无稳定反向画像时，作为反向“无模型进展期限”；有稳定画像后改由程序期限和画像计算。若预释放判定超时为空，它还通过 `max(3000, RevDecayRigidMaxMs)` 影响启动定位绝对反向时限 | 1000 ms |
| 反向固定空行程(ms) | `RevEmptyFixedMs` | **当前冗余** | 当前自适应反向在状态机确认释放完成后立即断电，不再额外执行固定空行程延时；仅旧固定时序路径执行 | 2000 ms |
| 预释放维持(ms) | `PreReleaseKeepMs` | 是 | 启动定位检测到反向释放完成后，继续保持反向输出的时间；为空回退 500 ms | 500 ms |
| 预释放判定超时(ms) | `PreReleaseDetectTimeoutMs` | 是 | 启动定位反向绝对上电上限；运行时至少 500 ms。为空时回退 `max(3000, RevDecayRigidMaxMs)` | 空；实际 3000 ms |
| 峰值忽略(ms) | `PeakIgnoreMs` | 是 | 上电涌流忽略窗口。项目值先钳制到 `>=0`；正式自适应监控又执行 `max(100, PeakIgnoreMs)`，因此小于 100 ms 的设置在正式圈不会缩短窗口 | 100 ms |

### 两个当前冗余字段的代码证据

`FwdOnLimitMs` 在启动定位中被读取，但 `ResolveStartupForwardTiming` 的注释和实现明确说明项目值仅审计，实际限制来自周期、程序级期限和学习画像：[`Controller/EpbCycleRunner.StartupPositioning.cs`](../../Controller/EpbCycleRunner.StartupPositioning.cs#L21)。旧路径仍在 [`Controller/EpbCycleRunner.cs`](../../Controller/EpbCycleRunner.cs#L1596) 使用它。

`RevEmptyFixedMs` 的等待只存在于旧循环，例如 [`Controller/EpbCycleRunner.cs`](../../Controller/EpbCycleRunner.cs#L1058)；当前自适应单圈在反向状态机返回 `ReleaseCompleted` 后结束，没有读取该字段。

## 7. 截图值与磁盘项目配置不一致

- `RevDecayRigidMaxMs=1000`

## 8. 整改建议

### P0：避免现场误调无效参数

1. 在 `AdaptiveCurrent` 模式下隐藏或只读 `FwdOnLimitMs`、`RevEmptyFixedMs`。
2. `FwdOnLimitMs` 表头若暂时保留，应改成“旧模式正向上限（当前不生效）”。
3. `RevEmptyFixedMs` 表头若暂时保留，应改成“旧模式反向固定空行程（当前不生效）”。

### P1：把真正生效的时序展示出来

建议新增“高级 EPB 安全参数（程序级，只读）”页，显示：

- 当前控制模式、适用通道、影子模式；
- 7 个程序级时间参数；
- 正/反向由当前周期推导出的绝对上电硬上限；
- `LearnCycle`、`OverrunPolicy`、各电气组 `StaggerMs`；
- `EpbProgramSafetyEffective.xml` 的最终值和来源。

程序级安全值建议默认只读。如确需现场修改，应采用受控的管理员入口并记录变更，而不是重新允许每个项目覆盖安全策略。

### P1：补齐液压高级设置可见性

当前界面只展示启用和目标压力，但建压/释压超时等字段真实控制 EPB 进入和退出动作。至少应提供只读详情，避免现场只看到“70 bar/100 bar”却无法判断为何等待 5 秒超时。

### P2：清理兼容影子字段

从 `EpbRow` 删除 8 个不建列、也不持久化的项目级安全字段；若必须兼容旧 XML，可只在加载器局部读取并输出一次迁移日志，不再放入公共项目配置模型，避免后续代码误用。

### P2：保存后回读核验

点击“保存”后应重新从最终项目路径加载并在界面提示：

- 实际保存文件完整路径；
- `HoldMs`、目标压力等关键生效值；
- 当前 `EpbProgramSafetyEffective.xml` 路径；
- 截图/编辑值与磁盘回读值是否一致。
