# 液压管路故障组隔离与人工恢复修复方案

## Summary

将液压故障处理从“局部故障可能升级为全局 StopAll/Watchdog”改为“液压管路级隔离”：

- 液压 2 建压或保压失败时，只冻结并断能该管路全部成员；液压 1 卡钳继续正常运行。
- 连续 3 个独立液压代次均以新鲜低压证据失败后，锁存“液压 2 硬件故障”，持续声光报警并等待操作员。
- 故障组当前未完成圈全部记为作废，不计入正式圈数；健康组的数据采集、落盘和节律不受影响。
- 不退出主程序，不进入 Watchdog 自动恢复阻断界面。
- 操作员无需额外确认弹窗：维修后使用现有“暂停→继续试验”或“停止→重新开始”即可触发正常预检。预检通过的故障组重新加入；仍失败则继续保持报警停机，健康组照常恢复或运行。

## Implementation Changes

### 1. 液压组故障状态机

- 保留连续 3 代确认策略。每次失败必须来自新鲜压力样本；建压成功并完成一次有效保压代次后清零连续失败计数。
- 第 1、2 次失败立即执行故障组安全边界：撤销组内通道执行权、EPB DO OFF、液压 DO OFF、AO 置零、确认安全压力，并作废组内在途圈。
- 第 1、2 次失败只启动该组的有界恢复代次，禁止发布全局 `SystemFaultRaised`、禁止调用全局 `StopAll`。
- 第 3 次失败转为 `HardwareConfirmed`，按配置中的液压组成员锁存 `AlarmStopped`；停止该组恢复任务，持续报警，健康液压组保持原 Timer、RunId 和正式圈节律。
- 仅当出现无法保证物理断能、DAQ 全局连续性损坏、主进程失去控制权等真正全局不变量失败时，才允许升级到 StopAll/Watchdog。

### 2. 数据封口与隔离边界

- 为液压组恢复增加独立的“作废圈终态”：冻结故障时捕获每个成员的精确 DAQ 设备、代次、序列和圈号，完成已有样本的有界落盘后提交 `AbortedByHydraulicGroupFault`。
- 跨 DAQ 代次的未完成圈不得继续等待旧代次封口，也不得触发全批次 `CycleWindowUnsealed`；以带原因、缺口和边界证据的作废记录结束。
- 作废圈不增加机械完成数、正式圈数或自适应有效样本数；重新加入后从原剩余目标继续。
- 健康组保持原持久化管线，不冻结、不切换 DAQ 代次、不关闭其程控电源。
- 修正正式圈安全边界传播：故障组 `Persistence=False` 只进入组内作废/恢复事务，不再调用当前导致外部恢复的全局授权撤销路径。

### 3. 操作员界面与恢复

- 主界面新增/复用管路级报警展示，内容明确为：
  - `液压2建压/保压连续3代失败，故障组已断能停止`
  - 配置成员 `EPB7–EPB12`，并单独标出本次启用成员；
  - 最近压力、目标值、允许下限、三次失败时间和相关圈号；
  - 提示“共享管路无法自动判断具体漏液卡钳，请现场检查组内成员”。
- 不显示“自动恢复已阻断”，不关闭主窗体；正常液压组的运行状态、圈数和曲线继续刷新。
- “暂停→继续试验”：
  - 暂停时安全暂停仍在运行的健康组，故障组保持 OFF；
  - 点击继续即视为操作员恢复意图，不再弹出额外确认；
  - 对故障组执行 DAQ、电源、建压、保压、释压和资格复核；
  - 通过后清除本次运行的管路报警并在下一公共正式槽整组加入；
  - 未通过则故障组继续 `AlarmStopped`，健康组仍恢复运行。
- “停止→重新开始”：
  - 正常结束当前批次；
  - 重新开始时对所有勾选通道执行既有完整预检；
  - 故障已修复则正常开始；仍不能建压则只重新隔离相应液压组。
- 增加组级恢复入口，例如 `ResumeInfrastructureAlarmGroupsAsync`，由现有继续/开始流程调用；不使用当前要求额外确认的单卡钳恢复入口，也不逐个恢复共享液压组成员。
- 报警记录保留历史证据，但不写成需要单独手工清除的永久配置禁用；一次成功的操作员恢复预检即可解除本次运行锁存。

### 4. 诊断与文档

- 日志为每次液压失败记录统一关联信息：RunId、液压组、成员、确认序号 `1/3–3/3`、压力证据、被作废圈和恢复事务 ID。
- 明确记录 `HydraulicGroupIsolatedHealthyGroupsContinuing`，并周期性证明健康组 Timer、DO 权限、DAQ 和落盘仍在推进。
- 若最终确需全局接管，日志必须记录具体违反的全局不变量，不能再用上层 `UnhandledSoftwareStartup` 掩盖首发液压原因。
- 在 `docs/02_Issues/` 新增最终实施与验收 Markdown，包含本次“卡钳11机械损坏漏液”的现场确认、旧故障链、修复状态机、数据口径、界面行为、测试结果和现场验收记录；原根因分析文档补充现场最终结论并链接实施文档。

## Test Plan

- 液压 2 单次新鲜低压：仅 EPB7–12 进入组内恢复，EPB1–6 继续完成正式圈，不产生全局 StopAll 或 Watchdog 请求。
- 液压 2 连续三代失败：第 3 次锁存整组报警，所有组内 DO/AO/共享压力输出确认 OFF；液压 1 持续运行。
- 中间一次完成合格建压和保压：连续失败计数清零，之后一次失败重新记为 `1/3`。
- EPB11 在正式圈中途发生低压且 DAQ 代次变化：该圈提交作废终态，不计数，不再产生 `CycleWindowUnsealed` 全局升级。
- 健康组连续性：隔离和报警期间 RunId、Timer、机械完成数、Raw/SQLite 序列持续单调推进，无重复圈、跳圈或误关电源。
- 暂停后继续且故障已修复：无额外确认框，故障组完整预检通过后整组在未来公共槽加入，剩余圈数正确。
- 暂停后继续但故障仍存在：故障组保持 OFF 和报警，健康组正常恢复，主程序不退出。
- 停止后重新开始：修复后所有勾选通道正常启动；未修复时仍只隔离液压 2。
- 声光报警失败、快照失败或日志延迟不得阻塞故障组断能，也不得影响健康组。
- 只有故障组 DO 无法确认关闭、全局 DAQ 连续性不可证明或控制权丢失时，才验证全局 StopAll/Watchdog 接管。
- 运行 `AdaptiveControlTests`、`EpbDiskWriterTests`，并补充液压 2 漏液硬件在环验收：机械压力表与软件压力同步记录，确认健康管路连续运行。

## Assumptions

- 液压组以配置为准：液压 1 为 EPB1–6，液压 2 为 EPB7–12；未启用成员不运行，但仍在界面中列为共享管路排查对象。
- 压力证据不能自动唯一定位到卡钳11，因此程序只定性到“液压2/组内候选卡钳”，不伪造单卡钳诊断。
- 操作员点击现有“继续试验”或“重新开始”即代表允许执行恢复预检，不增加新的确认步骤。
- 故障组恢复失败不阻止健康组继续或恢复；成功恢复前故障组始终保持全部控制输出 OFF。
