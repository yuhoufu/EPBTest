# V2.13.0.1 数据存储分级与低写入优化实施验收

## 结论

本补丁将程序级圈证据策略集中解析为 `CsvOnly`、`BinOnly`、`CsvAndBin` 三个严格值，继续保持环形 `.dat`、SQLite `index.db`、报警判据、控制时序、断电和无人值守身份链不变。版本从 2.13.0.0 升级为 2.13.0.1。没有生成发布包。

## 生效配置

配置位于 MTTFTest.exe.config（源文件为 `MTTfTest/App.config`）：

| 配置 | 默认 | 作用 |
| --- | --- | --- |
| `LatestStorageLevel` | `CsvOnly` | Latest 新包的圈文件格式 |
| `AlarmStorageLevel` | `CsvOnly` | 硬报警圈的原子证据格式 |
| `LearningStorageLevel` | `BinOnly` | 学习/资格圈封存格式 |
| `HistoricalEnabled` | `true` | 是否继续生成新的 HistoricalSnapshots |
| `HistoricalRetainCyclesPerChannel` | `12` | 每通道历史滚动快照上限 |
| `RawDataLoggingEnabled` | `false` | Raw 定时器和时间戳目录开关 |

缺失、非法或越界值回退到上表默认值并写启动警告；不存在 `None`。AlarmConfig 中 `WarningSnapshots.SaveCsv/SaveBin` 仍仅控制软预警证据，不会被上述 `AlarmStorageLevel` 覆盖。

## 设计与兼容性

`DataOperation/StorageFormatPolicy.cs` 负责 EXE 配置集中解析和启动策略日志，`DataRetentionPolicy` 接收解析结果。`EpbDiskWriter` 的 Latest、报警封存和学习/资格封存均按实际格式原子写入并校验；单格式校验只要求实际文件，旧 CSV+BIN 包在新策略下仍按双格式校验有效。报警清单继续写入 `snapshot-manifest.json` 并为每个 CSV/BIN 记录 SHA-256，报警元数据增加实际 `alarmCycleStorageFormat`。Latest 包使用 Latest 策略；通用 `FlushRecentTo`/Incident 导出保持旧 CSV+BIN，报警适配器使用独立 Alarm 策略，避免两个程序级级别串扰。

Latest 的保留清理和暂停/停止去重会识别当前策略要求的格式，同时兼容历史双格式包。SQLite 圈索引、环形 `.dat` 文件、圈号和终态语义不变。Learning BIN 仍可作为环形覆盖后的历史恢复来源。

Historical 禁用时只停止新 HistoricalSnapshots 导出，不删除旧目录；保留数由程序级配置控制。Raw 默认关闭时不再创建 `DataStore\\时间戳` 空目录，未来显式开启 `RawDataLoggingEnabled=true` 才创建 Raw 路径；未改变 `.dat` 预创建行为。

## 低写入项目边界

本补丁只实施了不会改变安全状态机的存储分级、Historical 开关和 Raw 空目录门禁。Adaptive 模型批量合并写、unattended checkpoint heartbeat、TestConfig dirty/hash guard、UI 日志批量追加、Telemetry 多级频率/删除、EpbAdaptiveProfiles 备份上限、Warning JSONL/Archive 时间保留及运行时清理，尚未在本版本强行改动；原因是当前调用链需要更长时间的崩溃/并发验证，贸然修改会危及控制、报警或恢复不变量。它们应作为后续独立补丁实施，并保留失败仅日志、暂停/停止/报警/关闭有界 flush 的安全门禁。

## 现场验收与回滚

现场先确认启动日志包含最终 StoragePolicy，分别用三种级别完成一圈并检查目标扩展名、`snapshot-manifest.json`、SHA-256 和 `index.db` 终态；再验证报警断电、暂停/恢复和无人值守交接。配置回滚只需恢复三个 `*StorageLevel` 到 `CsvAndBin`（旧包读取无需迁移）并替换 2.13.0.1 程序为 2.13.0.0；新增单格式文件不会影响旧双格式读取。若出现任何控制/报警/恢复异常，应立即停用新程序并保留现场目录，禁止手工删除 `index.db`、`.dat` 或报警证据。
