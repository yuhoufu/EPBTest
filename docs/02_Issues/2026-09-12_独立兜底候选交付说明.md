# 4.0.0.0 独立兜底候选交付说明

实施基线：`64681eb09733a4af4054037afe8e92c5142da30d`。分支：`codex/independent-fallback-v4`。
产品版本：4.0.0.0；候选标签：`v4.0.0.0-rc.1`。这是软件候选，现场主动恢复、24 小时和 168 小时耐久均未验收。

## 已实现边界

- 保留原保护、控制、自愈顺序和恢复预算。FallbackGuard 不引用 Controller，不操作 NI、液压、电源或业务库；主动模式仍调用原 Watchdog 恢复入口、原 Supervisor/SessionAgent 启动链及安全检查。
- F1：交接未交给 worker 时，校验、持久化、通知或调度异常均释放 busy；worker 仍在 finally 释放自己的占有权。
- F2：安全启动管道连接、写入及完整读取共享 5 秒总截止，使用可取消重叠 I/O，并关闭、等待本连接操作结束。安全代理监督最多 60 秒；超期保留未决硬件所有权并闭锁启动，不强杀代理。该期限不是物理安全完成证明。
- F3：液压组计数与已登记 worker、结构化通道恢复状态在同一发布门内建立；排队断电和冻结继续发生在 worker 启动前。前置异常不会先留下无 owner 的恢复计数。
- F4：SafetyOnly 不要求、也不携带续测许可。Supervisor 继续核对精确侧车进程、会话、交接凭证、参数和二进制身份；必须与回执的 Forbidden 处置匹配。
- 正式提交观察序号只在原 recorder 完成正式圈封存后推进，绑定 Run/Epoch/通道/圈号；重复或迟到旧圈不增序号。观察信息不替代正式数据。

## 接管协议和降级

每个会话在原项目日志目录生成 `fallback-<session>.json` 持久账本、`fallback-observation-<session>.json` 观察快照；外部开关单独保存。快照每秒发布，文件和管道帧上限 64 KiB。观察任务独立于原 Monitor 的循环。

账本以机器范围互斥和原子替换进行 CAS 更新。请求、Yield、Acquire、启动准备、精确 PID/启动时间绑定、逐路验证和交还分别记录阶段；代次在所有权变更时增加。损坏、弃置锁、旧 Run、未知启动结果不能被覆盖为成功。启动应答丢失后保留准备记录，先查询持久结果；不盲目重发启动。

控制管道 `MTTF-Fallback-v1-<session>` 仅向当前账户、SYSTEM 和管理员授权，命令总截止 3 秒。Request/Acquire 重复调用以同一命令 ID 和请求者调和；Query 无副作用。后台所有者在退出前必须交还事务。进程归属使用 PID 加启动时间，不能仅用进程名。

当前主动接管放行范围严格限定为：原主进程确切退出、原恢复没有未完成 worker、没有未决安全事务、原恢复许可仍有效、预算和停止事实允许。原主程序或 Supervisor 失联但仍可能执行时，只告警；外部不绕过 Supervisor。原执行入口没有提供安全隔离证明的场景，不宣称可主动兜底。

旧原侧车迟到操作不能穿过新的启动准备边界。原侧车更换时只有已证明旧实例退出且无未决启动，才能重新绑定原所有者。外部崩溃后，未执行的接管可以在确认其退出及原任务空闲后交还；已准备但结果不明的启动保留 Unknown。人工停止持久事实和旧启动身份不会被清除。

重新上电前再核对账本、实际进程身份及原停止标记。人工停止仍先启动原安全事务；外部停止记录失败会留下告警，不能通过重新发许可绕过。断电发生在用户点击尚未持久化的物理窗口仍不能保证保留点击。

业务静默初始观察预算为 `max(60秒, 配方周期×3)`，逐路计算；短采样中断不直接触发外部重启。原恢复仍忙时只能保持接管申请。逐路机械反馈、控制动作和至少三次正式提交均推进后，再经过至少一个配方周期（不少于 1 秒）的稳定观察才允许交还。禁用、人工停止、永久故障和目标完成通道分别排除；不能用总圈数替代逐路检查。

## 独立操作

完整解压后，原一键安装、修复、启动和卸载目录保持原布局。独立程序位于 `FallbackGuard/`，管理脚本位于 `Tools/`。以下参数必须使用目标项目的真实日志目录和当前会话 GUID（32 位 N 格式）。

```powershell
.\Tools\Manage-FallbackGuard.ps1 -Mode Enable -ProjectDirectory <项目日志目录> -SessionId <会话>
.\Tools\Manage-FallbackGuard.ps1 -Mode Run -ProjectDirectory <项目日志目录> -SessionId <会话>
.\Tools\Manage-FallbackGuard.ps1 -Mode Status -ProjectDirectory <项目日志目录> -SessionId <会话>
.\Tools\Manage-FallbackGuard.ps1 -Mode Disable -ProjectDirectory <项目日志目录> -SessionId <会话>
```

Enable 默认只观察。独立台架需要主动模式时才显式加 `-BenchActive`；这不代表本批次获得自动续测授权。任务安装使用 `-Mode Install`，以当前交互账户登录触发、隐藏窗口运行外部程序；退出登录后不保证原 WinForms 可自动进入交互会话，不配置自动登录。任务不负责启动主程序。每个独立任务绑定一个会话；新人工批次使用新会话时，应以新 SessionId 配置观察，并禁用、卸载旧会话任务。本候选不自动发现新项目。

禁用后任务入口正常退出，不重新启用外部兜底。接管中的后台事务须安全交还；未决事务可能使退出延后。`-Mode Uninstall` 只删除精确匹配项目/会话的独立任务，遇到未交还或未决启动则拒绝卸载，保留原恢复程序、配置和全部试验数据。

## 兼容与回退

| 项目 | 本候选 | 兼容规则 |
| --- | --- | --- |
| 原 Watchdog 主协议及安全回执 | 保持原 schema | 原实时保护算法与门限不变 |
| Supervisor 安全启动帧 | Safety request V6 | 新增 SafetyOnly 位；新旧 Watchdog/Supervisor 必须一起升级，禁止混用 |
| Fallback 协议、账本和观察 | v1 / schema 1 | 未知 schema、缺字段及损坏账本拒绝主动接管 |
| Fallback 默认模式 | 只观察 | 软件验证不能代替台架放行 |

回退先禁用独立兜底并交还，确认没有未决启动、安全和保存事务，再按原安全停机流程更换旧组件。旧版本不认识新账本，不允许未交还时在线混用。保留账本、停止事实和原有候选包/标签。

## 验证与证据

本地验证包括 Debug x86、AdaptiveControl、EpbDiskWriter、PowerSupplyDebugger、停止/Watchdog、独立协同故障注入和后台启停。`Tools/Test-FallbackGuard.ps1` 可在 jxcq 独立临时目录验证软件生命周期；它不注册任务、不发送硬件命令，不访问现场试验。

临时日志与本次实际结果统一记录在主仓库 `Codex/independent-fallback-evidence/`。早期 F1/F4 反例为失败结果，F2 随机管道测试验证可取消实现；F3 前置异常为真实方法入口注入。协议竞争测试不等同于完整硬件故障复现。现场部分/全通道停止、原链失败后的主动接管、安全代理真实迟退、保存超时后的完整恢复、锁屏/注销、任务注册、长稳均仍须按台架记录验收。

候选包使用 7-Zip LZMA2、`-mx=9`；Base 构建身份和外层清单记录同一源码提交及文件 SHA-256。交付时执行解压复验。没有自动部署、停止 WJ-EPB、修改现场数据或计数，也不检测 CAN。

本地专项已验证独立协同 24/24、停止生产接缝 11/11、真实 Runtime/侧车关闭 15/15、磁盘持久化 58/58、PowerSupplyDebugger 19/19。关闭专项补齐独立 DAQ 配置、schema 5 和连续运行 Epoch 测试夹具，失败路径精确清理测试侧车；没有放宽最终安全事实断言。Windows PowerShell 5.1 生命周期检查通过，私有内存约 13 MiB。最终 Release 全量结果以 Base/build-identity.json 的 verification 和交付证据为准。

发布回归期间另修复保留器元数据读句柄阻塞原子快照替换的竞态：读取允许删除共享且受 4 MiB 上限约束，新增持有生产读取句柄时同步提交的回归。故障回执专项为 42/42；历史失败与后续复验日志均保留在交付证据目录。

连续并发回归捕获 Windows 原子替换错误 1175。日志及 authority 生产文件替换加入最多 4 次、每次 25 ms 的重试，先回读确认已提交内容，保留目标文件，不把未确认写入视为成功。持续占用仍有界失败，释放后允许合法重试；不改变恢复许可或失败熔断规则。
