# V2.12.0.29 VS2022 独立候选封包与包身份校验修复

> 问题版本：V2.12.0.28  
> 整改版本：V2.12.0.29  
> 结论：截图中的两个拒绝均由发布目录身份校验触发，不是 DAQ、卡钳或编译器故障。

## 1. 现场现象与直接原因

### 1.1 `PackageIdentityMismatch`

截图同时显示：

- 正在运行的 EXE 为 `V2.12.0.28`；
- 目录中的 `build-identity.json` 仍记录 `V2.12.0.24`；
- Git、BuildUtc、Config 一侧出现 `unknown`。

这说明 VS2022 覆盖了 `bin\Release` 中的 EXE/DLL，却沿用了旧候选留下的身份与校验文件。
窗口标题只能证明 EXE 自身版本，不能证明同目录 DLL、配置和 EXE 来自同一次构建，因此旧程序按安全策略拒绝开始试验是正确的。

### 1.2 `PackageFileSetMismatch Manifest=96 Actual=112`

旧校验器递归统计整个程序目录。程序启动后生成的 `DataStore`、`log` 等文件也被算作“包外文件”，
而界面保存后的 `Config/*.xml` 内容变化又会造成哈希变化。因此一个原本正确的包在正常运行、保存配置后会把自己判为不完整。

本机取证还确认 `bin\Release` 留有多次运行生成的 `DataStore/<时间戳>/` 配置备份，这正是
`Actual` 大于 `Manifest` 的主要来源。

## 2. 根本整改

V2.12.0.29 将目录内容分成三类：

| 类型 | 示例 | 校验规则 |
|---|---|---|
| 不可变程序文件 | EXE、DLL、依赖、PDB、许可证 | 文件集合与 SHA-256 必须完全一致 |
| 可编辑项目配置 | `Config/*.xml` | 配置文件名集合必须一致；允许软件界面更新内容，实际内容随 SESSION 单独留证 |
| 运行期证据 | `DataStore/`、`Data/`、`log/`、`IncidentSnapshots-Fallback/` | 不参加程序包文件集合和哈希比较 |

这既保留了防止 EXE/DLL 混包的硬门禁，也避免正常数据落盘和配置保存让候选包自失效。

## 3. VS2022 直接使用方式

VS2022 选择 `Release | Any CPU` 后执行“重新生成”。项目完成编译后会自动：

1. 删除 `bin\Release` 中可能残留的旧 `build-identity.json` 和 `SHA256SUMS.txt`；
2. 从本次完整输出复制一个独立目录；
3. 排除历史运行数据；
4. 重新生成与本次 EXE/DLL/config 文件集合匹配的身份和 SHA-256 清单；
5. 在“输出”窗口打印候选目录，例如：
   `D:\Github\wanxiang\EPBTest\artifacts\vs2022\V2.12.0.29-VS2022-YYYYMMDD_HHMMSS`。

必须运行该独立目录中的 `MTTFTest.exe`，不要运行 `MTTfTest\bin\Release\MTTFTest.exe`。

VS 自动生成的目录状态为 `VS2022_RELEASE_CANDIDATE`，运行时显示
`PackageCode=VerifiedVs2022`，允许研发调试和现场试运行；它不会伪装为正式生产包，
`deploymentApproved=false`，也不能通过最终生产现场门禁。

## 4. 正式生产包仍保持强门禁

生产候选继续使用 `Tools\Build-Release.ps1` 从洁净 Git 提交生成。正式包仍必须满足：

- `FORMAL_RELEASE_CANDIDATE`；
- `gitDirty=false`；
- `deploymentApproved=true`；
- EXE/DLL 等不可变文件集合及 SHA-256 完全一致；
- 正式全量回归与现场门禁证据完整。

正式构建传入 `FormalReleaseBuild=true`，不会额外触发 VS 候选封包。

## 5. 自动验证

新增/扩展回归覆盖以下反例：

- V24 身份与 V29 EXE 混用必须拒绝；
- 不可变 DLL 被覆盖必须拒绝；
- 清单外程序文件必须拒绝；
- `Config` 文件被增删必须拒绝；
- 仅修改现有配置内容不得使包失效；
- 新增 `DataStore` 运行文件不得使包失效；
- 自洽的 VS2022 独立候选允许试运行，但代码必须为 `VerifiedVs2022`；
- VS 候选中的 DLL 被修改仍必须拒绝。

本次整改解决的是“VS2022 构建后无法直接获得可运行候选”和“正常运行后包自失效”。
它不替代真实 NI 2/8/24/72 小时、故障注入及每通道 100000 圈最终生产验收。
