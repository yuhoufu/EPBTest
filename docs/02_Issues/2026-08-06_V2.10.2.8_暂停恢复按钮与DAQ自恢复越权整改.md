# V2.10.2.8 暂停恢复按钮与 DAQ 自恢复越权整改

> 整改版本：V2.10.2.9  
> 状态：代码已实施并完成自动化验证；现场部署须经用户确认。

## 1. 现场现象

V2.10.2.8 批次暂停可进入 `暂停试验 -> 正在暂停… -> 继续试验`，但随后出现：

1. `继续试验`显示后仍不能正常触发批次恢复；
2. 试验看似自行恢复，而按钮仍停留在`继续试验`；
3. `正在暂停…`等过渡态缺少明确的不可点击反馈；
4. 暂停/继续按钮没有与`停止试验`一致的悬浮高亮和手形指针。

## 2. 日志证据与根因

现场日志显示：

- `2026-08-06 11:08:18.387` 批次已进入 `Paused`；
- `11:08:49` 左右 Dev1、Dev2 因持久化积压进入 DAQ 自动恢复；
- `11:08:51` DAQ 恢复流程直接恢复 EPB4、5、8、9、10、11；
- 同一时段没有批次 `ResumeChecking` 或 `Running` 状态转换记录。

因此，现场看到的“恢复”不是`继续试验`按钮成功执行，而是 DAQ 自恢复越过批次暂停状态直接恢复了通道定时器。

同时，界面点击保护的释放顺序存在错误：稳定状态重绘发生在 `_batchStartUiGuard` 清零之前，导致按钮文字虽然变成`继续试验`，`Enabled`仍为 `false`，之后又没有再次重绘。

## 3. V2.10.2.9 整改

### 3.1 按钮状态闭环

批次按钮统一按以下规则显示：

| 批次状态 | 按钮文字 | 是否可点击 | 鼠标 |
|---|---|---:|---|
| Running | 暂停试验 | 是 | 手形 |
| PausePending | 正在暂停… | 否 | 等待 |
| Paused | 继续试验 | 是 | 手形 |
| ResumeChecking / Qualification | 正在恢复… | 否 | 等待 |
| Stopping | 正在停止… | 否 | 等待 |

具体调整：

- 点击后立即禁用按钮并进入过渡文案，阻止重复点击；
- 异步操作结束时先释放点击保护，再根据批次真实状态重绘按钮；
- 可点击态增加手形指针、悬浮高亮和按下颜色；
- 禁用态使用灰色外观，明确表示当前不可操作。

### 3.2 DAQ 自恢复服从批次暂停

DAQ 自动恢复现在只负责修复采集与持久化链路，不再拥有批次恢复权限：

- 在 `PausePending`、`Paused`、`ResumeChecking`、`Qualification`、`Stopping` 期间，即使 DAQ 恢复成功，也保持通道定时器暂停；
- 不发布 `ChannelResumed`，不把通道重新加入运行态液压参与集合；
- 最终恢复统一由用户点击`继续试验`后，经过批次恢复流程一次性完成；
- 批次处于 `Running` 时，DAQ 自恢复仍按原逻辑恢复受影响通道。

这保证按钮状态、批次状态和通道实际运行状态使用同一个恢复边界。

## 5. 现场验收步骤

1. 运行状态点击`暂停试验`：按钮应立即显示`正在暂停…`，灰显且不能重复点击；
2. 暂停完成：按钮应显示`继续试验`，鼠标悬浮高亮并变为手形；
3. 暂停期间触发或等待 DAQ 自动恢复：曲线链路可恢复，但卡钳不得自行续跑；
4. 点击`继续试验`：按钮立即显示`正在恢复…`且不可点击；
5. 恢复完成：按钮必须返回`暂停试验`，所有允许恢复的卡钳从统一边界续跑；
6. 检查日志：应存在批次 `ResumeChecking -> Running`，不得仅有 DAQ 恢复日志却没有批次恢复状态转换；
7. 再执行一次暂停/继续，并验证悬浮、手形指针和重复点击保护均稳定。
