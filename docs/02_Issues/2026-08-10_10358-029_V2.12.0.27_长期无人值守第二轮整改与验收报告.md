## 1. 结论先行

V2.12.0.24 在约 6 h 45 min 后全停的首因，不是卡钳同时损坏，也不是 SQLite 持久化队列长期写不动。真正先满的是 DAQ **后台工程处理队列**。当时唯一处理线程同步执行 Windows 主机探针，探针中的 `Process.Refresh`、线程枚举、`DriveInfo` 和磁盘性能计数器发生长尾停顿；64 批处理队列只有约 0.64 s 余量，因此触发 `BackgroundQueueFull`。

全停和“停止后仍不能开始”来自后续软件级联：恢复截止点错误、抑制批次伪装成已落盘、DAQ Stop 后取消、压力陈旧门禁顺序反转、液压组恢复成员丢失、跨 Run 重试次数污染，以及局部故障被升级为整机停止。

V2.12.0.27 的目标不是靠扩大队列掩盖问题，而是建立以下硬约束：

1. 采集、控制和 OFF 安全链不得等待诊断、UI、普通日志或低优先级磁盘工作。
2. 正式耐久窗口内的批次只能真实写入、保留原批重试，或形成明确的永久缺口；不得静默跳号。
3. 恢复入口必须在任何等待前让受影响组暂停，冻结圈号和序号边界并登记尾段排除窗口，再提交整组 OFF，最后才等待液压/恢复所有权。
4. 截止后的非正式尾批可以明确排除，但绝不能推进物理持久化水位；排除数量和序号范围必须累计留证。
5. 输入 DAQ/压力故障必须在全部输出断电状态下先修复采集并取得新鲜压力，最后才允许重新上电。
6. 同步 NI 或存储内核调用永久不返回时，软件必须进入逻辑安全停机并尽快发起断能；没有外部硬联锁、监督进程和崩溃一致性本地日志，不能虚假承诺物理断能或当前进程一定能够自行恢复。

因此，V2.12.0.27 是针对 V24 现场链的第二轮代码候选，不等于已经通过生产长稳验收。

## 5. 关键不变量

### 5.1 正式耐久窗口

对冻结边界 `B` 和恢复时冻结的排除上界 `T`：

- `Sequence <= B` 的批次必须真实完成 recorder 写入；
- 恢复窗口尚未闭合时，`SuppressThrough=long.MaxValue`；恢复提交时把当时 `LastAccepted` 冻结为有限上界 `T`；
- `B < Sequence <= T` 的停止/恢复尾批可被明确排除，迟到到达的旧尾批仍必须排除；只有首个 `Sequence > T` 的新批次才能关闭活动排除窗口并恢复物理写入；
- 排除窗口必须记录累计数量、首末序号、区间数、CorrelationId 和 RunId 证据；
- 排除批次不得推进物理 `Persisted`；
- `TerminallyHandled` 与 `Persisted` 分账，前者可以包含明确排除，后者只表示 recorder 真实写入完成；
- 当前正式圈必须在排除区间前终止，恢复后的新正式圈从新节律槽开始；
- processing/Raw 永久 gap 发生时，当前圈作废、不计入完成次数，并禁止同进程伪恢复。

### 5.2 安全与恢复顺序

```text
故障登记
  → 整组进入 Recovering / Pause
  → 冻结圈号与 LastAccepted
  → 设置持久化尾批排除窗口
  → 提交整组最高优先级 OFF
  → 等待液压/恢复所有权
  → 排空冻结 Raw 发布前缀和 SQLite 真实耐久前缀
  → 断电态修复 DAQ，取得新 generation 与新鲜压力
  → 机械释放、资格确认
  → 共同未来节律槽重入
```

人工 Stop、退出和系统故障同样遵守“先撤权并断能，后等待所有权/封圈/落盘”。

## 8. 不能省略的现场故障注入

1. HostRuntime/系统探针阻塞 0.6 s、3 s、30 s，确认 DAQ 回调和两设备 processing 不受拖累。
2. 本机数据盘与 UNC 共享盘 100–200 MiB/s 并发读写、杀毒扫描、空间不足、断网和恢复。
3. Dev1 单独故障时 Dev2 健康组继续；不得由共享 worker 或共享状态锁直接拖停。
4. NI DO 写 20–100 ms、永久阻塞模拟、迟到完成和关闭竞态；验证 OFF 延迟与外部硬联锁。
5. 压力样本陈旧、DAQ 重建、Stop→Start 取消窗口、液压 lease 被占用和机械释放失败。
6. 运行中暂停、恢复、人工 Stop、窗口关闭；不得重复弹框，不得在持久化未闭合时退出。
7. 资源趋势：32 位地址空间、Private/Virtual/WorkingSet、handle、thread、GC、目标数据盘空间和队列。

注意：`RawTransferred` 当前只证明 Raw 发布链已经完成所有权处理；默认生产配置没有启用连续 Raw 文件落盘，不能把该字段表述成“连续 Raw 文件已持久化”。

## 9. 明确的工程边界

如果 SQLite、MMF、文件系统或 NI 驱动的同步内核调用**永久不返回**，同一进程无法安全取消该调用，也不能并行重写相同批次。当前候选会：

1. 由独立看门狗识别；
2. 提交 OFF/电源 Disable、锁存硬故障并进入逻辑安全隔离；软件若收不到硬件完成证据，不宣称已经物理断能；
3. 请求有界进程回收；
4. 若耐久边界无法证明，则拒绝强行退出和静默丢数，最终保持安全停机并留证。

若业务要求连这种主机/存储内核永久卡死也要自动续测，必须另行建设：

- 进程外 Windows Service/supervisor；
- 本机预分配 append-only spool，记录 RunId、Device、Sequence、Length、CRC 并强制落盘；
- 下游幂等重放；
- Raw/MMF 的 frame length、CRC、commit marker 和 committed-prefix；
- CampaignRunId 与 ProcessEpoch；
- 外部安全继电器或独立硬件 watchdog。

在该架构完成前，软件可以承诺“对已覆盖的软件瞬态故障自动恢复、对不可证明的永久内核故障安全停机”，不能承诺“任何主机/存储故障下都永不停机”。
