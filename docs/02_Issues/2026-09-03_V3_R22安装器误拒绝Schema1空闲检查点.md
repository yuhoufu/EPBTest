# V3 QUICKDEPLOY_R22 误拒绝 schema 1 空闲检查点复盘

## 结论

`QUICKDEPLOY_R22` 已撤回。安装失败不是 V3 主程序、EngineHost 或 Recovery Kernel 无法启动，
而是安装器第 3 步只接受 schema 5/6，错误拒绝了旧程序正常关闭时留下的 schema 1 空闲墓碑。

现场文件的关键属性为：

- `SchemaVersion=1`
- `Armed=false`
- `RestartPending=false`
- `GracefulPaused=false`
- `RunId/RootRunId/RecoveryNonce` 为空
- `SelectedChannels=[]`
- `RemainingFormalCycles={}`
- `LastReason=MonitorClosing`

该文件不包含活动试验、自动恢复授权、运行身份或待续圈数。按版本号直接拒绝属于安装器兼容性缺陷。

## 修复

`QUICKDEPLOY_R23` 增加 `Test-LegacyCheckpointIsProvablyInert` 属性判定：

1. schema 1-4 只有在所有授权标志显式为 false、身份字段显式为空、通道/剩余圈/恢复历史显式为空时，才按“可证明无授权的空闲墓碑”处理；
2. 空闲墓碑原样移入 `%ProgramData%\MTTFTest\MigrationArchive`，不迁移授权、permit、nonce、Owner、通道或剩余圈；
3. schema 1-4 只要包含活动标志、RunId、nonce、通道、剩余圈，或关键字段缺失，仍进入 `SafeIdleAlarmed` 并拒绝安装；
4. schema 5/6 仍必须同时具备 `MotorOffConfirmed`、`PressureSafeConfirmed`、`PersistenceDrained` 才能封存并迁移剩余正式圈；
5. 其他 schema 继续拒绝。
6. 安装器在停止旧 Supervisor 和登录任务之前先进行一次只读迁移资格预检，避免不支持的检查点导致旧运行环境先被停下；正式封存时再次校验，防止预检后的状态变化绕过门禁。

## 回归覆盖

部署契约新增以下验证：

- 现场同结构的 schema 1 `MonitorClosing` 空闲墓碑允许迁移；
- `Armed=true`、存在 RunId、存在通道、存在剩余圈、缺少关键字段五类情况全部拒绝；
- 在隔离临时 ProgramData/LocalAppData 中执行真实封存流程，确认活动路径已清除、原文件进入 MigrationArchive；
- 迁移回执必须为 `ArchivedProvablyInertTombstone`，且授权、通道和剩余圈均为空。

## 现场处理

不要删除或手工修改原检查点，也不要继续使用 R22。完整解压 R23 后重新运行
`一键安装正式版.cmd`。R22 失败发生在复制 V3 Current 之前，但已经停止旧 Supervisor/任务；
R23 重跑会重新安装并启动服务、任务和快捷方式。
