## 结论

I0018 与 I0016、I0017 是同一类故障链再次出现：Dev1 采样短暂失活 → 电流/压力采样保护 → 液压组恢复 → 未重入成员收尾误伤已重入成员 → 旧周期退出边界失败 → 全部停机且跨进程恢复没有接上。

## 为什么频发

三个事件都具备相同的放大机制：短时采集问题不是被收口为一次受控恢复，而是撞上恢复所有权/收尾错误，最终变为长期全停。软件因此表现为“一次短暂异常就要人工干预”。

I0018 前累计 Dev1 CallbackGapEvents=14（其中最新约1175ms），但该计数包含不同长度空窗，不能当作发生过14次同样严重故障。Dev2 同阶段仍有动作日志。此次资源快照不支持CPU、内存或磁盘耗尽导致的全机停顿；尤其不能把9月12日的远程诊断内存事件套用到本次。

仍待验证的触发根因：NI驱动回调投递延迟、设备传输、线程调度、GC及同步阻塞。现有日志缺少跨线程调度与设备级时序证据，不能指定其中某项为已确定根因，也不能据几次故障声称版本故障率有统计显著差异。后续应以有预算的本地环形追踪捕获故障前后调度/GC与DAQ序号；不得放宽采样、电流、压力安全阈值掩盖问题。
