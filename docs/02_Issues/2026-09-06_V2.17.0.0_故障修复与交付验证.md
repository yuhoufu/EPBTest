## 3. 耐久和计数契约

### 3.1 四个状态不能混用

1. **接收**：进入有界内存 FIFO；尚未落入耐久日志的批次不能宣称断电后可恢复。
2. **已耐久**：`raw-journal.db` 的 FULL 同步事务保存原始样本、目标圈/样本位置、DAQ generation/sequence 和 SHA-256，之后才写环形曲线文件。
3. **已应用**：重放/写入精确目标位置，刷新文件与索引后再回收日志。进程在“应用后、回收前”死亡，再次重放只覆盖相同位置，不追加计数。停止时也先应用已耐久而未应用的批次。
4. **已异常终结**：真实断序或非法批次记录 `data_gap`、缺口和原因；异常原文保留，拒绝提交为 completed/learning_completed/qualification_completed。健康后继可以继续，不把异常终态作为有效圈通过。

日志有效载荷默认上限 256 MiB，未应用记录不覆盖。SQLite 数据库/WAL、环形文件及其他证据文件的实际磁盘占用不等于这一载荷上限。磁盘长期不可写、容量不足或整个数据库损坏，系统必须安全暂停并保留证据；软件不能承诺在没有可写介质时继续完成可追溯试验。

### 3.2 次数口径

- 目标剩余次数继续使用 **机械完成次数**，包含实际完成的学习/资格动作及数据随后作废但确有机械完成回执的动作。
- 有效正式圈要求正式尝试完成且有效证据已提交。学习/资格圈单列；异常尝试单列。它们与机械完成数不是简单互斥相加关系。
- 旧项目已有机械次数/RunCount 保留为历史基线；后续只加唯一耐久机械回执。保留历史数不意味着已证明每一笔旧次数均有完整曲线。
- 数据圈号只是尝试身份。正向圈号和学习负圈号均参考保留账本，避免清理旧曲线后复用编号；不能用最大圈号补计动作。
- 控制层使用 RunId/RunEpoch/AttemptId/执行许可代次，落盘使用项目+通道+唯一圈号以及 DAQ 代次/序号关联。重启补交不会重复推进机械计数。

## 4. 持续恢复规则及安全边界

- 单通道/共享资源组先恢复；学习执行体无法继续、局部恢复用尽或任务不退出时，安全暂停全部通道并重建批次，必要时由独立进程接管。
- 保留原启用通道、配置身份和目标剩余次数。确定硬件故障按既有项目保护逻辑隔离；其余通道的原始恢复意图不能因某个旧 worker 退役而丢失。
- **任何滚动 10 分钟最多登记 3 次 EPB 主程序恢复启动尝试**；尝试失败仍计入频率窗口。耗尽后等最早记录移出窗口，再尝试；不会因为达到 3 次就永久撤销软件恢复意图。
- 普通软件熔断按既有 30/60/300 秒冷却；LastKnownGood 情况沿用 30 分钟探测。Supervisor 返回的启动窗口下次时间会传递给 Host。主程序和独立 Host 的记录共同约束恢复，进程重开不能清空安装范围的频率记录。
- 冷却不冒充机械进展、不延用过期上电许可。下一次动作前必须重新建立安全证明、新执行许可及业务执行体；只有首个新尝试动作和有效数据实际提交后才发布业务恢复成功。
- 人工停止/关闭所产生的撤权、急停和已确认硬件保护优先；旧 Run、旧 nonce、旧 lease 或迟到回调不得重新拉起或重新上电。真实身份不符仍被拒绝。
- 自动重启只针对 EPB 主程序及其受控进程，**不自动重启 Windows**。未知软件故障通过进展监督或独立宿主监督进入同样的断能、取证、冷却、重新验证流程。
