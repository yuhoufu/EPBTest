## 最终策略

### 1. 全局正式周期屏障

- `FormalBatchSlotCoordinator` 以 `RunId + SlotOrdinal` 冻结当前正式槽参与者。
- 任一卡钳完成自身动作后先关闭自身输出，再等待同槽其他已启用卡钳。
- 下一槽只在以下条件全部满足后放行：本槽成员完成或安全永久隔离、液压成员释放、电机 OFF 已确认、要求的持久化边界已提交。
- 下一槽使用上一槽完成时固定的首个未来墙钟边界。计时器迟到进入时复用该边界，不二次顺延，也不补跑历史槽。
- 完成目标、暂停、人工退出、取消勾选或永久报警的通道，从下一槽参与者快照移除。
- 液压成员等待预算与真实释压超时分离；共享等待不再误报为 `HydraulicBarrierTimeout`。

### 2. 周期超限判定

正式圈终态记录 `CallbackElapsedMs`、`PhysicalActionElapsedMs`、`SharedCoordinationWaitMs` 与 `PeriodOverrunKind`。只对控制成功、机械动作完成并完成持久化提交的圈累计普通超限。

| 条件 | 处理 |
| --- | --- |
| `PhysicalActionElapsedMs <= PeriodMs` | 连续超限清零并持久化 |
| `PeriodMs < PhysicalActionElapsedMs < 2 × PeriodMs` | 仅该卡钳连续超限加一；其他卡钳等待本槽收尾 |
| 连续第 8 次普通超限 | 锁存 `ConsecutivePeriodOverrun`，永久禁用该卡钳 |
| 到 `2 × PeriodMs` 时仍未确认自身输出 OFF | 撤销执行许可、取消本圈、高优先级 OFF，锁存 `PeriodOverrunHardLimit` |
| 到硬截止时电机已 OFF，仅在等待共享资源 | 不误报警，继续等待共享安全收口 |
| OFF、液压安全压力或报警写盘无法确认 | 升级组级/整批系统故障，禁止其他卡钳带风险继续 |

15 秒周期的硬上限为 30 秒。超限完成圈只计一次；硬截止前未完成的机械圈不计数。暂停、人工停止和系统取消既不增加也不清除连续超限。

### 3. 永久报警与项目配置

项目 `Config\TestConfig.xml` 是唯一持久事实源，新增字段：

- `PermanentAlarmLatched/Code/Reason/Utc/CorrelationId`
- `ConsecutivePeriodOverrunCount`
- `LastPeriodOverrunUtc`

锁存时一次原子提交报警字段、连续次数和 `Enabled=false`。写盘失败时保持内存报警与输出关闭，转系统故障并停止无人值守续跑。

- 重启先恢复锁存状态；禁用卡钳显示红色“永久报警”，不归一化成“未启用”。
- 右键“重置永久报警”仅在安全空闲时可用；清报警和连续次数、保留圈数、保持未勾选。
- 重新勾选锁存卡钳需二次确认；原子清报警和连续次数并启用，但不自动开始，仍执行完整预检。
- 旧项目仅将 `Enabled=false + Status=Alarm` 迁移为 `LegacyDisabledAlarm`，普通未启用通道不反推报警。

### 4. 自动恢复与版本

- Watchdog 接管安全退出使用强类型回执，旧主程序不再在关闭链中二次 `StopAll`。
- 新增 `WatchdogTakeoverExit`，与人工 `ShutdownExpected` 分离；接管退出不会撤销待消费的恢复许可。
- 同一主窗进入新 Session/Lease 时丢弃旧的缓存关闭回执，确保新会话实际执行安全停止。
- 恢复子进程提前退出、附加超时和检查点拒绝进入有界失败链；`Started/Attached` 残留会耐久归并为失败或阻断终态。
- 主程序及 Watchdog Host/Client/Protocol 的 Assembly/File/Product 版本统一为 `2.13.0.30`，ClickOnce `ApplicationVersion=2.13.0.30`。

## 验收口径

- “所有卡钳等待”是指当前正式槽内全部已启用参与者，包括不同液压组；并不允许正常卡钳跨槽提前上电。
- 慢卡钳 16 秒完成（周期 15 秒）时，仅慢卡钳记一次普通超限；其他卡钳显示等待，本槽闭合后统一走未来边界。
- 第 7 次超限重启后恢复为 7；第 8 次锁存永久报警并禁用。中间任何一个正常完成圈会清零连续次数。
- 30 秒仍带电只隔离未安全终止的卡钳；迟到异步代码受执行许可和代次栅栏约束，不得重新上电。
- 安全收口失败不是“让其他卡钳继续”的条件，而是整批故障条件。
