# V2.12.0.17 VS2022 生成失败修复记录

## 结论

2026-08-09 已在本机 Visual Studio 2022 Professional 的 `Release | x86` 配置下重新生成成功：**0 个错误**。截图中的 6 个错误并非 6 个独立故障，根错误是旧式非 SDK 项目没有在 VS 当前项目快照中编译新增源码；其余 `CS0006` 均为上游 DLL 未生成引起的连锁错误。

## 根因与处理

| 现象 | 根因 | 处理 |
|---|---|---|
| `IO.NI` 报 `CS0246 CoalescingTaskSupervisor` | `IO.NI.csproj` 是旧式项目，新增 `.cs` 文件必须显式列入 `<Compile Include>`；VS 长时间运行后仍持有旧项目快照 | 在 `IO.NI.csproj` 中显式加入 `CoalescingTaskSupervisor.cs` |
| 后续出现 `LatestPairMailbox` 找不到 | `Controller.csproj` 的磁盘清单已包含该文件，但旧 VS 会话没有载入最新项目模型 | 强制重载 `Controller` 项目；为旧式项目保留显式 include 说明 |
| 项目重载提示“无法连接 MSBuild 进程” | VS 会话从 2026-08-08 持续运行，残留多组失联 MSBuild node，项目加载服务已失效 | 保存已打开文档、结束失联 MSBuild 工作节点并完整重启 VS2022 |
| `Controller.dll`、`IO.NI.dll` 找不到 | 上述 `CS0246` 导致上游项目未产出 DLL | 根错误修复后自动消失，无需手工复制 DLL |

## 永久性项目修改

- `IO.NI/IO.NI.csproj`：加入 `<Compile Include="CoalescingTaskSupervisor.cs" />`。
- `Controller/Controller.csproj`：确认并保留 `<Compile Include="LatestPairMailbox.cs" />`。
- `Tools/Build-Release.ps1`：正式构建前校验五个关键新增源码的文件存在性和旧式项目 `Compile` 登记，任一遗漏即拒绝生成。

这两个项目都是旧式 .NET Framework 项目，不会像 SDK-style 项目那样自动编译目录中的全部 `.cs` 文件。以后新增源码时必须同步修改 `.csproj`，否则命令行、CI 或重新打开 VS 后可能出现类型缺失。
