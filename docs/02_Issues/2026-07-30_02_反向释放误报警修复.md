# EPB 反向释放误报警修复（2.0.1）

## 现象

2026-07-30 11:14:52.473 启动的试验中，EPB8/EPB9 出现
`ReverseAbsoluteOnTimeExceeded`。现场电流曲线已经进入反向空载区，但程序未在
5 秒绝对上电保护前确认释放。

## 根因

原逻辑保留 150 ms 窗口，同时要求窗口首尾覆盖至少 140 ms。快速电流回调的实际
间隔约为 10～31 ms；某些稳定节拍（例如 17 ms）在每次淘汰旧样本后只能形成约
136 ms 覆盖，因此窗口永远不合格。释放候选持续时间随之反复清零，最终触发绝对
上电超限。

这是程序判定逻辑对采样节拍过于敏感导致的误报警，不是 LabVIEW 问题；已有证据
也不支持程控电源限流或保护动作。

## 修复

- 反向释放改用 200 ms 稳健窗口，要求至少 120 ms 覆盖和 8 个样本。
- 使用窗口 P90 判断是否低于学习阈值，以 P90-P10 判断波动，允许忽略孤立毛刺。
- 低负载条件仍需连续保持 200 ms 才确认释放。
- 保留开路、异常高电流平台、三样本过流和绝对上电时限等安全保护。
- 报警目录新增 `adaptive-decision-timeline.csv`。
- `alarm-metadata.json` 升级为 schema 2，记录窗口统计、释放阈值、候选持续时间与
  最终判定原因。

## 回归覆盖

- 17 ms 固定采样节拍。
- 稀疏高电流毛刺。
- EPB8/EPB9 现场反向曲线的紧凑回归夹具。
- 持续高负载不得误判释放，且仍触发绝对上电保护。
- 原有夹紧、开路、DAQ 断流、过流、错峰、报警证据和电源联锁用例。

## 部署

版本为 `2.0.1`。部署前停止试验程序并备份原目录，再用 Release 包完整替换应用
文件；配置文件应先做差异合并，不能盲目覆盖现场 IP、通道和阈值配置。首次验证
建议仅选择 EPB8/EPB9，确认报警快照中可生成新增的自适应判定时间线。

本次只生成本地 Release 包，不自动写入 `\\wj-epb\debug\2.0.0`。
