# V2.13.0.43 自动恢复永久阻断彻底修复实施及验收

## 1. 结论与发布状态

针对封盘数据 `D:\EPB_Data\Backups\10243-028_V2.13.0.42_I0006_0831_0016` 中 V2.13.0.42 运行一段时间后自动恢复进入不可自恢复终态的问题，V2.13.0.43 已完成代码层面的架构性整改：安全动作已从主程序拆分为独立 SafetyAgent，恢复许可被收敛为唯一耐久事务，控制时间改用单调时间轴，真实 DAQ 恢复增加 5 秒稳定重入门禁，同时增加耐久本地告警、Windows Event Log 和签名 Webhook。

本次整改不再把“必须总能重新拉起主程序”当作无人值守成功的唯一标准。遇到真实配置损坏、证据被篡改或硬件持续失效时，正确终态是：

1. 物理输出持续 OFF；
2. 不消费未经验证的恢复许可；
3. 可恢复故障在同一许可或新的半开许可中自动复探；
4. 本地告警始终留存，Webhook 可用时持续送达；
5. 不依赖人工点击弹窗解除永久阻断。

截至 2026-08-31，本地代码实施、Release/Debug 编译和关键自动化分组已通过；真实 NI、液压、电源、压力传感器故障注入以及 24 小时/72 小时现场耐久尚未执行。因此：

> **代码整改状态：完成。现场正式发布状态：NO-GO。**

只有第 10 节全部现场项目通过并附上证据后，才能把状态改为“现场发布验收完成”。

根因和原始证据保留在 [V2.13.0.42 根因分析文档](../V2.13.0.42_0831_0016_自动恢复永久阻断根因分析与无人值守彻底解决方案-20260831.md)，本文不覆盖或改写该文档。

## 3. 已落地的代码变更

### 3.1 独立 SafetyAgent 与不可变 DAQ 配置

- 新增 `MTTFTest.SafetyAgent/` 工程，输出 `MTTFTest.SafetyAgent.exe`，目标为 `.NET Framework 4.8/x86`。
- SafetyAgent 仅引用配置、NI 基础控制、电源驱动和 Watchdog 协议，不引用 WinForms、`Main_Frm`、`ClsGlobal`、`TwoDeviceAiAcquirer` 或业务持久化管线。
- 删除 `MTTfTest/WatchdogSafetyShutdownWorker.cs`，并从 `MTTfTest/Program.cs` 和项目文件移除旧 Worker 入口。
- 新增 `Config/DaqRuntimeSettings.cs`。主程序在启用硬件前读取并验证采样率与批大小，同一进程中禁止用不同值重新配置 Watchdog 安全运行时。
- `FrmEpbMainMonitor`、`FrmDAQCalibrate`、`FrmTestSetting` 和压力校正硬件均显式接收同一个 `DaqRuntimeSettings`，不再从可变全局值决定硬件采样参数。
- `IO.NI/TwoDeviceAiAcquirer.cs` 在构造入口验证采样率、批大小、重复通道、空通道和未启用通道，失败抛出 `DaqRuntimeConfigException`，错误码为 `DaqRuntimeConfigInvalid`。
- 新增 `IO.NI/SafetyPressureProbe.cs`，只创建安全确认所需压力 AI 通道，使用快照中的显式采样参数，不启动完整生产采集器。
- SafetyAgent 的动作顺序固定为：DO OFF、AO=0、电源输出 OFF、压力稳定安全确认；截止时间和稳定保持时间只使用 `Stopwatch`。

### 3.2 安全快照 v2 与分阶段安全回执 v3

- `SafetyRuntimeSnapshot`/清单 schema v2 绑定以下身份：
  - SessionId、SessionGeneration、SessionLease；
  - HandoffId；
  - PermitGeneration、PermitId；
  - 主程序 SHA-256；
  - SafetyAgent SHA-256；
  - 经验证的采样率、批大小、压力通道和安全阈值。
- 快照目录只允许清单列出的文件；缺失文件、额外文件、路径越界、哈希变化和 schema v1 均在硬件打开前拒绝。
- 安全回执升级为 schema v3，`WatchdogSafetyHandoffState` 数值保持兼容，新增阶段：

```text
AgentStarted
  -> DoOffConfirmed
  -> AoZeroConfirmed
  -> PowerOffConfirmed
  -> PressureSafeConfirmed
  -> Completed
```

- 每次阶段推进原子写穿 `Revision`、`PreviousStageReceiptSha256`、`StageMonotonicElapsedMs`、`StageUtcTicks`、配置哈希和硬件确认位。
- SafetyAgent 崩溃或硬件瞬态失败后，从最后一个已确认阶段继续；已完成回执再次执行时不会重新打开硬件。
- Host 在 `Process.Start` 前先耐久写入启动意图，避免 SafetyAgent 快速推进后被 Host 的旧回执覆盖。

### 3.3 唯一恢复事务、失败域和自动半开

- 新增 `Watchdog.Protocol/RecoveryReplacementTransaction.cs`，唯一键为 `(SessionId, PermitGeneration, PermitId)`。
- 固定状态机为：

```text
Approved
  -> OldProcessExitProven
  -> SafetyAgentRunning
  -> SafetyCompleted
  -> MainLaunchIntent
  -> MainStarted
  -> Attached
  -> CheckpointCommitted
```

- AutomaticTakeover 与 ApplicationExit 只提交同一事务的观察结果；重复、迟到或并发观察返回 `AlreadyApplied`。
- SafetyAgent 瞬态/硬件失败在同一 Permit 内按 1、5、15、30 秒退避重试；硬件不可用期间输出保持 OFF。
- 只有 `MainLaunch` 域中实际执行 `Process.Start` 后的启动、附着或检查点提交失败才增加主程序连续启动失败数。
- 非永久的主程序启动失败进入自动半开：30 秒、60 秒、300 秒冷却后创建新 generation/new permit，再次执行完整安全确认。
- 配置、哈希或身份失败不盲目半开；系统保持 OFF 并持续告警。
- CircuitOpen 时停止高频许可轮询；重复身份不匹配只保留首次事件，后续按 30 秒汇总。

### 3.4 单调控制时间轴与 DAQ 稳定重入门禁

- `TwoDeviceAiAcquirer` 的控制序号、批次排序、新鲜度和恢复期限只依赖单调时钟与样本序号。
- UTC 作为审计映射单独维护 `EpochId`。墙钟前跳、后跳或连续小步校时只切换 epoch，不丢控制批、不重建 Task、不触发电源或机械恢复。
- 时钟诊断新增 `InvalidReason`、`CandidateRateHz`、`CandidateSkewPpm`、估算窗口、连续确认数和 `EpochId`。
- 单独出现 `DaqClockModelInvalid` 时重置估算器；只有同时存在回调陈旧、序号断裂或硬件读异常才升级到真实 NI Task 重建。
- 新增 `Controller/DaqRecoveryRejoinGate.cs`，默认 `DaqRecoveryStableWindowMs=5000`。稳定窗口必须同时满足：
  - 回调新鲜；
  - generation 不变、处理序号不回退且继续增长；
  - gap/discontinuity 计数不变；
  - 持久化边界闭合；
  - 输出 OFF 证据有效；
  - Watchdog 管道健康；
  - 无待处理接管许可。
- 任一条件失败都会清零稳定窗口；超时以 `DaqRecoveryStableRejoinTimeout` 失败并保持 OFF。
- 测试入口可注入虚拟单调时钟，生产入口固定使用 `Stopwatch.GetTimestamp()`。

### 3.5 无人值守告警

- 新增 `IUnattendedAlarmSink`/`UnattendedAlarmSink`，同时写入：
  - 项目日志目录下的耐久告警 spool；
  - Windows Application Event Log，事件源 `MTTFTest.Watchdog`；
  - JSON Webhook。
- Webhook 使用唯一 `EventId`，`X-EPB-Timestamp` 和 `X-EPB-Signature: sha256=<HMAC-SHA256>`。
- 失败退避为 1、5、15、30、60、300 秒；服务重启会重放未确认事件。
- 相同告警按稳定指纹压缩并累加 `OccurrenceCount`；发送期间出现新重复事件时，不会删除较新的耐久修订。
- Webhook 未配置、密钥缺失或发送失败时进入 `AlarmDeliveryDegraded`，本地告警和安全控制继续工作。
- 告警组件初始化失败时仍回退到本地 Event Log，不静默吞掉 P0 事件。
- 配置文件为 `MTTfTest/Config/UnattendedAlarmConfig.xml`。真实密钥只能从 `EPB_UNATTENDED_WEBHOOK_SECRET` 读取，禁止写入 XML、仓库或命令行参数。
- 管理员脚本 `Tools/Install-EPB-UnattendedAlarm.ps1` 负责事件源注册、目录写权限、HTTPS 地址和连通性预检；脚本不接收真实密钥参数。

| MainLaunch 非永久失败 | 冷却后允许半开 | 持续 OFF | 新 generation/new permit，重新做完整安全确认 | 本地 P0 + Webhook |
| Webhook 不可用 | 不影响安全状态机 | 由安全状态决定 | 持久 spool 并持续重连 | `AlarmDeliveryDegraded` + Event Log |
| DAQ 重入窗口内出现空窗/断链 | 禁止重新上电 | 持续 OFF | 重置 5000 ms 窗口 | 恢复进度与异常事件 |
