# V3 R24 安装报告成功但仍无界面：复盘与 R25 修复

## 结论与证据

这不是操作员未安装 R24。`2026-09-04 08:05:28` 的部署结果明确记录来源为
`V3.0.0.0_现场验证包_711330783215_QUICKDEPLOY_R24\Package`，结果却是 `PASS`。
08:08 只读核查发现 Current 的实际提交仍为 `8a944e8c6ca854434353f1bf83bf59647de288c2`
（R23），EngineHost PID `73232` 自前晚一直存活，UI 进程不存在。

原因有两层：

1. 安装器 `Test-CurrentSlotReplacementRequired` 只允许版本号严格增大。R23、R24 都是
   `3.0.0.0`，于是忽略修复包内容，跳过换包；最终检查只看服务和文件存在，错误报告成功。
2. Supervisor 的 `EngineHostPipeClient` 设置 `PipeStream.ReadTimeout/WriteTimeout`。
   本机 Windows PowerShell 5.1/.NET Framework 实测：管道连接成功、`CanTimeout=False`，
   设置属性立即抛出 `Timeouts are not supported on this stream`。即便 R24 正确落盘，
   原客户端仍无法正常读取 EngineHost 快照，因此此前仅测试身份绑定不足以证明启动链路。

旧宿主日志在 08:08 已约 504 MB；每次失败连接形成空探针，也持续触发旧宿主日志问题。
本次不删除日志或事故数据，保留原证据。

## 修复边界

- 同版本修复包按完整 build-identity 和全部清单文件哈希比较，不按产品版本号跳过；显式拒绝
  低版本静默降级。源包损坏拒绝安装；Current 损坏允许由完好的源包修复。
- 安装完成后再次核验 Current 与源包完全一致，结果写入实际提交和 package hash。
  全程保存 transcript；失败或未完成不能留下本次 PASS。
- 旧 EngineHost 在线时先请求人工物理维护隔离确认，再停止监督与登录任务、核验 PID、
  创建时间及路径，等旧宿主退出后换包；新进程或身份不明时拒绝操作。用户本次已确认
  现场停止、物理断能和泄压。此确认不充当运行内核的 SafetyProof，不放宽自动上电条件。
- 未正式批准的旧候选 LKG 不因“大版本相同”而继续保留为已验证回滚槽；更新候选基线并保留
  旧目录审计，不删除历史。
- 生产管道改用 Asynchronous IO + 总 deadline，取消时关闭句柄；覆盖连接后静默、断帧、
  乱身份回包和真实 EngineHost 快照读取，不再依赖测试专用客户端证明生产通信正确。
