# V2.13.0.16 EPB10 二次复核：Accepted 尾批与预触发语义闭环记录

## 1. 复核结论

二次复核确认，原 V2.13.0.16 实施稿仍有一个会影响波形完整性的代码缺口：圈封口终点曾取 `LastDiskPublishedSequence`。当采集链已经接纳到 1002、写盘发布水位暂时停在 1000 时，1001/1002 虽已属于该圈，却可能在封口后被排除。

该缺口现已修复并完成自动化回归。当前结论分两层：

| 层级 | 状态 | 判定 |
| --- | --- | --- |
| 根因、停机语义、圈头/圈尾、重复 Latest、恢复门禁 | 已闭环 | 代码和自动化证据完整 |
| 实际 NI、DO、程控电源、卡钳联调 | 待现场执行 | 属于发布验收，不是已知代码缺口 |

因此，**软件问题已经闭环；正式替换现场版本仍必须通过 HIL/实机验收后，才能宣告发布闭环。**

## 2. 本次发现的未闭环场景

修复前可能出现以下时序：

```text
DAQ/控制链接纳水位       AcceptedSequence = 1002
磁盘发布水位             DiskPublishedSequence = 1000
圈封口错误取值           endSequence = 1000
稍后到达写盘线程         sequence = 1001、1002
旧结果                   因 sequence > endSequence 被排除
```

这会产生一种比“完全没有波形”更隐蔽的错误：文件和圈头都存在，但圈尾少了已经接纳的批次。仅校验文件存在、样本数大于零或 `DiskPublished >= endSequence`，无法发现该问题。

## 3. 已实施闭环

### 3.1 唯一权威封口边界

`Controller/EpbManager.cs` 现在执行以下不变量：

1. 普通停止、报警和通用 Finalizer 以 `LastAcceptedSequence` 作为圈终点；
2. `LastDiskPublishedSequence` 只保留为诊断水位，不参与选择圈终点；
3. DAQ 恢复事故优先复用事故开始时的 `PreviousGeneration + FrozenBoundary`；
4. 同一次 Finalizer 捕获的边界用于圈封口、Raw 排空和耐久等待；
5. 已经以安全截止封闭的圈不得被后续更大水位重新扩大。

关键实现：

- `Controller/EpbManager.cs:863`：`SelectAuthoritativeCycleEndSequence`；
- `Controller/EpbManager.cs:879`：`CaptureCycleDaqBoundaries`；
- `Controller/EpbManager.cs:1052`：通用封口、Raw 排空和耐久等待共享捕获边界；
- `Controller/EpbManager.cs:4004`：DAQ 恢复 Finalizer 强制复用冻结边界。

### 3.2 延迟尾批处理

`DataOperation/EpbDiskWriter.cs` 的序号写入规则保持为：

```text
startAfterSequence < sequence <= endSequence  -> 属于本圈
sequence <= startAfterSequence                -> 圈开始前，排除
sequence > endSequence                        -> 圈结束后，排除
```

因此，圈封口后才到达写盘线程、但已经位于冻结 Accepted 边界内的 1001/1002 会继续写入并参与耐久确认；1003 及更大的新批次不会污染旧圈。

### 3.3 报警波形语义门禁

仅有“文件存在”不再等于证据完整。对启用 DAQ 序号边界的正式报警圈，`DataOperation/EpbDiskWriter.cs:650` 要求：

- `PreTriggerSampleCount >= 400`，按 2 kHz 为至少 200 ms 未上电基线；
- 存在明确的 `CycleEndSequence`；
- `CycleEndSequence >= CycleStartAfterSequence`；
- `LastWrittenSequence >= CycleEndSequence`。

500 点/250 ms 是预触发缓存容量，400 点/200 ms 是报警证据最低门槛。少于门槛的文件仍保留用于诊断，但 `SemanticEvidenceComplete=false`，不得冒充完整报警证据。

报警元数据已升级为 schema 7，并增加：

- `lastWrittenSequence`；
- `requiredPreTriggerSampleCount`。

关键实现：`DataOperation/EpbDiskWriter.cs:236`、`:650`、`:957`，`Controller/DoControlTrace.cs:679`、`:713`。

## 6. 现场最终验收

现场至少复核以下结果：

1. 注入前/后跳 1.5 s 的系统时间，当前圈安全截止，恢复完成前不得启动下一圈；
2. 反向释放阶段注入超过 100 ms 的 DAQ 陈旧，确认机械预释放门禁有效；
3. 报警 CSV 至少包含 400 点未上电基线，且 `LastWrittenSequence >= CycleEndSequence`；
4. 同一报警只生成一个带 `latest-manifest.json` 的 Final Latest；
5. 回放 85993 应按目标附近平台完成，真实过流/堵转仍应立即断电并锁存；
6. 连续运行期间不得再出现固定约 1.4 s 截头、Accepted 尾批缺失、只有断电尾部或同一报警双 Latest。

上述实机项目全部通过后，发布状态才可由“软件闭环”转为“现场闭环”。
