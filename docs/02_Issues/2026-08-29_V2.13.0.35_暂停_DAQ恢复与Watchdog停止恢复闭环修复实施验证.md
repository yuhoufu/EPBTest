# V2.13.0.35 暂停、DAQ 恢复与 Watchdog 停止恢复闭环修复实施验证

## 1. 结论与发布状态

V2.13.0.35 已完成代码实施、本机自动化、本机真实 Sidecar/命名管道进程夹具验证，以及 Debug x86、Release Any CPU 双配置构建。V2.13.0.34 现场问题中的六段失效链——暂停所有权丢失、DAQ 幽灵屏障、SystemFault Stop 回执不能被人工退出采用、Watchdog 关闭可逆、已终止 Session 被新 Sidecar 复活、恢复子进程拒绝后许可悬挂——已分别建立不可逆身份和有界终态。

当前状态：**候选版，待现场正式验收**。

本次没有生成正式发布包，没有提交 Git，也没有把候选版标记为正式放行。NI 双设备、CAN、四路程控电源、液压台架下的 100 轮组合故障和 8 小时长稳仍是正式放行门槛。

原始根因、封存数据和现场时间线仍以 [V2.13.0.34 根因文档](./2026-08-29_10358-029a_V2.13.0.34_暂停启动受阻_停止退出误接管与恢复卡住根因及彻底解决方案.md) 为准；本文只记录 V2.13.0.35 的实施和验证，不改写原文。

## 2. 版本与兼容性

主程序、Watchdog Sidecar、Watchdog Client、Watchdog Protocol 已统一为：


V35 继续读取既有合法 V4 durable relaunch 记录；协议新增字段和枚举均为加法兼容。V35 写入 `RejectedNoWork`、closing tombstone 或 bootstrap outcome 后，不允许 V34 对同一活动 Session 降级恢复。主程序、Client、Protocol 和 Sidecar 必须同包升级。

## 3. 根因到修复的映射

| V34 根因 | V35 修复 | 结果 |
| --- | --- | --- |
| PausePending 不是跨恢复事务 Owner | `BatchPauseSnapshot` 固化 `RunId + RunEpoch + PauseGeneration + CommandId + FrozenChannels`；通道投影同一身份 | 电源/DAQ 恢复不能再把精确暂停 Owner 收成通用 StartBlocked |
| 暂停提交前未复核运行载体 | 在 `_daqRecoveryCommitGate` 内复核 Timer、Runner、Formal、Energized、恢复 Owner 和暂停身份 | 载体丢失时禁止发布假 Paused，转一次 `PauseSafetyFailed → StopAll` |
| DAQ 屏障把事故相关设备当作实际参与者 | 动态注册 `DaqRecoveryParticipantToken`，事故出版和恢复准入分离，出版结束后 Seal | 没有上下文的 Dev2 记为 `NoRunnableContext`，不再阻塞 Dev1 |
| 暂停中的恢复没有合法终态 | 新增 `RecoveryExitDisposition`，精确暂停提交 `HeldForManualPause` | 保留 Timer/Runner/Formal，保持输出 OFF，不执行运行态重入 |
| SystemFault Stop 回执被 ManualUi 来源条件拒绝 | `StopSafetyResult` 固化安全事务身份；新增 `ManualExitIntentReceipt` | 同 Run/代次的安全结果可被人工退出采用，原始来源只用于审计 |
| Runtime Closing 未撤销 Engine Launch | `BeginSessionCloseExact` 先验证精确 Session 身份，持久化 tombstone，再关闭 Engine Launch/Connect/Reconnect | `IdentityMismatch`、Detach 或收口失败只能保留重试，不能恢复启动许可 |
| 新 Sidecar 忽略同 Session 人工终态 | Sidecar 在开管道前读取 closing、revocation、terminal manifest；恢复 Journal 保留 `ManualStopRequested` | 同 Session 终态在进程重启后仍不可逆，新 Sidecar 立即退出 |
| Disarmed 子进程拒绝恢复但 Permit 永久 Started | 新增 `RejectedNoWork` 与带 HMAC 的 `RecoveryBootstrapOutcome`；Sidecar 同时观察回执和精确进程句柄 | 无工作不计恢复失败、不打开熔断，覆盖窗有界关闭 |
| 覆盖窗固定显示“剩余 20 秒” | 所有等待改用 `Stopwatch + fixed deadline` | 剩余时间单调递减，NoWork、失败、退出或 Attach 后立即进入终态 |

## 4. 代码改造

### 4.1 暂停事务与恢复终态

- `Controller/EpbManager.PauseResume.cs`
  - 暂停事务身份在 `PausePending → Paused/ResumeChecking` 全程不变。
  - 安全边界后等待精确恢复 Owner 收口，再在 DAQ recovery commit gate 内提交前复核。
  - 任一冻结通道缺 Timer/Runner、身份错代、仍带电或仍有恢复 Owner 时，禁止发布“全部通道已安全暂停”；统一升级为安全停止。
- `Controller/ChannelRuntimeState.cs`
  - 增加暂停代次、暂停命令身份和 `RecoveryExitDisposition`。
- `Controller/EpbManager.cs`
  - 电源恢复在精确人工暂停 Owner 下只完成 OFF 和耐久截止，提交 `HeldForManualPause`；通用 `finally` 按强类型 disposition 收口。
  - DAQ 恢复在运行态共同槽之前处理人工暂停 Withdraw。

建立的不变量：

```text
Paused 可提交
  = 同 RunId/RunEpoch/PauseGeneration/CommandId
  + TimerActive
  + RunnerActive
  + FormalPhaseCommitted
  + Energized == false
  + 无恢复 Owner
```

### 4.2 DAQ 动态恢复屏障

- `Controller/EpbManager.DaqLiveness.cs` 只在真实 `DaqAutoRecoveryContext` 创建成功后注册屏障参与者，事故发布完成后统一封口。
- `Controller/EpbManager.RecoveryCoordination.cs` 引入单调参与者状态 `Registered → Ready/Withdraw → Terminal`；令牌在 `Dispose/finally` 必须终结。
- `NoRunnableContext` 只进入诊断，不进入 Expected；`HeldForManualPause` 是中性 Withdraw。
- 屏障诊断包含 Seal、参与者状态和 Withdraw/Terminal 原因；10 秒超时只保留为最终保险。

### 4.3 StopAll 与人工退出意图

- `StopSafetyResult` 和所有克隆、成功、失败、超时、复用路径均携带：

```text
SafetyTransactionId
RunId
RunEpoch
SafetyBoundaryGeneration
```

- `MTTfTest/EpbMonitorShutdownOwnership.cs` 的 `ManualExitIntentReceipt` 只采用同 Run、同代次且已满足物理断能、持久化边界和逻辑终态的 Stop 回执，不再要求原始 `Source == ManualUi`。
- 新 Run 会撤销旧人工退出回执；旧 Run、旧 RunEpoch 或旧安全代次均拒绝复用。
- Watchdog 收口异常时，界面语义改为“设备已 OFF，监督会话关闭待重试”，自动恢复保持撤权，不再提示等待自动接管。

### 4.4 Watchdog 不可逆关闭

- 新增 `Watchdog.Protocol/WatchdogClosingTombstone.cs`：本机与项目会话目录 WriteThrough 双写，绑定 SessionId、Generation、Lease、关闭意图、Stop 安全事务身份、状态版本和终态原因。
- `WatchdogRuntime.BeginSessionCloseExact` 在写 tombstone 前只读验证 Runtime/Engine 精确身份；tombstone 成功后在 Engine Gate 撤销 Launch、Connect 和 Reconnect。
- 关闭协调器的 closing→terminal 均通过同一会话端口；Engine、pipeline、journal 或 tombstone 任一阶段失败时保留同 owner 重试，不释放新会话准入。
- Sidecar 构造后、打开命名管道前读取 tombstone、`.revoked` 和 terminal manifest；命中同 Session 终态时记录 `TerminalSessionObservedOnStartup`、撤销活动 Permit 并退出。
- closing 和 bootstrap outcome 文件已纳入 Watchdog journal 文件名校验、清理及容量策略；旧 `.revoked` marker 保持兼容。

### 4.5 恢复许可有界终态

- `DurableRelaunchPermitState` 末尾新增兼容值 `RejectedNoWork = 9`；V4 校验器将其视为不打开熔断、不增加失败次数的中性终态。
- Sidecar 在许可发布后和真正 `Process.Start` 前再次读取 closing、revocation 和 durable checkpoint。已 Disarm、身份换代、revision 倒退或已知检查点不可读时，提交 `RejectedNoWork`，不创建主程序。
- 新增 `Watchdog.Protocol/RecoveryBootstrapOutcome.cs`，支持：

```text
RecoveryAccepted
RejectedNoWork
StartupFailed
RecoveryUiAttached
```

- bootstrap receipt 绑定 Session、Permit Generation/Id、子进程 PID/start ticks、checkpoint revision，并以 PermitNonce 计算 HMAC；Sidecar 只接受身份和 HMAC 均精确匹配的结果。
- 恢复子进程保留 `TryConsumeWatchdogRecovery` 二次检查。Sidecar 对精确进程的 `StartupFailed` 回执立即结束本次许可并进入统一恢复失败事务；Attach 前无回执退出最多再等待 5 秒 outcome，固定 20 秒 Attach deadline 到达后不再继续显示加载界面。

## 5. 不可破坏的不变量

| 编号 | V35 不变量 |
| --- | --- |
| I1 | 输出 OFF 优先；身份冲突、持久化失败和恢复异常均失败关闭，不恢复上电授权 |
| I2 | Paused 必须具有完整暂停身份、运行载体、Formal 参与者、无恢复 Owner 且无带电证据 |
| I3 | 精确 Pause Owner 下的恢复只能 `HeldForManualPause` 或整批安全停止，不能通用 StartBlocked |
| I4 | DAQ 屏障只等待已取得令牌的实际上下文，每个令牌都必须有有界终态 |
| I5 | Stop 安全事务来源与人工退出意图分离；旧 Run/旧代次回执不能复用 |
| I6 | closing tombstone 一经写入，同 Session 的 Launch/Connect/Reconnect 权限不可恢复 |
| I7 | 每个 RelaunchPermit 必须进入 Committed、RejectedNoWork、失败终态或操作员取消，不能永久 Started |
| I8 | 覆盖窗只显示基于单调时钟的剩余时间，终态后不得继续显示“主程序正在加载” |

## 8. 已知限制与遗留风险

1. 本机没有连接现场 NI Dev1/Dev2、CAN、四路电源和液压设备，因此不能证明驱动、通讯和物理响应在真实组合故障下的时序裕量。
2. 本次未生成受控 Release package；`PackageVerified=True`、Git commit、buildUtc、配置/文件哈希清单必须在正式打包流程中验证。
3. V35 closing/NoWork 状态对 V34 不向后兼容；活动 Session 不得混用或降级 Sidecar、Client、Protocol。
4. closing tombstone 项目副本写入失败会失败关闭并保留 UI 重试；这保证不会误恢复，但可能需要运维处理项目盘权限或空间问题。
5. 本机用测试宿主驱动真实 Sidecar/命名管道；真实 WinForms UI、现场驱动和硬件的 100 轮组合仍未执行。
