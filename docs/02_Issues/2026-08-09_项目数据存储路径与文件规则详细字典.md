# EPB 项目数据存储路径与文件规则详细字典

> 文档日期：2026-08-09
> 代码基线：MTTFTest `2.12.0.25`
> 适用对象：开发、测试、发布、现场运维及数据追溯人员
> 文档性质：当前实现说明；路径、文件内容和上限以本文列出的代码实现为准

## 1. 文档结论

程序的数据不是全部存放在项目目录。当前实际存在六类根路径：

| 缩写 | 路径定义 | 主要内容 |
|---|---|---|
| `W` | `Environment.CurrentDirectory`，进程工作目录 | 默认配置、12 路环形 `.dat`、每次打开主监控生成的配置快照目录 |
| `B` | `AppDomain.CurrentDomain.BaseDirectory` / `Application.StartupPath`，EXE 目录 | EXE 配置、发布身份、部分配置读取和 Incident 最后一级回退 |
| `S` | 当前 `TestConfig.StoreDir` | 所有项目的父目录 |
| `T` | 当前 `TestConfig.TestName` | 项目名称 |
| `P` | `S\T` | 当前项目配置、索引、快照、遥测和日志 |
| `U1` | `%LOCALAPPDATA%\Wanxiang\EPBTest` | 最后一次选择的项目 |
| `U2` | `%LOCALAPPDATA%\MTTFTest` | 无人值守运行恢复检查点 |
| `TMP` | `%TEMP%` | Incident 写入失败的第二落点 |

最重要的边界如下：

1. `P` 是项目证据目录，但 12 路原始环形文件固定在 `W\DataStore`，并不随项目切换。
2. `P\index.db` 记录圈在环形文件中的位置；CSV/BIN 是从环形文件和索引再次导出的证据副本。
3. `Latest` 当前默认每通道保留 10 个停止包，每个停止包最多包含最近 10 圈。
4. `HistoricalSnapshots` 当前每通道滚动保留约 12 圈 BIN。
5. 软预警默认只写每日 JSONL；完整 CSV/BIN 默认关闭。完整证据启用后才执行“每通道、每故障代码保留 30 次”。
6. 硬报警默认只保存报警通道最近 10 圈；同电源组开关默认关闭，不同电源组永不保存圈副本。
7. `run` 日志归档保留 7 天；`warning`、`error`、`ui-info` 归档保留 30 天。
8. Learning、Alarm、Incident、每日 Warning JSONL、快照错误文件和重置审计没有运行时总量上限。
9. 程序内“清空并重新学习”、运行时滚动保留和离线 BAT 是三套不同规则，不能混为一谈。

## 2. 当前项目如何确定

程序首先读取默认配置，然后尝试恢复上次项目：

```text
W\Config\TestConfig.xml
        │
        ├─ 初始 StoreDir / TestName
        │
U1\user-state.json ──存在且 P\Config\TestConfig.xml 有效──> 当前项目 P
        │
        └─ 不存在时才尝试 B\MTTFTest.exe.config 的 InitialProjectPath
```

当前首次引导配置为：

```text
InitialProjectPath = D:\EPB_Data\10358-029
```

一旦 `user-state.json` 已保存，后续启动优先使用该文件。确认现场实际项目时，应同时核对 UI、`user-state.json` 和 `P\Config\TestConfig.xml`，不能只查看软件目录下的默认模板。

## 4. 总体保留上限表

“运行时上限”指程序正常运行时自动执行；“离线上限”指把配套 BAT 复制到项目根并执行后才生效。

| 数据类别 | 运行时默认上限 | 可配置性 | 离线 BAT 规则 | 重要例外 |
|---|---:|---|---|---|
| 12 路环形 `.dat` | 100 MiB/通道，合计 1,200 MiB | 当前主程序中固定 | 不处理 | 位于 `W`，不属于 `P` |
| `index.db` | 无圈数/容量上限 | 无 | 不处理 | 仅“清空并重新学习”会删除重建 |
| Latest 包 | 10 包/通道 | `Count` 或 `Unlimited`，计数 1..100000 | 10 包/通道 | 未知或不完整目录不自动删除 |
| Latest 单包圈数 | 最近 10 圈 | 当前调用固定为 10 | 不改变包内容 | 圈数不足时保存实际可用圈 |
| Historical | `max(3, HardAlarmLastNCycles+2)`，当前 12 圈/通道 | 随报警圈数间接变化 | 12 圈/通道 | 删除失败可能短暂超过上限 |
| LearningCycles | 无运行时上限 | 无 | 按修改时间保留最近 3 个 RunId | 旧格式无成功/失败标识 |
| Warning 每日 JSONL | 每自然日一个文件；无保留天数 | 目录名可配置 | 当前 BAT 不识别、不删除 | 默认软预警主要数据 |
| Warning 完整证据 | 默认关闭；开启后 30 次/通道/故障代码 | `Count`/`Unlimited` | 30 次/通道/故障代码 | 限频 600 秒/类别；不完整目录不删除 |
| Warning 全局配额 | 默认 0，即关闭 | `SoftWarningQuotaMb` | 不修改配置 | 配额只归档旧 RunId 的完整证据 |
| Alarm 单事件圈副本 | 报警通道 10 圈；同组默认 0 | 同组开关及同组圈数可配 | 删除历史辅助 EPB 目录 | 不限制报警事件总数 |
| StartupPositioning | 单事件最多记录 10,000 个启动跟踪样本 | 代码固定 | 不单独处理 | Alarm 事件总数仍无限 |
| Incident | 无运行时会话上限 | 最近圈复制开关默认 false | 保留最新 10 会话 | 每个事故可有多个阶段 |
| PowerSupplyTelemetry | 每次 RunId 一个文件，无运行时天数/大小上限 | 无 | 删除严格早于 3 天的标准文件 | 活动运行文件不能离线清理 |
| `run` 日志 | 50 MiB/文件或跨日轮转；归档 7 天 | 代码默认 | 归档 7 天 | 活动文件不删除 |
| `warning/error` 日志 | 50 MiB/文件或跨日轮转；归档 30 天 | 代码默认 | 归档 30 天 | 活动文件不删除 |
| `ui-info` 日志 | 10 MiB/文件或跨日轮转；归档 30 天 | 代码默认 | 归档 30 天 | UI 只显示最近 2,000 行 |
| 错误摘要、重置/清理审计 | 无自动上限 | 无 | BAT 视为未知文件，不删除 | 会长期累计 |
| `W\DataStore\时间目录` | 每次主监控初始化一个，无自动上限 | 无 | 不处理 | 目前通常只含 4 个配置副本 |

## 5. 程序配置文件字典

### 5.1 `W\Config`

这些文件是程序级或默认模板，不会随项目自动复制到 `P\Config`，唯一标准项目配置是 `P\Config\TestConfig.xml`。

| 文件 | 作用和主要内容 | 写入规则 | 文件数量/上限 |
|---|---|---|---|
| `AIConfig.xml` | Dev1/Dev2 的 AI 物理通道、参数名、启用状态、Scale、Offset、ZeroValue；决定 12 路电流、两路压力及力信号映射 | 设置/DAQ 标定可能更新零漂 | 单活动文件；无历史自动清理 |
| `AOConfig.xml` | AO 设备、通道、压力与电压上下限、线性校正系数 | 压力输出校正保存时更新 | 单活动文件；可能保留一个 `AOConfig.xml.bak` |
| `DOConfig.xml` | EPB 正反转、使能、液压阀等数字输出映射 | 设置保存时更新 | 单活动文件 |
| `TestConfig.xml` | 默认项目模板；Basic、Timer、Hydraulics、ElectricalGroups、12 路 EpbRecords、EpbCycleRunnerConfig、DataStorageRetention | 新项目模板、设置保存及从项目同步时更新 | 单活动文件；保存用 `.tmp` 原子替换，正常不保留 `.bak` |
| `UIConfig.xml` | `FrmEpbMainMonitor` 控件勾选、可用状态和默认勾选状态 | UI 状态变化防抖保存 | 单活动文件 |
| `AlarmConfig.xml` | 串口、报警输出映射、命令、报警确认规则、快照与 Warning 证据策略 | 通常由发布/人工配置 | 单活动文件 |
| `PowerSupplyConfig.xml` | 四台程控电源的地址、组号、电压电流、OVP/OCP 等参数 | 通常由发布/人工配置 | 单活动文件 |
| `CAN_V4_3_0.dbc` | CAN 报文和信号定义 | 随发布包提供 | 单活动文件 |
| `TestConfig - 复制*.xml` | 仓库中的人工历史副本，不是程序标准命名或运行依赖 | 人工产生 | 程序不管理、不清理 |

### 5.2 `B\MTTFTest.exe.config`

它由 `App.config` 编译生成，保存程序级安全和性能参数，例如：

- `InitialProjectPath`；
- `DaqIncidentCopyRecentCycles=false`；
- DAQ 控制、持久化队列容量和时钟模型参数；
- 自适应控制安全阈值；
- 采样频率、批大小、CAN/串口等程序级设置。

该文件不属于项目配置。项目切换不能覆盖它，修改后通常需要重启程序。

### 5.3 `P\Config\TestConfig.xml`

这是当前项目身份、目标次数和运行进度的权威配置，主要内容包括：

| 节点 | 内容 |
|---|---|
| `Basic` | TestName、TestTarget、TestPeriod、LearnCycles、StoreDir、Owner、Description |
| `Timer` | 计时策略与超限策略 |
| `Hydraulics` | 液压目标、容差、保持和释放参数 |
| `ElectricalGroups` | 通道分组、错峰间隔和组内成员 |
| `EpbRecords` | 每通道 Enabled、TotalCount、RunCount、Status、起止时间和累计运行时长 |
| `EpbCycleRunnerConfig` | 每通道动作方向、阈值和循环参数 |
| `DataStorageRetention/Latest` | `RetentionMode=Count|Unlimited` 和每通道停止包上限，默认 `Count/10` |

保存时先写 `TestConfig.xml.tmp`，再使用 Replace/Move 发布为正式文件；临时文件正常不会残留。普通保存不建立永久 `.bak`。程序内“清空并重新学习”会在 `P\log` 另存一份 `reset-config-*.xml`。

### 5.4 自适应模型与安全快照

| 文件 | 内容 | 上限和生命周期 |
|---|---|---|
| `EpbAdaptiveProfiles.xml` | 最多 12 个通道 Profile；空行程电流、夹紧/释放时长、断电提前量、物理尾升、DO 完成延迟、峰值误差及连续异常计数 | 每类历史最多 30 个值；原子更新 |
| `EpbAdaptiveProfiles.xml.bak` | 上一次成功模型 | Replace 成功时覆盖为一个备份 |
| `EpbAdaptiveProfiles.xml.tmp` | 新模型临时文件 | 正常保存后删除；异常中断可能残留 |
| `EpbAdaptiveProfiles.xml.corrupt.*` | 无法解析模型的保护副本 | 无自动数量上限 |
| `EpbAdaptiveProfiles.xml.pre-v5.*` | 旧模型版本失效前副本 | 无自动数量上限；“清空并重新学习”当前不会删除该类 `pre-v` 副本 |
| `EpbProgramSafetyEffective.xml` | 本次生效的程序级安全参数、来源、策略版本和捕获时间 | 每次覆盖单文件，不按历史累积 |

## 6. 原始环形数据和圈索引

### 6.1 `W\DataStore\EPBx_sliding.dat`

主程序对 1..12 通道全部创建固定大小文件，不受通道 Enabled 影响：

```text
EPB1_sliding.dat ... EPB12_sliding.dat
```

当前主程序传入 `FileSizeMb=100`：

- 每文件精确固定为 100 MiB；
- 12 文件名义合计 1,200 MiB，约 1.17 GiB；
- 每条记录 32 字节；
- 单文件可容纳约 3,276,800 条记录；
- 写到文件尾后按记录位置回绕覆盖旧数据；
- 采用内存映射窗口读写，而不是一次映射整个文件。

32 字节小端记录布局：

| 偏移 | 类型 | 内容 |
|---:|---|---|
| 0 | Int64 | `DateTime.ToBinary()` 时间戳 |
| 8 | Int32 | 圈号 |
| 12 | Int32 | 圈内 SampleIndex |
| 16 | Double | EPB 电流 |
| 24 | Double | 所属液压组压力 |

项目切换只更换 `P\index.db`，不会更换这些 `.dat`。因此删除项目目录并不等于擦除环形物理字节；反之，仅复制项目目录也没有复制这 12 个原始环形源文件。

### 6.2 `W\DataStore\yyyy-MM-dd_HH-mm-ss`

每次打开主监控并完成采集初始化时都会创建一个时间目录，并复制当时的：

```text
AIConfig.xml
DOConfig.xml
AOConfig.xml
TestConfig.xml
```

当前 `InitDaqLogTimer(500)` 调用被注释，因此该目录通常不再写 `DAQ_Dev*_Raw/Stat.bin`，但配置副本目录仍会创建。这里没有自动数量或天数上限，配套项目 BAT 也不会处理它。

### 6.3 `P\index.db`

SQLite 数据库使用 WAL 模式：

```text
index.db
index.db-wal
index.db-shm
```

核心表 `epb_cycles` 字段：

| 字段 | 作用 |
|---|---|
| `epb_id`、`cycle_number` | 通道与圈号；组合唯一 |
| `start_time`、`end_time` | 圈开始和终止时间 |
| `start_position` | 圈在对应环形 `.dat` 中的记录级起点 |
| `sample_count` | 圈样本数 |
| `status` | `running`、`completed`、`alarm`、`failed`、`canceled`、`learning_*`、`aborted_on_startup` 等 |
| `created_at` | 索引行建立时间 |

正式圈使用正圈号，学习圈使用负圈号。数据库没有自动圈数或容量上限；Historical/Latest 的副本清理不会同步删除索引。程序启动时只把超过 2 小时仍为 `running` 的孤儿圈改为 `aborted_on_startup`。

运行中复制数据库时必须考虑 `-wal/-shm`；最安全做法是先关闭所有写入程序再备份。

## 7. 通用圈 CSV/BIN 文件

Latest、Learning、Warning 完整证据、Alarm 和可选 Incident 最近圈都复用同一圈文件格式。

### 7.1 CSV

文件名：

```text
EPB{通道}_Cycle_{六位圈号}.csv
```

列：

```text
Timestamp,RelativeTimeSeconds,Cycle,SampleIndex,EpbCurrent,GroupPressure
```

- `Timestamp` 为本地时间，默认保留 100 ns 格式位；
- `RelativeTimeSeconds` 从本圈首样本起算，并保证非递减；
- 电流默认三位小数，压力默认一位小数。

### 7.2 BIN

文件名与 CSV 同 stem，内容是不带额外文件头的连续 32 字节 `SampleRecord`。文件大小应为 `sample_count × 32`。CSV/BIN 对写入时使用临时文件并成对提交，任何一方失败都不能把半对文件当成完整证据。

## 8. Latest 停止包

路径：

```text
P\Latest\EPB{1..12}\yyyyMMdd_HHmmss_fff-NNNNNN\
```

生成入口包括自然完成、人工停止、报警停止、暂停及其他明确调用 `FlushRecent(channel, 10)` 的路径。每个成功包：

- 只查询正圈号且状态为 `completed` 或 `alarm` 的圈；
- 最多保存最近 10 圈 CSV+BIN；
- 先在隐藏 `.tmp-*` 目录写入并校验，再原子移动为正式目录；
- 不删除 `index.db` 中的圈记录。

保留配置位于项目 `TestConfig.xml`：

```xml
<DataStorageRetention>
  <Latest RetentionMode="Count" RetainStopPackagesPerChannel="10" />
</DataStorageRetention>
```

规则：

- `Count` 默认每通道保留最新 10 个完整包；
- 指定数量允许 1..100000，非法值回退 10；
- `Unlimited` 完全不清理；
- 未知命名、CSV/BIN 不成对或无法验证的目录会跳过，且不占有效包计数；
- 清理异步执行，删除失败只记警告，所以磁盘物理目录可能暂时超过上限。

## 9. HistoricalSnapshots

路径：

```text
P\HistoricalSnapshots\EPBxx\Cycle_NNNNNN\EPB{通道}_Cycle_NNNNNN.bin
```

每个正式圈可靠提交后，后台仅导出 BIN。运行时上限：

```text
keep = max(3, HardAlarmLastNCycles + 2)
```

当前 `HardAlarmLastNCycles=10`，所以通常为每通道 12 圈。该规则不提供 `Unlimited`，不改变 `index.db`。后台导出或删除失败时不会影响控制，本地目录可能短暂多于 12 个。

## 10. LearningCycles

路径：

```text
P\LearningCycles\{RunId 32位GUID}\EPBxx\Learning_NNNN\
P\LearningCycles\{RunId}\EPBxx\Learning_NNNN\Attempt_NNNN\
```

内容为学习/资格圈 CSV+BIN。学习圈使用负圈号，不计入正式完成次数。软件自愈重试时，后续尝试写入 `Attempt_NNNN` 子目录。

当前没有运行时跨 RunId 清理或容量上限。离线 BAT 只能按 RunId 目录最后修改时间保留最近 3 次，无法区分最近成功和最近失败。

## 11. WarningSnapshots

根目录默认是 `P\WarningSnapshots`，但 `AlarmConfig.xml/WarningSnapshots@RootDirectory` 可以改名。

### 11.1 默认轻量证据 `warning-events-yyyyMMdd.jsonl`

当前默认：

```xml
FullEvidenceEnabled="false"
ScalarEvidenceQueueCapacity="4096"
```

每条软预警先写入每日 JSONL，字段包含：发生 UTC、RunId、通道、圈号、AttemptId、故障代码、证据延迟、持久化队列深度、峰值、目标值、误差、连续数、原因及构建身份。

规则和上限：

- 每个发生日一个 `warning-events-yyyyMMdd.jsonl`，同日持续追加；
- 标量队列默认 4096，代码安全下限为 128；
- 写盘线程每批最多取 128 条；
- 队列满时不阻塞控制，累计丢弃，并在恢复写入时追加 `WarningScalarQueueDropped` 聚合记录；
- 当前没有对 JSONL 的文件大小、天数或文件数量进行自动清理；
- `SoftWarningRetainCountPerChannelCode=30` 不适用于 JSONL；
- 当前一键 BAT 不识别 `warning-events-*.jsonl`，也不会删除它。

### 11.2 可选完整 CSV/BIN 证据

只有 `FullEvidenceEnabled=true` 时才建立：

```text
P\WarningSnapshots\EPBxx\{FaultCode}\
  yyyyMMdd_HHmmssfff-CycleNNNNNN-StreakXofY\
```

每个完整事件包含：

| 文件 | 内容 |
|---|---|
| 圈 CSV/BIN | 对应预警圈完整样本 |
| `warning-metadata.json` | RunId、通道、圈号、FaultCode、AttemptId、峰值/目标/误差、连续数、样本范围、关联 Alarm 路径及文件哈希 |
| `checksums.sha256` | CSV/BIN 的 SHA-256 |

默认门禁：

- 单个完整证据 worker；
- worker 之外最多等待 1 个任务；
- 同“通道 + 故障代码”至少间隔 600 秒；
- 每个“通道 + 故障代码”保留最新 30 个完整事件；
- `Unlimited` 时不执行计数清理；
- 未知或不完整事件目录跳过；
- 新事件完整落盘后才删除旧事件。

### 11.3 Warning 全局配额和 Archive

`SoftWarningQuotaMb=0` 表示关闭全局配额，不是 0 MiB 上限。配置为正数后，超过配额时只选择非当前 RunId、存在 `warning-metadata.json` 的完整证据目录：

1. 压缩为 `P\WarningSnapshots\Archive\{事件名}-{GUID}.zip.tmp`；
2. 验证 ZIP 非空；
3. 改名为 `.zip`；
4. 写同名 `.zip.sha256`；
5. 删除源事件目录。

Archive 本身没有运行时天数上限。当前 BAT 的 Archive 识别位置仍按旧的类别子目录设计，因此会把根级 `WarningSnapshots\Archive` 当成未知目录跳过；这是现场容量检查必须注意的现状。

`DiskFreeWarningMb=10240` 只在可用空间低于 10 GiB 时告警，不会主动停机或删除 JSONL。

## 12. AlarmSnapshots

### 12.1 普通硬报警

事件目录：

```text
P\AlarmSnapshots\yyyyMMdd_HHmmss-EPBxx\
```

圈数据规则：

- 报警通道目录固定为 `EPBxx_ALARM`；
- 报警通道默认保存最近 10 圈 CSV+BIN；
- `HardAlarmIncludeSameElectricalGroup=false`，默认不保存同组其他通道；
- 开启后，同组其他通道各保存 `HardAlarmSameGroupLastNCycles`，当前默认 10 圈；
- 不同电源组通道永不导出圈 CSV/BIN；
- 普通快照同一通道存在 2 秒 cooldown，避免短时间重复事件；
- 当前不限制报警事件总数、总容量或保留天数。

事件根文件：

| 文件 | 作用 |
|---|---|
| `alarm-metadata.json` | 报警通道/圈、原因、RunId、错峰槽、封存状态、断电安全证据及最终自适应判定 |
| `electrical-stagger-plan.json` | 当前 RunId 的电源组错峰计划 |
| `do-control-timeline.csv` | 报警前后 DO 命令、结果、命令耗时和线程证据 |
| `adaptive-decision-timeline.csv` | 报警通道最近自适应控制判定轨迹 |
| `daq_timing.csv` | DAQ 回调、队列、处理耗时、时钟模型和质量标志；普通报警取约 60 秒 |
| `daq_runtime.csv` | GC、CPU、内存、磁盘、线程池和运行时诊断 |
| `fast-current-evidence.csv` | 报警通道最近约 5 秒的快速电流及原始尾部样本 |
| `power-supply-telemetry.csv` | 报警电源组最近约 60 秒遥测 |
| `snapshot-manifest.json` | 请求/实际/跳过通道、同组策略、文件角色、完整性和 SHA-256 |
| `warning-chain.json` | 软预警升级为硬报警时的前序证据链；没有链时可能不生成 |

### 12.2 启动定位报警

路径：

```text
P\AlarmSnapshots\yyyyMMdd_HHmmss_fff-EPBxx-StartupPositioning\
```

| 文件 | 内容/上限 |
|---|---|
| `startup-current.csv` | 启动定位时间、阶段、电流、斜率和判定；内存跟踪最多 10,000 个样本 |
| `fast-current-evidence.csv` | 最近约 5 秒快速原始电流证据 |
| `do-timeline.csv` | 本通道 DO 时间线 |
| `startup-metadata.json` | 故障代码、原因、峰值、期限、释放阈值、样本数和 DO 事件数 |

启动定位事件同样没有总数/天数上限。

## 13. IncidentSnapshots

会话和阶段：

```text
P\IncidentSnapshots\yyyyMMdd_HHmmss_fff-Dev1-{CorrelationId}\
  00-trigger-001-HHmmss_fff\
  10-cutoff-002-HHmmss_fff\
  20-rebuild-003-HHmmss_fff\
  30-validate-004-HHmmss_fff\
  90-recovered或90-terminal-NNN-HHmmss_fff\
```

文件规则：

- `incident.json`：每个阶段的设备、故障、RunId、恢复代次、队列深度、时钟状态、电源状态、阶段和结果；
- `daq_timing.csv` / `daq_runtime.csv`：`00-trigger` 和 `90-*` 等需要时序证据的阶段生成；中间阶段通常只写紧凑 JSON；
- `build-identity.json`：硬故障或终态证据，保存 EXE 路径/哈希、版本、Git/构建信息和发布包校验；
- `EPBxx\CSV+BIN`：只有终态完整证据且 `DaqIncidentCopyRecentCycles=true` 时才复制最近 10 圈。当前 `MTTFTest.exe.config` 默认是 `false`，因此正常不生成这些圈副本。

运行时没有会话数量、大小或天数上限。离线 BAT 按标准目录名保留最新 10 个完整会话。

硬故障快照失败时依次尝试：

1. 原项目 Incident 目录；
2. `TMP\EPBTest\IncidentSnapshots\...`；
3. `B\IncidentSnapshots-Fallback\...`。

回退目录写 `snapshot-failure-{GUID}.json` 和 `build-identity.json`。项目 BAT 不会处理项目外两个回退位置。

## 14. PowerSupplyTelemetry

每次正式批次开始建立：

```text
P\PowerSupplyTelemetry\yyyyMMdd_HHmmss_{RunId}.csv
```

主要列包括 UTC、单调时钟、SupplyId、电源组、圈号、阶段、连接/输出状态、VSet/ISet/OVP/OCP、实测电压电流功率、CV/CC、限压限流限功率、保护状态、操作/问题寄存器及错误。

写盘队列容量为 50,000 行；满时丢弃部分遥测并记错误，不阻塞控制。每累计 20 行或 1 秒刷新一次。文件在本次运行结束、全部电源关闭或安全停机时关闭。

运行时不按大小轮转，也不按日期删除。离线 BAT 删除文件名时间严格早于 3 天的标准 CSV。

## 15. 项目日志

### 15.1 `run.log`、`warning.log`、`error.log`

格式为 UTF-8 制表符分隔文本：

```text
yyyy-MM-dd HH:mm:ss.fff    LEVEL    Category    Message
```

换行、制表符和反斜杠会转义，便于单行检索。

| 文件 | 内容 | 单文件轮转 | 归档保留 |
|---|---|---|---:|
| `run.log` | INFO 运行、配置、控制和状态信息 | 跨日或下一条写入后超过 50 MiB | 7 天 |
| `warning.log` | WARN，可恢复异常和容量/证据警告 | 同上 | 30 天 |
| `error.log` | ERROR，控制、硬件、写盘和快照错误 | 同上 | 30 天 |

归档名为 `{stem}.yyyyMMdd.NNN.log`。只删除符合该正则的归档，活动文件和未知日志不动。项目路径尚未配置时，内存兼容缓冲最多 10,000 条；统一后台队列硬容量 32,768 条，满时丢弃而不反压控制线程。

### 15.2 `ui-info.log`

主界面信息框独立写入：

- 活动文件跨日或下一行写入后超过 10 MiB 时轮转；
- 归档名 `ui-info.yyyyMMdd.NNN.log`；
- 归档保留 30 天；
- 启动和 UI 内存最多读取/保留最近 2,000 行；
- 异步待写队列最多 512 行，满时累计丢弃，不阻塞 UI/控制；
- 无有效项目根时回退到 `W\ProjectLogs\log`。

### 15.3 无自动上限的日志/审计

| 文件 | 作用 | 自动保留 |
|---|---|---|
| `P\snapshot-export-errors.log` | Warning/Incident 等快照失败摘要 | 无轮转、持续追加 |
| `{导出目录}\export_errors.txt` | 某个圈导出校验失败的局部错误 | 无轮转 |
| `P\log\reset-audit-*.log` | 程序内清空进度的隔离、删除、回滚和结果 | 无自动清理 |
| `P\log\reset-config-*.xml` | 清空前的项目 TestConfig 备份 | 无自动清理 |
| `P\log\data-cleanup-*.log` | 一键 BAT 的计划、删除、字节数和失败审计 | 无自动清理 |

## 16. 程序内“清空并重新学习”产生的路径变化

只有用户在切换已有项目时明确选择“清空旧进度和运行数据，重新学习”，并通过二次不可恢复确认，才执行这一流程。

### 16.1 被移入隔离区后删除

```text
Latest
HistoricalSnapshots
AlarmSnapshots
WarningSnapshots
IncidentSnapshots
LearningCycles
PowerSupplyTelemetry
index.db / index.db-wal / index.db-shm
EpbAdaptiveProfiles.xml
EpbAdaptiveProfiles.xml.bak
EpbAdaptiveProfiles.xml.corrupt.*
EpbAdaptiveProfiles.xml.tmp-*
```

先移动到：

```text
P\.reset-staging-{时间}-{GUID}
```

再保存清零后的 `P\Config\TestConfig.xml`，最后删除 staging。提交前失败会回滚；提交后物理删除失败时 staging 可能保留，但旧数据已经离开活动路径。

### 16.2 被保留

- 项目参数、通道 Enabled、每通道 TotalCount；
- 项目日志归档、重置审计和重置前配置备份；
- `snapshot-export-errors.log` 和未知根文件；
- `EpbAdaptiveProfiles.xml.pre-v5.*` 旧策略备份；
- `W\DataStore` 的共享环形 `.dat` 和时间配置快照。

RunCount、状态、起止时间和运行时长会清零；模型活动文件被删除，下一次运行重新完成学习。

## 17. 离线一键 BAT 的实际边界

脚本位置：

```text
Tools\EPB项目旧数据一键清理.bat
```

复制到项目根运行。默认直接删除，`/scanonly` 只写计划审计。脚本不修改 `Config` 和 `index.db`。

| 路径 | BAT 处理 |
|---|---|
| Alarm | 保留 `_ALARM` 和公共证据，删除标准辅助 `EPBxx` 圈目录；不删除整个事件 |
| Latest | 每通道保留 10 个可识别完整包 |
| Warning 完整事件 | 每通道/故障代码保留 30 个可识别完整事件 |
| Warning 每日 JSONL | 不识别，不删除 |
| Warning 根级 Archive | 当前识别位置不匹配，作为未知目录跳过 |
| Incident | 保留最新 10 会话 |
| Learning | 按最后修改时间保留最新 3 个 RunId |
| Telemetry | 删除严格早于 3 天的标准文件 |
| Historical | 每通道保留最新 12 圈 |
| run 日志归档 | 7 天 |
| warning/error/ui-info 归档 | 30 天 |
| 活动日志、重置审计、清理审计、错误摘要 | 不处理 |
| `W\DataStore`、TEMP、EXE 回退 | 位于项目外，不处理 |

BAT 只应在所有程序关闭并完成外部备份后运行。发现 `index.db-wal`、`index.db-shm`、本机 MTTFTest/EPBTest 进程、非法项目根或重解析点时会拒绝或跳过。

## 18. 条件性/遗留文件

### 18.1 `P\Archive\EPBx`

`EpbDiskWriter.PersistLatestCyclesNow(..., "archive")` 仍可把超出 N 圈的旧圈导出到：

```text
P\Archive\EPB{通道}\yyyyMMdd_HHmmss\CSV+BIN
```

随后删除这些圈的数据库索引。该接口在代码中标为“基本为弃用状态”，当前主流程使用 `FlushRecent`，没有调用全局 `ApplyRetentionPolicy()`。因此该目录不是正常运行必然产物；一旦存在，当前运行时和 BAT 都没有明确清理规则。

### 18.2 旧 DAQ/CAN 写盘文件

代码仍保留 `DAQ_Dev*_Raw/Stat.bin`、`EMB_CAN*_Raw/Stat.bin` 和 `*WriteDiskErrorLog.txt` 的旧上下文，但主监控中的 `InitDaqLogTimer(500)` 当前被注释，相关管理器也未接入现行主流程。文档不把它们计为正常项目输出；如果现场发现这些文件，应先核实是否使用了旧程序或重新启用了遗留入口。

## 19. 现场定位和备份检查表

### 19.1 确认正在写哪个项目

1. 在设置界面核对 StoreDir/TestName；
2. 查看 `%LOCALAPPDATA%\Wanxiang\EPBTest\user-state.json`；
3. 确认 `P\Config\TestConfig.xml` 的 Basic 与 UI 一致；
4. 查看 `P\log\run.log` 最近写入时间；
5. 查看 `P\index.db`、Telemetry 或快照目录更新时间；
6. 确认快捷方式“起始位置”，由此确定真正的 `W\DataStore`。

### 19.2 完整备份至少包含

- 整个项目目录 `P`；
- 程序关闭后的 `P\index.db`；
- 与运行时对应的 `W\DataStore\EPB1..12_sliding.dat`；
- `W\Config` 和 `B\MTTFTest.exe.config`；
- 如需无人值守恢复，另备份 `U2\unattended-run-checkpoint.json`；
- 如有 Incident 写入失败，检查 TMP 和 EXE 回退目录。

只备份 `P` 可以保留已导出的证据，但不能保证保留仍只存在于共享环形 `.dat` 中的原始圈数据。
