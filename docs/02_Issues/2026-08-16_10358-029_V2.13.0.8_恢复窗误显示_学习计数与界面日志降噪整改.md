## 4. 恢复提示窗误显示的根因

### 4.1 直接根因

V2.13.0.8 的恢复窗线程使用了：

```csharp
Application.Run(form);
```

WinForms 会在进入消息循环时自动显示传入的 `form`。独立 Sidecar 又是在每次普通“开始试验”时启动，因此即使：

- 当前只是 `MainProcess` Attach；
- `_transitionActive == 0`；
- 没有心跳丢失；
- 没有 Watchdog 接管；

恢复窗仍会自动出现在普通主程序上方。

### 4.2 为什么窗口一直不消失

原逻辑只会在“恢复过渡已激活”且收到稳定运行阶段心跳时隐藏窗口。普通 Attach 没有设置恢复过渡标志，所以这个被 WinForms 意外显示的窗口反而没有对应的隐藏闭环。

### 4.3 V2.13.0.9 修复

1. `RecoveryTransitionWindow` 改用无主窗体的 `ApplicationContext` 运行消息循环；预创建句柄时保持不可见；
2. `Show()` 成为唯一可见性入口，只由真实 `BeginTakeover`、恢复退避、重启或 `RecoveryProcess` Attach 调用；
3. Watchdog 协议新增 `MainUiReady`；
4. 只有带恢复意图启动的主程序，才在 `Main_Frm.OnShown` 发送 `MainUiReady("MainWindowShown")`；
5. Sidecar 收到该消息后立即隐藏恢复窗并清除过渡标志；
6. 原有 Learning/Formal/ManualPaused 稳定心跳隐藏逻辑继续作为兜底。

修复后的状态转换为：

```text
普通启动：Sidecar 启动（隐藏） -> MainProcess Attach（仍隐藏） -> 正常运行

异常恢复：心跳超时/安全异常 -> Watchdog 接管（显示）
        -> 等待旧进程退出/退避/重启（持续显示）
        -> RecoveryProcess Attach（持续显示）
        -> 主程序窗口 Shown -> MainUiReady -> 立即隐藏
```

主要代码位置：

- `MTTFTest.Watchdog/RecoveryTransitionWindow.cs`
- `MTTFTest.Watchdog/WatchdogHost.cs`
- `Watchdog.Protocol/WatchdogProtocol.cs`
- `MTTfTest/WatchdogRuntime.cs`
- `MTTfTest/Main_Frm.UnattendedRecovery.cs`

## 6. 第二轮关闭时空引用的根因与修复

### 6.1 现场异常

`log/error.log` 在 15:57:02.917 记录：

```text
System.NullReferenceException
Controller.EpbManager.get_ActiveLearningChainId()
Controller.EpbManager.LearningExecutionDirectory(Guid runId)
Controller.EpbManager.SealLearningCycleAsync(...)
```

旧代码判断：

```csharp
_activeRunChainIdentity?.EffectiveRootRunId != Guid.Empty
    ? _activeRunChainIdentity.EffectiveRootRunId
    : _activeBatchId;
```

关闭/停止流程会清空 `_activeRunChainIdentity`，而最后一个学习通道仍可能在异步封存。空条件访问得到的 nullable 值与 `Guid.Empty` 作 `!=` 比较时可能进入真分支，随后再次直接解引用已经为空的 `_activeRunChainIdentity`，从而抛出异常。

### 6.2 V2.13.0.9 修复

新增不可变的 `LearningEvidenceContext`，在学习或资格阶段开始时一次性冻结：

- 当前执行 `RunId`；
- 根学习链 `ChainId`；
- 根学习链目录；
- 当前执行目录。

后续 `SealLearningCycleAsync`、学习回执写入和状态更新全部使用冻结上下文，不再在异步收尾期间读取 `_activeBatchId` 或 `_activeRunChainIdentity`。批量学习、资格圈和单通道学习三条调用路径均已统一修改。

同时增加回归用例，验证活动学习链被并发清空时仍回退到已经冻结的执行 RunId，不能进入全零目录，也不能再发生空引用。

主要代码位置：

- `Controller/EpbManager.BatchStart.cs`
- `Controller/EpbManager.PauseResume.cs`
- `Controller/EpbManager.cs`

### 9.2 真实 Watchdog 恢复验收

必须在确认设备和人员安全、控制输出可由 Watchdog 断能的条件下执行：

1. 让试验进入稳定正式运行；
2. 仅强制结束主程序 `MTTFTest.exe`，不要结束 `MTTFTest.Watchdog.exe`；
3. 预期：Watchdog 检测失联后显示恢复窗，并执行安全断能、旧进程确认和退避重启；
4. 恢复窗应覆盖“旧进程退出—倒计时—创建新进程—加载恢复身份”整个过渡期；
5. 新主程序主界面出现后，恢复窗应立即消失，不应等到自学习或正式圈开始才消失；
6. 新进程应恢复到授权状态，计数只能单调前进，不能回退、跳增或重复计数；
7. 检查新 Watchdog 会话，应该依次看到 `TakeoverRequested`、`RecoveryBackoff`、`RecoveryProcessLaunched`、`Attached/RecoveryProcess` 和 `MainUiReady`；
8. 若没有 `TakeoverRequested`，恢复窗绝不能出现。
