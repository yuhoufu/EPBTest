# V2.14.0.0 无人值守自恢复架构实施计划

## 目标与安全边界

- 以现有根因文档为基线，交付版本统一升级为 `V2.14.0.0`。
- 所有可执行、可验证的瞬态软件故障自动恢复；恢复期间始终先断能、封圈、重建、复核，再恢复上电。
- 确认的卡钳、液压或电路硬件故障按最小故障域持久隔离，健康且资源独立的通道继续运行；故障域未经人工维修和完整复核不得自动重新使能。
- 程序包、配置、数据存储均无法恢复，或 OS/服务已无执行能力时，进入 `SafeIdleAlarmed`：保持断能、持续本地声光报警和封盘，不承诺不可能实现的无限恢复。
- 工控机保持 Windows 用户登录；网络 webhook 仅保留为可选能力，不作为无人值守启动门禁。
- `V2.14.0.0` 完成软件验收后先标记现场候选，只有通过 24/72/168 小时长稳才转为正式无人值守版本。

## 核心实施

### 1. 先修复本次两个确定性阻断

- 为程控电源新增强类型输出结果：`PswOutputState`、`PswOutputCommandResult`、`SafetyPowerOffReport`。
- 新接口以“实际回读为 OFF”表示成功；`SetOutputAsync(false)` 返回 `false` 只能表示输出状态为 OFF，不再被解释为调用失败。
- 保留旧接口兼容现有调用并标记废弃，所有安全链改用强类型接口；逐电源记录连接、身份、OFF 写入、两次回读、耗时和异常。
- 安全交接回执升级到 schema 5。服务在精确验证旧 PID、启动时间和 permit 后，单调补齐：
  `OldProcessExitProven`、`LogicalQuiescent`、`CallbacksIsolated`、`HardwareResourcesReleased`。
- PID 重用、回执回退、身份不符或未知进程状态一律 fail-closed；崩溃后的数据修复状态与物理安全证明分开记录。

### 2. 建立常驻监督服务

- 将 `MTTFTest.Watchdog.exe` 改为双模式宿主：
  - 正式模式注册为自动延迟启动的 Windows 服务 `MTTFTestSupervisor`；
  - `--console` 模式用于开发和自动化测试。
- 服务使用 `LocalSystem`，安装目录仅允许 Administrators/SYSTEM 修改；SCM 恢复策略为 5、15、60 秒重启，之后持续重启。
- 主程序不再自行拉起临时 Sidecar，而是向服务注册 Session、PID、启动时间、项目、RunId、可执行文件哈希和配置身份。
- 新增登录会话 `SessionAgent`：
  - 通过登录计划任务常驻当前桌面；
  - 只负责显示恢复窗口和在可见桌面启动主程序；
  - 只能消费服务签发的单次 `LaunchCapability`，不能自行生成恢复许可。
- `LaunchCapability` 必须绑定 Session、permit generation/id、桌面会话、EXE 路径和 SHA256、参数哈希、nonce、有效期；消费采用持久 CAS，确保任意时刻最多一个主程序。
- SafetyAgent 由服务直接监督和拉起。服务或 SessionAgent 崩溃时，从持久回执最后成功阶段幂等续跑，不重新执行已完成的安全动作。
- 服务、SessionAgent 和主程序使用带 Windows ACL、挑战 nonce 和协议版本的命名管道；旧协议只读迁移，不得授权 V2.14 恢复。

### 3. 收敛恢复状态机和失败计数

统一系统状态为：

`Running → Degraded → Isolating → Safe → RecoveringLocal → Requalifying → Running`

局部恢复超出既有 3 次、60 秒无进展或 300 秒总期限后：

`Safe → ProcessReplacement → Requalifying → Running`

同一当前包在真实启动、附着、checkpoint 或首圈提交阶段连续失败两次后：

`PackageRollback → ProcessReplacement`

- 拆分计数为 `SafetyPrerequisiteFailure`、`MainLaunchFailure`、`MainAttachFailure`、`CheckpointResumeFailure`、`FirstCycleCommitFailure`。
- 同一 operation/permit/fingerprint 只允许计数一次；只有真正执行过对应阶段才增加该阶段计数。
- 安全前置失败按 1/5/15/30/60/300 秒退避重试，不消耗主程序拉起预算。
- LastKnownGood 仍无法启动时保持断能，30 分钟自动半开探测一次；恢复条件重新成立后可自动退出安全等待。
- UI 删除按字符串前缀统一翻译“停止超时”的逻辑，固定显示首发故障、停止结果、恢复门禁、当前动作、分阶段计数和下次重试时间。

### 4. 最小故障域隔离

- 审计并收口所有直接调用 `StopAll` 或发布全局 `SystemFault` 的路径；局部模块只能提交结构化故障事实，由唯一恢复协调器决定作用域。
- Dev1/Dev2 DAQ 停更时，仅冻结对应通道，500 ms 内断电，当前圈作废，健康设备继续；重建后验证回调连续性、零电流、压力、配置和设备 generation，再恢复受影响通道。
- 卡钳确认故障持久禁用单通道；液压确认故障隔离所属液压组；程控电源或共享电路确认故障隔离所属电气组。
- 只有共享安全资源无法隔离、跨域故障或安全证明无法形成时才允许整机进入 `SafeIdleAlarmed`。
- 确认硬件故障不执行周期性重新上电；人工维修、重新勾选和完整资格检查后才能解除。

### 5. 数据、包和配置自恢复

- 圈状态继续兼容现有 `status` 字段，新增强类型 `CycleTerminationReason`，覆盖：
  `Completed`、`Failed`、`AbortedByDaqLoss`、`AbortedBySafetyStop`、`AbortedBySoftwareRecovery`、`AbortedByHydraulicFault`、`DataIncomplete`。
- SQLite 增量增加最后完整 sequence、缺口范围、设备 generation、恢复事务 ID 和终止原因；旧记录按现有状态安全迁移。
- 物理安全、数据是否完整、是否允许续测分别判定；数据不完整不能阻断断能证明，但必须先修复或显式封为非完成圈。
- 存储异常先执行 WAL 修复、临时文件清理和允许删除的历史遥测/过期快照轮转；不得删除当前项目正式圈、报警证据和数据库。
- 仍无可写存储时作废活动圈并安全停机，不允许跳过落盘继续产生正式圈。
- 增加 Current/LastKnownGood 双槽：
  - 管理员安装时验证 manifest、版本、文件哈希并由服务使用 DPAPI 机器密钥封印槽描述；
  - 运行时发现当前槽损坏或候选发生重复软件启动失败，先完成安全闭包，再原子切换到 LastKnownGood；
  - 配置使用独立的已封印有效快照，并优先回滚配置，再判断是否回滚程序包；
  - 硬件故障不得触发程序包回滚；
  - 候选通过首圈只代表恢复成功，通过完整 168 小时后才能晋升 LastKnownGood。

### 6. 本地无人值守告警

- webhook 保持可选且默认关闭，不产生联网依赖。
- 服务成为 P0 声光报警唯一硬件所有者；主程序只能提交告警或请求人工确认，避免多个进程同时控制 RS-485 蜂鸣器和灯。
- 进入 `SafeIdleAlarmed` 时强制写 Windows Event Log、耐久 JSON 告警、事故封盘、状态机、配置身份、硬件探针和 Dump。
- 确认硬件故障允许人工静音蜂鸣器，但故障灯和持久锁存保持到维修复核；瞬态软件故障在恢复首圈提交后自动解除当前提示，历史证据不删除。

## 版本、部署与公共接口

- 主程序、Controller、Watchdog、Protocol、Client、SafetyAgent、SafetyHardware、SessionAgent 及版本断言全部统一为 `2.14.0.0`。
- Watchdog journal、handoff、launch capability、package slot descriptor 和恢复事务统一升级到 schema 5；提供 v2-v4 的只读、保守迁移。
- 新增幂等安装/修复/卸载脚本，负责服务、登录计划任务、目录 ACL、双槽、SCM 恢复策略和安装后健康检查。
- 正式无人值守模式要求服务、SessionAgent、SafetyAgent、schema 5、可信包槽和 package manifest 全部有效；工程模式可降级运行，但永久显示“非受控包”且不能签署长稳放行。
- 发布脚本显式还原 `.NET 8` 的 `win-x64/win-x86` 资产，消除当前 Solution 首次构建因 RuntimeIdentifier 未还原而失败的问题。

## 测试与验收

- 保留当前已验证通过的 197 个恢复、Watchdog、液压、报警、电源测试作为回归基线。
- 新增强类型电源契约测试：OFF 回读 0、回读仍为 1、连接超时、身份错误、多电源部分失败和逐组诊断。
- 新增真实进程端到端测试：服务、SessionAgent、SafetyAgent、模拟 NI、模拟 SCPI，从 `SafeButRestartRequired` 一直验证到 checkpoint 和恢复后首圈提交。
- 对主程序、服务、SessionAgent、SafetyAgent 在 permit、断电回执、旧进程退出、launch intent、attach、checkpoint、首圈提交前后逐点强杀；唯一合法终态为 `Running/RunningDegraded/SafeIdleAlarmed`。
- 覆盖 PID 重用、回执损坏/回退、服务重启、用户锁屏、Agent 丢失重启、当前槽篡改、原子切槽中断、配置回滚、磁盘满和数据库修复。
- 对 Dev1/Dev2 分别注入回调停更、任务停止、队列停滞、NI 错误、GC 停顿、慢盘和动作边界故障，验证断电上限、最小隔离、作废圈和健康通道续测。
- 完整执行 Debug x86、Release Any CPU、AdaptiveControlTests、EpbDiskWriterTests、PowerSupplyDebugger.Tests、发布包构建与离线包校验。
- 现场依次执行 24、72、168 小时：
  - 可恢复故障全程无需人工；
  - 活动 EPB 数据失新后 500 ms 内断电；
  - 30 秒内形成独立安全证明；
  - 180 秒内恢复并提交首个正式圈；
  - 无双主进程、双 permit、无限中间态和 completed 圈缺口；
  - 确认硬件故障只隔离最小域且不自动重新上电。
- 168 小时通过前，manifest 标记 `FIELD_CANDIDATE_PENDING_168H`；通过后才生成正式 `2.14.0.0` 标签并晋升 LastKnownGood。
