# V2.12.0.17 退出数据耐久门禁与流畅运行补充整改

## 结论

V2.12.0.16 已解决无限自维护、CPU 忙等和后台任务先于硬件释放的关闭顺序问题。进一步按“试验必须流畅持续运行、报警证据不能丢失”反证时，仍发现一个退出数据完整性缺口：主窗口关闭只使用 `StopSafetyResult.CanReleaseAcquisition`，即只要求电机 DO 和程控电源关闭确认。若最后一批 Raw/SQLite 在 10 秒内尚未越过耐久边界，旧路径仍会关闭持久化 worker、释放采集资源并结束进程。

这不会造成带电退出，但可能把一次临时磁盘/网络存储停顿变成最后圈、报警圈或最近 10 圈证据永久缺失。V2.12.0.17 因此把“允许释放采集硬件”和“允许结束应用进程”拆成两个不同门禁：

- `CanReleaseAcquisition`：电机 DO 与程控电源关闭已确认；
- `CanCloseApplication`：在上述条件之外，停止时接受的 Raw/SQLite 前缀也必须完成真实持久化。

持久化边界未确认时，电机和电源保持关闭，窗口保持打开，写盘恢复链继续按原 FIFO 批次重试；操作员恢复磁盘或网络存储后再次关闭。程序不再通过销毁 writer 来“解决”积压，也不会让未持久化批次冒充正常退出。

## 根因与风险

`RunStopSafetyAsync` 已经捕获 Dev1/Dev2 停止生产边界，并验证：

1. DAQ 工程处理和 Raw 发布越过停止边界；
2. 两个设备的持久化序号越过有效边界；
3. 队列深度为零；
4. 持久化状态为 `Recovered`；
5. 活动圈已提交唯一终态。

但是旧代码随后无条件对 `ApplicationClosing/ProgramExit` 调用 `_persistence.ShutdownAsync(10000)`。该方法在排空超时后仍 Dispose 并取消 worker。窗口只检查 `CanReleaseAcquisition`，因此 `PersistenceBoundaryConfirmed=false` 也能继续第二次关闭重入。这形成如下风险链：

```text
磁盘/网络短暂停顿
  -> 最后 Raw 批次保留在 writer 重试链
  -> 10 秒停止边界未确认
  -> 旧窗口仍允许结束进程
  -> writer 被取消/释放
  -> 最后圈或报警证据无法补写
```

## 代码整改

| 文件 | 修改 |
|---|---|
| `Controller/ChannelRuntimeState.cs` | 新增 `StopSafetyResult.CanCloseApplication`，明确要求电机关闭、电源关闭和持久化边界三者同时确认 |
| `Controller/EpbManager.cs` | 只有 `ApplicationClosing/ProgramExit` 且耐久边界已确认时才关闭持久化 worker；未确认时保持恢复链存活 |
| `Controller/DaqPersistenceCoordinator.cs` | `ShutdownAsync` 排空超时时不再 Dispose；保留 FIFO、worker 和恢复能力，补写完成后才允许关闭 |
| `MTTfTest/FrmEpbMainMonitor.cs` | 首次关闭若数据边界未确认则取消窗口关闭，显示边界详情并要求存储恢复后重试 |
| `MTTfTest/UnattendedRecovery.cs` | 进程自重启先检查 StopAll 物理安全与数据耐久结果，再停止采集、关闭 writer 和释放硬件；取消重启不得破坏原进程 |
| `Tests/AdaptiveControlTests/Program.cs` | 扩展停止安全契约：覆盖未确认边界禁止退出、退出来源与普通停止的 writer 生命周期差异 |
| 版本与发布工具 | 主程序、程序集、构建、验证、现场门禁和清理工具统一迭代为 `V2.12.0.17` |

关闭语义现在是：

```text
StopAll 撤销运行授权
  -> 电机高优先级 OFF + 程控电源关闭回读
  -> 封闭活动圈时间窗
  -> 等待 Raw 发布和 SQLite/BIN 耐久边界
     -> 未确认：保持进程与 writer 存活，禁止关闭
     -> 已确认：关闭 writer，排空控制/液压任务，释放硬件并退出
```

压力证据陈旧但电机和电源已确认关闭时，仍沿用既有现场策略允许退出并留下安全警告；这与数据耐久门禁无关。电机或电源关闭未确认时仍绝对禁止退出。

## 台架验收

除既有 2/8/24/72 小时门禁外，V2.12.0.17 必须加入退出故障注入：

1. 在正式圈及报警证据写入期间制造 15—30 秒可恢复磁盘或网络共享停顿。
2. 点击关闭后确认电机和程控电源先关闭，但窗口显示“数据耐久边界未确认”并保持运行；任务管理器中进程不得退出。
3. 恢复存储，等待队列、最老批次年龄和未解决写故障回到零，再次关闭。
4. 检查 SQLite `integrity_check=ok`、`running=0`，停止边界前序号无缺口，报警目录包含触发圈和最近 10 圈。
5. 日志不得出现 writer 已释放后访问、未观察异常、后台任务排空超时或关闭成功但 `Persistence=Unconfirmed`。

V2.12.0.17 解决的是软件可证明的数据退出语义。真实存储永久损坏或磁盘空间耗尽时，程序会保持安全断能和进程存活等待处理，不会虚假宣称“持续试验”或“完整退出”。总体验收状态仍以[上线要求完成性追踪矩阵](./2026-08-09_V2.12.0.16_上线要求完成性追踪矩阵.md)为基础，现场执行时版本参数必须改为 `V2.12.0.17`。

六通道真实 SQLite/BIN 的 120/300/180 秒持续压力及资源平台化证据见[V2.12.0.17 六通道 2 kHz 离线持续写盘压力验证](./2026-08-09_V2.12.0.17_六通道2kHz离线持续写盘压力验证.md)。
