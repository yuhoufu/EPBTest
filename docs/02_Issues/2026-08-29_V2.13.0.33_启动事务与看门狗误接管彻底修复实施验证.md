## 1. 实施结论

V2.13.0.33 已同时关闭 V2.13.0.32 的三条连锁故障：

1. 启动定位 OFF 超过 100 ms 时仍立即进入失效安全断能，但会等待原始 OFF 命令和同代电源组恢复共同终结；框架恢复不再消耗三次机械尝试。
2. 命名管道写入超时只退休精确连接代次。心跳传输异常必须再经独立 Windows UI 探针确认，纯传输故障不再直接强杀主程序。
3. 恢复进程退出使用强类型意图。恢复许可获批、待处理、熔断或身份冲突时，退出所有权交还给 Watchdog；回执不可用时主程序保持安全空闲和可见诊断，不再自杀式退出。

程序集及应用版本已统一到 `2.13.0.33`，线上 Watchdog 协议保持 `v3`，没有引入混合版本无法识别的新消息。Debug x86、Release Any CPU 构建和全部指定自动化测试均通过。

## 3. 修复不变量

### 3.1 启动定位安全事务

- 100 ms OFF 失效安全阈值没有放宽；超时仍立即关闭对应共享电源组。
- OFF 回执区分未接纳、100 ms 内成功、已接纳仍执行、最终成功和最终失败。
- 允许重新上电必须同时满足：原始 OFF 已终结、组输出已关闭、程控电源恢复并通过回读、当前 run/epoch 仍有效。
- 恢复失败、恢复硬截止或 run/epoch 变化时保持断能，不执行下一次机械定位。
- 同组通道共享同一个恢复完成任务和所有者；旧 incident/旧 generation 不能清除新代次联锁。
- `ExpectedOutputDisabled`、等待恢复、Runner 修复和执行许可刷新属于框架恢复，不增加机械尝试计数；真实过流、保护动作和最终硬件写失败仍保留现有硬件故障策略。

### 3.2 Watchdog 传输与应用存活

- 每一连接代次只有一个写入所有者；任何旧代写任务均无权清理新连接。
- 生命周期消息优先于普通心跳消息，且两个队列都有硬容量；不允许无界堆积或并行写管道。
- 单次写入上限仍为 500 ms。超时只产生该代次的写入超时和连接退休，不直接形成进程接管证据。
- 经身份校验的同进程重连从附着时重新获得 5 秒传输宽限，避免首个新心跳前再次退休；这不会重置 UI 就绪状态，也不抑制正式进度和 StopAll 安全期限。
- 心跳 3 秒进入怀疑、5 秒进入 UI 探测；单次探针上限 500 ms，每秒一次，连续三次无响应才确认 `HeartbeatUnresponsive`。
- 新进程在 `MainUiReady` 前有 15 秒启动宽限；同一 PID/启动时间的 `MainUiReady` 跨管道重连保留，新进程正式附着才重置。
- UI 响应只能否定“纯心跳传输故障”造成的误杀。进程退出、PID 身份失配、StopAll 硬截止、输出无法确认关闭和正式机械进度停滞仍可独立触发接管。

### 3.3 恢复退出所有权

- `RelaunchApproved`、`RelaunchAlreadyPending`：旧主进程发送现有 `WatchdogTakeoverExit` 语义后退出，Watchdog 保持运行并且只消费一次许可。
- `CircuitOpen`、`IdentityConflict`：旧主进程退出，Watchdog 保持阻断和诊断状态，不拉起新进程。
- 精确 takeover correlation 已接管：交还已有接管事务，不创建第二个退出事务。
- 无活动会话、回执超时或回执无效：主程序不得退出，继续保持安全空闲、窗口可见并等待人工处理或链路恢复。
- 只有明确的人工关闭使用 `ShutdownExpected`，允许主程序与 Watchdog 正常共同退出。

## 4. 关键事件时序

### 4.1 OFF 超时但最终成功

```text
启动定位提交高优先级 OFF
  -> 100 ms 内未完成
  -> 立即锁存并关闭共享电源组
  -> 原始 OFF 稍后完成
  -> 唯一组恢复所有者关闭组输出、恢复程控电源并回读
  -> 同代 Completion=Recovered 且 run/epoch 有效
  -> 修复 Runner/执行许可并复核电源准入
  -> mechanicalAttempt++
  -> 执行下一次 StartupPositioningAsync
```

### 4.2 管道阻塞但 UI 可响应

```text
写入超过 500 ms
  -> 退休精确连接代次并记录队列/写入/退休原因
  -> 心跳年龄达到 5 秒
  -> PID+启动时间身份通过，WM_NULL 探针响应
  -> HeartbeatTransportDegraded
  -> 等待客户端重连；禁止进程接管
```

### 4.3 恢复进程失败并获准再拉起

```text
RecoveryAttemptFailed
  -> Sidecar 返回 RelaunchApproved / RelaunchAlreadyPending
  -> 主程序以 WatchdogRecoveryExit 收口
  -> 线上发送既有 WatchdogTakeoverExit（协议仍为 v3）
  -> 旧主程序退出
  -> Watchdog 保持运行，消费耐久许可并只拉起一次
```
