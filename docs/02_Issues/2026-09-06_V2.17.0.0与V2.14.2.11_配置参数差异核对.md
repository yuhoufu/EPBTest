# V2.17.0.0 与 V2.14.2.11 配置参数差异核对

日期：2026-09-06。仅比较与说明，本次没有修改程序、发布包、现场配置或封存。

**不完全一致。需要分别看“版本改变的程序参数”和“现场项目配置与发布模板的差异”。**

- V2.14.2.11 源码参考版本与 V2.17 候选包共有 159 个 AppSettings，只有 3 个值变化，均为 DAQ 存活年龄门槛，156 项不变。这 3 项旧值另由 I0040 的实际运行检查点确认。
- 这 3 项在 V2.16 的 `f41dc4a` 提交中收紧，V2.17 沿用；V2.17 相比 V2.16 的 App.config 和 8 份默认 XML 均未再改动。
- 发布包仍携带 `10358-029` 的既有默认模板，现场是 `10243-028`。模板中的压力、电流、动作时长、通道集合不能当作现场升级后的有效值。
- **模板差异不是本次稳定性修复要求改变现场工艺参数。继续同一试验应保留现场当前项目配置与进度，不把模板覆盖过去。**

## 2. 确实因版本调整而变化的三项参数

| 参数 | 2.14.2.11 现场 | 2.17 候选包 | 改变与原因 |
|---|---:|---:|---|
| `DaqLivenessWarnThresholdMs` | 250 ms | 75 ms | 更早识别过期数据；这个值还被 Runner 新鲜度准入/安全切断使用，并非只决定提示文字 |
| `DaqLivenessSuspectThresholdMs` | 1500 ms | 100 ms | 更早进入可疑数据判定及重新资格验证流程，避免以旧数据继续判定控制效果 |
| `DaqLivenessTripThresholdMs` | 5000 ms | 250 ms | 更早触发独立 DAQ 故障升级/恢复，缩短真正停止产出数据后的发现时间 |

来源是 V2.16 的 `f41dc4aa981586886014e0e234a3b6e106cc3691`（独立采样与积压准入改造）。V2.17 的已确认方案要求保留既有新鲜度保护门槛，所以本次修复快照竞争、恢复所有权和持久化，没有把这三项放回 2.14 的宽松值。

从判定逻辑看，收紧会使相同的采集/调度停顿更容易触发保护；它不会让采集本身变得更连续。这是 2.16 与旧版停机敏感性的重要差异之一。但现场还有已确认的快照时钟竞争、恢复清理和写盘堵塞缺陷，不能把全部异常都归结为这三项。

**不要把 Trip 当成唯一断能时间。** 两版控制快环配置均有 50 ms 警告/100 ms 硬故障门槛，Runner 还有自身的新鲜度切断路径。因此旧版 Trip=5000 ms 不代表它允许带电使用 5 秒前的数据；新版也不能概括为“总要等满 250 ms 才会断能”。

源码还收紧了可接受范围：

| 参数 | 2.14 源码范围 | 2.17 源码范围 |
|---|---|---|
| Warn | 100—5000 ms | 20—200 ms |
| Suspect | 200—30000 ms | 50—249 ms |
| Trip | 300—300000 ms | 100—5000 ms |

读取函数会把超范围值夹到上下限，再要求 Warn < Suspect < Trip。因此直接把旧值 250/1500/5000 填进新版配置，实际会读成 **200/249/5000**，不会原样恢复成旧版行为。代码证据：[读取与范围校验](D:/Github/wanxiang/EPBTest-v2.17-stability/Controller/EpbManager.cs:2709)、[数值截限](D:/Github/wanxiang/EPBTest-v2.17-stability/Controller/EpbManager.cs:2875)、[Runner 切断关联](D:/Github/wanxiang/EPBTest-v2.17-stability/Controller/EpbManager.cs:5470)。

### 补充：门槛数值之外，触发逻辑也变得更敏感

2026-09-06 针对“收紧是否导致更多异常”再次复核：前述 159 项 AppSettings 比较不包含下面两项代码策略差异。

| 判定策略 | 2.14.2.11 源码参考 | 2.16 引入、2.17 沿用 |
|---|---|---|
| Trip 的超龄确认 | 回调年龄达到门槛，连续 3 次确认 | 观察年龄达到门槛，1 次确认 |
| 存活监督比较的年龄 | 主要比较 CallbackAge | 取 CallbackAge、SampleAge、ControlEnqueueAge、ControlProcessedAge 的最大值 |

因此不仅“5000 ms 变成 250 ms”，确认次数也减少了，而且采集仍有回调、控制处理跟不上的情况也会被纳入。这提升故障发现能力，也提升对调度/处理延迟的敏感性；不能把更严格直接等同于持续运行更稳定。

实际触发还受到试验是否活动、设备是否带电或仍需监督、已有恢复事务、数据序号是否继续推进等条件约束，不是任意空闲时一次超龄就整机重启。样本序号已恢复推进的历史空窗有单独路径：标记受影响圈作废，而不立即重建 DAQ。

代码证据：[实际 Observe 判定](D:/Github/wanxiang/EPBTest-v2.17-stability/Controller/EpbManager.DaqLiveness.cs:149)、[单次 Trip](D:/Github/wanxiang/EPBTest-v2.17-stability/Controller/EpbManager.DaqLiveness.cs:252)、[Runner 使用 Warn 门槛](D:/Github/wanxiang/EPBTest-v2.17-stability/Controller/EpbManager.BatchStart.cs:5351)。

另发现 [EpbManager 的一处提示](D:/Github/wanxiang/EPBTest-v2.17-stability/Controller/EpbManager.cs:5510) 仍写“×3 才重建 DAQ”，与当前执行代码的单次判定不一致。这是遗留提示文字，不能作为实际策略依据。本轮仅补充说明，没有改动已封装程序或修改保护门槛。

## 3. 现场工艺参数与包内默认模板的全部差异类型

下表右栏是“包内模板”，不是已经在远程机上生效的值。所有这些模板值在 `6ed4d47` 源码中已存在，8 份 XML 与本次包一致；不是 V2.17 为了修复故障新改的工艺参数。

| 项目 | 2.14.2.11 现场 10243-028 | 2.17 包内模板 | 范围/说明 |
|---|---|---|---|
| 项目名称 | 10243-028 | 10358-029 | 不同项目 |
| 目标次数 | 200000 | 100000 | Basic/TestTarget 及 12 个通道的 TotalCount |
| 启用卡钳 | 4、5、7、8、9、12 | 仅 1 | 正确升级应保留原选通道 |

| 正向通电上限 `FwdOnLimitMs` | 3000 ms | 5000 ms | 12 个通道相同差异 |
| 保持时间 `HoldMs` | 5000 ms | 1000 ms | 12 个通道 |
| 预释放保持 `PreReleaseKeepMs` | 100 ms | 500 ms | 12 个通道 |

这部分没有“为了稳定性应当把 70/40 bar 改成 100/100 bar”这样的结论。模板只用于引导创建项目，不能代替现场试验要求。此前交付文档已经要求迁移现场配置，但没有把包内默认模板做成 10243-028 专用模板；本次核对把具体差异补全。上表任何工艺值都不应仅因为升级而覆盖现场值。

UIConfig 还有 5 个曲线显示选择差异：

| 显示选择 | 现场 | 模板 |
|---|---|---|
| CheckEpbA7、CheckEpbA8、CheckEpbA12 | 勾选 | 不勾选 |
| CheckEpbA10、CheckEpbA11 | 不勾选 | 勾选 |

它们是曲线显示选择，与 TestConfig 中决定实际启用通道的 Enabled 分开。

TestConfig 共检测出 278 处叶子差异：Basic 2、Runner 63、Hydraulics 6、EpbRecords 207。其中 EpbRecords 的 19 处为目标和启用设置，另 188 处是历史运行进度/状态字段；它们不是 188 项工艺调参。另有 UIConfig 的 5 处显示差异。

历史状态差异包括 RunCount、MechanicalCycleCount、RunTime、StartTime、LatestStartTime、Status、周期超时记录、永久报警字段和人工重新学习标记。模板中有零进度、旧模板时间或缺失字段，不能据此清空现场进度或锁定事实。部分旧字段在模板未写出会走类型默认值；这不表示新版删除了这些能力。完整数值逐条保留在 JSON 中。

## 4. 已核对一致的参数

- AIConfig、AOConfig、DOConfig、AlarmConfig、PowerSupplyConfig、UnattendedAlarmConfig：现场接管快照与新版模板的 XML 参数值一致，6 份均无参数差异。
- 项目周期 15 秒、学习 10 圈一致。
- 现场独立安全快照确认采样率 2000 Hz、每批每通道 20 点一致，都是 10 ms 批次；并不是从 50 点改成 20 点。
- 液压释放安全压力 5 bar、样本最大年龄 100 ms、稳定确认 100 ms、释放超时 5000 ms 一致。
- 检查点中的 FormalAdmission 300 ms、OrphanGrace 10000 ms、NoProgress 60000 ms、MaxTotal 300000 ms、电源断能证明 0.5 A/1000 ms 一致。
- 12 项程序安全有效参数数值一致，包含正向进展期限 3000 ms、反向进展期限 2500 ms、关断电流阈值 0.1 A/1000 ms、峰值证据最大延迟 100 ms 等。1 和 1.0 按数值等价处理。
- 源码 AppSettings 对比还确认：持久化队列容量 256、水位 128/32、年龄 1000/100 ms、恢复超时 10000 ms、新鲜批次 10、DAQ 稳定窗口 5000 ms 等未变化；没有对应旧 EXE.config 全量现场快照的项仅记为源码一致。

现场 `EpbAdaptiveProfiles.xml` 是项目运行学习结果，包含 6 个通道各自的模型、电流和时序统计；包内没有一份可与之按固定值比较的通用学习结果。最终动作还受该模型、实时样本和保护规则影响，不能仅凭静态 XML 推导每次动作波形。

## 5. V2.17 新增/改变的运行约束（不属于 AppSettings 三项改值）

| 规则 | 新版处理 | 修改目的 |
|---|---|---|
| 软件恢复额度用尽 | 仍限制 10 分钟最多 3 次程序重启；额度满进入持久冷却，窗口释放后再试 | 避免额度耗尽后永远停住；人工停止和硬件锁仍优先 |
| 实际动作无进展 | 对启用通道增加 max(60000 ms, 3×周期) 的进展期限；现有恢复 owner 监督另行保留 | 发现学习/运行显示正常但没有真实动作的情况 |
| 原始耐久日志 | 新增 256 MiB 有效载荷上限；SQLite FULL 耐久、幂等重放，未应用数据不覆盖 | 防止进程退出或暂时写盘故障丢失已耐久证据 |
| 管道交换 | 新增 10 秒有界交换取消 | 防止对端不读/不答使退出和接管无限等待 |
| 无进展诊断 | 至少间隔 60 秒、最多 100 份/约 50 MiB，异步采前后证据 | 抓到故障证据，同时限制诊断对运行的影响 |

这些变化按前一轮已确认计划实现，用来处理旧版的故障路径，不要求改变卡钳目标电流、液压目标或动作时长。

## 6. 对当前交付的结论

1. **工艺参数应保留现场当前值。** 安装器会保留已有 ProgramData 配置；已有项目 TestConfig 会直接加载，保留进度。不能因此假定任意新装环境都会自动选择 10243-028：新装且缺少配置时仍可能使用包内模板。
2. **DAQ 门槛确实比 2.14 更严格，且 Warn 不只是提示。** 这项需结合真机采样抖动、实际动作和数据进行验收，不能把收紧本身当成连续运行保证，也不能通过改几个 XML 值假称已恢复旧版策略。
3. 本次只做核对，未更改任何包内或现场参数。未读取此刻远程机的配置，因此结论对应 I0040 当时现场与已交付候选包。
