# V2.13.0.24 两条 ERROR 与人工停止关闭链彻底修复实施及验收

## 1. 结论

V2.13.0.22 封盘日志中的两条 ERROR 已按真实生命周期根因修复，不是通过日志过滤或降级掩盖：

1. Watchdog 首次命名管道不可用时，共享连接预约任务的异常现在由发布者显式观察，不再在 GC 后产生 `TaskScheduler.UnobservedTaskException`。
2. 人工停止后关闭窗口时，AO/DO/DAQ 和控制层资源现在只有一个同步释放所有者；`FormClosed` 不再对已释放 AO 二次归零，因此不会再伪报“AO 冷启动安全基线写零失败”。
3. 人工停止结果只有在带有效 RunId、CorrelationId、完成时间并满足既有关闭准入时才可复用。任何新启动或重新使能硬件的入口都会先撤销旧凭证，防止上一轮停止授权污染下一轮运行。

目标版本已经统一升级为 **V2.13.0.24**。

## 2. 根因与代码整改

### 2.1 Watchdog 未观察异常

首次启动采用“先连接现有 Sidecar，连接不到再拉起”的策略。第一次 `PipeUnavailable` 已被上层正常捕获，但 `ConnectReservation.Completion` 是另一条共享 Task；当没有并发 Joiner 等待它时，该 Task 的 fault 未被观察，最终由 GC 触发全局未观察异常日志。

整改：

- `ConnectReservation` 增加统一 `PublishFailure`。
- 保留原始异常并继续向 Owner/Joiner 传播。
- 发布共享失败后立即读取共享 Task 的 `Exception`，明确标记为已观察。
- `PipeUnavailable`、LaunchFailure、HandshakeRejected、Fail-Closed 的分类和处理策略均未改变。

### 2.2 AO 二次归零误报

原关闭顺序为：

1. `EpbManager.ReleaseHardwareForRestart()` 执行 AO 归零并 Dispose，随后清空 Writer。
2. `FormClosed` 再次调用同一 AO 的 `ResetAll()`。
3. 第二次归零找不到 Writer，被错误记录为“冷启动安全基线写零失败”。

整改：

- `AoController` 的写入、归零和 Dispose 使用同一个生命周期锁。
- Dispose 改为幂等；Dispose 后操作直接拒绝，并最多记录一次准确的生命周期 WARN。
- Dispose 前真实写零失败仍保留 ERROR。
- 增加内部测试计数，证明 Manager 只在 Dispose 前执行一次 AO 归零。

### 2.3 人工停止与关闭资源所有权

整改：

- `EpbManager.ReleaseHardwareForRestart()` 改为同步的一次性释放边界；并发调用者等待同一执行者完成。
- 新增 `EpbMonitorHardwareReleaseOwner`：
  - Manager 已创建时由 Manager 释放全部控制资源。
  - 初始化中途失败或 Manager 释放异常时，执行一次 DO 断能、AO 归零、DAQ 停止的直接兜底。
  - `FormClosing` 和 `FormClosed` 共享同一所有者。
- 新增 `ManualStopExitReceiptOwner`：
  - 只接受 `ManualUi` 来源且带有效 RunId/CorrelationId 的完成结果。
  - 仍有活动批次时禁止复用。
  - 新批次、批次恢复、单通道恢复、报警通道重启、检查点恢复均在重新使能硬件前撤权。
- 压力证据不足时的既有现场退出策略未改变。

1. V2.13.0.24 冷启动、运行、人工停止、关闭至少重复 5 次。
