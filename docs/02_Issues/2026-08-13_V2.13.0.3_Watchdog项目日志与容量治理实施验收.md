# V2.13.0.3 独立 Watchdog 项目日志与容量治理实施验收

日期：2026-08-13  
范围：独立 `MTTFTest.Watchdog.exe`、主进程 Watchdog 客户端、共享 Journal 存储策略与自动化测试。  
边界：本次不改变 Watchdog 的 3/5 秒判定、StopAll、旧进程身份校验、Kill、恢复进程启动或硬件控制逻辑；不迁移或删除旧 `%LOCALAPPDATA%\MTTFTest\Watchdog` 数据。

## 1. 验收结论

此前实现把 `session-*.json`、撤权 marker 和无上限的 `watchdog-error.log` 写在 `%LOCALAPPDATA%\MTTFTest\Watchdog`，只在主程序正常停止时复制部分文件到封存目录。主进程完全卡死或被终止时，项目封存包可能没有 Sidecar 最终状态，也没有完整状态转换链；全局错误日志还存在无限增长风险。

现已改为：每轮 Sidecar 启动前，主程序把 `<StoreDir>\<TestName>\WatchdogSessions` 和解析后的容量策略通过命令行传给独立进程；Sidecar 从启动起直接把权威快照、事件、错误、租约和终态 manifest 写入项目目录，不再依赖主程序退出时从 LocalAppData 复制。主进程侧的启动、Attach、ACK 失联、重连和生命周期事件另写 `client-events`，可与 Sidecar 视角交叉复核。

自动化已验证项目直接落盘、终态证据、单会话轮转、时间/数量/总容量清理、存活进程保护、项目盘故障应急缓冲、EventId 回灌去重、本机撤权以及真实 Sidecar 的 3 秒怀疑/5 秒接管链。现场主程序、真实网络封存根、NI/程控电源和 24/72 小时长稳仍需单独演练，不能用本地自动化替代。

## 2. 文件布局与证据内容

```text
<StoreDir>/<TestName>/WatchdogSessions/
  session-<SessionId>.json                    # 每秒最新状态，原子覆盖
  session-<SessionId>.sidecar-events.jsonl    # Sidecar状态转换/60秒检查点
  session-<SessionId>.sidecar-events.1.jsonl  # 最多3个历史段
  session-<SessionId>.client-events.jsonl     # 主进程启动/连接/重连视角
  session-<SessionId>.client-events.1.jsonl
  session-<SessionId>.errors.log              # Sidecar错误，分段
  session-<SessionId>.errors.1.log
  session-<SessionId>.lease.json              # Sidecar PID+启动时间活动租约
  session-<SessionId>.revoked                 # 项目侧撤权证据
  session-<SessionId>.manifest.json            # 终态、原因、丢弃数和字节数
```

最新状态继续包含当前 PID/启动时间、恢复次数、人工停止、最后心跳及 ACK 序号、最后心跳 UTC、RunId/RunEpoch、恢复阶段、通道集合、持久化/DAQ 证据和最后原因。JSONL 事件增加 `SchemaVersion=2`、不可变 `EventId`、事件序号、UTC、来源、Session/Run 身份、进程身份、心跳/ACK、接管原因、安全阶段、恢复上下文和 `DroppedEventCount`。

Sidecar 每秒只更新一个最新快照，不逐秒追加事件；正常心跳每 60 秒追加一次轻量检查点。`Starting`、`Attached`、`HeartbeatSuspect`、`TakeoverRequested`、`StopCompleted`、旧进程终止、恢复退避/启动/附着失败、发送失败、撤权和运行终态立即追加。主进程侧记录 Journal 策略、Sidecar 启动、Attach、连接丢失、ACK 超时、同 Session 重连和人工/正常终止。

## 3. 非阻塞写盘与项目盘异常

`WatchdogJournalStore` 使用独立 `BelowNormal` 后台线程和 1024 条有界事件队列。心跳线程只更新内存快照并序列化当前小对象，不执行目录扫描、文件写入、轮转或清理；项目盘慢、拒绝访问或断开不会阻塞 3/5 秒监督判定。队列压力优先丢弃周期性心跳检查点；关键状态仍登记，发生丢弃时累加 `DroppedEventCount`。

项目路径语法必须有效且不能是卷根。路径缺失或非法时，主程序拒绝启动不可审计的 Sidecar，并明确降级到进程内恢复；路径配置异常会清空旧值，不能误写到上一个项目。路径有效但暂时不可写时，当前项目+Session 使用：

```text
%LOCALAPPDATA%/MTTFTest/WatchdogSpoolV2/<ProjectPathHash>/session-<SessionId>/
```

作为临时缓冲。全机缓冲最多 8 MiB、最长 7 天；最新快照覆盖保存，事件按 EventId 单条暂存，项目恢复后先检查项目事件段是否已有同 EventId，再回灌并删除本机副本。缓冲自身失败或达到上限时仍不影响监督，优先牺牲检查点并在后续快照中报告丢弃数。

人工停止的本机撤权 marker 是控制面安全状态，不等待项目盘：主程序先原子写 `%LOCALAPPDATA%\MTTFTest\WatchdogControlV2\session-<id>.revoked`，Sidecar 同时检查本机和项目 marker；项目镜像再由后台 Journal 线程完成。因此项目盘阻塞不会延迟向 Sidecar 发送停止消息，也不会重新授予 Kill/重启权限。本机控制 marker 同样按 7 天和 8 MiB 上限治理。

应急缓冲只能处理明确失败或能够返回的 I/O。若底层文件系统调用永久不返回，独立写盘线程可能停在该调用上，但监督、IPC 和接管线程仍独立运行；此时新日志留在有界内存队列，项目盘恢复或进程重启前不能承诺全部落盘。现场 UNC 演练必须覆盖这种边界。

## 4. 轮转与保留策略

程序级安全默认如下：

| 配置 | 默认值 | 含义 |
|---|---:|---|
| `WatchdogJournalRetentionDays` | 90 | 最长保留天数 |
| `WatchdogJournalRetainSessionCount` | 32 | 最多保留 Session 数 |
| `WatchdogJournalMaxTotalBytes` | 134217728 | 项目 Watchdog 总预算 128 MiB |
| `WatchdogJournalMaxSessionBytes` | 16777216 | 单 Session 总预算 16 MiB |
| `WatchdogJournalHeartbeatCheckpointSeconds` | 60 | 周期检查点间隔 |
| `WatchdogJournalEmergencySpoolMaxBytes` | 8388608 | 本机应急缓冲 8 MiB |

Sidecar 事件每段 3 MiB，保留当前段和 3 个历史段；错误日志每段 1 MiB，保留当前段和 1 个历史段；主进程事件每段 512 KiB，保留当前段和 1 个历史段。字符串和通道数组另有单事件长度限制，单条异常不能绕过分段预算。

清理顺序固定为：超过 90 天、超过 32 个 Session、超过 128 MiB，均按最旧优先。当前 Session 和通过 PID+启动时间确认仍存活的其他 Session 永不删除；崩溃租约只有在进程身份确认失效后才能成为候选。清理器只识别 `SchemaVersion=2` 且符合严格文件名的平面文件，不递归、不跟随 reparse、不删除未知文件或旧格式。

清理由 Sidecar 独立低优先级线程执行，使用项目路径哈希命名的跨进程 mutex；每批最多 16 个文件或 32 MiB，批次间隔至少 5 秒。删除结果写入当前 Session 的 `RetentionDeleted` 事件。若只剩活动 Session、未知文件或权限失败而无法满足总预算，只记录错误并保留证据，不升级到控制、StopAll 或恢复链。

## 5. 自动化验收

执行命令：

```powershell
MSBuild.exe Tests\AdaptiveControlTests\AdaptiveControlTests.csproj /t:Build /p:Configuration=Debug /m:1
Tests\AdaptiveControlTests\bin\Debug\AdaptiveControlTests.exe --watchdog-journal
Tests\AdaptiveControlTests\bin\Debug\AdaptiveControlTests.exe --recovery-hardening
Tests\AdaptiveControlTests\bin\Debug\AdaptiveControlTests.exe --recovery-coordination
MSBuild.exe TfTest.sln /t:Build /p:Configuration=Release /p:Platform=x86 /m:1
```

本轮结果：

| 验收项 | 结果 |
|---|---:|
| Watchdog Journal 专项 | PASS 9/9 |
| Recovery hardening | PASS 10/10 |
| Recovery coordination | PASS 24/24 |
| Debug 主程序/Sidecar 构建 | PASS，只有既有编译警告 |
| `TfTest.sln` Release\|x86 | PASS，Sidecar 和 Protocol 已进入 Release 构建 |

另执行一次 Adaptive 全量回归，前置用例及本次新增 Watchdog 9 项均通过，运行 95.5 秒后在既有 DAQ 持久化并发用例 `RecorderAbsenceAndSupervisorFaultRetainOriginalOrder` 失败，信息为“worker监督补写成功后未发布Recovered”。该失败不在本次 Watchdog 日志改动路径内；因此不把 Adaptive 全量记录为 PASS，也不在本任务中改动 DAQ 持久化实现。

专项测试真实启动 `MTTFTest.Watchdog.exe`，附着一个仍存活的独立模拟主进程，只发送一次心跳。测试确认约 3 秒出现 `HeartbeatSuspect`、约 5 秒收到 `RequestStopAll`，项目 JSONL 同时具有 `HeartbeatSuspect`、`TakeoverRequested` 和 `HeartbeatUnresponsive`；随后写入本机撤权 marker，确认 Sidecar 退出且没有终止仍存活的模拟主进程。

其余专项覆盖配置缺失/非法回退、项目快照/事件/错误/manifest、崩溃残留半行不破坏此前完整 JSONL、16 MiB 单会话轮转、时间/数量/字节清理、存活租约和未知文件保护、项目盘不可写时 8 MiB 缓冲、EventId 回灌去重以及 1500 个故障盘检查点登记不阻塞生产者。
