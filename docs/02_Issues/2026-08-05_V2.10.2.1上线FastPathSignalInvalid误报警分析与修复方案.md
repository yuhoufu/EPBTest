# V2.10.2.1 上线 `FastPathSignalInvalid` 误报警分析与修复方案

## 1. 结论

V2.10.2.1 于 2026-08-05 12:52:54 报出的 EPB5 `55.413 A` 不是实际过流，而是
DAQ 原始批次数组被两个线程并发使用造成的**二次工程值换算**。

同一份 `double[,] raw` 在 DAQ 回调中先被发布给后台处理队列；后台线程会调用
`ConvertToEngineeringInPlace`，把数组从“原始电压”原地改成“工程值安培”。DAQ
回调和快速控制链随后仍把这份共享数组当原始电压，再执行一次
`ConvertFastVoltageToEngineering`。EPB 电流通道换算斜率约为 `10 A/V`，所以约
`-7.5 A` 的已换算值被再次乘以 10，形成约 `-75 A` 的快速代表值，经过因果滤波后
形成 `-55.413 A`，最终触发三样本 18 A 保护。

V2.10.2.1 新增的最终证据归因工作正常：程序用 2 kHz 完整证据确认峰值只有
`10.443 A`，因此没有把它归类为真实过流，而是正确归类为
`FastPathSignalInvalid`。但该分类按失效安全策略仍会断电并报警，所以现场看到
“新版仍报错”。此次需要修复的是共享数组所有权，而不是取消报警或放宽 18 A
阈值。

**处置结论：V2.10.2.1 不具备继续现场长跑的条件。完成 P0 代码修复和准入测试前，
回退到现场已验证版本 V2.9.0；不得关闭过流保护、提高 18 A 阈值或把
`FastPathSignalInvalid` 简单降级后继续运行。**

## 5. 代码根因

当前 `OnAiBatch` 的所有权顺序为：

1. `EndReadMultiSample` 返回 `double[,] raw`；
2. 先执行 `EnqueueForProcessing(new Item(..., raw, ...))`；
3. `Item.Raw` 只保存数组引用，没有复制；
4. `EnqueueForProcessing` 立即释放后台信号量；
5. DAQ 回调继续用 `raw` 计算 `ComputeFastRepresentative`，并向控制环复制 RawTail；
6. 后台线程可同时取出同一引用并执行
   `ConvertToEngineeringInPlace(item.Raw, item.Device)`；
7. 快速链若读到已转换元素，会在
   `ConvertFastVoltageToEngineering` 中再次应用斜率和截距。

对应代码位置：

- `IO.NI/TwoDeviceAiAcquirer.cs`：`OnAiBatch`
  - 先发布后台队列：约第 1940 行
  - 快速代表值计算：约第 1965 行
  - 控制环复制 RawTail：约第 2002 行
- `ProcessLoop`
  - 原地工程值换算：约第 2548 行
- `ConvertToEngineeringInPlace`
  - `raw[c, i] = (v - zero) * scale + offs`：约第 3009 行
- `Item`
  - `Raw = raw`，仅引用传递：约第 3478 行

V2.10.2.1 的 `DaqCallbackProducerGate` 只保证同一设备不会有两个 DAQ 回调生产者，
不能防止“DAQ 回调生产者”和“后台处理消费者”并发访问同一 `raw`。因此上一轮 P0
整改解决了回调重入、批次身份和最终归因，却遗漏了跨队列缓冲区所有权。

近期后台落盘/UI 性能优化使后台消费者更快取得批次，会提高这个既有竞态的命中概率，
但根因仍是发布顺序和共享可变数组，而不是“后台太快”。

`Quality=None` 也符合该缺陷：当前质量位只检查非有限值、批次身份和接近 DAQ
`±10 V` 量程等条件，没有“数组已从 V 转成 A”这一状态。被误当作电压的 `-7.5`
仍未达到 `9.5 V` 的近量程阈值，所以不会被标记为 `AdcNearRail`。

## 6. P0 修复方案

### 6.1 推荐方案：后台发布必须是 raw 的最后一次所有权转移

在 `OnAiBatch` 中调整顺序：

1. DAQ 回调独占 `raw`；
2. 完成快速代表值、质量标记、控制元数据和 `ControlBatchRing` 深复制；
3. 确认回调后续不再读取 `raw`；
4. 最后调用 `EnqueueForProcessing(new Item(..., raw, ...))`，把唯一所有权交给后台；
5. 后台取得所有权后才允许原地工程值转换。

修复前：

```text
EndRead(raw)
  -> 发布 raw 引用给后台并唤醒后台
  -> 回调继续读 raw 计算快速值/复制尾点

后台同时执行 ConvertToEngineeringInPlace(raw)
```

修复后：

```text
EndRead(raw)
  -> 回调计算快速值
  -> 控制环复制所需尾点和元数据
  -> 回调不再访问 raw
  -> 最后发布 raw 引用给后台
  -> 后台取得唯一所有权并原地换算
```

该方案不需要为每个 20 点批次克隆二维矩阵，性能和 GC 成本最低。关键约束是：
**调用 `EnqueueForProcessing` 后，DAQ 回调不得再读写 raw。**

### 6.2 防御性补强

P0 重排之外建议同时补充：

- 在 `Item.Raw` 和 `OnRawBatch` 注释中明确“借用/所有权”约定；订阅者不得保留或修改
  数组引用；
- 将后台发布封装成名称明确的方法，例如 `TransferRawOwnershipToProcessing`，降低后续
  重构再次把代码插到所有权转移之后的风险；
- 调试构建加入缓冲区状态断言：`CallbackOwned -> ProcessingOwned -> Engineering`；
- `fast-current-evidence.csv` 的 RawTail 必须只记录真正的原始电压；若 EPB 电流通道
  RawTail 与 Representative 持续呈约 1:1 而非约 1:10 关系，应记录
  `RawBufferOwnershipViolation`；
- 保留当前 2 kHz 最终证据归因。它在本次事故中成功阻止了把失真值标成
  `ConfirmedOverCurrent`。

### 6.3 不建议的方案

- 不提高 18 A 阈值；失真值可达 39～75 A，提高阈值只能延迟下一次误报并削弱真实
  保护；
- 不增大 `PeakEvidenceMismatchToleranceA`；本次偏差为 27～45 A，不是 1 A 容差
  标定问题；
- 不减少“三样本过流”灵敏度；本次污染能持续多个批次；
- 不把 `FastPathSignalInvalid` 无条件降级为普通警告；快速保护证据失效时继续带电会
  失去安全边界；
- 不用给后台加 `Sleep`、降低线程优先级或扩大队列来“降低复现率”；竞态仍然存在；
- 不把所有批次都 `Clone()` 作为首选正式方案；虽然能隔离所有权，但在 2 台设备、
  2 kHz、20 点/批的长期运行中会增加分配和 GC 压力。若无法保证顺序约束，才使用
  池化双缓冲或显式复制。

## 7. 必须新增的回归测试

### 7.1 确定性并发回归

使用 `Barrier`/测试钩子强制以下顺序，不依赖随机压力：

1. DAQ 回调取得含已知原始电压的 `raw`；
2. 后台线程等待所有权转移信号；
3. 控制链计算 Representative 并复制 RawTail；
4. 才允许后台执行原地工程值转换；
5. 断言快速 Representative 等于一次换算值，RawTail 始终为原始电压；
6. 连续重复至少 100,000 批，Dev1/Dev2 分别覆盖。

旧代码下应可通过测试钩子稳定复现二次换算；修复后同一用例必须稳定通过。

### 7.2 现场数据回放

把本次 EPB5 Batch 18414～18425 和 EPB11 Batch 9353～9360 转成回归夹具，验证：

- Representative 只应用一次换算；
- 快速滤波不产生 39 A、55 A 或 75 A；
- 2 kHz 完整峰值与快速峰值差异回到允许范围；
- 不触发 `OverCurrent3Samples`；
- 注入真实连续 `>18 A` 原始电压时仍先断电，并最终归类
  `ConfirmedOverCurrent`。

### 7.3 所有权与单元换算不变量

- `EnqueueForProcessing` 前，`raw` 状态只能是 Voltage；
- `EnqueueForProcessing` 后，回调路径不再访问 `raw`；
- `ConvertToEngineeringInPlace` 对同一批只能执行一次；
- 控制环 RawTail 与回调刚取得的电压样本逐点一致；
- EPB5 斜率为 10 时，输入 `-0.7515 V` 应得到约 `-7.54 A`，不得得到约
  `-75 A`；
- Dev1、Dev2 并行运行不得共享数组、滤波状态或所有权状态。

### 7.4 现有保护回归

修复后仍须通过现有 AdaptiveControlTests，重点保留：

- 三连续点真实过流；
- 2 kHz 证据封口；
- `ConfirmedOverCurrent` / `FastPathSignalInvalid` /
  `FastPathEvidenceUnavailable` 分类；

## 11. V2.10.2.2 实施结果

### 11.1 已实施代码修复

- `IO.NI/TwoDeviceAiAcquirer.cs` 的 `OnAiBatch` 已调整所有权顺序：先完成

### 11.2 新增回归覆盖
