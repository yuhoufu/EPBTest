## 2. 八项根因与修复语义

### 2.1 正式槽参与者退休伪造安全证据

根因：旧逻辑在移出液压参与集时直接从正式槽退休，等价于伪造电机 OFF、液压释放和持久化完成，可提前释放下一槽。

修复：改为“请求退休—安全栅栏确认”两阶段，绑定 RunId/RunEpoch。只有执行授权已撤销、电机 OFF、液压租约关闭、已开始圈完成耐久封圈后，才代为关闭尚未进入的未来槽。已进入槽仍由自身 scope 提交终态。证据失败或超时会使槽位 fail-closed 并升级整批安全停止；旧运行迟到确认不能作用于新批次。

### 2.2 回调 fallback 忽略已开始圈持久化

根因：回调异常退出时固定上报“不需持久化”，已开始但未提交或未作废的圈也可穿过屏障。

修复：fallback 捕获本回调的 CycleAttemptContext。未开始圈可安全退出；一旦 attempt 已创建，必须 IsDurablyCommitted，即耐久完成或明确耐久作废，否则阻断下一槽。

### 2.3 历史累计峰值屏蔽当前持续高负载平台

根因：高负载平台保护将历史累计峰值纳入放行条件，早先短促高峰可屏蔽随后 10.8A 等当前堵转平台。

修复：平台确认仅使用当前确认窗口的 P10/P90、当前电流和斜率。历史峰值只保留为诊断，不再影响切断。持续平台在一个确认窗内终止，短过渡和正常近目标平台不误切。

### 2.4 2 × Period 瞬时 OFF 被误当作物理动作终止

根因：硬截止点只查当下输出，落在 Hold 或正反转间隙时会看到短暂 OFF，随后旧 Runner 仍可再次上电。

修复：Runner 新增本圈物理动作代次，只在 RunOneAsync 已返回、所有可能上电阶段结束后标记该代次终止。到 2 × Period 时，仅“同代次已终止 + 当前 OFF”可等待共享收口；其余情况立即取消 attempt、撤销执行许可、高优先级 OFF 并永久隔离。

### 2.5 重复 XML 记录使永久报警清除后复活

根因：目标更新表只保留同一通道的最后一个 XML 元素，人工清除后旧副本可在重载时重新锁存。

修复：报警原子更新对同通道全部重复元素写入一致值。人工重置同时清理运行内存报警、连续超限和持久化失败锁存，防止重载反弹。

### 2.6 通道熔断覆盖先前启动故障

根因：带通道身份的软件熔断直接替换 startFaults，可丢失同批其他已失败通道。

修复：通道熔断与已累积启动故障取并集、去重并排序。只有无通道身份的 DAQ 等基础设施熔断才扩大为整批，健康通道仍可重新启动。

### 2.7 Watchdog 退出观察器读取可变子进程身份

根因：旧观察器共享单次门闩并从 journal 重新读取 PID，旧主进程退出期间恢复子进程附加后，可误观察新 PID，也会阻止新进程建立自己的退出观察器。

修复：观察器创建时冻结 PID、进程启动 UTC ticks 和 attach epoch，后续存活检查、Dump 与 Kill 只作用于该精确身份。新进程验证附加后重置观察器所有权，旧观察器不能清除新 epoch；新 PID 的 ShutdownExpected 可正常结束 Host。

### 2.8 增量备份依赖 .NET Core API

根因：Path.GetRelativePath 在 Windows PowerShell 5.1/.NET Framework 中不可用；无 BOM UTF-8 脚本还会被 5.1 按 ANSI 误解析。

修复：先对源根和文件做绝对路径规范化及忽略大小写的目录边界校验，再以规范化前缀长度截取相对路径；脚本保存为 UTF-8 BOM，兼容 Windows PowerShell 5.1。
