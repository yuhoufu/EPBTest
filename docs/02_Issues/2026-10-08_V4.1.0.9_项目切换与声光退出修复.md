## 问题根因与修复

### 项目／卡钳变化后不能启动

界面所选项目与安装级独立恢复注册绑定的项目不一致时，已有身份门禁拒绝启动；普通配置保存还会让默认模板和 UI 显示 XML 进入控制摘要，造成无关摘要变化。启动授权返回业务层之前的失败也会留下没有真实停止事务的 Closing 会话，后续启动继续被上一会话阻挡。

修复内容：

1. 人工“开始”在已有安全停止边界检查所选项目；复用维护位、执行器服务停止确认、独占执行租约与受保护注册文件完成绑定更新。恢复启动不能重新登记配置或创建人工授权。
2. 更新使用有界事务记录与旧／新快照；未提交的中断恢复旧的一致、已停止状态，已提交的中断完成新状态，服务重启以新注册构造运行时。失败不拼接新旧项目身份。
3. 当前项目 TestConfig 是控制配置来源。UIConfig 和运行目录中的默认 TestConfig 模板不再参与独立控制摘要；当前项目控制参数、其它控制 XML、可执行文件和数据库身份继续核验。
4. 增减参与卡钳沿用已有持久选择和人工运行授权；保留同项目永久隔离，不因重新绑定解除。切换项目不继承上个项目的运行票据。
5. 已访问项目额外记忆数据库创建时间和 Windows 文件标识，切回时拒绝替换文件。首次升级尚无历史文件标识的数据库只能沿用旧注册证据，不能追溯过去从未记录的文件身份。
6. 区分“尚未授权控制的启动取消”和“真实安全停机”。前者可在管道、引擎、日志等资源均终结后写独立会话终态，保持电机 OFF、电源 OFF、压力安全等证明为 false；已发出运行授权或已有真实停止事务则继续原有安全证明链。
7. 完成／停止通知先写入的空关闭记录，可以在没有既有安全、接管或恢复证据时一次性补入真实停止事务；已有身份不能替换。并发补入只允许一个身份成功，后续仍须提交真实最终安全结果。
8. 连接刚 Attached 就开始关闭时，普通首心跳被 Closing 拒绝不再误判为通信故障；保留当前精确管道发送 StopCompleted。真实写入失败、身份变化和超时仍按原规则拒绝，不把它们当作正常关闭。

差异核对：`Controller/` 中仅 `Alarm/AlarmManager.cs` 修改了报警输出生命周期；`IO.NI/`、`DataOperation/`、`Config/`、`PowerSupply.Core/`、`Timing/` 及其它 Controller 控制文件没有修改。主窗口与监控窗口仅衔接上述授权、收尾和报警入口。

### 主程序正常关闭后仍有声光报警

原来主程序与 Supervisor 都可能打开同一报警串口。历史 P0 锁存保留在 Supervisor，主程序关闭并释放串口后，Supervisor 可能重新输出旧事件；仅将蜂鸣器静音不能满足全部声光关闭要求。旧静音处理还会覆盖故障代码和原因，损失原始证据。

修复内容：

1. 安装模式下 Supervisor 统一持有报警串口；主程序提交通道灯和蜂鸣器需求，不再与后台竞争串口。开发模式保留原直接输出路径。
2. 增加“安装报警”界面入口，可刷新、仅静音、关闭全部声光；关闭输出不清除故障锁存或原代码／原因。
3. 正常关闭仅在原有安全收尾成功或确认从未授权控制的空闲路径发起。按事件 ID 和版本进行持久比较更新，再等待同一版本的 OFF 命令已发送；写入失败、输出失败、超时或新故障到来时保留窗口并明确提示。
4. 同一事件重复上报保持静音／输出关闭状态，新事件重新启用声光，不形成永久屏蔽。Dispose 和进程异常退出不自动确认 P0 已处理。
5. 请求使用实际命名管道对端 PID、进程启动时间、安装身份、可执行文件摘要和用户身份验证；请求自报 PID 不能替代真实对端身份。输出操作与原故障证据分别保留。
6. 界面和日志区分持久状态、软件发送回执、现场物理状态。`CommandSent` 只证明串口写入路径完成，不代表蜂鸣器或灯的物理反馈已验收。

## 操作说明

1. 正常停止旧试验，等待安全停止、数据收尾和会话释放完成。暂停不等于停止。
2. 打开目标项目，确认项目参数和参与卡钳，保存后点击“开始”。安装级绑定由程序在该入口同步，操作员不需要编辑注册 JSON 或运行维护脚本。
3. 不选卡钳、数据库身份变更、仍有活动试验或收尾未完成时，按提示处理后重试。不要删除状态文件绕过门禁。
4. 在主窗口“安装报警”查看原故障。“仅静音蜂鸣器”保留灯；“关闭声光（保留故障）”关闭当前事件输出，保留锁存和审计。新故障可重新报警。
5. 正常关闭窗口，等待现有安全停止与声光关闭完成。如果提示声光关闭未确认，窗口保持打开；检查设备和状态后重试，不能将该提示理解为设备已关闭。

| 运行／暂停时切换或绑定中断 | 活动状态拒绝；中断恢复一致状态，安全停止后可正常重试 |
| 启动拒绝、握手失败后重试 | 无残留失败会话或子进程；未授权取消不声称真实安全停机 |
| 正常关闭监控窗口与主程序 | 电机、电源、压力、落盘按原逻辑收尾；蜂鸣器和全部报警灯实际关闭 |
| 静音／全关后重开、Supervisor 重启 | 已处理旧事件不重新响灯；原故障和审计仍可见 |
| 关闭过程出现新故障、串口故障或写入冲突 | 新故障不被旧确认覆盖；失败可见、可重试，不提前声称物理关闭 |
| 崩溃或安全停止未完成 | 仍按现有异常恢复／报警责任处理，不冒充正常退出 |
| 真实 NI、电源、液压与长期运行 | 按现有工况验证控制节拍、保护、计数与数据完整性，记录具体持续时间与日志区间 |
