> 版本原则：不以固定版本号、Git 信息或文件哈希作为 Watchdog 恢复许可；现场必须全量替换同一次构建的发布目录

## 1. 最终结论

本次 EPB4、EPB5 自行暂停的直接触发是 Dev1 出现约 `1171.826 ms` 的历史回调空窗。旧实现先执行 Timer Pause 和安全 OFF，后创建 DAQ 恢复上下文；只要中间同步链没有返回，就会留下“Timer 已暂停，但没有恢复 owner”的孤儿暂停。独立 Watchdog 又无法识别这种局部失活：其旧恢复进度被持续增长的持久化序号刷新，也没有心跳 ACK、sidecar 退出监测和同 Session 重连。

本轮整改已经同时修复三层问题：

1. **存储恢复不变量**：冻结边界唯一、suppression 与冻结边界原子安装、恢复 Finalizer 只能使用 FrozenBoundary、矛盾立即终止、事故圈只作废一次；
2. **进程内恢复可达性**：先提交恢复上下文和事故圈身份，再执行 Pause/DO/电源动作；Timer 孤儿暂停可被补建，电源关闭有独立 5 秒硬期限；
3. **进程外兜底有效性**：Watchdog 使用真实恢复阶段进度、识别孤儿暂停和电源待断，监视 ACK 和 sidecar 生存状态，必要时整批 StopAll、终止旧进程并持续退避重启。

代码级和确定性自动测试已通过。真实 NI 断开、真实电源通信阻塞、旧进程强制终止以及新进程 `SafetyTakeover` 仍必须在现场做一次受控演练后，才能给出硬件级最终签字。

## 2. 整改后的完整行为

```text
用户点击“开始试验”
  → 主程序创建本轮 Session，隐藏启动 MTTFTest.Watchdog.exe
  → Watchdog Attach/ACK，主程序进入学习和正式试验
  → DAQ 空窗或基础设施异常
      → 先登记 RunId/RunEpoch/Correlation/恢复 owner/事故圈
      → 再执行整组 Pause、DO OFF、电源 Disable、FrozenBoundary
      → 进程内恢复成功：双 DAQ/通道共同验证后重入
      → 进程内恢复卡住：5 秒电源/孤儿期限或 60 秒阶段无进展
          → Watchdog RequestStopAll
          → 旧进程可响应：收口并主动退出
          → 旧进程 15 秒不退出：校验 PID+StartTicks+Session 后强制终止
          → 5/15/30/60 秒持续退避启动同一路径主程序
          → 新进程先 SafetyTakeover，再恢复健康剩余通道
用户人工停止/正常完成/关闭软件
  → 写入跨进程撤权标记
  → 旧 Watchdog 不得再 Kill 或拉起进程
  → Journal 封存，Watchdog 退出
```

Watchdog 仍然不直接打开 NI 任务、不直接操作 DO/AO/电源/液压、不写业务 SQLite，也不修改正式圈计数。所有硬件安全接管和数据恢复仍由新主进程的既有 Controller/DataOperation 路径执行。

## 3. 根因与代码修复一一对应

| 原问题 | 已实施修复 | 结果 |
|---|---|---|
| Safety 先 Pause，恢复上下文后创建 | 新增统一幂等 `PublishDaqRecoveryIncident`；首个事故先登记 owner、Run 身份和 Correlation，再进入安全 I/O | 不再允许无 owner 的安全暂停成为正常终态 |
| safety event、publication、liveness 可能重复创建事故 | 首个事件是唯一提交点；重复事件只合并诊断，不重复登记尝试或启动恢复 | 同一事故只创建一个恢复事务 |
| 同一扫描双 DAQ 使用不同事故号 | liveness 显式向各设备传递共享 `batchCorrelation` | 双 DAQ 属于同一批次屏障，未共同验证不得单边重入 |
| Timer `Paused` 被认为天然“已有恢复 owner” | 按 RunId、RunEpoch、Device、Correlation 和 Channel 验证真实 owner；增加孤儿暂停检测与一次性补建 | EPB4/5 这类局部停机可被进程内补建或由 Watchdog 5 秒接管 |
| 电源 Disable Task 可长期不返回 | 按电源组保存实际 Task；运行态或 Task 未完成均视为 Pending；独立 5 秒期限升级 `ExternalRecoveryRequired` | 不再用“已经发起关闭”冒充“已经关闭” |
| 持久化序号增长被当作恢复进展 | `RecoveryProgressSignature` 只使用恢复阶段、owner、incident、orphan、power pending 等业务进展 | 健康 DAQ 继续写盘不会无限刷新 60 秒停滞计时 |
| sidecar 死亡或 pipe 断开不可见 | 心跳 ACK；3 秒 ACK 超时/进程退出发布 `TransportLost`；同一 Session 自动重连一次 | 初次握手成功不再被误当成整轮持续在线 |
| 人工停止与自动 Kill/重启竞态 | 人工停止先写 `.revoked`；Watchdog 在接管、Kill 和 Relaunch 前反复检查撤权及 PID 启动时间 | 人工停止最高优先级，旧 Session 不得恢复新 Run |
| 同 PID 被操作系统复用 | 进程身份使用 `PID + ProcessStartUtcTicks` | 不会把 PID 相同的新进程当作旧进程终止 |
| EPB5 事故圈仍提交 `completed` | 事故身份改为 `RunId + RunEpoch + Channel + Cycle`；恢复触发即标记，晚到完成只能消费一次作废标记 | 事故圈恰好一个 `AbortedBySoftwareRecovery`，不增加正式成功数 |
| 自然完成后 UI 又调用 StopChannel | 自然 `Completed` 分支不再执行 `StopChannel` | `Completed` 不再被覆盖成 `ManualStopped` |
| 永久报警与普通 Alarm 状态混用 | Controller 暴露权威永久故障锁存快照和原因；Watchdog 不再从 UI 文本推断 | 永久报警只排除对应通道，其他健康通道可续测 |
| Journal 没进封存包 | 本轮和恢复进程均配置 `StoreDir\TestName\WatchdogSessions`；停止、完成、关闭时复制 Session JSON/撤权标记 | 后续可判断事故时 sidecar、心跳、接管次数和最后阶段 |

## 4. 存储恢复不变量

### 4.1 唯一 FrozenBoundary

- `DaqCutoffSnapshot` 是一次事故中每个设备不可变的截止快照；
- `DaqPersistenceCoordinator.InstallCutoff` 在同一准入门内捕获 `LastAccepted` 并安装 `SuppressAfter`；
- suppression 只能从 `FrozenBoundary + 1` 开始，后续重试不得扩大正式耐久义务；
- 恢复 Finalizer 使用显式 FrozenBoundary，不再动态读取更高的 PublishedSequence；
- `CycleFinalizeBoundary > FrozenBoundary`、冻结值变化或 suppression 覆盖到冻结前缀时，立即形成 `RecoveryBoundaryContradiction`，不得伪装恢复成功。

### 4.2 前缀闭合条件

只有同时满足下列条件，冻结前缀才算闭合：

- `Published/Persisted/TerminallyHandled >= FrozenBoundary`；
- 没有 `Head/InFlight <= FrozenBoundary`；
- Raw 已移交并排空；
- 无永久写入失败、永久空洞或失速；
- 事故圈终态已提交且没有 `running/open` 遗留。

SQLite、CSV、BIN 和 index 格式没有因此迁移，恢复剩余圈仍以 SQLite 已提交的正式成功圈为唯一依据。

## 5. StopAll 与旧 Run 隔离

- StopAll 先递增/撤销旧 `RunEpoch`，并发起整组 DO OFF 和电源 Disable；
- `RecoveryTaskRegistry` 统一跟踪名称包含 Recovery、SelfHealing、Finalize、Restart、FaultHandling 的恢复任务；
- StopAll 有界等待 DAQ 恢复、恢复所有权和统一任务表；未闭合项写入 `StopSafetyResult`，不得伪造 `FullyConfirmed`；
- 旧 Run 的迟到任务必须携带原 RunId/RunEpoch，不能删除新 context、消费新事故标记或启动新 DAQ；
- StopSource 按 `ManualUi / AlarmInterlock / SystemFault` 发布，不再把系统故障统一显示为人工停止。

## 6. 独立 Watchdog 的触发与退避

Watchdog 只按下列结构化证据接管，不使用“圈数多久没有增长”：

1. 主程序明确发布 `ExternalRecoveryRequired`；
2. `RecoveryActive=true` 且真实恢复签名 60 秒无变化；
3. 存在健康候选通道的孤儿 `PausePending/Paused`，持续 5 秒；
4. 电源关闭 Task/遥测仍 Pending，持续 5 秒；
5. 5 秒没有主程序心跳，或主进程已经退出。

进程死亡优先于候选通道集合判断；即使最后心跳来不及提供候选集合，Watchdog 也会先执行整批安全接管。恢复启动不设置次数耗尽终止门，退避为 `5 s → 15 s → 30 s → 后续每 60 s`，只要当前 Session 未被人工撤权就持续尝试。

固定版本号、GitCommit、BuildUtc、发布 manifest 和文件哈希只作为诊断证据，不是 Watchdog 恢复硬门禁。Watchdog 始终启动本轮开始时记录的同一绝对 EXE 路径。

## 10. 现场必须执行的故障演练

### 10.1 生命周期

- 打开软件但不开始：无 Watchdog；
- 点击开始：Watchdog 单实例启动并出现 Attached/HeartbeatAck；
- 人工停止：立即生成撤权标记，Watchdog 退出且不得重启主程序；
- 再次开始：创建全新 Session，旧 Session 消息无效；
- 正常完成和关闭：Watchdog 自动退出，Journal 出现在项目 `WatchdogSessions`。

### 10.2 EPB4/5 同类事故

受控制造 Dev1 回调空窗或使用测试 seam，验证：

- EPB4/5 首先安全 OFF；
- 日志必有同一 Correlation 的恢复上下文和 FrozenBoundary；
- 事故圈只有 `AbortedBySoftwareRecovery`，没有跨空窗的正式 `completed`；
- 能在进程内恢复时，两通道重新学习并续测；
- 人为阻塞恢复 owner 后，5 秒孤儿/电源期限或 60 秒阶段期限必须触发整批接管。

### 10.3 强制进程接管

- 冻结/挂起主进程，使心跳停止；
- 3 秒应进入 Suspect/TransportLost，5 秒进入 Unresponsive；
- 15 秒内旧进程不退出时，Watchdog 校验 Session 和 PID 启动时间后终止旧进程；
- 新进程先执行全部 DO OFF、电源 Disable、AO 归零、压力安全、DAQ 重建和 SQLite 恢复；
- 永久报警、人工禁用、人工单通道停止和已完成通道不重启；
- 其余健康剩余通道重新学习并按 SQLite 剩余次数续测；
- 连续制造启动失败，确认退避为 5/15/30/60 秒且不会因次数耗尽永久退出；
- 在任一退避阶段点击人工停止，后续不得再拉起。

## 11. 仍然存在的物理边界

独立软件 Watchdog 不能在旧进程完全卡死时直接控制 NI、电源或液压。从旧进程失去执行能力到新进程完成 `SafetyTakeover` 之间，仍存在只能通过日志间接描述、不能由软件独立证明已断能的安全空窗。

本实现遵循用户选择：允许 Watchdog 在 15 秒后强制终止并由新进程接管，以恢复无人值守试验。若未来要求“主程序完全卡死后仍在确定的百毫秒级内物理断能”，必须增加默认断开的硬件安全继电器/硬件 Watchdog；不能通过第二个软件进程同时抢占同一 NI 任务来实现。
