# V2.13.0.22：Watchdog 逻辑源新鲜度、接管取消与人工停止修复实施及验收

> 实施日期：2026-08-25（Asia/Shanghai）
> 对应项目：10358-029a
> 前置根因报告：`2026-08-25_10358-029a_V2.13.0.15人工停止卡顿与V2.13.0.21_Watchdog误接管_根因及彻底解决方案.md`
> 代码版本：V2.13.0.22
> 当前结论：P0 代码闭环和自动化/生产 seam 验收完成；24 小时台架与 72 小时现场耐久仍是正式发布门槛

## 1. 结论

本次修复没有改变现场事实：V2.13.0.15 在人工停止前稳定运行约 19 小时 44 分钟，人工停止是为了切换测试 V2.13.0.21，并非 V2.13.0.15 自行故障。

V2.13.0.22 已关闭 V2.13.0.21 的两条确定性 P0 故障链：

1. Controller 的不可变聚合快照现在拥有独立的 `LogicalSourceVersion` 和捕获时间。机械圈完成会触发异步发布，250～1000 ms、默认 500 ms 的运行健康定时器提供周期兜底；总聚合版本的其他变化不能伪装成逻辑源刷新。
2. Sidecar 先验证逻辑源新鲜度，再判断机械进度。旧源只会先触发 `WatchdogLogicalSourceStale` 和 Ping 刷新，不会再伪报 `ChannelProgressStalled`；刷新持续失败 5 秒才进入有界安全接管。
3. 监督期限绑定 `SessionId + PID + ProcessStart + AttachEpoch + RunId + RunEpoch + LifecyclePhase + RuntimeContractRevision`。进程、Run、阶段或合同切换均重建基线，不继承上一个 PID 的停滞年龄。
4. 自动接管改为可取消、代次隔离事务。`BatchStartFailedSafeIdle` 或人工停止如果先于 kill 线性化，当前代次的 dump 后续、kill 和 relaunch permit 全部失效，并只记录一次 `TakeoverCancelled`。
5. 当前人工停止入口已保留并验证“先启动 `StopAllAsync`，后处理 UI、Watchdog、检查点和批次取消”的顺序；外部 I/O 在后台执行，UI 最多只等待 250 ms 的通知优先窗口，不再把物理断能排在同步管道/日志刷新之后。

这不是简单放大 60 秒阈值。真实机械停滞仍按原阶段预算被识别，只有陈旧监督数据被隔离。

## 2. 逻辑源生产与协议闭环

### 2.1 独立源版本

`LogicalQuiescenceSnapshot` 新增：

- `SourceVersion`
- `CapturedUtcTicks`

`WatchdogChannelProgressSnapshot` / `WatchdogChannelProgress` 新增：

- `ProgressVersion`
- `LastProgressUtcTicks`
- `ProgressKind`

`RecoveryAggregateStore.PublishLogicalSource` 在自己的短锁内递增逻辑源版本并写入 UTC 捕获时间。DAQ、Stop、ownership 或 operational source 的发布只递增总聚合版本，保留原逻辑源版本和时间，不再掩盖旧源。

### 2.2 生产触发

生产端采用事件与周期双保险：

```text
机械圈完成
  -> 更新机械完成计数/时间
  -> 更新通道 ProgressVersion/LastProgressUtc/ProgressKind
  -> 单飞 ThreadPool 发布 LogicalSource

TimerRuntimeHealth（默认 500 ms）
  -> 无论批次是否活动都发布一次 LogicalSource
  -> 批次活动时继续执行原 Timer/Recovery 健康检查
```

发布仍通过 `_recoveryContractGate` 一次性采样并提交深拷贝；心跳线程只读取已提交聚合，不退回到跨字典拼装。

### 2.3 心跳消费

心跳透传：

- `LogicalSourceVersion`
- `LogicalCapturedUtcTicks`
- 每通道进度三元组
- Host 写入的当前 `AttachEpoch`

Sidecar 使用两种时钟共同验鲜：

- UTC 捕获年龄超过 3 秒；或
- 同一逻辑源身份在 Sidecar 单调时钟中超过 3 秒没有变化。

第二项保证 Windows 墙钟回拨时旧源也不能永久显得新鲜。旧协议载荷两个字段都为 0 时保留兼容行为。

旧源处理顺序为：

```text
首次过期 -> WatchdogLogicalSourceRefreshRequested -> Ping
5 秒内仍是同一旧源 -> WatchdogLogicalSourceStale 接管原因
任何旧源状态 -> 禁止执行 ChannelProgressStalled 计算
```

Ping 会要求客户端立即发送一次心跳；周期生产者负责提交新逻辑源。如果生产者本身已失效，才按“监督数据源失效”启动原有 `RequestStopAll` 安全链，而不是根据旧机械计数直接 kill。

## 3. SafeIdle 接管取消事务

新增 `TakeoverTransactionCoordinator`，每个自动接管获得唯一：

- `Generation`
- `CorrelationId`
- 当前进程/附着/Run 的 `AuthorityIdentity`
- `CancellationToken`
- 单调阶段

阶段为：

```text
StopRequested -> DumpCapture -> ProcessTermination
              -> RelaunchPermit -> Relaunching -> Completed
```

关键规则：

1. `BatchStartFailedSafeIdle` 和 `ManualStopIntent` 调用同一个取消入口；
2. 等待循环使用事务 CancellationToken；
3. dump 前、dump 后、kill 前、permit 前、relaunch 前均重新验证当前代次；
4. kill 与 SafeIdle 取消共享同一线性化锁；取消先获得锁时 kill 委托根本不会执行；
5. 旧事务 worker 到达 `finally/Complete` 前，不能被下一代覆盖；
6. 取消日志记录代次、correlation 和取消前阶段，便于现场审计；
7. 进程终止授权已经先线性化时，后到的 SafeIdle 不伪称“取消成功”。

这关闭了现场 `09:58:00 BatchStartFailedSafeIdle` 后仍于 `09:58:08` dump、`09:58:09` kill 的竞态窗口。

## 4. 人工停止链复核

V2.13.0.22 沿用 V2.13.0.21 已具备、但 V2.13.0.15 现场包尚未包含的停止顺序修复：

1. 点击后立即创建 CommandId；
2. 第一个可能阻塞的业务调用是 `_epb.StopAllAsync(ManualUi)`；
3. 之后才同步 UI 开关；
4. `NotifyManualStop` 在后台线程执行；
5. checkpoint 清理和批次取消分别排队；
6. UI 对 Watchdog 通知只做最大 250 ms 的 `WhenAny`，不等待外部 I/O 完成；
7. Stop 核心自身保持幂等，重复入口复用结果。

生产 StopAll seam 覆盖了真实十阶段、DO 物理失败、DO 准入拒绝、持久化截止以及 aggregate 到 heartbeat 的一次派发；WinForms 生产回调链覆盖了真实 STA 消息泵、断线关闭、Stop envelope、资源释放和重新绑定。

因此 V2.13.0.15 的“运行稳定”和“人工停止旧入口卡顿”继续作为两个独立结论；V2.13.0.22 不再包含旧入口顺序。

### 4.1 两项 P1 生产链复核

当前生产代码还具备根因报告要求的两项外围闭环：

- Watchdog `StartAsync` 由 `WatchdogAttachWaitCoordinator.WaitAsync` 统一观察启动、Attached、失败和截止任务；传输硬化测试覆盖首连、握手超时、50 圈真实 Sidecar 和重连 ABA，不再依赖无人观察的启动 Task。
- Sidecar 的 `RecoveryTransitionWindow` 运行在独立 STA 线程，接管时置顶显示故障原因、全断能/恢复状态和人工停止按钮；主进程监视窗关闭或重启退避期间它仍由 Sidecar 持有。WinForms 生产测试确认真实消息泵与关闭/重绑资源链。

现场若仍只看到灰色 MDI 而没有 Sidecar 过渡窗，应同时核对运行的 `MTTFTest.Watchdog.exe` 版本和完整包校验，不能只替换主 EXE。

## 7. 现场上线与回退步骤

1. 保留 V2.13.0.15 完整目录作为已知稳定回退包，不覆盖原目录。
2. 从干净提交生成 V2.13.0.22 独立候选目录并执行 seal/verify。
3. 启动前核对四个程序集均为 `2.13.0.22`，且 `PackageVerified=True`。
4. 先做 4、5、11、12 通道学习回放：每 15 秒完成一圈，连续至少 10 圈；确认 `LogicalSourceVersion` 周期递增，机械完成到 Sidecar 可见小于 2 秒。
5. 做一次 `BatchStartFailedSafeIdle(FormalRunNotCommitted)` 故障注入；验收 `TakeoverCancelled` 一次，dump/kill/relaunch permit 均为 0。
6. 做人工停止并保持管道不读/日志慢/检查点慢场景；确认 StopAll 先进入、无新上电圈、UI 消息泵可响应。
7. 完成 24 小时台架、20 次受控恢复、20 次人工停止/再启动。
8. 台架通过后再做 72 小时现场耐久。任何门槛失败，立即停止 V2.13.0.22 长时运行并回退完整 V2.13.0.15 包。
