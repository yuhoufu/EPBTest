# V2.12.0.18 内存映射命名隔离与并行写盘闭环

## 结论

V2.12.0.18 修复了 `EpbDiskWriter` 的跨数据目录全局 MMF 名称冲突。此前每个写盘器无条件创建 `EPB1_MMF`—`EPB12_MMF`；即使两个实例使用完全不同的项目目录，也会在 Windows 全局命名空间互相阻塞并抛出 `IOException: 当文件已存在时，无法创建该文件`。

修复后，映射名包含规范化数据根目录的稳定 FNV-1a 64-bit 作用域：

```text
EPB_{DataStorePathScope}_{Channel}_MMF
```

由此同时满足：

- 同一 `DataStorePath` 跨进程仍使用同一映射名，保留写盘互斥和数据安全边界；
- 不同项目、不同测试目录或独立诊断目录使用不同映射名，不再互相阻塞；
- 映射作用域不使用运行时随机哈希，相同目录在重启后保持稳定；
- 正式主程序原有单实例 Mutex 继续保留，不以 MMF 改名替代进程级单实例保护。

## 发现过程

完成性审计并行启动控制/恢复综合测试和写盘回归时，综合测试在创建第二个临时目录写盘器时失败。两个测试目录均带独立 GUID，排除文件路径相同；源码检查确认冲突来自固定的全局 `EPB{ch}_MMF` 名称。

这不是算法断言失败。单独运行时原 `28/28` 写盘测试通过，但并行运行能够稳定暴露跨目录命名碰撞，因此纳入产品修复，而不是只把测试改回串行。

## 现场边界

本修复消除了不同数据目录之间不必要的系统级互斥，但不证明真实 NI、网络共享、液压和电源在 24/72 小时内满足上线红线。V2.12.0.18 仍必须依次完成 2 h 故障注入、8 h 压力、24 h 六通道联合验收和 72 h 无人值守验证；每阶段必须使用同一 RunId、EXE SHA 和配置 SHA。
