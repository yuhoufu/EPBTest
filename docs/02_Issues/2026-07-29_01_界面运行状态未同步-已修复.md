# 界面运行状态未同步

## 问题来源

- Inbox：`docs/01_Inboxes/2026-07-29_01_界面运行状态未同步.md`
- 发现日期：2026-07-29
- 影响界面：`FrmEpbMainMonitor`
- 现场程序路径：`\\wj-epb\soft_1.2_1`
- 现场数据路径：`\\wj-epb\EPB_Data\EPB_Fatigue`

## 现象

主监控界面左侧 EPB 状态区已经显示 EPB-10 为 `RUN`，完成次数为 2；右侧下拉框也选择了 EPB-10，但详情区仍显示：

- 运行时间：`00D 00H 00M`
- 完成次数：0
- 剩余次数：10
- 进度：0.0%

即同一通道在两个区域中的运行状态和进度没有同步。

## 根因

`FrmEpbMainMonitor.OnEpbChannelCycleCompleted` 收到单圈完成事件后，只更新了左侧 `EpbGroup[channel - 1].CtrlCycles`，没有调用右侧详情面板的刷新逻辑。因此内存中的 `EpbTestRecord` 虽然已经更新，右侧控件仍保留上一次选择通道时写入的旧值。

同时，批量启动后的代码会遍历所有选中通道并直接调用 `UpdateEpbSummaryPanel(record)`。当同时运行多个通道时，后遍历到的通道可能覆盖右侧面板，造成下拉框通道与详情数据来源不一致。

报警、暂停、恢复事件此前也只写日志，没有同步更新 `EpbTestRecord.Status` 和当前详情面板。

## 修复

修改文件：`MTTfTest/FrmEpbMainMonitor.cs`

1. 新增 `RefreshCurrentEpbSummary(int channel)`，统一执行右侧详情刷新。
2. 刷新前校验事件通道是否等于下拉框当前通道，避免其他运行通道覆盖当前详情。
3. 支持从非 UI 线程触发时通过 `BeginInvoke` 切回 UI 线程。
4. 单圈完成后，在更新左侧次数的同时即时刷新当前通道的运行时间、完成次数、剩余次数、进度和状态灯。
5. 批量启动后只刷新当前下拉框通道，不再用遍历中的其他通道覆盖详情。
6. 报警、暂停、恢复事件同步更新记录状态，并在该通道被选中时刷新详情。

## 现场回归建议

1. 仅选择 EPB-10，开始试验。
2. 保持右侧下拉框为 EPB-10。
3. 每完成一圈，确认左侧次数和右侧“完成次数”同步增加，剩余次数及进度同步变化。
4. 同时选择多个 EPB，固定查看其中一个通道，确认其他通道完成圈次时不会覆盖当前详情。
5. 分别触发暂停、恢复和报警，确认当前通道状态灯与实际状态一致。
