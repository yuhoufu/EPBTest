## 2. 运行身份：RunId、RootRunId 与 RunChain

`DataOperation/ LearningRunManifest.cs` 中的 `RunChainIdentity` 约定如下：

| 字段 | 含义 |
|---|---|
| `RunId` | 一次实际执行（含一次恢复执行）的不可变身份。每次人工新启动生成新的 `RunId`。 |
| `RootRunId` | 恢复链根身份；同一无人值守恢复链的多个执行共享它。缺省时归一化为本次 `RunId`。 |
| `ParentRunId` | 本次恢复执行直接继承的父执行，供审计链回溯；不是保留计数单位。 |
| `RunEpoch`/`RestartGeneration` | 运行代次和重启代次，用于区分旧执行的时间/状态，不改变根链目录。 |
| `RunChainId` | `EffectiveRootRunId` 的别名，即 `RootRunId` 非空则取它，否则取 `RunId`。 |

目录约定为：

```text
<StoreDir>/<TestName>/LearningCycles/<RootRunId>/
  learning-run-manifest.json
  Executions/<RunId>/EPBxx/Learning_NNNN[/Attempt_NNNN]/...
```

一个 Learning manifest 记录整条链的执行列表、每个执行的 `RunId/RootRunId/ParentRunId/RunEpoch`、计划与实际圈数、Learning/Qualification Attempt、文件 bytes/SHA-256、最终状态和模型 hash/commit receipt。成功链只有在模型提交凭据、计划证据、Attempt receipt 和文件校验都通过后，才可能成为保留候选。

“最近 3”是最近 3 个完整成功 **RunChain（根目录）**，不是最近 3 圈；每条链保留该运行全部通道、Learning/Qualification 圈和必要 Attempt。失败/取消链另按 `LearningFailedRunRetainCount=3` 保留。当前链、运行中目录、状态 Unknown、旧格式/无 manifest、`.tmp` 或校验不完整目录永远不进入自动删除候选。

## 3. 已实现的在线治理

### 3.1 Learning

`EpbManager` 在运行链终态发布 `learning-run-manifest.json`，发布成功后只向 `DataHousekeepingService` 登记候选。`DataHousekeepingService` 负责：

- 独立 `BelowNormal` 后台线程和有界队列，不持有控制、恢复、SQLite 或看门狗锁；
- 当前链、非终态、reparse、越界、`.tmp/.partial`、manifest 未声明文件和 hash/bytes 不一致均跳过；
- 同卷改名到 `.retention-staging-*`，sidecar 在改名前 WriteThrough/Flush，移动后转正；
- 每批最多 16 个文件或 32 MiB，默认批次间隔 5 秒；DAQ/报警/停止/恢复忙碌时延期；
- 进程启动续扫 pending/staging，未知 staging 不删除；文件占用、权限、改名、删除失败只写 Warning 并保留目录；
- Dispose 最多等待 2 秒；worker 未退出时不提前释放仍可能被访问的 queue/CTS。

`LearningRetentionMode=Unlimited` 需要重启后生效；启动扫描、manifest 发布后的入队、候选计算和删除路径均被关闭，不删除任何 Learning 数据，也不恢复已经删除的数据。

### 3.2 Telemetry

`PowerSupplyCoordinator` 的保护监控仍以 100 ms 轮询运行；`PowerSupplyTelemetryCsvRecorder` 只改变持久化采样：稳态按 1 Hz，事件窗口按 10 Hz，事件前 60 s、后 30 s；每小时或 100 MiB 分段，封口后写 segment manifest（行数、bytes、drop 计数、run identity、SHA-256），默认保留 3 天。事件/状态变化不走稳态队列，稳态压力只报告丢弃计数；封口和过期清理在后台线程进行，失败只 Warn。

Telemetry 的 spill cursor、sequence 恢复、`.tmp` 未封口段和路径边界均按持久化安全规则处理：cursor/manifest 只在原子提交后推进，重启从已提交 cursor/sequence 继续，活动 `.tmp` 不作为完整分段清理，越界/非法路径拒绝处理；这些安全路径已有回归覆盖，但尚未在现场 UNC 卷验证。

### 3.3 Incident

`SessionKey = normalized Device + immutable faultCode + RunEpoch`。同 key 在 60 秒窗口内且尚未 terminal 时合并；不同 device、faultCode、epoch 或 terminal 后的新观察创建新会话。每个 phase 先提交轻量 `incident.json`，再写 receipt；终态只在 phase receipts 已提交后原子发布 `session-manifest.json`。

- active session、每日字节、最低剩余空间只抑制重证据；summary、trigger、terminal 和 stage JSON 必须保留；
- 默认 `DaqIncidentCopyRecentCycles=false`，不复制最近圈；
- storm `>2/h` Warn、`>5/h` Error，只记录告警，不改变恢复控制；
- terminal manifest 发布后才向独立 `IncidentHousekeepingService` 入队；每设备完整终态保留 10；active、无 terminal、unknown、旧格式、损坏 receipt 不删；共享根必须所有已声明设备 terminal 且 quiet，且所有设备都超出各自保留名额后才可删；
- 删除使用同卷 staging、pending sidecar、Flush(true)、move 后转正、启动续扫和 5 秒批次限速；未知 staging、未知文件、`.tmp`、reparse、manifest 未声明文件拒绝删除；失败仅 Warn。

### 3.4 Sol 窄范围终审闭环

- P0/P1 终审结论：本次治理全范围可验收，无遗留 P0/P1。Learning、Telemetry、Incident、在线清理及恢复边界均完成窄范围源码复核；现场/8 天容量目标仍按本文未验证项管理。
- Learning 终审闭环：fatal 回滚和提交失败路径保留原始 fatal；Failed receipt 仅 best-effort 写入，receipt 写失败不覆盖/吞掉原 fatal，不触发自愈，也不把该运行标记为 Successful。owned staging 每个删除批次都会重新检查 active/protected 状态，活动链或受保护根立即跳过并保留。
- Telemetry 终审闭环：producer 路径保持零同步 I/O；已封口但缺 manifest 的 orphan sealed 段可补写 manifest 后再参与治理；祖先目录 reparse 检查阻止越界遍历；StopAll 对 Telemetry writer 采用非阻塞 detach，不把持久化清理拖入安全停机等待。
- Incident P0/P1 终审闭环：shared expected-device 解析失败不再降级为当前设备，而是保留冻结 baseline、延期 phase 且不发布；普通 device-scoped root 与显式 shared correlation root 分离。
- 终态 manifest 真正提交（`published=true`）后才入队 housekeeping；Incident evidence worker 使用独立私有观察/日志和持久重试，不进入 `TaskSupervisor`、看门狗、断电或 DAQ 恢复故障链，StopAll 不等待它。
- 验收覆盖稳定 SessionId 合并、100 个不同 Correlation、双设备 shared/普通根、异常注入、receipt/manifest 原子提交、容量门禁、retention sidecar/续扫和 worker drain 边界；Incident 专项结果为 5/5。
- 可选后续加固：Telemetry 严格要求 `_seg` 后缀使用纯数字序号可进一步收紧命名校验；当前不影响治理正确性或本次验收结论，不作为阻塞项。

### 3.5 独立 Watchdog Journal

主程序在每轮启动和恢复附着前，把项目 `WatchdogSessions` 路径及解析后的预算传给 Sidecar。Sidecar 直接维护原子最新快照、状态转换/60 秒心跳检查点、分段错误、PID+启动时间租约和终态 manifest；主进程另记启动、Attach、ACK/pipe 失联、同 Session 重连和生命周期事件。正常退出不再从旧 LocalAppData 复制快照，主进程完全卡死时仍由独立进程继续写项目证据。

所有文件 I/O、轮转和清理位于 Sidecar/客户端私有有界线程，不进入 3/5 秒监督、StopAll、控制、DAQ 回调或 TaskSupervisor。项目路径有效但暂时不可写时按项目路径哈希进入本机 8 MiB/7 天缓冲，恢复后按 EventId 去重回灌；人工停止先同步写本机控制面撤权 marker，项目镜像异步完成，项目盘故障不能恢复 Kill/重启授权。

清理只识别 SchemaVersion 2 的严格 Watchdog 文件，保护当前/存活 Session；顺序为 90 天、32 Session、128 MiB。旧 `%LOCALAPPDATA%\MTTFTest\Watchdog` 没有项目身份，不自动迁移或删除。详细实现、文件布局、自动化和现场边界见 `2026-08-13_V2.13.0.3_Watchdog项目日志与容量治理实施验收.md`。

## 5. 数据路径与不变量

```text
<StoreDir>/<TestName>/
  index.db[,-wal,-shm]                 # 正式圈索引，治理器不触碰
  LearningCycles/<RootRunId>/          # Learning 完整运行链
  PowerSupplyTelemetry/<time>_<RunId>.csv[/_segNNNN + .manifest.json]
  Latest/EPBxx/<package>/              # 停止包 Count10
  AlarmSnapshots/                      # 报警圈和诊断证据
  WarningSnapshots/EPBxx/<code>/       # Warning Count30
  IncidentSnapshots/Run-*-Incident-*/ # phase JSON/receipt/session manifest
  HistoricalSnapshots/EPBxx/Cycle_*    # 历史圈 Count12
  WatchdogSessions/session-<id>.*       # 独立Watchdog快照/事件/错误/租约/终态
```

在线清理器不删除 `index.db`、WAL/SHM、当前 Run/Chain、活动 `.tmp`、未知目录或缺少完整 manifest 的旧目录。所有删除先做路径、reparse、状态、receipt、hash/bytes 校验；同卷 staging 失败时保留原目录或 staging。清理器不停止主程序、不调用恢复/断电、不改变 TaskSupervisor/watchdog 状态；任何 I/O 失败仅 Warn、退避或留待下次续扫。

## 8. 回滚与旧数据处置

1. 发现回放缺证据、索引不一致、磁盘异常或 I/O 延迟升高时，先停止新重型证据写入并切换新的封存根；不要删除或重建 `index.db`。
2. 恢复上一版二进制和配置时，可将新格式恢复为 `CsvAndBin`，将 `TelemetryPersistenceMode` 临时改为 `Raw`（仍受显式轮转上限），将 `LearningRetentionMode` 改为 `Unlimited`；重启后才会停止新的 Learning 清理入队。已删除数据不会被回滚配置恢复。
3. `DaqIncidentCopyRecentCycles=true` 只应作为有时限、有容量预算的专项取证开关；常态保持 `false`。Incident 完整保留数可以临时增大，但不得用它绕过磁盘余量门禁。
4. V2.13.0.0 旧目录没有新 manifest 的，程序不按修改时间、目录名或通配符自动删除；必须先外部备份，在副本执行 SQLite `integrity_check`、`running=0` 和文件清单审计，再由单独审批的历史工具处理。`index.db`、`index.db-wal`、`index.db-shm` 必须整体快照，不单独删除。

## 9. 未现场验证、未实施和后续验收

### 未现场验证

- 8 天同类试验 ≤3 GiB、连续 24 h 新增 bytes、真实卷余量门禁和清理 I/O 对控制延迟的影响；
- 真实 NI DAQ/程控电源故障风暴下的跨设备共享 Incident 根、进程重启续扫和占用文件退避；
- 真实 UNC 路径/网络卷上的 `GetDiskFreeSpaceEx`、权限和断线恢复；当前仅有源码复用与注入测试，未做现场 UNC 验证；
- 现场回放器对 BinOnly/CsvOnly 与新 Telemetry/Incident manifest 的完整兼容性。
- 真实主程序强杀/活锁、现场 UNC 永久阻塞、Watchdog 24/72 小时长稳和 128 MiB/90 天自然清理；当前真实 Sidecar 自动化只验证存活模拟进程停止心跳后的 3/5 秒接管与撤权。

### 未实施

- 旧 V2.13.0.0 无 manifest 数据的自动迁移、自动删除或“旧目录一键治理”；
- 用一次本地测试替代现场长时容量门禁；
- 跨进程运行中动态加入、且未在启动时预注册或未携带显式 shared correlation 的新设备发现；当前边界是启动预注册 + 显式 shared correlation，未知后来设备不会被旧进程臆测加入根。

### 现场补验清单

- 新封存根先 dry-run，核对 Learning 成功/失败各 3 个完整 RunChain、Incident 每设备 10 个 terminal 会话、Telemetry 3 天分段和 Warning Count30；
- 运行前/每 24 h/结束时记录各根目录字节、卷余量、Telemetry 行数/bytes/drop、housekeeping 队列和 Warn；
- 注入占用、权限失败、进程重启和看门狗窗口，确认主程序、控制、自恢复、报警和 watchdog 状态不变；
- 备份旧目录后只在副本处理历史数据，现场原目录保持可回滚。
