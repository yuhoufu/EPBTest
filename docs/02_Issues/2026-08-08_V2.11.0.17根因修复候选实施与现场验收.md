# V2.11.0.17 根因修复候选实施与现场验收

> 状态：候选版，待台架与现场验证。本文不构成正式发布或现场验收结论。
>
> 基线：`4fa397b`；程序版本：`2.11.0.17`；安全策略版本：`2026.08.08.1`。

## 1. 修复结论

V2.11.0.16 现场出现的“首次可运行、停止后无法再次启动”和约 100 ms 峰值陈旧误判，不是通过放宽阈值、扩大队列或延长报警容差解决。本候选版直接修复以下状态机根因：

1. 峰值证据使用封口后的墙钟时间计算年龄，把正常排空等待误算成样本陈旧；
2. 液压通道在异常、取消和落盘失败路径中缺少强制归还作用域，旧代次成员可残留；
3. StopAll 只证明物理输出关闭，没有证明旧任务、租约、代次、Gate 和恢复所有者已经归零；
4. 同类软件恢复缺少统一熔断及整批恢复出口，可能不断创建 Recovery 代次；
5. 无人值守只有进程重启路径，缺少一次受预算约束的同进程“停止—重建—完整学习—续测”。

## 2. 已实施改动

### 2.1 峰值捕获时间语义

- 峰值封口时冻结 `LogicalCutoffUtc`，全速率处理线程继续推进 `ProcessedThroughUtc`；仅当水印覆盖截止点时设置 `IsCutoffCovered=true`。
- `DrainCompletedUtc` 和 `DrainElapsedMs` 只记录冻结截止点后的排空诊断耗时，不参与峰值有效性判定。
- 峰值新鲜度统一为 `LogicalCutoffUtc - LastSampleUtc`，不再使用封口完成后的 `DateTime.UtcNow`。
- 捕获身份错配、截止未覆盖或排空超时时，当前逻辑圈返回软件恢复结果，不生成电流硬故障，也不累加连续峰值偏差。
- “连续三圈峰值偏差”仅消费身份一致、截止覆盖完整且尾差合格的证据。

涉及代码：

- `IO.NI/TwoDeviceAiAcquirer.cs`
- `Controller/EpbCycleRunner.Adaptive.cs`
- `Controller/EpbCycleRunner.StartupPositioning.cs`

### 2.2 液压租约作用域与 epoch 隔离

- 新增不依赖 `IAsyncDisposable` 的 `HydraulicChannelLeaseScope`，提供幂等 `CompleteAsync` / `AbortAsync`。
- 租约携带液压组 epoch、代次 Key 和通道身份；协调器在处理迟到归还时校验 epoch，旧租约不能释放新代次成员。
- 协调器显式登记活动作用域；作用域关闭的 `finally` 才注销租约。成员、代次、活动操作和租约都进入健康判定。
- 学习、资格、正式圈、DAQ 恢复、持久化 Begin 失败和取消路径均增加最终归还。
- 归还前必须确认本通道电机 OFF；OFF 失败时先升级电气组紧急关闭，并保留租约映射，禁止伪装成“逻辑已清场”。
- 新代次申请前先关闭不匹配的旧作用域，避免旧 Gate 泄漏让新申请永久等待。

涉及代码：

- `Controller/HydraulicGroupCoordinator.cs`
- `Controller/EpbManager.cs`
- `Controller/EpbManager.BatchStart.cs`
- `Controller/EpbManager.PauseResume.cs`

### 2.3 液压健康快照与安全重建

- 新增 `HydraulicGenerationSnapshot`，记录组 epoch、准入状态、活动代次、活动操作、活动租约、Gate 可用性、Pending 成员和重建次数。
- `RebuildGroupAsync` 执行：关闭准入、强制终结旧代次、确认安全释压、关闭旧作用域、等待活动操作/租约归零、替换 Gate、递增 epoch、验证后开放准入。
- 批量启动在 DAQ、电源和任何电机动作前预检全部启用液压组；每组最多安全重建一次，仍不健康则整批启动失败，不允许 H1/H2 半批动作。
- 活动操作或作用域不能退出时，热重建返回失败；上层无人值守恢复升级为进程自重启。

### 2.4 StopAll 可重新启动屏障

`StopSafetyResult` 新增：

- `LogicalQuiescenceConfirmed`
- `LogicalError`
- `LogicalState`
- `CanRestartInProcess`

`CanRestartInProcess` 现在同时要求：

- 电机 DO、程控电源和安全压力均已确认；
- 批次生命周期和批次会话退出，旧 BatchId 清空；
- Timer、Runner、Stop/Cycle CTS 清零；
- 液压参与者、通道租约、代次、活动操作和 Gate 全部健康；
- DAQ 恢复、液压/电源软件恢复、组重置任务及恢复所有者清零；
- StopAll 已递增运行 epoch，旧恢复不能再提交。

`PrepareForFreshRestartAsync` 在等待旧批次生命周期退出后执行最终逻辑检查。停止结果缓存只有在物理和逻辑条件都仍成立时才允许复用。

### 2.5 有界自愈与无人值守兜底

- 软件恢复循环按异常类型和关键错误消息形成状态指纹；相同无进展指纹最多三次，总尝试也有硬上限。
- DAQ 启动、程控电源启动和液压启动预检均改为三次熔断，不再无限创建 Recovery 代次。
- 熔断指纹只导出一次完整诊断快照，然后通过 `SystemFaultRaised` 和 `UnattendedBatchRecycle` 交给无人值守协调器，避免重新进入原液压恢复循环。
- 同一指纹十分钟内只允许一次同进程恢复：`StopAll → 生命周期 Join → 液压健康重建/预检 → 不少于5圈完整学习 → 按剩余正式圈续测`。
- 同进程恢复失败或同一指纹再次出现时，升级现有进程自重启；继续受“十分钟最多三次”预算约束。预算耗尽后撤销授权并保持安全停机。
- 检查点升级为 schema 3，记录同进程恢复指纹、十分钟历史、最后恢复/重建结果及剩余圈数；项目、配置或可执行文件哈希变化时拒绝自动续测。

涉及代码：

- `Controller/SoftwareSelfHealingLoop.cs`
- `Controller/HydraulicGroupCoordinator.cs`
- `MTTfTest/UnattendedRecovery.cs`

## 4. 现场候选验收清单

以下项目必须在真实 NI 设备、三组程控电源和现场液压系统上完成；自动化通过不能替代现场验收：

- [ ] 连续 20 次“启动—停止—同进程重新启动”；
- [ ] 六通道、双设备 2 kHz，正式运行至少 100 圈；
- [ ] 无 `FullRatePeakInvalid Age≈100ms`，峰值诊断使用 `TailLag/Covered/Drain`；
- [ ] 无 `HydraulicBarrierTimeout Pending=[4,5]`；
- [ ] StopAll 后 10 秒内任务、CTS、参与者、租约、代次、恢复对象归零，`CanRestartInProcess=true`；
- [ ] H1 预检失败时 H2 也没有电机动作；
- [ ] EPB4/5 每圈只使用一个 H1 代次，电气错峰约 800 ms；
- [ ] Dev1、Dev2 持久化队列不达到硬上限；
- [ ] 同一故障第一次触发同进程恢复，再次出现升级进程自重启；
- [ ] 自重启预算耗尽后保持安全终态，不再循环动作。
