# V2.13.0.30 自动恢复、周期超限与永久报警持久化修复实施及验证

## 1. 结论

V2.13.0.30 已完成代码实施并通过本地构建与自动化回归。最终运行语义如下：

1. 当前正式槽内任一卡钳未完成时，其他卡钳保持自身输出关闭并等待；全槽安全闭合后统一进入首个未来周期边界，不补跑。
2. 普通周期超限只归因于超限卡钳。连续 8 个已完成且已持久化的超限圈触发永久报警。
3. 15 秒周期下，到 30 秒仍未确认自身输出 OFF 的卡钳立即被永久隔离；已 OFF、仅等待共享收口的卡钳不误报警。
4. 永久报警与连续超限次数写入当前项目 `Config\TestConfig.xml`，软件重启后仍保持红色“永久报警”，即使通道已取消勾选。
5. Watchdog 自动接管退出不再冒充人工退出，也不再撤销正在消费的恢复许可。

本结论是“软件实施及本地自动化验证通过”，不是“现场硬件验收通过”。NI、CAN、液压和共电源条件仍需在试验台验证。

## 3. 实际修改

### 3.1 全局正式槽屏障

新增 `FormalBatchSlotCoordinator`，以批次 `RunId` 和正式槽序号冻结参与者。每个通道提交以下结构化终态：

- 电机 OFF 是否确认；
- 机械圈是否完成；
- 液压成员是否已退出；
- 控制结果与持久化边界；
- 回调、自身动作和共享等待耗时；
- 是否已永久隔离。

屏障 fail-closed：异常退出若无法证明电机 OFF 或液压释放，不能伪装为安全完成。上一槽最后一个参与者完成时立即固定下一释放边界；下一圈迟到进入不会再额外空等一个周期。

液压成员屏障预算调整为至少 `2 × PeriodMs + ReleaseTimeoutMs`，用于区分正常共享等待和真实释压失败；真实安全压力确认仍受独立 `ReleaseTimeoutMs` 约束。

### 3.2 超限判定与永久隔离

`EpbCycleOutcome` 增加：

- `CallbackElapsedMs`
- `PhysicalActionElapsedMs`
- `SharedCoordinationWaitMs`
- `PeriodOverrunKind`

自适应和旧控制路径均统计自身正向、保持和反向动作时间；外部相位等待、全局槽等待、共享资源等待和写盘不用于给正常兄弟卡钳计超限。

普通超限只在“控制成功 + 机械圈完成 + 正式圈耐久提交”后累计。正常圈清零；第 8 次锁存 `ConsecutivePeriodOverrun`。硬截止到达且通道仍带电时取消当前 attempt、撤销执行许可、执行高优先级 OFF，并锁存 `PeriodOverrunHardLimit`。高优先级 OFF 返回失败时不会清除运行带电标志，而是升级整批安全停止。

### 3.3 永久报警持久化与 UI

`EpbTestRecord`、`ConfigLoader` 和 `EpbTestRecordStore` 已支持永久报警与连续超限字段。`ConfigLoader.UpdateTestEpbAlarmState` 对项目 XML 使用同文件锁、临时文件和原子替换，一次提交报警、连续次数与可选启用状态。

UI 行为：

- 锁存通道即使 `Enabled=false`，状态仍显示红色“永久报警”；
- 悬浮提示显示报警码、报警时间和连续超限次数；
- 新增 `WaitingForSlotBarrier`，属于合法运行等待，不触发计时器/Watchdog 假故障；
- 右键状态格可清除永久报警，保留试验圈数并保持未勾选；
- 重新勾选时二次确认，原子清报警并启用，但不会自动启动。

### 3.4 自动恢复

- 新增协议消息 `WatchdogTakeoverExit`，不属于人工终止消息。
- 主程序关闭意图使用 `RuntimeShutdownIntent` 区分会话关闭、人工应用退出和 Watchdog 接管退出。
- Watchdog 接管链使用 `WatchdogTakeoverExitReceipt`/`RuntimeShutdownReceipt`，只有真实 `WatchdogStopAllCompleted` 才授权旧主窗退出。
- 修复同一主窗绑定新 Session/Lease 时复用旧缓存关闭任务的问题。
- Host 对接管退出只观察旧 PID 有界退出，不设置 `ManualStopRequested`，不撤销恢复许可；人工 `ShutdownExpected` 保持原语义。
- 子进程提前退出、20 秒附加超时、检查点/许可拒绝进入耐久失败、重试或熔断链；不允许永久停在 `Started`。

## 4. 周期始终超限时的最终处理

以 `PeriodMs=15000` 为例：

| 场景 | 最终处理 |
| --- | --- |
| 单圈 16 秒完成 | 本圈正常计数；仅该卡钳超限次数 `+1`；全体等待收尾后走未来边界 |
| 连续 7 圈均为 16 秒 | 保持运行，项目中持久化连续次数 7 |
| 第 8 圈仍为 16 秒 | 本圈完成并只计一次；该卡钳锁存 `ConsecutivePeriodOverrun`、取消勾选并永久禁用 |
| 中间出现一圈不超过 15 秒 | 该卡钳连续次数清零并写盘 |
| 30 秒时仍带电且本圈未完成 | 本圈取消且不计数；强制 OFF、撤销执行许可、锁存 `PeriodOverrunHardLimit` |
| 30 秒时已 OFF，仅等待兄弟卡钳、液压或收尾 | 不把该卡钳误判为硬超限，继续等待当前槽安全结束 |
| OFF、液压安全压力或报警写盘无法确认 | 转组级/整批系统故障，停止无人值守续跑；其他卡钳不得冒险继续 |

因此，一个卡钳变慢不会让其他正常卡钳“各跑各的”并跨槽上电；它们在当前槽内等待。这避免共电、共液压关系下出现跨槽动作，同时通过第 8 次或 2 倍周期硬截止把持续异常通道从后续槽永久隔离。
