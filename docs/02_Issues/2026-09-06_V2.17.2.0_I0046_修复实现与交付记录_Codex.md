`Controller/EpbManager.DaqLiveness.cs` 恢复为旧提交对应文件；`EpbManager.cs` 恢复默认值和范围；`MTTfTest/App.config` 改为 250/1500/5000。

这意味着从 5000ms 起连续三次检查确认，不能解释成等待 15000ms。Warn 仍用于执行器新鲜度截止的参数传入，其实际消费方式保持现有调用关系。独立控制数据质量、100ms ControlHardFaultAge、代次校验、OFF 未确认 5s 接管、持久化有界队列与超时并未撤销。样本陈旧但回调新鲜时，旧版存活监督不 Trip，独立控制质量仍拒绝陈旧样本。

安装后必须检查安装目录实际 `MTTFTest.exe.config`。如果现场配置被部署规则或人工修改保留，以实际加载值为准，不能仅检查源仓库。

## 3. P0：主子窗体共享正确的退出类型

现场确定的缺陷是：子窗体授权先按 SessionClose 关闭 sidecar，之后主窗体的替换退出复用已经终结的共享关闭任务，造成批准许可后被普通 ApplicationClosing 取消。

本次修改：

1. `Main_Frm` 将本次退出类型传到所有监控子窗体。
2. 子窗体授权将该类型继续传入主窗体共享关闭入口。
3. 普通 SessionClose 遇到已经确定的看门狗退出所有者时，沿用所有者的类型；显式 ApplicationExit 保留人工退出语义。
4. sidecar 收到晚到普通 ApplicationClosing 时，只有退出回执、关闭墓碑、当前进程 PID/启动时间及当前许可绑定都匹配，才保留接管。人工停止、会话撤权、失效许可仍优先阻止接管。
5. 保留路径记录 `LegacyApplicationClosingPreservedReplacement`，继续观察既有退出事务。该分支不会凭空生成许可，也不跳过旧进程退出证明和实际拉起流程。

关键文件：`MTTfTest/Main_Frm.WatchdogUi.cs`、`MTTfTest/FrmEpbMainMonitor.cs`、`Watchdog.Protocol/WatchdogSafetyReceipts.cs`、`MTTFTest.Watchdog/WatchdogHost.cs`。

## 4. P1：安全投递先于同步取消和观察者

DAQ 恢复的第一段采用 `HighPrecisionTimer.RequestSafetyPauseNonBlocking` 封住下一圈，避免 `Timer.Pause` 同步发布外部观察者。随后冻结原圈身份和持久化边界、提交整组最高优先级 OFF、启动共享电源 Disable 及拒绝项兜底、撤销液压参与权并投递释放。

周期 CTS 从字典摘除时捕获确切旧对象，再单独调度 Cancel/Dispose。取消回调不占用截止执行线程；迟到任务不会再次按通道查询并取消新一圈 CTS。边界冻结仍保留现有身份锁定规则，未通过放宽边界消除等待。

新增 `FieldMetric DAQ_CUTOFF_TIMING`：WatchdogsMs、PauseAdmissionMs、FreezeBoundaryMs、SubmitOffMs、StartPowerDisableMs、OffFallbacksMs、HydraulicReleaseMs、CancelCyclesMs、PublishObserversMs，携带 Device、RunId、RunEpoch、RecoveryEpoch、CorrelationId。计时用单调时钟；日志在安全投递阶段结束后消费。

物理 OFF 未确认仍受独立短预算监督，不因 RecoveryActive 豁免。阶段计时在调用返回/抛异常后汇总；永久卡在某阶段时仍需依靠已有监督、转储及线程栈，不能指望该阶段提前产出完成耗时。

## 5. P2：写盘诊断与确定可保持语义的优化

### 5.1 分段诊断

新增 `EpbWriteTiming`，通过生产监控窗体连接到采集器已有内存诊断环，不在写盘锁中同步写日志文件：

- 每设备批次记录总时长、Device/Generation/Sequence、样本数和成功状态。
- 超过 50ms 或失败时，Detail 记录线程 ID、通道锁等待、raw gate 等待、raw 准备到提交总时长、raw Commit、索引锁等待/Commit、ring/MMF Flush、checkpoint 和 raw 回收。
- 普通批次保留数值总耗时与刷盘/提交数值，避免逐批格式化长字符串。
- CompleteCycle、AbortCycle、ExportCycleAttempt 记录操作总时长、通道/圈号、成功状态；这些操作不具备设备批次的 Sequence 身份。
- 诊断 Kind 为 `StorageWrite`，与已有 `Persistence` 队列消费总耗时区别使用。阶段存在包含关系，不能把 RawStage、Checkpoint 与其子阶段相加当成总耗时。
- 诊断回调在本次方法持有的写盘锁释放后执行；回调异常不能改变写入成功或失败的结果。外层非本方法持有的锁不在该保证范围内。

诊断覆盖进入设备写入核心及圈关闭/尝试导出；入参校验前的失败仍由已有非法批次隔离证据描述。磁盘卷 IOPS、过滤驱动与 OS/GC 调度不由这些软件阶段计时直接测得，后续现场用 ETW/磁盘性能采集与时间戳关联。

### 5.2 本次优化

- 原始日志预检沿用原有活跃圈、序列、截止、容量条件；无待写帧时跳过空事务及共享 raw gate。
- checkpoint 对同一圈的多帧只更新一次最大样本前缀，减少重复 SQLite 命令和索引 UPDATE；仍检查每个圈的索引身份存在，最大值用 checked 计算。
- 保持 FULL、先 raw 持久化、再 ring flush(true)、再索引提交、最后回收 raw 的顺序。Persisted/FIFO/重试幂等/异常圈终态规则不变。

本轮没有启用文档中要求先评估的 group commit，也没有将通道状态锁移出耐久边界；这些方案需要额外的所有权设计和掉电测试。没有降低 synchronous，也没有添加 Defender 排除。不能把上述优化描述成已证明修复了现场磁盘饱和：封存只证实存在慢写，未证实正常期持续饱和。

## 6. P3：容量事件由当前恢复收口

`DaqPersistenceQueueFull` 首次出现仍走统一安全截止/恢复。未出现 DurabilityBlocked 的容量事件，不再在 Begin 后无条件另开升级链；相同 Run 的既有设备恢复和 CorrelationId 归并机制继续使用。

实际写失败、DurabilityBlocked、恢复超时和真实数据缺口仍升级；物理 OFF 确认与恢复无进展预算仍有效。队列容量、暂停/恢复水位及数据守恒逻辑保持原值。
