# 独立兜底持续自动绑定（ACTIVE_BENCH_4）

用户只需执行一次“JXCQ启动主动接管.cmd”。它注册当前用户的安装级常驻任务，不再要求项目目录、SessionId，也不要求每次开始试验重新点击。主程序尚未运行时等待；新会话出现后自动绑定；登录后自动启动。任务入口所在候选目录必须保留。

项目发现沿用主程序配置：优先读取当前用户 `%LOCALAPPDATA%\Wanxiang\EPBTest\user-state.json` 的 `storeDir`、`testName`，组成项目目录；没有此文件时读取安装目录 `Current\MTTFTest.exe.config` 的 `InitialProjectPath`。要求项目 `Config\TestConfig.xml` 存在，然后使用其 `WatchdogSessions` 子目录。配置损坏、项目不可用或尚未保存有效项目时告警等待，不猜测历史目录，不改写主程序配置。

配置路径必须与唯一的当前安装侧车命令行一致，快照还需满足协议、Session、Run、PID、启动时间和时效校验。原恢复进程短暂失联也不被视为取得接管权。硬件接管仍由已有 FallbackGuard 协议约束，监控脚本没有硬件操作和主程序启动入口。

切换前先持久禁用旧会话，等待外部进程退出且账本为 Original/Idle、无未完成启动事务。无法证明交还时保持旧绑定并告警。先持久化绑定意图，再启用和拉起外部进程；监控异常退出后的重启先走同一调和流程。禁用开关持久保存；日志登录触发也不能重新启用它。卸载不强杀接管进程，未交还时保留任务等待用户重试卸载。

状态位于 `%LOCALAPPDATA%\MTTFTest\FallbackBindings`，按规范化安装路径的哈希隔离。状态文件带 UTC 时间，查询时应结合 TaskState 判断是否为当前状态。1 秒轮询，小 JSON 上限 64 KiB；不扫描大日志。任务使用与主程序相同用户的交互登录身份，用户注销时不会继续作为系统服务运行。

## 验证

- Windows PowerShell 5.1：自动身份绑定 10/10、生产监控循环注入 13/13。
- 注入覆盖无程序等待、同会话不重复启动、换会话、旧事务阻止切换、交还后切换、启动意图先落盘、持久禁用、异常退出遗留意图调和。
- 本地及 JXCQ 实际任务：安装后等待、重复启用不重复进程、禁用退出、再次触发不复活、卸载和精确进程退出均通过。
- JXCQ 监控等待态 Private Bytes 为 89,321,472（约 85.2 MiB）；本地为 111,255,552（约 106.1 MiB）。这是短时测量，128 MiB 为目标，长时占用与同时接管需继续验收。
- 底层 EXE/DLL 未改变，沿用源码 73525bda6eb99ac7504b4b9ea9ecf60406016be0 已完成的构建和恢复回归。本次改动只涉及部署脚本。
- 新会话切换测试采用确定性配置/进程接缝；未把等待任务存活视为真实试验恢复成功。真实硬件、实际主程序换项目接管、24 小时及 168 小时仍待验。

## 安装及回退

1. 将候选包解压到固定目录，保留完整目录结构；已有本版本主程序时无需为监控功能重复安装主程序。
2. 使用运行试验程序的同一 Windows 用户双击 `JXCQ启动主动接管.cmd`，看到“已启用常驻监控”即可。默认主程序安装目录为 `C:\Program Files (x86)\MTTFTest`。自定义安装仅需首次以 `-InstallRoot "实际目录"` 指定安装根目录，项目和会话仍自动读取。
3. 正常打开主程序、选择并保存项目、开始试验。之后重新开始或换项目无需操作独立入口。
4. 用 `查询主动接管状态.cmd` 查看等待、绑定或交还状态。停用用 `禁用主动接管.cmd`；彻底移除任务用 `卸载主动接管后台任务.cmd`。
5. 从 BENCH_3 升级时会先禁用旧会话任务，只有安全交还后才迁移。若提示等待交还，待完成后再执行一次安装。不同候选目录已注册常驻任务时先从旧目录禁用及卸载，保留账本，再启用新目录。
6. 回退监控脚本时先禁用并完成交还、卸载本任务，然后启用原候选入口；不得删除所有权账本来绕过未完成事务。本次不自动推送、不替换现场主程序。
