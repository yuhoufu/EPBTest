## 第二轮后续代码复核：定位到未收敛的停止监督投影

对当前代码与已回传 sidecar 原始事件对照，新增确认如下：

1. Controller/EpbManager.cs 的 FinalizeLogicalQuiescenceForRestartAsync 只对调用方 result 和 _lastStopSafetyResult 执行 TryCompleteLogicalCleanup。该路径没有同步更新 StopSafetyTransactionRunner 的终态投影。
2. Controller/StopSafetyTransactionRunner.cs 的 PublishTerminal 仍直接把 RequiresProcessRestart 映射为 TakeoverRequired，并保存 _lastTerminalResult。临时 LogicalCleanupPending 与真正需要进程接管的硬失败在这个投影上没有区分。
3. WatchdogHostStopMonitor 和 HostStopSafetySupervisor 把终态 TakeoverRequired 作为粘性接管事实。已有测试明确要求旧快照不能清除它，因此不能简单增加一次 false 心跳覆盖，也不能删除身份校验。
4. 现场顺序直接支持该竞争链：21:46:14.888 清场完成；21:46:15.067 新批次 f9c2d199b89d49dca1e225fab03b380a 开始预检；21:46:15.391 sidecar 发出 TakeoverRequested，原因仍为上一停止代次 Generation=1 的“Stop safety completed with restart required”；21:46:15.443 新批次收到 StopAllAdmission:SystemFault；21:46:15.446 启动取消；21:46:25.957 许可因 RecoveryLegacyAuthoritySessionOrRunSuperseded 拒绝。

修复方向：临时逻辑尾声不得提前发布不可撤销的硬接管终态；需要在原事务和原截止预算内表示“物理及保存已完成、逻辑尾声待确认”，完成后统一提交 Controller 结果与监督投影。真正超时、数据缺口、压力不确认的粘性接管仍保留。还须覆盖完成与看门狗判定并发、迟到旧代次更新、人工停止、新批次启动和旧许可请求的整链回归。此处为已定位差距及修复设计，尚未声称代码整改或测试通过。

持久化积压是另一条仍需处理的触发问题。不能因定位到监督竞争就忽略设备写入超过保护预算，也不能以延长1秒保护线作为替代。后续应从本轮 daq_timing 细分环形刷盘、RawJournal FULL提交、数据库检查点及锁等待，验证设备批处理是否覆盖真实学习入口。
