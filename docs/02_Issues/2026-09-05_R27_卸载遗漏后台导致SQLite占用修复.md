# R27 卸载遗漏后台导致 SQLite 占用修复

用户在 2026-09-05 11:02:55 使用 d87fa2a15bf1 / R26 卸载器，删除 Current/x86/SQLite.Interop.dll 时收到访问被拒绝。脚本已删除服务和计划任务，程序目录清理中断。

卸载第 3 步只调用 SessionAgent、主界面、SafetyAgent 和 Watchdog 的停止逻辑，没有处理 EngineHost；旧停止函数忽略错误且不等待进程退出。SQLite 本机模块可因此保持加载，阻止程序目录删除。本机该文件 ACL 允许管理员完全控制，未发现只读属性。读取日志后发现用户已重新安装，故本次没有直接停止或删除本机已安装环境。

## 修改

- 卸载统一停止安装目录内的五类进程，包括 EngineHost 和安装目录内旧槽位的进程。
- 核验进程路径并保留进程句柄，停止后等待最多 10 秒；权限错误、身份不明或等待超时明确报错，不能继续删程序文件。
- 目录删除仅对名称为 MTTFTest 的已解析非根目录执行，瞬时占用最多重试三次；失败说明可重试卸载，不改 ACL，不删除 ProgramData。
- 保留一次 Y/A 卸载确认，支持上次卸载已移除服务/任务后的重复运行。
- 快捷部署器升级为 R27；复用已经验证的 86797b165db6 程序包，只更新外层安装/卸载脚本及外层哈希清单，分别记录程序提交与部署器提交。
