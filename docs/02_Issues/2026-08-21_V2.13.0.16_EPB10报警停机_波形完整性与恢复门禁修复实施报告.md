# V2.13.0.16 EPB10 报警停机、波形完整性与恢复门禁修复实施报告

## 1. 发布结论

本次修复版本为 **V2.13.0.16**，针对封存数据
`D:\EPB\_Data\10358-029\_V2.13.0.15\_0821\_1750` 中 EPB10 的以下问题完成代码整改：

1. 85993 被误判为 `AbnormalHighCurrentPlateau` 并永久报警停机；
2. DAQ 中断发生在反向释放阶段后，未重新确认机械释放就开始下一正式圈；
3. 系统墙钟跳变约 1.415 s 后，落盘波形被 UTC 圈边界截掉圈头；
4. 报警文件“存在”却不包含未上电基线，仍被标为证据完整；
5. 同一次报警先后生成两个内容相近的 `Latest` 目录；
6. 二次复核发现：圈封口曾使用滞后的 `DiskPublishedSequence`，已经被采集链接纳、但尚未发布到磁盘的尾批次可能被错误排除。

### 1.1 “这个报警是否不应停机”的最终回答

需要区分“立即安全动作”和“永久报警结论”：

| 场景 | V2.13.0.16 的预期行为 |
| --- | --- |
| 85992 反向释放过程中发生 `DaqSampleStale>100ms` 或墙钟跳变 | **必须立即断电并暂停当前圈**，这是正确的失效安全动作 |
| DAQ 恢复后，机械释放尚未重新确认 | **不得开始下一正式圈** |
| DAQ 重鉴定和受控机械预释放均成功 | 允许恢复正式循环，不锁存为卡钳硬故障 |
| 85993 这种从 2.318 A 持续爬升至约 14.56 A、接近 15 A 目标的平台 | **不应判为异常高电流永久报警停机**，按快速负载上升后目标附近平台安全完成 |
| 真正超过安全阈值、持续高位无进展、双源确认过流、DO 断电失败等 | 继续执行原有硬故障停机、联锁和持久禁用策略 |

因此，V2.13.0.15 的问题不是“断电动作太保守”，而是把一个应当先暂停、恢复、重新定位的基础设施异常，最终错误归类成了 EPB10 的永久高电流硬故障。V2.13.0.16 保留立即断电，修正恢复门禁和最终故障语义。

## 3. 已实施修复

### 3.1 圈归属改为 DAQ 代次与批次序号

权威圈边界不再依赖墙钟 UTC，而是使用：

```text
Device + Generation + Sequence
```

实现位置：

- `DataOperation/EpbDiskWriter.cs:561`：新增 `BeginCycleAtDaqBoundary`；
- `DataOperation/EpbDiskWriter.cs:1508`：新增序号化批次写入；
- `DataOperation/EpbDiskWriter.cs:1867`：按 DAQ 序号封闭圈窗口；
- `Controller/EpbManager.CycleAttempts.cs:50`：正式圈开始时读取当前 DAQ generation 和最后接纳序号；
- `Controller/EpbManager.cs:863`：中止、停止、恢复和报警路径统一选择并捕获权威圈边界；
- `Controller/DaqPersistenceCoordinator.cs:989`：把设备、代次和序号传递到落盘层。

新规则如下：

1. 正式圈开始时记录 `startAfterSequence`；
2. 同一圈只接收相同设备、相同 generation 的连续批次；
3. 圈结束/作废时记录 `endSequence`；
4. UTC 仅保留作显示、目录命名和审计，不再决定样本属于哪一圈；
5. 普通封口的权威终点取 `LastAcceptedSequence`，`LastDiskPublishedSequence` 只用于诊断，不得把已接纳但尚在写盘队列中的尾批排除；
6. DAQ 恢复事故优先使用事故开始时冻结的 `PreviousGeneration + FrozenBoundary`，禁止后续新代次批次污染旧圈；
7. 同一次封口捕获的边界同时用于圈封口、Raw 排空和耐久等待；若安全路径已经以更早边界封口，后续只允许等待更强水位，不允许扩大已封闭圈；
8. 写盘线程可以在封口后补写 `sequence <= endSequence` 的已接纳尾批，严格排除 `sequence > endSequence`；
9. generation 不一致或圈内序号出现永久空洞时，拒绝伪装成完整圈。

这同时消除了“墙钟跳变后固定截掉圈头”和“Accepted 已前进但 DiskPublished 暂时滞后时截掉圈尾”两个边界错误。

### 3.2 增加 250 ms 未上电预触发波形

`EpbDiskWriter` 为每个通道保留最多 500 点短缓存。按 2 kHz 采样率折算，缓存容量为 250 ms；报警证据完整性要求至少 400 点，即 200 ms：

- 未开正式圈时持续更新预触发缓存；
- 正式圈开始时，把同一设备、同一 generation 的缓存原子写到圈头；
- 随后再接续正式上电批次；
- 预触发样本数量和最低要求写入报警元数据；
- 少于 400 点时仍保留文件用于诊断，但明确判为证据不完整，不能作为完整报警波形发布。

实现位置：`DataOperation/EpbDiskWriter.cs:234`、`:559`、`:1566`。

因此新 CSV 的预期起点是未上电基线，而不是电流已经上升到 5～14 A 后的中间位置。

### 3.3 墙钟跳变从“只记日志”升级为安全恢复事件

墙钟跳变检测阈值由 500 ms 收紧到 100 ms：

- `IO.NI/WallClockStepDetector.cs:24`；
- `IO.NI/TwoDeviceAiAcquirer.cs:3094`。

检测到跳变后，当前映射不确定批次不再进入控制和落盘链，而是发布
`DaqWallClockStep`：

```text
检测到墙钟跳变
  -> 丢弃当前映射不确定批次
  -> 受影响通道立即安全断电并冻结当前圈
  -> 当前圈以明确恢复终态封存
  -> 强制重建 DAQ task/generation 和采样时间映射
  -> 使用加严的新鲜批次数进行重鉴定
  -> 机械预释放成功后才允许重新进入正式循环
```

`DaqWallClockStep` 与 `DaqClockModelInvalid` 共用时钟故障代次锁存，避免同一 generation 重复上报。报警界面显示为“系统时间跳变，采集时间轴正在自动重建”。

注意：这不会把系统校时直接判为 EPB 卡钳硬件损坏；它属于可恢复的软件/采集基础设施事件。若重建失败或超过恢复预算，系统才保持恢复失败停机。

### 3.4 DAQ 中断后增加机械释放重鉴定门禁

当 DAQ 新鲜度故障发生在通道活动期时，系统为该通道记录
`MechanicalRequalificationGeneration`。恢复链必须按以下顺序执行：

```text
安全断电
  -> 当前圈作废
  -> DAQ generation 重建/新鲜度稳定 500 ms
  -> 程控电源恢复并验证
  -> 按电气错峰计划执行受控预释放/重新定位
  -> 释放完成判据通过
  -> 清除机械重鉴定门禁
  -> 从未来完整正式槽重新加入
```

实现位置：

- `Controller/EpbManager.cs:3563`：DAQ 安全截止时登记机械重鉴定；
- `Controller/EpbManager.cs:4844`：自动 DAQ 恢复先恢复电源，再机械预释放；
- `Controller/EpbManager.cs:6112`：后到的新鲜度恢复同样受机械门禁；
- `Controller/EpbManager.cs:6132`：机械重鉴定门禁登记和清除；
- `Controller/EpbManager.PauseResume.cs:1452`：复用已有受控机械释放实现。

这样，85992 反向释放被中断后不会再仅凭“电流已经清零”直接开始 85993。

### 3.5 修复“首个有效样本已经越过负载上升阈值”的状态机边界

`Controller/Adaptive/EpbAdaptiveControl.cs:630` 新增快速负载上升分支。

当满足以下条件时：

1. 本圈尚未形成空行程基线；
2. 历史空行程模型已经稳定；
3. 当前电流超过历史负载上升阈值；
4. 短窗口具有明确正斜率；

状态机允许从 `EmptyTravel` 进入 `LoadRise`，并记录软预警
`RapidLoadRiseWithoutObservedEmpty`。历史基线仅用于识别状态转换，不会伪装成“本圈已观察到的空行程基线”。

对于 85993 的实际序列：

| 上电后时间 | 电流 |
| ---: | ---: |
| 46 ms | 0.054 A |
| 94 ms | 1.719 A |
| 109 ms | 2.318 A |
| 283 ms | 2.975 A |
| 531 ms | 6.926 A |
| 1044 ms | 12.973 A |
| 1233 ms | 14.548 A |
| 后续平台 | 约 14.556 A |

新逻辑识别为快速负载上升，并最终按 `NearTargetPlateau` 安全完成，不再进入
`AbnormalHighCurrentPlateau threshold=7.5A`。

本修复没有提高 7.5 A 通用阈值，也没有放宽真实过流阈值。真正处于空行程状态的持续异常高平台、超过目标安全上限、双源确认过流等保护仍然有效。

### 3.6 报警证据增加“语义完整性”门禁

报警圈证据除原有文件存在、格式和样本数量校验外，新增：

- `SampleClockDevice`；
- `SampleClockGeneration`；
- `CycleStartAfterSequence`；
- `CycleEndSequence`；
- `PreTriggerSampleCount`；
- `RequiredPreTriggerSampleCount`；
- `LastWrittenSequence`；
- `SemanticEvidenceComplete`。

`Controller/DoControlTrace.cs` 将报警元数据升级为 schema 7。

对于启用序号边界的正式报警圈，只有同时满足“预触发不少于 400 点、存在明确终点、`endSequence >= startAfterSequence`、`LastWrittenSequence >= endSequence`”时，才允许 `SemanticEvidenceComplete=true`。任何一项不满足，系统都会保留精确原因并标记“文件存在但波形语义不完整”，不得继续把它写成完整报警证据。该检查解决了 V2.13.0.15 中 85993 CSV 只有断电尾部却仍显示 `alarmCycleEvidenceComplete=true` 的问题，也防止尾批未耐久就提前宣告完整。

### 3.7 报警 Latest 改为封账后单次发布

删除 `StopChannelOnAlarm` 快速停机阶段的即时 `FlushRecent(10)`。快速路径只执行断电、状态锁存和资源撤销；报警圈完成原子封账后，再由
`EnsureLatestStopSnapshotAsync` 统一发布最终包。

实现位置：

- `Controller/EpbManager.cs:2767`：禁止快速停机阶段生成临时 Latest；
- `Controller/EpbManager.cs:2956`：报警圈封账后生成最终 Latest；
- `DataOperation/EpbDiskWriter.cs:2018`：写入 `latest-manifest.json`；
- `DataOperation/EpbDiskWriter.cs:2129`：只有带 Final manifest、圈集合及文件校验一致的包才允许复用。

manifest 包含：

- `snapshotState=Final`；
- EPB 通道和存储格式；
- `requiredTerminalCycle`；
- 每圈圈号、终态和样本数；
- 每个 CSV/BIN 文件的 SHA-256。

因此同一次 EPB10 报警不会再先生成“不含 85993”的临时目录，再生成“包含 85993”的最终目录。旧版本没有 manifest 的目录也不会被误当成 V2.13.0.16 的最终幂等证据。

## 4. 修复后的完整停机逻辑

### 4.1 可恢复的 DAQ/时钟异常

```text
DAQ 陈旧或墙钟跳变
  -> 高优先级 DO OFF
  -> 冻结并作废当前正式圈
  -> 暂停受影响通道
  -> 重建/验证 DAQ generation
  -> 验证连续新鲜批次
  -> 恢复并验证程控电源
  -> 执行机械预释放/重新定位
  -> 成功：从未来完整槽续测
  -> 失败：保持暂停，按恢复失败策略升级
```

该链路会“暂时停动作”，但不会把卡钳永久禁用为高电流硬件故障。

### 4.2 确定的卡钳硬故障

```text
真实过流/持续异常高位无进展/DO断电失败/确认的硬件故障
  -> 高优先级 DO OFF
  -> 电流清零和组级安全确认
  -> 报警圈原子封账
  -> 单次发布 Final Latest
  -> 锁存 AlarmStopped
  -> 按既有策略持久禁用故障通道
```

硬故障保护路径没有被削弱。

## 7. 现场验收门禁

自动化回归已覆盖软件逻辑；正式替换 V2.13.0.15 前，仍应在实际 NI、DO、程控电源和卡钳硬件上执行以下验收：

1. 正常运行时将系统时间向前和向后调整 1.5 s；
2. 确认受影响通道立即断电、当前圈作废，并出现 `DaqWallClockStep` 恢复提示；
3. 确认重建 generation、连续新鲜批次和机械预释放完成前，不启动下一正式圈；
4. 恢复后的 CSV 必须从未上电基线开始，且没有约 1.4 s 固定截头；
5. 在反向释放阶段注入 DAQ 超过 100 ms 陈旧，验证下一圈受机械门禁阻止；
6. 回放或模拟 85993 快速负载上升波形，预期为目标附近平台完成，不得出现 7.5 A 高平台硬故障；
7. 模拟真正过流和持续高位堵转，确认仍会高优先级断电并锁存硬故障；
8. 同一次报警只允许一个 Final Latest，且必须包含报警终止圈和 `latest-manifest.json`；
9. 核对 manifest 中样本数和 SHA-256；
10. 核对报警 schema 7 中 generation、起止 sequence、`LastWrittenSequence`、预触发样本数和最低预触发要求。

验收通过标准：上述 10 项全部通过，且连续运行期间不再出现缺少未上电圈头、只有断电尾部、同一报警两个 Latest 或释放未确认即续测。

## 8. 安全边界与已知限制

1. 本次修复确认的是软件写 DO、DAQ 电流清零代理和恢复流程；现场仍没有独立的继电器物理触点反馈，因此 `PhysicalOffStatus=NotMeasured` 的证据边界保持不变。
2. 预触发语义完整性目前确保“存在同一 DAQ generation 且不少于 400 点/200 ms 的未上电圈头”，并记录可审计的起止序号和最后写入序号；机械位置仍由受控预释放流程和电流/时间判据确认，不应把电流清零单独解释为机械释放完成。
3. 如现场 HIL 验收出现 generation 切换后无预触发样本，系统将把证据标为不完整并保持安全状态。这是预期的失效安全行为，不能通过关闭完整性校验规避。

## 9. 最终判定

V2.13.0.15 的 EPB10/85993 不具备“异常高电流硬件故障”的充分证据，因此不应按该报警永久停机；但 85992 的 DAQ 中断发生时，立即断电并暂停是正确且必须保留的。

V2.13.0.16 已把两者拆分为正确的安全语义：

- **不确定时先断电、暂停、恢复和重新定位；**
- **恢复条件全部通过后自动续测；**
- **只有确定的卡钳硬故障才锁存报警停机；**
- **所有正式/报警波形按 DAQ Accepted/冻结序号归属，保留已接纳尾批并包含未上电预触发；**
- **同一次停止只发布一个可审计的 Final Latest。**
