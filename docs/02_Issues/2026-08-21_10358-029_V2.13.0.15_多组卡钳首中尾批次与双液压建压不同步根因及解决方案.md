# 10358-029 V2.13.0.15 多组卡钳首/中/尾批次与双液压建压不同步根因及解决方案

## 1. 结论先行

本次截图中的现象不是实时曲线绘制错位，也不是 15 s 周期逐圈漂移。V2.13.0.15 的正式圈仍按共同墙钟周期运行，但只保证了**每个液压组内部**的电气错峰，没有建立跨液压组的共同执行锚点。

直接原因有三项：

1. P1、P2 由各自的液压代次独立建压、独立等待压力资格；每套液压资格完成后，又各自用 `DateTime.UtcNow + 2 ms` 生成电机执行锚点。因此 P1、P2 的物理响应差异会直接传递为两个“首批”卡钳的启动差。
2. 压力建压由多个通道计时器分别进入液压协调器，不是一个全局批次 owner 同时提交 P1/P2。现场建压命令本身已有 0～33 ms 的提交差；两套液压响应和压力采样再把资格完成差扩大到 32～124 ms。
3. 当前错峰计划按“本次仍选中的组员”重新压缩编号。发生稀疏选择、启动隔离、学习失败或资格失败后，原中批/尾批成员可能被重新编号成首批，首/中/尾身份不是固定契约。

截图时的 EPB04 与 EPB10 都确实是 `Phase=0 ms`，并非配置错相位；它们实际相差 47 ms，是 P1/P2 各自资格完成、各自重新定锚的结果。

建议在下一版引入“**固定批次身份 + 全局周期槽协调器 + 双液压共同建压命令时刻 + 全部活动液压资格完成后的共同电机锚点**”。首/中/尾分别固定为 0/800/1600 ms，成员缺失时跳过对应位置，禁止把后续成员向前压缩。

```text
  -> EPB04/EPB10 虽然都是 Phase=0ms，实际启动仍跟随各自液压资格时刻
```

## 5. 源码根因

### 5.1 共同 `t0` 存在，但只是一条墙钟基准

`EpbManager.BatchStart.cs` 中先取一次 `nowUtc`，再为 P1/P2 使用相同的周期上取整算法生成 `t0OfGroup`。因此最外层周期基准本来是一致的。

问题发生在正式圈回调之后：代码按液压组分别调用 `HydraulicEnterAtGroupAnchorAsync`，没有一个跨 P1/P2 的同槽 owner。

### 5.2 两套液压分别建压、分别等待资格

`HydraulicController.BuildAndQualifyAsync` 对单个液压执行：

1. `SetPressure(hydId, true)`；
2. 写入对应 AO 压力；
3. 每 10 ms 检查一次压力新鲜度和目标窗口；
4. 连续稳定 200 ms 后返回本液压的资格结果。

P1、P2 是两个独立调用。设备写入时刻、压力上升速度、传感器刷新相位和线程调度均可能不同。

### 5.3 每个液压资格完成后各自重新定锚

`HydraulicGroupCoordinator.InitializeGenerationAsync` 在单个液压资格完成后执行：

```csharp
var actuationAnchorUtc = DateTime.UtcNow.AddMilliseconds(2);
```

随后 `EpbManager.BatchStart.cs` 使用该液压租约自己的 `ActuationAnchorUtc` 创建 `QualifiedPhaseWindow`。这会把 P1/P2 的资格差原样变成两个首批电机的计划差。

当前机制能保证**同一液压代次内部**的成员不会跨周期或挤在一起，但不能保证**多个液压组之间**的首/中/尾批次一致。

### 5.4 首/中/尾身份会被压缩重排

`ElectricalStaggerPlanner.Build` 当前先取“已选通道与组成员的交集”，按通道号排序，然后用交集中的索引计算相位：

```text
PhaseMs = selectedIndexInGroup * StaggerMs
```

启动定位、学习或资格阶段发生通道隔离后，`EpbManager.BatchStart.cs` 会用剩余通道重新构建错峰计划。例：

```text
Group2 原成员：EPB04=首、EPB05=中、EPB06=尾
若 EPB04 被隔离：当前计划会重排成 EPB05=首、EPB06=中
```

这不符合“首/中/尾是固定可观察批次”的目标，也会使恢复前后的实时曲线语义发生变化。

### 5.5 反向波形不能用统一首批锚点自然重合

EPB04、EPB05、EPB10 都采用独立自适应控制。正向启动以后，每个卡钳何时达到夹紧终点、何时进入反向释放由自身电流、斜率、预测峰值和机械行程决定。

因此，即使正向首/中/尾启动做到毫秒级对齐，反向沿仍可能相差数百毫秒。为了曲线重合而强制快卡钳等待慢卡钳，会改变机械受压时间和控制语义，不建议作为本次整改目标。

## 6. 目标时序定义

### 6.1 固定批次映射

建议把批次身份固定为配置成员位置，而不是当前选中集合中的临时序号：

| 批次 | 固定序号 | Group1 | Group2 | Group3 | Group4 | 相位 |
| --- | ---: | --- | --- | --- | --- | ---: |
| 首批 | 0 | EPB01 | EPB04 | EPB07 | EPB10 | 0 ms |
| 中批 | 1 | EPB02 | EPB05 | EPB08 | EPB11 | 800 ms |
| 尾批 | 2 | EPB03 | EPB06 | EPB09 | EPB12 | 1600 ms |

规则：

- 某成员未选、禁用或隔离时，仅跳过该位置；
- 其他成员不得向前补位；
- 同一 Run 内的 `BatchOrdinal` 不可变；
- 恢复成员只允许从下一个完整全局周期槽按原固定序号重入。

### 6.2 对齐边界

本次应对齐：

1. P1/P2 的计划建压时刻；
2. 活动液压全部资格完成后的共同电机锚点；
3. 所有电气组的首批、中批、尾批正向启动时刻。

本次不强制对齐：

- 各卡钳达到电流目标的时刻；
- 反向释放启动时刻；
- 各卡钳最终断电时刻；
- P1/P2 的物理压力上升斜率。

这些量反映硬件和自适应控制差异，应该在曲线上保留，而不是用额外等待掩盖。

## 7. 推荐控制方案

### 7.1 新增全局周期槽协调器

为每个正式圈建立不可变键：

```text
GlobalSlotKey = (RunId, PhaseKind, Slot)
```

每个槽冻结以下快照：

- 本槽活动液压组；
- 每个液压组的活动通道；
- 每个通道固定 `BatchOrdinal`；
- 共同 `PressureBuildDueUtc`；
- 共同 `MotorAnchorUtc`。

只有全局槽 owner 能发起本槽的 P1/P2 建压和批次放行。各通道计时器不再直接独立触发液压建压。

### 7.2 将“开始建压”和“等待资格”拆开

当前 `BuildAndQualifyAsync` 把输出命令与资格等待合在一个方法里，不便于多液压同步提交。建议拆为：

```text
BeginBuild(hydraulicId, dueUtc)
WaitQualifiedAsync(hydraulicId, generation, token)
```

全局槽 owner 在共同 `PressureBuildDueUtc` 对所有活动液压并发提交建压；每组仍保留自己的资格对象、压力监控、超时和安全释放逻辑。

Windows、CLR 和两块 NI 设备不是硬实时系统，不能承诺物理 0 ms 差，但可以保证相同计划时刻、同一个调度 owner，并记录实际提交偏差。

### 7.3 全部活动液压资格完成后只生成一次共同电机锚点

推荐流程：

```text
共同周期槽到期
  -> 所有活动液压同时提交建压
  -> P1/P2 分别完成自己的压力资格
  -> 等待本槽全部活动液压资格完成
  -> MotorAnchorUtc = max(所有资格完成时刻) + GuardMs
  -> 首批：MotorAnchorUtc + 0ms
  -> 中批：MotorAnchorUtc + 800ms
  -> 尾批：MotorAnchorUtc + 1600ms
```

较快液压在等待较慢液压期间继续执行现有保压监控。任何一组压力跌出允许窗口，禁止放行该组电机。

`GuardMs` 建议先取 20～50 ms，通过现场 P95 调度偏差再收敛；不要继续使用每个液压各自的 `now + 2 ms`。

### 7.4 故障和恢复策略

全局对齐不能扩大故障范围：

- 单个液压建压失败：仅隔离该液压组及其成员；健康液压不得被误判为硬件故障。
- 对齐等待必须有绝对期限，不能因故障组无限等待。
- 故障组确认隔离后，健康组从下一个完整全局槽继续，不在当前半槽补发。
- 健康组继续时仍保留固定 `BatchOrdinal`，禁止压缩相位。
- 恢复组完成 DAQ、电源、压力和机械定位预检后，只能在下一个完整槽重入。
- 任何通道不得在压力资格、新鲜度或电源许可未确认时为了对齐而上电。

### 7.5 暂停/恢复路径使用同一协调器

`EpbManager.PauseResume.cs` 当前也会按单液压租约的 `ActuationAnchorUtc` 建立窗口。批量启动、正常暂停恢复、软件自恢复和无人值守恢复必须调用同一 `GlobalSlotCoordinator`，否则初始运行对齐后，恢复路径仍会重新错位。

### 7.6 UI 增加批次标记，不修改物理控制结果

为便于人工观察，实时曲线可增加四类竖线或背景区：

- `PressureBuild`；
- `首批`；
- `中批`；
- `尾批`。

标记使用控制层记录的 `GlobalSlotId/PlannedUtc/ActualUtc`，不能根据曲线峰值反推。可选增加“按全局槽归一显示”模式，让不同周期叠加比较；原始时间轴仍应保留。

## 10. 验收标准

### 10.1 正常双液压运行

- P1/P2 的 `PressureBuildPlannedUtc` 完全相同。
- 正常负载下，实际建压命令差建议：P95 ≤ 20 ms，最大 ≤ 50 ms。
- 所有首批实际正向启动差：P95 ≤ 20 ms，最大 ≤ 50 ms。
- 中批相对首批：800 ms ± 20 ms（P95）；尾批相对首批：1600 ms ± 20 ms（P95）。
- 任一电机实际启动不得早于本槽全部活动液压资格完成和共同 `MotorAnchorUtc`。
- 连续运行至少 24 h，无逐圈累积漂移。

### 10.2 稀疏选择

- 仅选 EPB05、EPB10 时，EPB05 仍为中批 800 ms，EPB10 仍为首批 0 ms。
- 仅选 EPB06、EPB12 时，两者均保持尾批 1600 ms，不能压缩成首批。
- 缺失批次只显示为空，不影响其他组同序号成员对齐。

### 10.3 故障隔离

- P2 建压超时时，只隔离 P2 及其成员；P1 在明确的新完整槽继续。
- 健康组不得在旧半槽立即补发，也不得改变其成员 `BatchOrdinal`。
- 故障期间所有危险输出保持安全，不能为了通过对齐测试绕过门禁。

### 10.4 恢复重入

- 单通道、单电气组或单液压恢复后，必须等待下一个完整 `GlobalSlot`。
- 恢复前后同一通道的 `BatchOrdinal` 不变。
- 重入后重新满足双液压共同资格时，首/中/尾批恢复对齐。

### 10.5 人工曲线复核

- 实时图能看到共同 `PressureBuild` 标记。
- 首/中/尾三批标记在不同电气组间垂直对齐。
- 允许压力斜率、峰值时刻和反向沿存在硬件/自适应差异；不得把这些自然差异误判为调度失败。

## 11. 实施优先级

1. **P0：固定 `BatchOrdinal`，禁止稀疏选择、隔离和恢复后压缩重排。**
2. **P0：增加全局周期槽 owner，并在全部活动液压资格完成后生成唯一 `MotorAnchorUtc`。**
3. **P0：所有启动/暂停/恢复入口统一使用该协调器，保留现有安全门禁和液压故障隔离。**
4. **P1：拆分液压建压提交与资格等待，压缩 P1/P2 建压命令差。**
5. **P1：补齐全局槽和批次日志、自动化测试与 24 h 现场验收。**
6. **P2：实时曲线增加 PressureBuild/首/中/尾标记和按槽归一观察模式。**

## 12. 最终判断

V2.13.0.15 当前实现的真实语义是“同一液压组内部错峰、不同液压组独立资格后各自起跑”，而不是“所有电气组按首/中/尾三批全局起跑”。截图和 47 圈日志都与该实现完全一致。

要满足人工观测目标，不能只调小 `StaggerMs` 或改 UI 曲线；应固定批次身份，并把共同锚点提升到跨 P1/P2 的全局周期槽。与此同时，反向沿和压力上升斜率属于真实机械差异，应保留并通过批次标记辅助观察，而不应为了视觉重合改变自适应控制过程。
