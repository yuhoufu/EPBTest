# V2.13.0.38 Watchdog 关闭事务修复实施及验收

## 结论

V2.13.0.37“多次点击主程序右上角 `×` 仍无法退出”的 Watchdog 关闭事务缺陷已按计划完成代码修复，并将研发候选版本统一提升为 **V2.13.0.38**。

本次整改把两个此前混用的概念拆开：

- `Closing` 是禁止重拉、禁止重连的关闭围栏，不是 Sidecar 立即退出的终态；
- `Terminal`、`StopCompleted`、明确应用退出、legacy revocation 或 Closing owner 已退出，才允许 Sidecar 发布终态并结束。

真实 Runtime、真实 Sidecar 和 NamedPipe 两轮回归已经证明：Sidecar 在 `Closing` 后等待超过 1 秒仍保持原权威进程且不重拉，收到 `PhysicalStopConfirmed → StopCompleted` 后 journal 发布 `ManualStopCompleted`，Runtime 第二阶段关闭复用原 Closing v1 围栏并推进到 Terminal v2，未再出现 `ShutdownIdentityMismatch`。

当前结论是：**软件侧研发验证通过，尚未达到生产放行条件。** 本次没有创建 Git tag、提交、正式生产包或发布批准记录；NI/CAN/液压/程控电源真机验证以及 100 次现场退出循环仍待执行。

关联根因与现场证据见 [V2.13.0.37 主程序退出被 Watchdog 身份门禁阻止分析](./2026-08-30_V2.13.0.37_主程序退出被Watchdog身份门禁阻止分析.md)。原分析文档及 `截图/V2.13.0.37_退出问题/` 未作修改。

## 代码实施

### Runtime 关闭事务

主要修改位于 `MTTfTest/WatchdogRuntime.cs`、`MTTfTest/ShutdownRetention.cs` 和 `MTTfTest/WatchdogRuntime.CallbackPipeline.cs`。

新的关闭顺序如下：

1. 冻结当前 `RuntimeTransportSessionContext`，拒绝 active context 引用替换；
2. 若已有 tombstone，先校验 SessionId、Generation、Lease 以及非空的停止事务、Run 和 boundary 身份；
3. 新围栏通过 Engine 原子 CAS 标记精确 SessionId/Generation/Lease 为 Closing；
4. Runtime context、callback pipeline 和 ingress gate 进入 Closing；
5. 写入 Closing tombstone v1；普通 Closing 不再写 legacy `.revoked`；
6. 同一上下文已经 Closing 且存在同一耐久事务时，复核公开三元身份或 Engine 已 detach 事实后复用原 tombstone，不再重复 Engine 内部连接代际 CAS，也不增加 StateVersion；
7. Engine、pipeline、journal 均完成后，把 tombstone 推进为 Terminal v2，再发布 legacy 兼容撤权。

不同 SessionId/Generation/Lease、不同停止事务或不稳定 Runtime context 仍返回 `IdentityMismatch`。该分支不会调用 Engine shutdown 或关闭替代会话，原有 ABA fail-closed 防护保留。

tombstone 双写失败仍返回 `TombstonePersistenceFailed`，并尝试写本机/项目 legacy marker 作为安全撤权回退；该错误不被误标为可退出终态。

`NotifyRunStopped`、`NotifyRunCompleted`、`NotifyApplicationClosing` 现在都捕获一个冻结 context，并用同一 context 完成围栏、journal 和生命周期帧发送，避免在调用过程中重新捕获到其他会话。

### Sidecar 生命周期

主要修改位于 `MTTFTest.Watchdog/WatchdogHost.cs`。

| 关闭证据 | 活动 NamedPipe | 主进程存活 | Sidecar 动作 |
| --- | ---: | ---: | --- |
| 无证据 | 任意 | 任意 | 正常监督 |
| Closing | 是 | 是 | 撤销 relaunch/reconnect permit，记录 `ClosingFenceObserved`，继续保持管道 |
| Closing | 否 | 任意 | 作为遗留/不可恢复的关闭会话发布终态，不恢复旧会话 |
| Closing | 是 | 否 | 记录 `SessionClosingOwnerExited` 并发布终态 |
| Terminal | 任意 | 任意 | 发布/保持终态并结束 |
| legacy `.revoked` | 任意 | 任意 | 保持兼容的立即终态语义 |

Sidecar 启动时发现遗留 Closing 会记录 `ClosingSessionObservedOnStartup`，撤销 relaunch permit并结束该旧会话。`RunStopped` 和 `RunCompleted` 不再直接取消 Sidecar；`StopCompleted`、`ApplicationClosing`/`ShutdownExpected` 等明确退出协议仍负责发布终态。

### UI 与诊断

主要修改位于 `MTTfTest/MainWatchdogUiLifecycleAdapter.cs` 和 `MTTfTest/Main_Frm.WatchdogUi.cs`，没有修改任何 `*.Designer.cs` 或新增控件。

- 关闭任务进行中时，多次点击 `×` 仍加入同一 Main-owned 关闭任务；
- 真正的 `ShutdownIdentityMismatch` 保持 fail-closed，但不再无意义地重复等待剩余 15 秒；
- 主窗口标题显示“退出受阻：Watchdog会话身份冲突，请导出诊断包”；
- 日志补充 expected/current SessionId、Generation、Lease、Engine active/attached、context 稳定性和引用一致性、tombstone state/version/identity；
- 非粘滞的 journal/archive 收口仍保留原有有界重试路径。

## 新增及强化的测试

### 真实 Runtime + Sidecar + NamedPipe

`Tests/AdaptiveControlTests/WatchdogRuntimeShutdownRetentionProductionTests.cs` 新增两轮端到端用例，实际覆盖：

- 创建真实 Runtime session并达到 exact Attached；
- `ManualStopIntent` 建立 Closing v1；
- 同一停止事务重复进入仍复用 v1；
- Closing 和 `RunStopped` 后等待，Sidecar 不退出、不替换、不写 legacy revoked；
- Sidecar journal 出现 `ClosingFenceObserved`；
- `PhysicalStopConfirmed → StopCompleted` 后 manifest 含 `ManualStopCompleted`；
- StopCompleted 导致 pipe EOF 后，Runtime shutdown 仍复用原围栏；
- tombstone 最终为 Terminal v2，事务身份保持不变；
- 连续两轮使用不同 SessionId，不继承上一轮授权或 retained failure；
- 两轮均无 `ShutdownIdentityMismatch`。

该测试在整改过程中先复现了旧竞态：公开 SessionId/Generation/Lease、active lease 和 context 引用全部一致，Sidecar EOF 后第二次 Engine CAS仍返回 `ShutdownIdentityMismatch`。据此完成幂等复用修正后，用例通过。

### 安全反例与策略矩阵

- Host integration 新增 `Closing` 活动保持、启动遗留 Closing、owner 退出、Terminal、legacy revocation 和无围栏六类判定；
- Runtime retention 继续验证 IdentityMismatch sticky owner 不调用 Engine/pipeline，且 UI 可识别为 sticky blocking failure；
- tombstone 持久化失败继续阻止 DetachedRetained/Terminal 放行，并不被误分类为身份冲突；
- transport-hardening 的 recovery exact authority/session CAS、旧 lease/generation、Shutdown/Begin ABA、新会话隔离和 guarded send 测试继续通过；
- active replacement 在旧 owner 完成前仍被 retention install gate 阻止。
