## 1. 结论

V2.13.0.39 已把 V2.13.0.38 的故障链从“管道发送超时后状态分裂”改造成可恢复、可证明、可退出的闭环：

1. Watchdog 发送超时现在按冻结的精确连接身份只断开一次，并进入唯一重连；发送 Worker 不再冒充 monitor/reconnect Worker；
2. 重连只允许附着原 Session/PID/start/nonce，成功后立即发布最新状态快照，旧 Writer、旧连接代际和迟到任务不能污染新连接；
3. 人工暂停的 Run、命令、安全证明和阶段进度耐久双写，Sidecar 即使断管也能看到 `Completed`/`Resumed`，不再依据断线前快照误杀主程序；
4. 停止围栏升级为 schema v2，物理安全、压力安全、数据落盘、逻辑静默和终态分阶段单调推进；“精确会话已断开”与真实 ABA 身份冲突已经分离；
5. 正常停止完成后 Sidecar 直接发布终态并退出，不杀主程序、不重启监控界面；
6. 异常停止采用耐久安全交接。主 UI 在数据边界、授权撤销、回调隔离和硬件资源释放成立后可以退出，Sidecar 继续监督无界面单次安全 Worker 到安全终态；
7. 监控窗口关闭、人工停止、主窗口关闭和 Watchdog 关闭加入同一精确会话 single-flight；重复点击不会重复执行 `StopAll`；
8. 监控关闭超过 250 ms 时动态显示 Marquee 进度遮罩；关闭链不再以模态错误框永久扣留窗口；
9. 新试验与应用退出使用不同许可：重新开始保持严格 fail-closed，应用退出可接受完整终态或已经耐久接受的安全交接；
10. 主程序、Controller、Watchdog Host/Client/Protocol 和 ClickOnce 版本统一为 `2.13.0.39`，线协议固定为 v4。

本轮没有通过扩大超时、放松 ABA 校验或强杀 Watchdog 来换取表面退出。正常路径仍要求完整安全终态；异常路径只把 UI 生命周期与硬件安全执行 Owner 分离，硬件状态未知时禁止新试验，Sidecar/安全 Worker 继续负责断能和卸压。

## 3. 传输层闭环

### 3.1 精确断线来源与不可变作用域

`Watchdog.Client` 新增内部可注入写入端口、断线来源和冻结作用域：

- `IWatchdogPipeWritePort`：生产默认实现保持原公共构造兼容，测试可注入一次性写阻塞；
- `TransportBreakOrigin`：区分 Send、Reader、Monitor、Reconnect；
- `TransportBreakScope`：冻结 Session、连接代际和实际连接对象；
- 断线关闭采用精确对象/代际 CAS，重复故障只由第一个调用者关闭连接并发布 `TransportLost`。

V2.13.0.38 的直接缺陷是发送超时把发送队列 Owner 送进只认可 monitor/reconnect Worker 的身份门禁。V2.13.0.39 不再进行这种跨职责身份比较：发送路径只证明“我持有当前精确连接作用域”，monitor/reconnect 仍证明自己的 Worker lease，两类证据互不冒充。

500 ms 生产写入截止没有被放大。超时后的目标序列为：

```text
TransportLost
  → ReconnectStarted
  → Reconnected（原 Session/PID/start/nonce）
  → ImmediateStateSnapshot（最新心跳）
```

重连完成前的旧 Writer、旧 ACK、旧连接代际和迟到任务全部受精确 CAS 隔离；新连接附着后立即捕获当前 heartbeat，不等待下一常规心跳周期，因此 Sidecar 不会继续以断线前的暂停阶段做判断。

### 3.2 确定性故障注入

新增测试写入端口对第一次写入分别阻塞 600、750、1000 ms。三档均验证：

- 只发生一次精确连接关闭；
- 只存在一个重连监督；
- 重连仍是同一权威会话；
- `ImmediateStateSnapshot` 只发布一次；
- 迟到旧 Writer 不得写入新连接。

## 4. 人工暂停与继续

### 4.1 不可变进度快照

`ManualPauseProgressSnapshot` 在原阶段信息之外增加：

- RunId、RunEpoch；
- PauseCommandId；
- 电机断能、电源关闭、压力安全和持久化边界证明；
- 单调 ProgressVersion；
- `Resumed` 终止阶段。

Controller 在 `CurrentCycleDrain → PhysicalOffConfirm → PersistenceDrain → Completed` 以及继续试验的 `Resumed` 每次推进时发布克隆后的不可变快照。暂停安全边界现在明确执行：

1. 等待当前圈收口；
2. 电机停止；
3. 关闭供电；
4. 液压释放；
5. 数据持久化边界；
6. 发布 `Completed`。

继续试验仍属于同一批次，不创建新 RunId/RunEpoch；由既有恢复链重新使能授权硬件、DAQ 和曲线数据源。

### 4.2 耐久暂停凭证

新增 `WatchdogManualPauseReceipt` schema 1。Runtime 把每次阶段推进双写到：

- 本机 Watchdog 会话目录；
- 项目 `WatchdogSessions` 目录。

文件名为 `session-<sessionId>.manual-pause.json`。Store 只接受同一精确 Session/Generation/Lease、同一 Run/命令和递增 revision；读取时从两个副本中选择最新有效记录，单侧损坏不会把新状态回退为旧状态。

Sidecar 每 250 ms 先读取 Closing、handoff 和 manual-pause 凭证，再处理管道活性。`Completed`/`Resumed` 会取消旧暂停接管；任何耐久停止意图优先于旧暂停快照。

## 5. 停止围栏 schema v2

### 5.1 单调安全阶段

`WatchdogClosingTombstone` 保留原 `Closing/Terminal` 外层状态，同时升级到 schema 2，增加：

```text
ClosingIntent
  → PhysicalSafe
  → DataDrained
  → LogicalQuiescent
  → Terminal
```

凭证携带 StopSafetyTransactionId、安全 Owner、handoff ID，以及电机、电源、压力、持久化、逻辑静默和数据连续性证明。所有推进要求：

- Session/Generation/Lease 完全一致；
- Stop 事务完全一致；
- revision、外层状态和 SafetyStage 单调；
- 同 revision 只允许字节语义一致的幂等重试；
- 不允许从 v2 回退到 v1。

旧 schema v1 仍可读取，但无论它的外层状态是否写成 `Terminal`，都只映射为 `ClosingIntent`，不能成为硬件安全完成证明，也不能让 Sidecar 误退出。

### 5.2 精确断开不是 ABA

Client/Runtime 增加四类精确关闭结果：

- `Marked`；
- `ExactSessionDetached`；
- `NoEngineSession`；
- `IdentityMismatch`。

当 Session/Generation/Lease 一致而连接代际已被清除时，Runtime 以 `ExactSessionDetached` 写入耐久关闭意图；只有实际精确身份不一致才返回 `IdentityMismatch`。这样既修复断管后无法封口，又保持真实 ABA fail-closed：旧窗口/旧进程不能关闭替换后的新会话。

StopAll 的阶段事件持续推进 v2 围栏；只有电机、电源、压力、持久化和逻辑静默全部确认，才允许写入 `Terminal`。NamedPipe 即使不可用，Sidecar 也能从耐久记录看到正常终态并退出。

## 6. Sidecar 策略

### 6.1 人工路径与无人值守路径分离

人工暂停、人工停止和应用退出不再拥有自动续跑或完整 UI 重启权限。Sidecar 在提示、发送 StopAll、dump、终止进程、启动 Worker和发布终态前，都会重新读取最新耐久凭证：

- 已有 Closing 意图：取消旧暂停接管并禁止 relaunch；
- 已有安全 `Terminal`：发布终态并退出；
- 已有 handoff：进入安全交接监督；
- 暂停 `Completed/Resumed`：取消旧暂停接管；
- 真实普通无人值守崩溃且没有人工凭证：继续沿用原 relaunch permit 和恢复入口。

人工暂停/停止路径不再调用 `LaunchIdleRestart`，不杀主程序来“换一个空闲界面”。正常停止也不启动恢复进程。

### 6.2 有界安全交接

新增 `WatchdogSafetyHandoffReceipt` schema 1，状态严格单调：

```text
Requested → Accepted → WorkerStarted → Completed
```

凭证包含：

- Session/Generation/Lease；
- HandoffId 和一次性 nonce；
- StopSafetyTransactionId、RunId/RunEpoch；
- 已完成/缺失安全位；
- Sidecar/Worker PID 与 start ticks；
- 持久化完成、运行授权撤销、回调隔离、硬件资源释放证明；
- 尝试次数、revision、时间戳与最终细节。

主程序在正常收口无法形成完整进程内终态时，请求耐久 handoff。只有以下本进程边界已成立，`Accepted` 才能授权 UI 退出：

- 持久化边界完成；
- 运行授权已撤销；
- 硬件回调已隔离；
- 本进程硬件资源已释放。

这不是“硬件已安全”的伪证明。电源/压力仍未确认时，责任被明确转交给仍存活的 Sidecar 和安全 Worker；新试验始终保持禁止。

Sidecar 等旧主进程退出后才启动 Worker；Worker 失败时按 250/1000/5000 ms 封顶退避重启，没有“放弃安全动作并恢复试验”的总截止。Sidecar 必须观察 `Completed` 后才能发布 `SafetyHandoffCompleted` 并退出。

## 7. 无界面安全 Worker

`Program.Main` 在创建任何 WinForms 对象和单实例门禁之前识别：

```text
--watchdog-safety-shutdown <sessionId>
--handoff-id <handoffId>
--handoff-nonce <nonce>
```

`WatchdogSafetyShutdownWorker` 的执行边界为：

1. 以每个 handoff 独占 Mutex 防止重复 Owner；
2. 读取并校验同一精确 Session/Generation/Lease、handoff ID/nonce 和至少 `Accepted` 的凭证；
3. 加载冻结项目配置；项目路径不可用时只回退到应用 Config；
4. 对所有配置通道/电源组/液压组幂等执行 DO OFF、电源关闭、AO 归零；
5. 使用新鲜、连续稳定的压力回读确认安全；
6. 写入 Worker 身份、最终安全位和 `Completed`；
7. 退出进程。

Worker 不创建 `Main_Frm`、监控窗口或完整恢复 UI，不恢复试验，也不接收普通启动授权。

## 8. UI 与退出闭环

### 8.1 单一 Stop/Close Owner

人工停止、监控窗口 `×`、主窗口 `×` 和 Watchdog 请求统一加入同一精确会话 `StopSessionReceiptOwner`。多次点击只等待已有任务，不重复执行 StopAll、Flush 或 Watchdog shutdown。

`StopSessionReceipt` 明确拆分：

- `CanStartNewSession`：要求 `StopSafety.CanRestartInProcess`、匹配的退出意图、精确 Watchdog 完整终态和 UI 资源释放；
- `CanExitApplication`：要求持久化边界、UI/硬件资源释放，并接受精确 Watchdog 终态或精确、耐久、已接受的安全交接。

因此“可以退出旧 UI”不再等价于“可以重新上电”。压力、持久化、逻辑静默或 Watchdog 新会话条件任一缺失时，都不能开始新试验。

### 8.2 关闭进度遮罩

新增 `FrmEpbMainMonitor.CloseOverlay.cs`，没有修改任何 `Designer.cs`。关闭任务超过 250 ms 后才动态创建半透明遮罩和 Marquee 进度条，阶段文字依次反映：

- 电机停止；
- 供电关闭；
- 液压卸压；
- 数据保存；
- Watchdog 释放；
- 窗口关闭。

关闭链路不弹出会阻止退出的模态错误框。异常写入运行日志/诊断并自动尝试耐久安全交接；持久化边界本身未完成时仍 fail-closed，不伪造退出授权。

### 8.3 主窗口快速退出

监控窗口完成关闭后生成精确 `ApplicationCloseReceipt` 并交给 Main 缓存；创建新会话时立即撤销。若监控已关闭且回执仍匹配当前精确会话，主窗口再次点击 `×` 只刷新日志并关闭，不重复等待 StopAll 或 Watchdog。

`Program.Main` 的 finally 同样检查该回执，避免窗口已完成安全关闭后又执行一次 Watchdog shutdown。现场性能目标保持为监控已关闭后主窗口 1 秒内退出。

真实 ABA 替换仍阻止旧窗口触碰新会话，但旧窗口在释放自身资源后不会因为无法终止新会话而被永久扣留。

## 14. 现场验收方案

### 14.1 前置条件

1. 将当前改动审查后形成干净 commit；
2. 在同一 commit 上重新执行正式 `Build-Release.ps1`；
3. `Verify-Release.ps1 -RequireDeploymentApproved` 必须通过；
4. 现场只从不可变正式候选目录启动；
5. 标题、SESSION 和运行身份必须显示 V2.13.0.39 且包已批准；
6. 先做空载/单通道，再扩大到计划通道和 100 轮循环。

### 14.2 100 轮暂停—继续

每轮记录 SessionId、RunId、RunEpoch、PauseCommandId、暂停/恢复时间和通道计数。通过标准：

- 暂停完成时电机、电源和液压处于安全态，数据边界完成；
- 点击继续后沿用同一 RunId/RunEpoch；
- 机械完成次数和剩余次数连续，无回退、跳号或重复；
- DAQ 和实时曲线恢复，无空曲线；
- Sidecar 不误杀、不重启 UI；
- 无 `ManualPauseHardDeadlineExceeded`、`ManualPauseIdleRestartLaunched`、`ShutdownIdentityMismatch`。

### 14.3 100 轮暂停—停止—关闭

每轮按“运行 → 暂停 → 停止 → 关闭监控 → 关闭主程序”执行。通过标准：

- 所有电机 OFF；
- 四组电源 OFF 且回读确认；
- 压力低于安全阈值且样本新鲜、连续稳定；
- Raw/SQLite/项目日志完成持久化边界；
- 正常路径 Sidecar 有界退出，无新完整 UI；
- 监控关闭期间 UI 可响应，超过 250 ms 显示进度；
- 重复点击 `×` 不产生第二次 StopAll；
- 监控关闭后主窗口 `×` 目标 1 秒内完成；
- 无残留主程序、Sidecar 或安全 Worker。

### 14.4 异常安全交接

分别强制电源 OFF 确认超时和压力安全确认超时：

- 主程序不得伪造完整安全终态；
- 数据边界、授权撤销、回调隔离和硬件资源释放后写 `Requested`；
- Sidecar 精确写 `Accepted`，旧主进程退出后启动无界面 Worker；
- 现场不出现监控窗口或自动续跑；
- Worker 可按退避重试，最终写 `Completed`；
- Sidecar 在 `Completed` 后退出；
- 整个过程禁止创建新试验会话。

### 14.5 ABA 与故障注入

- 真实替换会话后让旧窗口发起关闭，必须只能释放旧窗口自身资源，不得关闭新会话；
- 暂停期间注入 600/750/1000 ms Watchdog 写阻塞，必须同权威重连并立即上报最新阶段；
- 在暂停硬截止前后并发触发人工停止，Closing 意图必须压过旧暂停快照；
- 损坏本机 pause/handoff 副本，必须从项目副本恢复最新 revision；
- 断开项目盘，验证本机凭证继续保护安全状态，项目盘恢复后不发生 revision 倒退。

## 15. 放行与回滚边界

### 15.1 放行条件

同时满足以下条件才可改变“未生产放行”结论：

- 正式候选来自干净 commit；
- 包身份、逐文件哈希和配置集合验证通过；
- 两组各 100 轮现场循环通过；
- 异常安全交接和 ABA 故障注入通过；
- 无禁止事件和残留进程；
- 保存现场日志、WatchdogSessions、运行数据库和验收记录。

### 15.2 回滚

若现场发现以下任一情况，立即停止扩大试验并封存证据：

- 电机、电源或压力安全项无法确认；
- Sidecar 在正常停止后重启完整 UI；
- `ManualPauseHardDeadlineExceeded` 在已完成暂停后仍出现；
- `ShutdownIdentityMismatch` 把精确断开误判为 ABA；
- 监控窗口或主窗口再次永久受阻；
- 新试验越过不完整终态；
- 包身份为 missing/not approved/mismatch。

回滚不允许以强杀 Sidecar 作为常规策略。先确认物理安全、保存凭证和日志，再切回上一受控生产版本。
