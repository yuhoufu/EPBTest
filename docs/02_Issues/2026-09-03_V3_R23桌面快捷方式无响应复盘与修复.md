# V3 QUICKDEPLOY_R23 桌面快捷方式无响应复盘与修复

## 结论

`D:\Users\L\Desktop\MT EPB 试验系统 V3.lnk` 本身存在、目标和参数也正确。
“双击无反应”是 Supervisor 启动编排缺陷：安装后 Recovery Kernel 已先启动唯一
`MTTFTest.EngineHost.exe`，桌面入口又无条件申请启动第二个 EngineHost；SessionAgent
正确执行单实例保护并返回 `ProcessRoleAlreadyRunning:EngineHost`，但 launcher 是后台进程，
错误没有显示到桌面，因此表现为界面不出现。

R23 不再用于现场启动验证。修复后的快捷部署修订为 `QUICKDEPLOY_R24`。

## 现场证据

- 快捷方式目标：`C:\Program Files (x86)\MTTFTest\Current\MTTFTest.Watchdog.exe`
- 参数：`--launch-main --main-executable "C:\Program Files (x86)\MTTFTest\Current\MTTFTest.exe"`
- Supervisor 服务：`Running`
- SessionAgent：运行中
- EngineHost：PID `73232`，已于 `2026-09-03 22:35:25` 消费 EngineHost capability
- UI：没有 `MTTFTest.exe` 进程
- 按快捷方式参数直接复现：退出码 `2`
- 精确拒绝原因：`SupervisorMainLaunchRejected:ProcessRoleAlreadyRunning:EngineHost`

这说明问题不在快捷方式路径、UAC、安装目录或主程序缺失，而在 Supervisor 把“显示界面”
错误地实现成了“总是新建硬件宿主后再显示界面”。

## 修复

`SupervisorServiceRuntime.LaunchMainThroughSessionAgent` 的初始 UI 启动流程改为：

1. 先通过 schema 7 命名管道读取在线 `EngineStateSnapshot`；
2. 快照结构有效时，精确复用其 `SessionId + RunId + RunEpoch`；
3. 只为 `ProcessRole.UserInterface` 签发一次性 capability，不启动第二个 EngineHost；
4. 只有不存在可通信的有效 EngineHost 时，才创建新 Session/Run 并启动 EngineHost；
5. UI 仍由 Supervisor 监控，异常退出后单独重启，不影响 EngineHost；
6. 恢复 UI 启动也不再把 `RunEpoch` 固定为 `1`，而是使用 EngineHost 的真实 epoch。

即使 EngineHost 因硬件初始化失败处于 `SafeIdleAlarmed`，也必须复用它并打开 UI 显示告警；
不得因 `HardwareInitialized=false` 再启动第二个硬件宿主。
