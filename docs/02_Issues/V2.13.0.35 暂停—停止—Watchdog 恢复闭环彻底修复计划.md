# V2.13.0.35 暂停—停止—Watchdog 恢复闭环彻底修复计划

## Summary

- 单版迭代至 `V2.13.0.35`，一次修复暂停所有权、DAQ 幽灵屏障、Stop 回执复用、Watchdog 不可逆关闭及恢复子进程卡住整条因果链。
- 保持“输出 OFF 优先”原则；任何身份冲突、持久化失败或恢复异常均失败关闭，不恢复上电授权。
- 交付状态为候选版：代码、自动化和本机真实双进程验证完成；现场 100 轮及 8 小时长稳保留为正式放行门槛。

## Implementation Changes

### 1. 暂停事务与恢复终态

- 将现有 `BatchPauseSnapshot` 扩展为包含 `RunId、RunEpoch、PauseGeneration、CommandId、FrozenChannels` 的不可变暂停事务；从 `PausePending` 到 `Paused/ResumeChecking` 始终沿用同一身份。
- 通道状态补充暂停代次和命令身份；暂停安全边界完成后，在 `_daqRecoveryCommitGate` 内逐通道复核：
  `TimerActive + RunnerActive + FormalPhaseCommitted + Energized=false + 无恢复 Owner + 代次一致`。
- 引入 `RecoveryExitDisposition`：
  `RejoinedRunning、HeldForManualPause、SafeIdleFault、Superseded、CancelledByStop`。
- 电源/DAQ 恢复遇到精确 `PausePending/Paused` Owner 时提交 `HeldForManualPause`，保留 Timer、Runner 和 Formal 参与者，不再由通用 `finally` 写成 `PowerRecoveryTerminalWithoutRejoin/StartBlocked`。
- 若暂停边界发现运行载体丢失或恢复 Owner 未收口，不发布 Paused；整批只执行一次 `PauseSafetyFailed → StopAll`，UI 显示“已安全停止，暂停未完成”。

### 2. DAQ 恢复屏障

- 分离“事故关联设备”和“实际恢复参与者”：屏障只接收已成功创建 `DaqAutoRecoveryContext` 的设备。
- 新增 `DaqRecoveryParticipantToken`，状态只能单调进入 `Ready、Withdraw(reason)、Terminal(error)`；令牌在 `finally/Dispose` 中必须终结。
- 批次出版期间开放注册，全部事故提交后封口；未取得上下文的设备立即记为 `NoRunnableContext`，不进入 Expected。
- `HeldForManualPause` 作为中性 Withdraw；暂停恢复不等待运行态共同槽。
- 屏障日志持久化 Run/Correlation、Registered、Ready、Withdrawn 和 Terminal 快照；保留 10 秒超时仅作最终保险。

### 3. StopAll 与人工退出意图

- `StopSafetyResult` 增加并完整克隆：
  `SafetyTransactionId、RunEpoch、SafetyBoundaryGeneration`。
- 所有成功、失败、超时和复用路径统一从 `StopSafetyProgressSnapshot` 写入上述身份。
- 新增 `ManualExitIntentReceipt`，采用同 Run/RunEpoch/安全代次且已满足物理断能、持久化和逻辑终态的 Stop 回执，不再要求原始 `Source == ManualUi`。
- 保留原始触发来源用于审计；SystemFault StopAll 后再点击停止、关闭监控和关闭主窗，共用同一安全事务及 `StopSessionReceipt`。
- 新 Run 启动前撤销旧人工退出回执；任何旧 Run/旧代次回执均拒绝复用。
- Watchdog 收口异常时保持自动恢复撤权，UI 显示“设备已 OFF，监督会话关闭待重试”，不再提示“等待 Watchdog 自动接管”。

### 4. Watchdog 不可逆关闭

- 在协议层新增原子 WriteThrough 的 `WatchdogClosingTombstone`，记录 SessionId、Generation、Lease、关闭意图、Stop 安全事务、状态版本及终态原因；同时写本地与项目会话目录。
- 新增身份绑定的 `BeginSessionCloseExact`：
  - 精确匹配 SessionId/Generation/Lease；
  - 建立持久化 tombstone；
  - 在 Engine Gate 内置 `_sessionClosing`，撤销/阻止 Launch、Connect、Reconnect；
  - 保留当前管道生命周期发送通道。
- 人工停止顺序固定为：
  `启动 StopAll → 建立 Close Fence → ManualStopIntent → 等待安全回执 → PhysicalStopConfirmed/StopCompleted → Sidecar 终态证据 → Engine/回调/Journal 收口`。
- `IdentityMismatch` 和 `TryDetachActive` 失败只能形成可重试的 retained receipt；tombstone 与 Launch 撤权不可回滚，也不得提前释放 UI。
- Sidecar 构造后、打开管道前读取 tombstone、revocation marker 和 terminal manifest；同 Session 已终止则撤销活动 RelaunchPermit、记录 `TerminalSessionObservedOnStartup` 并立即退出。
- 恢复现有 Journal 时保留 `ManualStopRequested`，禁止新 Sidecar 将人工终态重置为 false。
- 将 closing 文件纳入 Journal 校验、清理和容量策略；旧 `.revoked` marker 继续兼容。

### 5. 恢复许可有界终态

- 在 `DurableRelaunchPermitState` 末尾新增兼容值 `RejectedNoWork`，作为不打开熔断、不计恢复失败的终态；更新 V4 校验、序列化和迁移逻辑。
- Sidecar 发放许可及 `Process.Start` 前均复核关闭 tombstone、撤权 marker 和耐久检查点；已解除武装时直接提交 `RejectedNoWork`，不创建主程序。
- 子进程保留 `TryConsumeWatchdogRecovery` 二次校验，并新增独立 `RecoveryBootstrapOutcome`：
  `RecoveryAccepted、RejectedNoWork、StartupFailed、RecoveryUiAttached`。
- bootstrap 回执绑定 Session、Permit Generation/Id、子进程 PID/start ticks、检查点 revision，并使用 PermitNonce 计算 HMAC；原子落盘后由 Sidecar 验证。
- Sidecar同时观察回执和精确子进程句柄；未 Attach 前退出须在 5 秒内进入 NoWork/FailedTerminal，撤销许可并关闭覆盖窗。
- 覆盖窗统一使用 `Stopwatch + 固定 Deadline`；剩余时间持续递减，终态后不得继续显示“主程序正在加载”。

## Interfaces and Compatibility

- 对外控制模型仅做加法：`StopSafetyResult`、通道暂停身份字段及诊断快照保持现有成员兼容。
- Watchdog 协议增加 closing tombstone、bootstrap outcome、`RejectedNoWork` 和精确关闭回执；主程序、Client、Protocol、Sidecar 必须同包升级。
- V35 可读取既有合法 V4 记录；V35 产生新状态后不支持用 V34 对同一活动 Session 降级恢复。
- 不引入第二套接管管道；终态消息继续使用现有生命周期专用发送队列。
