## 1. 更新前检查

1. 确認主程序安装路径、版本、PID/启动时间和项目为上述目标。
2. 记录六个启用通道4、5、7、8、9、12的机械次数、正式提交、RunId和RunEpoch，以及最近报警。
3. 对照交付SHA-256核对7z；解压后运行包内 `Install-AutomaticRecoveryBundle.ps1 -Mode ValidatePackage`，确保逐文件校验通过。
4. 确认磁盘、可用内存、提交额度充足，无当前安全接管或未完成落盘。实时数值显示为0的旧缺陷不能用于证明电流或压力安全。
5. 不删除项目数据，不重置次数，不复制候选Base中的试验参数覆盖现场配置。

## 2. 安全停止与退出

1. 在正在运行的监控窗口点击“停止试验”。运行中直接关闭会被拒绝，这是既定安全行为。
2. 等待该停止事务的电流断电、程控电源关闭、液压释放、数据保存和逻辑收口完成。值缺失、过期、压力未释放或后台落盘未完成时，停止更新操作。
3. 正常关闭主程序；允许后台保存继续完成，不按固定30秒强杀。
4. 核对匹配该PID和启动时间的 application-exit 回执：GracefulCompleted，MotorsOff、PowerOff、PressureSafe、PersistenceDrained、LogicalQuiescent均为true，RelaunchDisposition=Forbidden。
5. 确认该进程退出后再操作安装；进程消失本身不是安全回执。

## 3. 迁移独立监督任务

原独立任务的入口绑定旧解压目录，因此须从**原包**执行 `卸载独立数据库监督.cmd`。它先持久禁用并等待原协议交还；存在未交还许可时不能强删任务或杀进程。核对旧观察器和旧外层监控退出，原任务移除。

本步骤仅迁移独立监控，不删除试验数据。新包仍使用原Supervisor、SessionAgent和安全联锁。

1. 从新快捷方式或“启动试验.cmd”打开主程序。该cmd只打开软件，实际试验启动仍需通过界面安全准入。

3. 点击开始。需要学习/定位时等待其正常完成，不绕过安全条件。
4. 核验各通道实时值已经显示正确单位并随采集变化；P1/P2压力值和曲线相符。
5. 至少观察多个15秒周期：六通道动作与机械计数、正式提交均推进，保存序号持续增加；保存失败或某通道停滞均不能判为通过。
6. 同时确认独立数据库观察器已绑定当前Run和进程，数据库观察结果新鲜。
7. 当前现场仅执行正常运行观察，不为演示兜底而拔设备、强杀正在带电的主程序或制造真实安全故障。受控故障注入结果与真实台架恢复验收应分别记录。

## 7. 失败处理与回退

- 安全停止未完成：保留所有保护组件，不更新、不强杀。
- 新包安装失败：保留安装日志、Current和retired目录，不反复卸载删除证据。
- 新程序不能通过安全准入或不推进：通过同样的人工停止和安全退出流程收口后，再决定回退。
- 回退前从当前新包禁用并卸载独立监督，确认交还。安装器不会用普通Install覆盖更高版本。需要回退时，在确认安全退出和独立监督交还后，使用新包的“一键卸载.cmd”移除程序安装，再从核验过的旧包执行安装。卸载只针对程序目录和服务/任务，保留ProgramData与项目数据。安装前后再次核对六通道历史次数。不能假定直接运行旧安装cmd就已经回退。
- 不从程序包恢复/覆盖现场index.db，不把试验次数回写到旧值。原4.0.0.0有已知显示和绑定缺陷，2.14.2.12有本报告所述全停链，回退版本也不能称为无故障基线。
