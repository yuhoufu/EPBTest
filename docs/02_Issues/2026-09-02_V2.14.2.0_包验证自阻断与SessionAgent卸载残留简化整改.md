# V2.14.2.0 包验证自阻断与 SessionAgent 卸载残留简化整改

## 结论

V2.14.2.0 在远程机无法开始试验的直接原因是程序把 `Config\TestConfig.xml` 同时当作运行时可写配置和不可变发布文件。监控窗加载后会调用 `UpdateDefaultTestFromProject`，刷新默认配置中的项目字段和时间；点击开始时 Supervisor 又按安装槽清单复算该文件 SHA256，因此稳定触发：

```text
SupervisorPackageSlotUnproven:
PackageSlotFileIdentityMismatch:Config\TestConfig.xml
```

启动失败后的 Watchdog 收口返回“资源收口未完成”。监控窗第一次关闭实际已经完成设备停机和资源释放，但 Watchdog 关闭授权无法建立，于是方法返回 `false`、隐藏遮罩并重置关闭状态，原监控界面重新出现。更严重的是 `_formClosedFlag` 已经置为完成，第二次关闭会提前返回 `true` 却不再调用 `Close()`，因此窗口可能永久关不掉。关闭遮罩原来还使用循环式 `Marquee`，进一步放大了“关闭后又恢复”的观感。

按操作要求，版本选择和交付包状态改由操作人员负责。软件不再以版本、manifest、逐文件 SHA256、DPAPI 槽证明或配置哈希阻止安装、启动、恢复和关闭。物理断能、PID/启动时间、会话参数、单实例与硬件故障隔离仍保留。

程序产品版本未由本次整改修改；快捷部署脚本修订号更新为 `QUICKDEPLOY_R9`，仅用于区分已经包含简化逻辑和卸载修复的新部署包。

## SessionAgent 卸载残留

旧的一键卸载只执行计划任务删除。Windows 删除计划任务定义不会终止该任务已经启动的进程，因此可能出现：

```text
Session agent task: Not installed
MTTFTest.SessionAgent <PID>
```

残留 Agent 只等待 schema 5 管道请求；Supervisor 已卸载时没有合法发送方，V2.13.0.44 也不使用该许可协议，所以不会主动接管 V2.13.0.44。它只占用少量资源和当前桌面会话的 Agent 单实例名。

整改后的卸载顺序为：停止 Supervisor、停止并注销计划任务、按完整可执行路径终止 `Program Files\MTTFTest\Current` 下的 SessionAgent、删除服务和快捷方式。路径匹配避免误伤其他目录中的旧版主程序或 Watchdog。

## 实施范围

- `Controller/RuntimeBuildIdentity.cs`：包身份改为 `OperatorManaged`，仅记录、不阻断。
- `MTTFTest.Watchdog/SupervisorServiceHost.cs`：删除主 Sidecar、恢复记录和 SafetyAgent 的包槽验证。
- `Watchdog.Protocol/PackageSlotDescriptor.cs`：恢复启动直接使用操作人员选择的可执行文件；LastKnownGood 只按目录存在性选择。
- `Tools/Install-MTTFTest-Unattended.ps1`：删除版本、manifest、逐文件 SHA256、DPAPI 描述和槽指针逻辑，仅检查必要组件存在；卸载补齐 SessionAgent 进程清理。
- 快捷安装/修复入口：不再先运行 `Verify-Release.ps1`。
- `MTTfTest/FrmEpbMainMonitor.CloseOverlay.cs`：循环动画改为只前进的阶段进度。
- `MTTfTest/FrmEpbMainMonitor.cs`：Watchdog 启动失败且 UI 从未绑定时，设备、数据和窗体资源完成收口即可关闭；已释放资源的重试路径会再次真正调用 `Close()`，不再只返回成功状态。
- 快捷部署生成器：不再限定 V2.14.2.0、干净工作区或发布身份验证。
