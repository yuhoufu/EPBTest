继续按主报告第 8—12 节反证后，V2.12.0.28 又关闭了五个长期无人值守缺口：

1. DAQ processing/Raw 入口改为每设备预分配 SPSC 环，队列节点与环操作稳态零分配；
   Raw 批次仍使用池化数组和短生命周期包装对象，不能表述为整条数据链完全零分配。
2. 终态 `ChannelOff` 使用每设备预分配四级优先级环并只做有界提交，NI 慢写不再阻塞
   DAQ subscriber；方向/压力兼容生产路径尚未全部迁入该环。
3. 恢复、人工 Stop、硬件确认均先冻结运行授权并提交整组 OFF/电源 Disable，再做封圈、观察者、日志和恢复所有权等待。
4. 正式圈由 `CycleAttemptContext` 统一持有身份、取消、Begin 状态和精确一次终态；执行 tombstone 阻止旧 Runner 未退出时启动新圈。
5. 事故证据统一为全局“1 个运行 + 1 个等待”的有界出口，trigger/terminal 每阶段绑定构建身份，派生症状只合并到同一根事故。

因此，V2.12.0.28 是可进入真实 NI 分阶段验收的第三轮源码候选。它不是生产放行结论：
真实 2/8/24/72 h、共享盘和 NI 故障注入、以及每个配置通道 100000 圈均未完成。

## 3. V2.12.0.28 第三轮代码整改

### 3.1 DAQ 数据链

- Dev1/Dev2 processing 与 Raw 发布分别使用预分配、有界 SPSC 环和独立 worker；一个设备的容量、等待和异常不直接消费另一设备的队列。
- processing 入口拒绝必须先锁存永久 sequence gap，再发布故障；失败圈不计数，禁止以更大水位伪装完整前缀。
- HostRuntime 在独立低优先级线程采样，ProcessLoop 只读缓存；诊断停顿不再反压采集。
- 处理提交点前的失败保留/锁存同一序号；提交点后的观察者异常由 supervisor 重新进入，不留下无人消费的尾队列。
- 1024 批只是爆发缓冲，独立 500 ms age watchdog 才是提前发现机制；扩容不被当作根治。

### 3.2 持久化与停止边界

- `Persisted` 只表示 recorder 真实写入成功；截止尾批进入 `TerminallyHandled` 和有限排除账本，不再伪推进物理水位。
- 恢复入口先冻结物理耐久边界 `B`，恢复提交时冻结排除上界 `T`；`B < seq <= T` 可明确排除，首个 `seq > T` 才恢复物理写入。
- 排除证据保留 CorrelationId、RunId、RunEpoch、累计数量、首末序号和区间数，有限窗口关闭前不清身份。
- 持久化 worker 保留 `CurrentBatch` 原序重试；活动圈上限、recorder 暂时不可用或写入异常均不得提前推进水位。
- 独立单调时钟 watchdog 识别永久同步写阻塞并发布一次 `DaqPersistenceWriteStall`；该状态禁止同进程伪恢复。
- Stop 在 DAQ 停止后冻结同一最终边界，Raw、processing、SQLite 和 STOP 数值门必须对同一边界闭合。

### 3.3 安全断能和 DO 调度

- 每个物理设备具备 64 槽预分配命令环，固定优先级为：
  `EmergencyGroupOff > ChannelOff > DirectionChange > Pressure`；同优先级保持 FIFO。
- 当前生产关键链中，终态 `ChannelOff` 已接入该环；方向和压力仍保留兼容同步写路径，
  其优先级入口已有组件验证，但不能表述成四类生产调用已经全部迁移。
- DAQ subscriber 只在有界时间内提交终态 OFF，不等待 NI 写、观察者、日志或电流清零。
- 物理 OFF 完成和电流清零后才提交正常终态；100 ms 独立 deadline 超时只提交一次硬故障，迟到回调只能补证据。
- 准入与 Dispose 线性化；已接纳命令精确一次完成，容量满或停止门竞争在调用预算内明确拒绝。
- 恢复、人工 Stop、电气组故障和硬件确认均先整组 Pause/Cancel、异步 OFF 和不可取消的电源 Disable，再等待封圈、液压、观察者和证据导出。
- 软件没有硬件完成证据时，只能声明“已发起断能并进入逻辑安全隔离”，不能宣称已经物理断能；永久 NI 卡死仍依赖外部硬联锁。

### 3.4 正式圈统一生命周期

- `CycleAttemptContext` 在 recorder `Begin` 前登记 RunId、RunEpoch、Device、Channel、Cycle、AttemptId、Kind 和取消令牌。
- Begin 状态明确为 `Registered/Begun/Failed`；只有 Begun 可以调用 recorder 的 Complete/Abort/Alarm，Registered 只撤销，Failed 不伪造不存在的圈终态。
- Complete、Abort、Alarm 三类并发终态只能有一个胜出；持久化失败保留 context，允许对同一终态精确重试。
- 每通道 execution tombstone 持续到旧 Runner callback 的 `finally`；终态可以先提交，但旧执行区退出前新 attempt 一律拒绝。
- 批量启动、单通道恢复、正式重入、供电前和机械预释放前均等待旧 execution quiescence；超时保持 OFF，不调用硬件委托。
- 自适应峰值令牌由精确 owner 管理，旧圈迟到取消不能误伤下一圈。

当前统一生命周期覆盖正式圈。学习/资格圈仍沿用原有幂等守卫，尚未迁入同一个
`CycleAttemptContext`，属于后续结构统一项，不影响本轮正式圈串圈门禁的结论。

### 3.5 日志、事故证据和 UI

- 普通日志约 1 s 合并软刷；硬报警、Stop、close 和正式证据终态才 durable flush。
- 日志 dirty/flush 改成单调版本水位；Shutdown 先关闭准入、等待 FIFO 屏障并耐久刷新，再交换 store。
- DAQ 事故导出全局严格限制为 1 个运行、1 个等待；派生症状只合并，terminal 不会被普通 derived 饿死。
- trigger/terminal 阶段目录均写 `build-identity.json`；根目录 `manifest.jsonl` 记录阶段演进。
- UI 跳过显示批只影响视觉抽样；只有真实 DAQ 时间断点才断笔，不增加 UI 队列、刷新率或点数。

### 3.6 DO 延迟模型和峰值语义

- 模型分别记录 decision、DO write started、DO write completed 和 current-clear 时刻，并维护每通道/设备延迟分布与 P95。
- 物理峰值晚于决策只改变“时间窗是否可比”，不再被改写成后台证据处理 lag。
- lag=25 ms 且物理峰值晚 150 ms 不报警；真实 lag=101 ms 只产生一次独立处理滞后诊断。

## 4. 必须保持的不变量

### 4.1 数据不变量

1. 正式耐久边界内的 accepted sequence 只能真实持久化、保留原批重试，或锁存永久 gap；不得静默跨越。
2. 明确排除的停止/恢复尾批不属于成功正式圈，不推进物理 Persisted，并且必须留可审计区间。
3. processing、Raw、SQLite 和 STOP 对账必须使用同一个冻结边界。
4. `BackgroundQueueFull` 表示当前批未被 processing 接受，是数据连续性红线，不是普通“自维护一下继续跑”的软预警。

### 4.2 恢复不变量

```text
故障登记
  → 整组 Recovering / Pause
  → 冻结圈号、正式 attempt 和 LastAccepted
  → 设置有限尾批排除窗口
  → 批量提交 OFF 并启动电源 Disable
  → 撤销液压参与并等待恢复所有权
  → 排空冻结的 Raw / processing / SQLite 前缀
  → 断电态修复输入 DAQ并取得新鲜压力
  → 机械释放和资格确认
  → 等旧 execution 完全退出
  → 共同未来节律槽重入
```

任一步不能证明完成，系统保持 OFF/Stopping/Recovering，不得通过旧压力、旧 Runner 或更大水位恢复计数。

## 9. 工程边界

若 NI 驱动、SQLite、MMF 或文件系统同步内核调用永久不返回，同一进程不能安全取消旧调用，
也不能在同一资源上并行重写。当前软件能够发现、发起断能、锁存故障并拒绝伪恢复；
若耐久边界无法证明，会保持安全停机而不是静默丢数。

若业务要求这类永久主机/存储故障下也自动续测，还必须建设：进程外 Windows Service/supervisor、
本机预分配 append-only journal、CRC/commit marker、幂等重放、CampaignRunId/ProcessEpoch，
以及独立硬件 watchdog/安全继电器。该架构不应由当前进程内 `Task.Run` 超时替代。

- V2.12.0.28 必须从最终提交的独立洁净 worktree 构建，工作树在测试前和写 identity 前都必须再次证明 HEAD 未变化且 `git status --porcelain` 为空。

- 上表计数用于说明第三轮实现冻结快照；正式候选的 Git SHA、BuildUtc、EXE/config SHA、
  最终测试计数、600 s soak 和批准状态只以候选目录中的 `build-identity.json`、
  `SHA256SUMS.txt` 为准。
- 不得从 Visual Studio 的可变 `bin\Release` 目录部署。
- 当前结论是“主事故链和第三轮软件缺口已形成可验收候选”，不是“已经证明 100000 圈无人值守上线”。
