不能用代码审查或自动化测试证明软件“绝对没有任何新 Bug”。本次复核采用的可交付结论是：

- 二次审计确实发现 V2.13.0.44 的两处边界遗漏，因此 **V2.13.0.44 不应继续作为现场候选**；

## 3. 原事故链是否已经闭合

| 原事故现象/根因 | 当前处理 | 闭合状态 |

| 主程序窗口响应但控制进度停止，Watchdog 无限等待 | 先给主程序自处理机会；5 秒无确认升级为独立安全接管 | 已闭合 |
| 强杀后缺少优雅关闭墓碑，恢复阻断 | 启动预置哈希绑定凭据；精确旧进程退出证据；SafetyAgent 独立物理安全回执 | 已闭合 |

上述“闭合”指代码路径和自动化证据闭合，不等同于真实硬件长稳已经完成。

## 4. 不影响正常运行的复核

本轮 V2.13.0.45 两个补丁都不进入稳定运行的高频控制路径：

1. 历史周期修复 SQL 只在数据库启动审计或 Watchdog 事故恢复时执行，不在每圈、每批或 DAQ 回调中执行；
2. 旧 Sidecar 枚举与判定只在 Watchdog 启动清理阶段执行，不在正常心跳、控制批次或 UI 刷新中执行；
3. Sidecar 清退判定新增的是收紧条件，不放宽终止权限；任何身份、父进程、安全证据不确定都拒绝清退；
4. 合法历史终态、其他项目进程、活动安全交接和当前版本实例都不会被修改或终止；
5. 未改变 2 kHz DAQ、10 ms 控制批次、告警阈值、压力新鲜度、硬件断电判据和正式完成计数规则。

因此，本轮补丁没有给正常试验循环增加数据库、网络、进程枚举或硬件同步等待。

## 7. 已知剩余风险

本次没有发现新的已知阻断缺陷，但以下风险只能通过现场环境消除：

- NI 驱动和实际板卡是否按配置分配 10 秒输入缓冲，以及现场负载下是否仍出现 `-200279`；
- CAN、液压、电源、机械负载并发时，5 秒接管期限是否满足物理安全响应；
- 杀进程时刻恰好落在安全凭据/墓碑/回执耐久写入边界的真实磁盘行为；
- 同机多项目、旧新版本并存和安全交接期间的真实进程权限、杀毒软件和文件锁影响；
- 24/72 小时长稳中的内存、句柄、磁盘空间、日志吞吐和 UI 响应趋势。

这也是不能宣称“绝对零 Bug”的原因。当前证据支持的是“代码候选可进入现场验收”，不是“无需现场验收即可无人值守上线”。

## 8. 现场放行清单

现场必须使用 V2.13.0.45 的干净受控包，并完成以下验证：

1. 启动后核验主程序、Watchdog、SafetyAgent、Controller、Protocol 均为 `2.13.0.45`，发布身份与 SHA-256 全通过；
2. 读取 NI 实际输入缓冲配置，验证双设备在 2 kHz 下均达到设计裕量；
3. 注入 3 秒控制停滞：主程序应自处理，Watchdog 不应误接管；注入超过 5 秒停滞：Watchdog 应转独立安全接管；
4. 制造 EPB4/5 同根 DAQ 故障风暴，确认只生成一次根故障、一次 StopAll，UI 可操作且控制线程不等待 UI；
5. 在墓碑写入前强杀主程序，确认先取得独立物理安全回执，再自动恢复；恢复后不存在双主程序或双有效 Watchdog；
6. 保留活动安全交接文件并启动新版本，确认旧 Sidecar 不被清退；损坏交接 JSON 后重复验证，仍应 fail-closed；
7. 同机建立不同项目的 Watchdog 身份，确认新项目不会清退其他项目 Sidecar；
8. 检查事故数据库修复结果：无遗留 `status='running'`，无 `end_time < start_time`，被中断周期不计正式完成数；
9. 完成 2 小时故障注入、24 小时和 72 小时长稳，核对报警、恢复次数、内存、句柄、磁盘、UI 延迟和完成数；
10. NI、CAN、液压、电源、机械安全负责人签字后，将状态从“条件 GO”转为“正式 GO”。

任一安全证据缺失、损坏或身份不一致都必须保持 fail-closed，不能为了自动恢复绕过安全门禁。
