# V2.12.0.10 连续运行会话与自维护风暴验收闭环

> **已由 V2.12.0.11 取代：** 后续审计发现最后通道终态会在统一压力、电源、Raw 与持久化边界确认前提前写 `Closed=True`，并漏检 `_runnerCache`。修复见 [V2.12.0.11 会话终态统一安全与耐久收尾整改](./2026-08-09_V2.12.0.11_会话终态统一安全耐久收尾整改.md)。

## 结论

V2.12.0.9 已完成控制、写盘、恢复和后台任务的代码收口，但最终完成性审计发现现场门禁仍可能把同一项目目录内多个短运行的最早、最晚日志时间拼成一次 24/72 小时长跑；门禁也没有直接统计“进入自维护的独立根事故数”和“结束时仍卡在 Recovering 的通道”。因此即使软件反复重启或频繁自维护，旧门禁仍存在误放行可能。

V2.12.0.10 增加不可拼接的连续会话证据和自维护风暴红线。正式验收只统计同一 `RunId` 的 `SESSION Start` 到匹配终态之间的数据；区间内出现第二个 Start、第二个 RunId、构建身份不完整、`GitDirty=true`、终态未闭合、恢复风暴或通道滞留自维护，均直接失败。

这次修改不放宽任何故障阈值，也不减少安全断电。它解决的是“软件是否真的连续稳定运行”不能被机器证明的问题。

## 原门禁缺口及根治

| 缺口 | 可能造成的误判 | V2.12.0.10 整改 |
|---|---|---|
| 用所有日志的最早/最晚时间计算时长 | 多个 1 小时运行跨越一天，可伪装成 24 小时连续运行 | 写入 `FieldMetric SESSION`，仅使用同一 RunId 的 Start—终态区间；只验收目录内最新一次 Start，最新运行未闭合时禁止退回旧成功会话 |
| 版本只要求“日志中出现过目标版本” | 同目录混入旧版本仍可能通过 | 验收区间观察到的版本集合必须严格等于目标版本 |
| 未验证固定二进制和配置 | 中途换 EXE/配置无法自动拒绝 | Start 同时写入 EXE SHA、发布配置 SHA、Git commit、GitDirty、BuildUtc；正式门禁要求哈希完整且 `GitDirty=false` |
| 没有结构化通道状态迁移 | 无法判断自维护频率和最终是否恢复 | 状态真实变化时写入 `FieldMetric STATE`，包含 RunId、设备、通道、状态、原因、关联号和运行代次 |
| 没有恢复风暴红线 | 反复自维护仍可能被当成“已自动恢复” | 每设备任意 10 分钟内独立根事故最多 3 个；同一根事故每通道只能进入一次 Recovering |
| Recovering 缺少关联号时被统计器忽略 | 恢复风暴可因空值或全零 GUID 而被漏计 | 每条 Recovering 必须携带非空、非全零根事故关联号，否则直接失败 |
| 终态不检查 Recovering 残留 | 停止时通道仍处于自维护也可能通过 | 每个验收通道必须有状态证据，且最后状态不得为 Recovering |
| StopAll 先清 RunId 再发布终态 | 停止状态无法归属原运行 | Stop 捕获原 RunId，并以 `runIdOverride` 写入全部终态状态 |

## 结构化证据

### SESSION Start

正式阶段真正建立后记录一次：

```text
FieldMetric SESSION Phase=Start RunId=<32hex> Channels=4,5,8,9,10,11 Closed=False \
ProductVersion=V2.12.0.10 ExeSha256=<64hex> ConfigSha256=<64hex> \
GitCommit=<40/64hex> GitDirty=False BuildUtc=<UTC>
```

### SESSION 终态

人工停止、安全停止、自然完成或末通道报警停止记录匹配 RunId 的 `Stop/Complete/ChannelStop/AlarmStop`。正式封存要求 `Closed=True`。

### STATE 状态迁移

只有状态、原因、RunId 或关联号真实变化时记录，避免每圈重复日志：

```text
FieldMetric STATE RunId=<32hex> Device=Dev1 Channel=4 State=Recovering \
Reason=<code> CorrelationId=<32hex> RunEpoch=<n> ...
```

同一恢复关联在同一通道重复进入 Recovering、不同恢复关联在 10 分钟内超过上限，或者关联号为空/全零，门禁均失败。这使“频繁进入自维护”从主观界面现象变为可量化回滚条件。

## 正式验收命令

```powershell
python Tools/validate_epb_field_gate.py "<V2.12.0.10封存目录>" `
  --expected-version V2.12.0.10 `
  --minimum-hours 24 `
  --performance-gates required `
  --max-recovery-correlations-per-10m 3 `
  --artifact-scan full `
  --log-scan full `
  --database-scan full
```

72 小时验收只把 `--minimum-hours` 改为 `72`。禁止中途重新开始、重启程序、替换 EXE 或配置；发生这些行为必须从新的 Start 重新计时。
