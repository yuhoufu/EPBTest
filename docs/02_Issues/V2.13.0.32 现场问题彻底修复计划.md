# V2.13.0.32 现场问题彻底修复计划

## 总结

- 以当前未封版的 `V2.13.0.31` 工作区为基线，保留全部现有修改，版本迭代为 `V2.13.0.32`。
- 修复停止后拒绝启动、主窗口无法关闭、Watchdog 管道竞态、暂停期间 DAQ 恢复失败及分析文档中的软件隐藏问题。
- EPB12 的软件侧改为“操作员确认 + 完整重新学习 + 2 圈资格复核”；不降低 13.5 A 门槛，也不掩盖待排查的物理故障。
- 非受控发布包按已选策略继续允许启动，但增加持续可见告警和完整身份审计，不设置启动硬门禁。

## 核心实现

### 1. 停止、重新开始和退出统一收口

- 新增唯一的 `StopSessionCoordinator/ApplicationExitCoordinator`，人工停止、立即重新开始、主窗体 X、监控窗 X、菜单退出和 Watchdog 接管退出全部加入同一个 single-flight 任务。
- 用组合 `StopSessionReceipt` 取代当前设备侧 `ManualStopExitReceipt`：
  - 包含 `RunId`、停止命令身份、`SessionId/Generation/Lease`、`StopSafetyResult`、Watchdog shutdown 回执、UI 资源释放结果。
  - 只有设备、持久化、DAQ、Watchdog 和 UI 资源均终态后，`CanRestart/CanClose` 才为真。
- 删除人工停止完成后的 fire-and-forget shutdown：
  - 顺序等待安全断能、持久化闭合、停止通知、Watchdog 精确会话终止和 UI 资源释放。
  - 此前“可以重新开始”的提示改为“设备已停止，正在释放 Watchdog 会话”。
  - 操作员在收口过程中点击开始时，加入同一任务；终态成功后自动继续本次启动，无需再次点击。
- 关闭时先保留监控界面并显示阶段进度，全部收口成功后才销毁子窗口和主窗口，杜绝灰色 MDI 空壳。
- 收口超时显示未终止的 worker/租约/句柄，并提供：
  - “重试收口”：继续复用同一精确会话。
  - “撤权后安全退出”：仅在输出 OFF、持久化闭合、耐久撤权标记成功且 Sidecar 确认 `ShutdownExpected` 后启用；任何条件缺失都保持窗口可见。
- Sidecar 终态日志明确记录 `ExpectedApplicationExit`、`OperatorCanceledRecovery` 或 `ProcessExitedUnexpectedly`，正常关闭不得触发自动恢复。

### 2. Watchdog 传输和会话租约

- 将当前同步 `WriteLineAsync + WhenAny` 改成每个会话一个 writer worker：
  - 总容量 256，其中 8 个槽保留给 `ApplicationClosing`、`ShutdownExpected`、`StopCompleted` 等生命周期消息。
  - 单 worker 串行写管道；同优先级保持 FIFO，生命周期消息优先于心跳。
  - 队列满时普通消息返回 `AdmissionBusy`，不得误判为传输断开；生命周期消息不得被普通心跳挤占。
- shutdown 顺序固定为：设置不可逆 Closing 栅栏、拒绝新发送、取消 connect/reconnect/launch/heartbeat、停止发送队列、Dispose 管道以解除在途 I/O、等待全部 worker、最后生成终态回执。
- 所有写任务均由 writer worker 观察；预期的 ODE/IOE 合并为一次结构化传输故障，不再产生 `TaskScheduler.UnobservedTaskException`。
- `WorkerTerminationState` 增加 `SendTerminal` 并纳入 `AllWorkersTerminal`；保留旧构造重载兼容现有调用方。
- 所有迟到回调必须同时校验 `SessionId + Generation + Lease + ConnectionIdentity`，Closing 后不得再次连接或拉起 Sidecar。

### 3. DAQ 暂停恢复、主机时序和电源遥测

- 为批次暂停状态增加单调 `Generation`，以不可变快照原子发布；DAQ 恢复在准入、断电确认、提交前分别复核暂停代次。
- 人工暂停前、暂停过程中或恢复提交前出现暂停代次变化时：
  - 跳过电源重启和公共 slot 重入；
  - 合法提交 `DaqRecoveredHeldForManualPause`；
  - 保留新 DAQ generation、新鲜批次、压力与持久化资格；
  - 不再转成 `StartBlocked`。
- “继续试验”必须等待活动 DAQ 恢复终态，再复核 generation、新鲜度、压力和持久化边界，随后统一加入未来公共节律槽。
- Dev1/Dev2 使用完全对称的状态路径；电源 OFF 回读增加有界稳定窗口并记录首次、最终遥测。
- 将电源持续限流、低压确认等剩余墙钟时长判断改为 `Stopwatch`；UTC 只用于显示和审计时间戳。
- 新增 `TelemetryCallTimeoutMs=1500`：
  - 每台电源使用独立的串行执行器，安全命令优先于轮询。
  - 超时后撤销旧传输代次、观察旧任务并重连；旧任务未结束时不得无限创建替代任务。
  - 无法有界终止时停止正式运行并交给安全接管，不阻塞 Watchdog/DAQ 关键链路。

### 4. 通道故障、取证和隐藏问题

- 对 `ForwardUnderTargetHighLoadStall`：
  - 禁止无人值守自动调用报警恢复入口。
  - UI 显示真实故障详情并要求操作员 Yes/No 确认，不能再由代码直接传入 `operatorAcknowledged=true`。
  - 清除受影响方向的旧自适应模型，执行 `max(5, Test.LearnCycles)` 个完整学习圈，再执行 2 圈不计正式目标的资格复核。
  - 全部通过后按公共未来 slot 重入；任一步失败均保持 `AlarmStopped` 和输出 OFF。
  - 其他纯软件瞬态故障继续沿用现有有界自动恢复策略。
- 报警快照补充电源 V/I、DO 命令与回读、最近 10 圈基线差、负载端电压/继电器反馈/温度；无传感器的字段明确写 `NotMeasured`。
- DAQ 取证队列改为按 IncidentId、设备分别保存 trigger/terminal：
  - 容量只限制重型导出任务，不再拒绝根事故。
  - 双设备同源事件写入同一个事故目录，manifest 为每台设备记录 `TriggerCaptured/TerminalCaptured/PhaseKeys`。
  - 未齐全时只能标记 `Deferred/Incomplete`，不得声明完整快照。
- 液压异常增加稳定 `FaultCode`：
  - 陈旧样本为 `HydraulicSampleStale`；
  - 无样本/非法值为 `HydraulicSampleUnavailable`；
  - 真实低压为 `HydraulicPressureBelowMinimum`。
  - 保留现有异常类型兼容调用方，所有 lease-abort 任务纳入非阻塞监督并产生唯一终态。
- EPB5 软预警不改变保护门槛，新增诊断配置：
  - 100 个正式成功圈为一个窗口；
  - 预警率达到 10% 且连续 2 个窗口时生成维护提示；
  - 日志只保留首次、状态变化和窗口汇总，证据文件仍保存完整计数与峰值、动作时长分位数。
- 增量封存脚本增加一致性边界：
  - 使用 Python 标准库 SQLite online backup 生成独立 `index.db` 并执行 `integrity_check`，最终包不携带活动 WAL/SHM。
  - 活动 `.csv.tmp` 可复制，但 manifest 必须标记 `InProgress=true`、源/快照长度与哈希，不宣称行尾完整。
  - 所有文件生成 SHA-256；最终归档原子发布，中断只留下可识别的 staging。
  - 增加归档回读、哈希、SQLite 完整性及已封口 CSV 行尾验证。

## 假设

- 不回滚、覆盖或清理当前用户的未提交修改。
- 本轮不自动提交 Git，也不在脏工作区生成可宣称为正式现场包。
- EPB12 的物理根因和 Windows 主机调度/校时问题在文档中保留为现场验收项；软件侧负责安全隔离、可靠复核和完整取证，不虚构“硬件已修复”结论。
