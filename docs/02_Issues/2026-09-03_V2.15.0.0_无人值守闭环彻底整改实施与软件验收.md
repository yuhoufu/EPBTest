## 1. 正式版目标与边界

V2.15.0.0 将“无人值守”定义为：软件自身可恢复故障不需要人工干预；硬件故障、Windows 服务/OS 不可恢复或存储无法形成安全证明时，系统持续保持断能并进入 `SafeIdleAlarmed`，禁止为追求自动拉起而绕过证据门禁。

正式运行仅允许以下启动链：

```text
桌面快捷方式/登录任务
  -> MTTFTest.Watchdog.exe --launch-main
  -> LocalSystem Supervisor
  -> 交互会话 SessionAgent
  -> 单次 LaunchCapability
  -> MTTFTest.exe
```

直接双击 `MTTFTest.exe`、旧 schema capability、重复消费 capability、PID/StartTicks 不一致或 EXE 哈希错误均拒绝启动并写入 ProgramData 审计。生产二进制没有“无服务兼容模式”或测试绕过开关。

## 2. 根因到整改的闭环映射

| V2.14.2.11 风险 | V2.15.0.0 整改 | 失败后的安全结果 |
|---|---|---|
| Sidecar、SafetyAgent 从多个 receipt 镜像中选择“最新”文件，存在授权竞争 | Supervisor 在 ProgramData 持有唯一 schema 6 authority；项目目录只保存证据镜像；原 Session 项目根、主 EXE 路径/哈希及旧 PID/StartTicks 必须同时回绑 | authority 不可证明时 `SafeIdleAlarmed`，不启动主程序 |
| Watchdog 心跳提供器可能与 UI、控制、配置或存储锁互相阻塞 | 心跳传输脉冲使用独立长期线程，只读取原子发布的不可变语义快照 | pulse 或 snapshot 停滞独立判定并冻结首发证据 |
| DAQ 回调积压后陈旧数据仍可能进入控制 | Dev1/Dev2 独立同步固定块读取线程；同时校验 CallbackAge、SampleAge、积压和序号 | `>100 ms` 数据不参与控制；`>=250 ms` 立即断能并作废当前圈 |
| 双 DAQ/慢遥测故障可能被多个 EPB、液压组、电源组重复放大 | 同时间窗基础设施故障合并为一个恢复事务，由唯一 owner 推进 | 一个故障只形成一个恢复事务和一组终态证据 |
| 异常 fallback 同步生成 `SafetyUnproven`，MotorOff 后仍可能过早 StopAll | 正常、异常和 fallback 共用幂等 `FormalSafetyClosureTransaction` | 进入 `PendingSafetyClosure`；有进展则等异步收口，只有超时/无进展/物理反向才一次性 StopAll |
| UI 消失与受控退出不能可靠区分 | UI 隐藏/关闭前先持久化 typed-exit transaction；心跳携带 UI lifecycle | 无事务的 WindowMissing 仍作为故障；受控退出仅获有限宽限 |
| 主程序可绕过 Supervisor 直接启动 | SessionAgent 一次性消费 Supervisor 签发的 schema 6 `LaunchCapability`；主程序逐字段复核 | 拒绝直启、旧 capability、PID 复用、错误路径/哈希和字段篡改 |
| 各组件版本号分散，发布包可能混版 | `Build/UnattendedVersion.props` 统一 Assembly/File/Informational/ApplicationVersion | 任一正式组件不是 `2.15.0.0` 时发布脚本立即失败 |
| schema 5 活动授权可能被错误继承到新版本 | 安装器先验证断能证明并封存旧会话，只迁移剩余圈数 | permit、nonce、authorization 明确不迁移 |

## 3. Supervisor 唯一安全权威

### 3.1 schema 6 authority

新增 `SupervisorSafetyHandoffBeginRequest/Response` 与 `SupervisorSafetyAuthorityToken`。authority ID 绑定：

- `SessionId`
- `HandoffId`
- permit generation 与 permit ID
- 初始 receipt revision
- 初始 canonical SHA-256

SafetyAgent 只读取命令行固定指向的 ProgramData authority 文件，并复核 authority ID、路径、初始 revision、canonical hash、Session、Handoff 和 nonce。后续阶段只能在同一 authority 上单调推进；项目 receipt、本地历史副本和备份均不能参与授权仲裁。

### 3.2 字段级拒绝与损坏处理

协议和服务端已把笼统 identity mismatch 拆分为 schema、状态、Session/Handoff、nonce、permit、路径、EXE 哈希、revision、canonical hash 等明确失败原因。

权威文件损坏时先隔离坏文件。只有 Supervisor 能证明原 Session、注册项目根、主 EXE 路径/哈希、旧 PID/StartTicks 身份及其退出状态时，才能创建新的 crash-recovery 安全事务并重新执行幂等断能；不能证明时保持 `SafeIdleAlarmed`。旧 PID 身份不匹配与退出状态未证明分别返回 `SupervisorSafetyHandoffOldProcessIdentityMismatch` 和 `SupervisorSafetyHandoffOldProcessExitUnproven`。

Supervisor 审计、authority、服务身份、SafetyAgent 阶段结果和失败字段会写入项目 `SupervisorEvidence`/`WatchdogEvidence`，用于事故封存而不是恢复授权。

## 4. DAQ 时序与正式圈安全收口

### 4.1 读取与新鲜度

Dev1、Dev2 分别使用独立长期 `LongRunning` 读取线程执行同步固定块读取。读取线程只负责采样、时间戳、序号和立即入环，不执行液压、UI、日志或落盘业务。

`DaqFreshnessSnapshot` 已增加：

- `SampleAgeMs`
- `BufferedSamples`
- `ReaderLagState`
- `ConsecutiveFreshBatches`
- 陈旧丢弃起止范围

控制门禁如下：

1. CallbackAge 或 SampleAge 超过 100 ms，批次标记为陈旧，不得参与控制。
2. 达到 250 ms，立即关闭输出、作废当前圈并登记单一基础设施故障。
3. 在全输出关闭时丢弃积压旧批次并记录序列缺口。
4. 只有新 generation 已生效、连续三个批次新鲜且无新缺口时才允许重新进入控制。

### 4.2 幂等正式圈收口

每个正式槽按 Run/Epoch/Slot/Channel 建立一个 `FormalSafetyClosureTransaction`。状态包括 `PendingSafetyClosure`、`Closed`、`TimedOut`、`NoProgress` 和 `PhysicalStateReversed`。

MotorOff 已确认但液压释放或持久化仍在进行时不立即升级 StopAll。限定时间内完成记为 `SafeAborted`；仅真正超时、无进展或 MotorOff 物理状态反向时，通过既有单次升级门触发一次 StopAll。

## 5. 独立心跳、UI 生命周期和首发证据

`WatchdogHeartbeat` 已拆分传输与语义：

- `PulseSequence`
- `SnapshotRevision`
- `SnapshotCapturedUtcTicks` / `SnapshotAgeMs`
- `UiLifecycle`
- `ControlProgressVersion`
- `TypedExitTransactionId`

专用心跳线程不访问 EpbManager、配置、存储或 UI 锁。控制语义由另一专用发布线程生成不可变快照。

控制快照停滞、UI 无事务消失或双 DAQ 首次越限时，Watchdog 按 Session 限频写入进程/线程、CLR/GC、ThreadPool、DAQ 读取线程、积压和 Windows Application/System Event Log，并抓取首份轻量 dump；执行接管前再抓完整 dump。

## 6. 启动、升级和版本

### 6.1 单次 LaunchCapability

首次启动由交互 launcher 向 LocalSystem Supervisor 请求；故障恢复时，Sidecar 不再本地构造或签发 capability，而是把 durable authority 中固定的 intent、Session、permit generation/ID、authority revision/SHA-256 提交给 Supervisor。Supervisor 逐一验证 Sidecar PID/StartTicks、所属 Session、原注册主 EXE 路径/哈希、当前交互 Session 和全部恢复绑定后，签发 60 秒有效的 schema 6 capability。初始请求夹带恢复字段、恢复请求缺任一字段、Session 不属于该 Sidecar 或 authority 字段被混用时均拒绝。

SessionAgent 使用 DPAPI LocalMachine seal 验证后以 `CreateNew` 方式单次消费，记录启动 PID/StartTicks；主程序启动门再次逐字段核对 canonical capability 与 consumption record，包括 permit、EXE、参数摘要、Session 和桌面 Session。由此，首次启动和恢复拉起都只有 Supervisor 服务一个 capability 签发者。

应用内 fatal restart 不再直接 `Process.Start` 主程序，只写入 Supervisor-owned relaunch 请求并退出。

### 6.2 旧协议/运行检查点安全换代

Supervisor 旧协议状态为 schema 5；现场证据进一步确认 V2.14.2.11 的 `unattended-run-checkpoint.json` 自身已经使用 schema 6，两者不是同一个 schema。安装器顺序为：停止旧会话和登录任务，以严格 UTF-8 读取并接受旧运行检查点 schema 5/6，验证 `MotorOffConfirmed`、`PressureSafeConfirmed`、`PersistenceDrained`，封存旧 checkpoint/WatchdogSessions/schema 5 Supervisor JSON，然后只写入剩余圈数迁移记录。迁移记录明确：

```text
authorizationMigrated = false
permitMigrated        = false
nonceMigrated         = false
```

任一断能证明缺失即终止安装并保持 `SafeIdleAlarmed`。

### 6.3 统一构建身份

以下八个正式组件由同一 MSBuild 版本源生成 `2.15.0.0`：

- `MTTFTest.exe`
- `Controller.dll`
- `MTTFTest.Watchdog.exe`
- `MTTFTest.Watchdog.Protocol.dll`
- `MTTFTest.Watchdog.Client.dll`
- `MTTFTest.SafetyAgent.exe`
- `MTTFTest.SafetyHardware.dll`

正式包 identity 记录 commit、BuildUtc、GitDirty、主 EXE SHA-256、包内容聚合 SHA-256，以及上述每个组件的文件版本、二进制 SHA-256、PDB 名称和 PDB SHA-256。递归校验发现缺文件、多文件、哈希或版本不一致即失败。
