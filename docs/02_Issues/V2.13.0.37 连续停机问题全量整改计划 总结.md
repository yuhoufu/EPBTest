# V2.13.0.37 连续停机问题全量整改计划

## 总结

以当前工作区的 V2.13.0.36 未提交整改为基线，保留并复核已有修改，在此基础上完成 I0003、I0004、I0005 暴露出的全部控制链、Watchdog、日志和发布身份问题，最终版本定为 `V2.13.0.37`。V2.13.0.30 仅作为长期运行行为基准，不回退或复制旧实现。

完成标准：

- I0003 暂停期间恢复成功后进入 `HeldForManualPause`，不再错误进入 `StartBlocked`。
- I0004 的 DAQ 时间证据过期、持久化安全中止不会被误判为液压失压或全局安全失败。
- I0005 在主程序/UI仍存活时优先修复通信，重连能撤销过期接管；恢复标记不再刷屏；每次停止请求获得当前结果而非历史超时缓存。
- 所有恢复所有权、形式槽位和 StopSafety 路径都能确定性收口，不遗留永久 owner。
- 普通运行、警告、错误日志具备可观测健康状态和独立应急落盘。
- 自动化门禁全部通过；硬件长稳门禁如无法本地执行，在新文档中明确保持“待现场验证”，不得宣称通过。

## 核心实现和接口调整

### 1. 统一恢复事务与物理断电证据

- 扩展现有 `RecoveryIncidentCoordinator` 和 `RecoveryContractSnapshot`，不再让 DAQ 恢复维护第二套独立事务。
- 引入单调恢复阶段：`Detected → SafetyOffSubmitting → SafetyOffConfirmed → DaqRebuilding → FreshnessConfirmed → PersistenceClosed → 终态`。
- 复用现有 `RecoveryExitDisposition` 作为终态：`HeldForManualPause`、`RejoinedRunning`、`SafeIdleFault`、`Superseded`、`CancelledByStop`。
- 新增不可变 `SafetyOffReceipt`，记录命令、关联、目标、提交/完成时间、硬件写入或电源读回、运行代次和最终证据状态。
- 为 `IPowerSupplyCoordinator` 增加返回 `PowerSafetyDisableResult` 的安全断电方法，保留原 `DisableGroupAsync` 兼容现有调用；DAQ 和 StopSafety 只接受带代次且 `ConfirmedOff=true` 的结果。
- DO 关闭以高优先级命令的硬件完成回执为准；仅“入队成功”或仅 `Task` 完成不再作为安全证据。允许同代次迟到成功回执，拒绝旧代次回写。
- DAQ 恢复只保留一个 60 秒硬截止；10 秒电源、采集重建等阶段时限只产生诊断，不得取消父恢复。
- `HeldForManualPause` 只有在断电证据、DAQ新鲜度和持久化边界全部闭合后才能发布；60 秒内无法证明安全闭环则进入 `SafeIdleFault`，维持断电并要求人工处置。
- 暂停恢复继续保留 Timer、Runner 和许可，恢复完成后原子执行恢复前检查；任一检查失败先回滚已使能电源，再保持暂停，不产生半恢复状态。

### 2. 形式槽位、持久化和液压级联

- 将形式参与者终态从布尔字段改为明确三态：
  - `SafeCommitted`：机械循环和持久化提交均完成。
  - `SafeAborted`：本次循环未计数，但持久化中止边界已可靠落盘且物理状态安全。
  - `SafetyUnproven`：断电、液压释放或持久化边界无法证明。
- 增加 `CycleAttemptClosureReceipt`，携带 Attempt、Run/Epoch、通道、槽位、`Committed/Aborted/Unknown`、持久化版本和耐久性证据。
- `SafeAborted` 正常释放槽位，不增加完成次数，也不撤销整批权限；只有 `SafetyUnproven` 才触发批次安全失败。
- 槽位号小于零时禁止提交正式终态；保持设备断电并转入恢复或安全故障，不再产生 `Slot=-1` 的形式批次记录。
- 同一 DAQ 时间缺口内出现的 `HydraulicSampleStale/Unavailable` 合并进原 DAQ incident，不再竞争第二个恢复 owner。
- “最后压力约 70 bar 但样本年龄超限”显示为时间证据过期，不得归类为真实低压；只有新鲜样本持续低于阈值并通过复核才允许升级为硬件液压故障。

### 3. 恢复注册表和 StopSafety 收口

- `RecoveryIncidentCoordinator` 在正常返回、异常、取消的 `finally` 路径强制发布终态；业务代码遗漏终态时自动转入安全故障终态，不能留下 `WorkerCompletedWithoutTerminal`。
- 注册表增加 `SupersedeThroughEpoch` 和隔离审计状态。旧代次 worker 可以保留审计记录，但必须从活动 owner 集合移除，且不能再修改新代次状态。
- `StopAll` 先建立控制栅栏并立即提交 DO OFF、启动电源禁用，再执行 Timer/Runner 冻结和非关键清理。
- 将进程级历史缓存改为“物理安全事务单飞 + 请求级回执”：
  - 新增 `StopRequestReceipt`，记录请求 ID、来源、开始/完成时间、加入的物理事务、前序事件及本次实际结果。
  - 活跃物理事务可以被多个请求加入；事务超时或隔离后，新请求必须建立新代次并重新执行幂等安全动作。
  - 旧 orphan 通过代次栅栏禁止迟到回写。
- 保留现有 `StopAllAsync` 返回类型以兼容调用方，新增带完整回执的方法供 UI 和 Watchdog 使用。
- 截止点附近出现有效物理进展时重新核验安全证据；可报告“设备已安全、后台收口延迟”，但不得把一次 Freeze 超时永久缓存为后续请求结果。

### 4. Watchdog、恢复标记和日志自监控

- 建立统一 Watchdog 健康决策，分别评估 Transport、Application、Control、Physical：
  - PID存活且UI响应时，心跳或逻辑源过期只能触发连接重建/安全停止请求，不能直接结束主进程。
  - 只有进程死亡、连续确认UI无响应，或物理安全硬截止失败才能进入强制接管。
- 每次连接退休或重连建立新的传输代次并重置逻辑新鲜度宽限期。
- 同 authority 重连后，在收到身份匹配的首个新鲜心跳时原子撤销旧 takeover；Dump、Kill、Permit 等每一阶段继续校验接管代次。
- `DurableCheckpointIdentityChanged` 且当前无工作时执行完整回滚：撤销恢复状态、清理 permit/root/fingerprint，保留审计记录，并允许当前存活主程序继续提交。
- 升级恢复标记格式，包含 RunId、Epoch、Stage、生成代次和内容哈希；旧格式兼容读取但进入限频等待。
- 为每个标记建立 `Accepted/Rejected/Deferred` 处理账本，采用退避重试和每分钟最多一条汇总日志；成功或终态拒绝后原子归档，消除 `ContextMissing` 高频刷屏。
- 扩展 `ProjectLogHub` 健康快照：接收序号、耐久序号、最后成功时间、最后失败、队列深度和丢弃数。
- 仅当存在“已接收但未耐久”的日志或明确写入失败超过 5 秒时报告 `DiagnosticSinkStalled`，无日志流量不误报。
- 增加独立后台应急 spool，默认上限 16 MB；项目路径不可写时落到 `%LOCALAPPDATA%` 下按项目根哈希隔离的目录。恢复后按序回放，日志系统自身故障不得继续写入同一故障 sink。
- 在 Watchdog 心跳中增加向后兼容的日志健康字段；日志故障用于告警和审计，不单独构成杀进程依据。

## 自动化、版本和验收门禁

- 将根因文档中的 T01–T15 全部固化到现有测试工程，覆盖：
  - I0003 的 4/39 ms 迟到 OFF、1.25/1.38 秒 DAQ 恢复、暂停保持和原子恢复。
  - I0004 的 1009/1128 ms 样本过期、约 70 bar 压力、持久化 `SafeAborted`、owner 自动收口。
  - I0005 的 UI存活通信断线、同 authority 重连撤销接管、NoWork 回滚、5625 次恢复标记去重限频，以及第二次停止请求不复用旧超时。
  - registry 正常返回漏终态、异常、取消、旧代次迟到写入和 `SupersedeThroughEpoch`。
  - 日志 sink 断开、应急 spool、重放、容量上限和无流量误报。
  - 1000 轮随机并发交错，验证无双 owner、无非法状态回退、无半恢复和无旧代次污染。
- 运行本地门禁：
  - Debug x86 和 Release Any CPU 全量编译。
  - `AdaptiveControlTests`、`EpbDiskWriterTests` 和 `PowerSupplyDebugger.Tests` 全部执行。
  - 运行现有发布构建与校验脚本，验证主程序、Host、Client、Protocol、Controller 的版本、文件清单和 SHA-256 一致。
- 所有本地门禁通过后，将相关程序集版本统一升至 `2.13.0.37`。当前工作区未清洁时只允许生成带 `DIRTY_CANDIDATE_NOT_FOR_PRODUCTION` 标识的验证候选，不得生成正式现场包。
- 现场晋级保持分层：2小时故障注入、8小时/100轮、24小时、72小时、7天。每一级均要求零强制接管误判、零 owner 残留、零半恢复、日志和持久化边界连续；未执行的级别明确标为待验证。
