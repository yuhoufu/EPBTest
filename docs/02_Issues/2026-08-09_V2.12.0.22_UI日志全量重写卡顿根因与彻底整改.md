# V2.12.0.22 UI 日志全量重写卡顿根因与彻底整改

## 1. 结论

V2.12.0.20 六通道现场会话证明控制、DO、持久化和进程资源已经稳定，但 UI 仍存在最高约 5.9 秒的消息泵停顿。V2.12.0.21 修正了这类停顿造成的曲线视觉断线，却没有消除停顿本身，因此不能作为“界面已经流畅”的最终结论。

继续审计发现，主界面存在两套互相叠加的日志显示维护逻辑：

1. 主窗体每 150 ms 从 512 条有界队列最多追加 50 行；
2. 电源安全分部又订阅 `RtbInfo.TextChanged`，每次追加后读取全部 `RtbInfo.Lines`、去空行、创建新数组、重新拼接整段文本、赋值回 `RtbInfo.Text`、再次扫描裁剪并强制 `ScrollToCaret`。

也就是说，原本的“批量增量追加”实际上每批仍会退化为对约 2000 行文本的全量重建，并同步触发 RichTextBox 布局、滚动和 RDP 绘制。这是 V2.12.0.20 长时间运行时反复卡顿的直接软件根因。

V2.12.0.22 删除重复 `TextChanged` 全量格式化链，将显示维护收口为唯一的增量路径：复用批次容器、原位删除头部越界行、自动滚动最多 2 Hz，并记录 Append/Trim/Scroll 分阶段最大耗时。完整项目日志仍异步写盘，控制和数据链完全不依赖屏幕 RichTextBox。

## 3. 代码整改

### 3.1 删除重复全量格式化链

从 `FrmEpbMainMonitor.PowerSupply.cs` 删除：

- `RtbInfo.TextChanged` 上的安全信息格式化匿名处理器；
- 每次读取 `RtbInfo.Lines.Where(...).ToArray()`；
- 每批重新赋值整个 `RtbInfo.Text`；
- 第二套 `TrimSafetyInfoDisplay` 和重复 `ScrollToCaret`。

屏幕日志只允许 `FrmEpbMainMonitor.UiInfoFlushTimer_Tick` 一个所有者维护。

### 3.2 增量、原位、有界显示

- 50 行批次 `List<string>` 改为窗体字段复用，不再每 150 ms 创建新列表；
- 仍保持待显示队列容量 512，日志风暴不会撑大内存；
- 超过 2000 行时，不再获取和回写完整 `Lines` 数组；
- 使用 `GetLineFromCharIndex`、`GetFirstCharIndexFromLine`、`Select` 和空 `SelectedText` 原位删除头部，单次回落到 1800 行；
- 自动滚动节流为最短 500 ms 一次，避免每批强制 RichTextBox/RDP 同步滚动；
- 原来直接写 `RtbInfo.AppendText` 的启动/停止提示统一改走 `LogInfo` 有界链。

### 3.3 可验证的现场指标

V2.12.0.22 的 `FieldMetric UI` 新增：

- `AppendMaxMs`
- `TrimMaxMs`
- `ScrollMaxMs`
- `RenderedBatches`
- `RenderedLines`

现场门禁除原有窗口 P95<200 ms 外，又强制要求单次 `FlushMaxMs` 及三个分阶段最大值都 <200 ms；字段缺失也拒绝放行。这样不能再用平均值掩盖周期性 700 ms 卡顿。

## 6. 部署与复验

V2.12.0.21 和 V2.12.0.22 均已被 V2.12.0.23 完成性审计取代，不建议再部署。

V2.12.0.22 首轮至少连续运行 2 小时，并满足：

1. 所有 10 秒窗口 `DelayP95Ms < 200`；
2. `FlushMaxMs`、`AppendMaxMs`、`TrimMaxMs`、`ScrollMaxMs` 均 <200；
3. `Dropped=0`、`FileDropped=0`；
4. 曲线没有 UI 跳帧造成的视觉断线；
5. 控制、DO、持久化和序号红线继续全部通过。

然后按 8 h、24 h、72 h 顺序验收。该方案已并入 V2.12.0.23；未取得同一 V2.12.0.23 Git SHA、EXE SHA、配置 SHA 和连续 RunId 的现场证据前，只能认定软件根因已整改，不能签字为无人值守生产验收完成。

每一阶段正常停止并封存后，唯一正式验收入口为：

```powershell
.\Tools\Invoke-Field-Acceptance.ps1 `
  -DataDirectory '\\wj-epb\EPB_Data\10358-029_V2.12.0.22_封存目录' `
  -ReleaseDirectory '.\MTTfTest\bin\Release' `
  -MinimumHours 2
```

该入口先执行 `Verify-Release.ps1 -RequireDeploymentApproved` 的全包递归校验，再把已验证的 ProductVersion、EXE SHA、配置 SHA、GitCommit 和 BuildUtc 绑定到运行会话。以下任一情况都必须失败：旧版本日志、同版本不同二进制、配置被替换、`GitDirty=true`、未闭合会话、多个 RunId 拼时长、缺少分阶段 UI 指标，以及使用 `quick/none` 跳过完整日志、事故或 SQLite 扫描。历史目录快速诊断仍可直接调用 Python 工具，但其结果不得作为正式放行签字。
