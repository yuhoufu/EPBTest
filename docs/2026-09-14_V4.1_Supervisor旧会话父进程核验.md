# V4.1 Supervisor 旧会话父进程核验

## 已确认的问题

Supervisor 的 `MonitorLoopAsync` 在会话 Watchdog 退出后，读取已有 `SupervisorLaunchRecord` 并调用 `StartFromRecord`。旧记录保存了会话、EXE、项目及子进程身份，但未保存原主程序 PID 和启动时间。因此仅凭该记录不能判断旧会话是否已经被独立恢复替代。

## 本轮修改

- 新建会话记录保存请求主程序的 PID 和启动时间。
- 每次 `StartFromRecord` 对独立绑定安装核验注册项目、数据库／配置身份、持久状态和父进程操作系统身份。
- 维护、独立安全清理及未许可的接管阶段拒绝重建。
- 活动批次只允许当前 Controller；替代进程消费凭证后、提交新批次前，可以凭 Ticket.Consumer 身份启动其监督。
- 已停止且未 armed 的旧批次允许新手动主程序建立监督，但仍验证项目及准确的存活进程路径、PID、启动时间。
- 旧记录缺少父身份时，在独立绑定安装中拒绝猜测恢复；未绑定的旧模式保持原行为。
- 绑定独立安装后，Supervisor 拒绝不能绕道工程模式直接启动 Watchdog；即使旧正式模式标记丢失，也不允许此回退。
- 默认 `SystemSidecarProcessLauncher` 也拒绝独立绑定主程序直接创建 Watchdog。生产 `WatchdogRuntime` 已显式传入 `SupervisorSidecarProcessLauncher`。

## 验证范围

Debug x86 构建与独立测试结果记录在仓库根 `Codex/v41-session-parent-*`。新增状态测试覆盖当前父身份、旧 PID、PID 启动时间变化、清理期间禁止重建及停止后的新手动进程监督许可。

这些测试没有在 jxcq 上实际启动 Supervisor 会话，也没有证明旧 SafetyAgent 已退出。主程序存活不等于试验恢复。

## 尚需完成

父身份核验只是重建入口的约束。检查与子进程创建之间仍需通过持久子进程登记及接管清理解决并发窗口；现有存活 Watchdog／SafetyAgent 的精确身份登记、禁止再次拉起和硬件句柄释放还未全部完成。不能将本修改单独视作完整独立接管交付。

父进程核验修改的 Debug x86 构建、worker 17/17、状态 161/161、完整 AdaptiveControl 833/833、磁盘 58/58、电源 19/19 均实际退出码 0；日志分别为仓库根 `Codex/v41-session-parent-build-final.log`、`v41-session-parent-process.log`、`v41-session-parent-adaptive-full.log`、`v41-session-parent-disk.log`、`v41-session-parent-power.log`。

完整回归后补充的工程直接启动限制已重新完成 Debug x86 构建（`v41-session-parent-direct-build.log`）；针对性 Fallback 回归单独记录在 `v41-session-parent-direct-fallback.log`，不将之前的全量结果冒充补充修改后的再次全量结果。本轮不操作 WJ-EPB。
