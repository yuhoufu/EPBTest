# V4 完整包的会话监督组件安装补齐

## 问题和范围

真实主窗接管测试发现，新安装的独立恢复包仍需要 Supervisor 和交互 SessionAgent 承载原主程序会话。只注册独立 SYSTEM 执行器及最高权限启动任务，不能证明新安装具备完整启动链。本次补齐原有会话监督组件的注册和生命周期，不把它们作为独立执行器的存活依赖。

## 实现

新增 Tools/Manage-SessionHost.ps1，归属检查先于维护：校验服务安装路径、SYSTEM 身份以及登录任务的唯一动作路径；其他安装的注册不改动。安装注册原有固定名称的 Supervisor 和 SessionAgent 登录任务；旧主程序登录任务如属于本安装则停用，避免第二个旧启动入口争用。不会因此开始试验。

安装、修复、升级完成及回滚恢复会话监督；文件替换前先停止本安装监督和登录代理。卸载只删除归属确认的注册。主程序及会话辅助进程仍活动时拒绝维护；代理清理核对 PID、启动时间及路径，清理后再次确认。保留其他安装及项目数据。

SCM 停止/启动使用 ServiceController 请求后限时等待 15 秒，避免 Stop-Service 同步等待使后续期限失效。失败保留维护与文件事务记录，不报告安装成功。

安装包文件清单纳入新脚本，落到安装目录 Tools，并随修复、升级文件事务管理。旧包和标签保留，回滚仍读取原包清单。

## 已有验证

- 归属保护模拟 8/8：空注册、正确注册、其他安装路径、非 SYSTEM 服务、外部登录任务、多动作任务。无 SCM/任务修改。
- 卸载结果与失败重试、升级最终登记、文件修复、已提交升级回滚脚本回归通过。
- 顶层一键包校验和 RecoveryGuard 包兼容性入口通过。入口明确物理硬件、计数落盘和长期运行未验证。
- Windows PowerShell 5.1 入口测试曾暴露本次编辑丢失 UTF-8 BOM，已恢复 BOM 后重新通过；不能仅以 PowerShell 7 解析通过代表 5.1 兼容。

证据：仓库根目录 Codex/v41-sessionhost-regression。

## 未完成的验收

本记录不代表新脚本已经通过真实 SCM 安装/修复/升级/卸载。仍需 jxcq 隔离环境的完整安装包生命周期验证，并在退出后恢复原监督注册，确认无残留任务和进程。真实电流、压力及继电器执行仍需台架验收，本轮不部署 WJ-EPB。
