# wj-epb：EPB 3.0.0.0 与独立 RecoveryGuard 部署测试方案

状态：验收准备方案，尚未批准执行，尚无完整安装包交付结论。现场路径、当前版本、账户及配置必须在授权检查后填入，不沿用推测值。用户再次明确确认部署前，不停止旧版、不安装、不切换入口、不启用自动恢复。

## 目标与安全边界

旧版持续试验期间完成可离线完成的工作，把中断窗口压缩为“安全停止和数据收口→切换→启动确认”。不承诺未经测量的秒级切换时间。不以传输全量日志或临时现场编译占用切换窗口。

所有设计恢复入口采用同一要求：确认真实停滞，排除正常自学习、冷却、保压及有进展的等待；实际发出断能和卸压；以命令之后的新鲜电流、压力反馈覆盖全部受影响通道和共享液压组，达到安全阈值并满足稳定时间，才允许收敛旧实例和续测。命令成功、缓存低值、进程重启、界面显示运行都不能单独证明恢复成功。恢复完成必须有匹配试验身份的真实业务提交。

当前硬件范围不含 CAN，不进行 CAN 检测，也不将遗留库或设备状态列为门禁。I0050 液压恢复状态发布一致性另立第二步验证，不混入本轮通过结论。

## 交付前必须完成

| 项目 | 必须提供的证据 | 当前结论 |
| --- | --- | --- |
| 源码及构建 | 审查后的提交身份、构建参数、完整依赖和文件哈希 | 待冻结 |
| 本地回归 | 同一产物的控制、持久化、电源、Guard 结果及失败处置 | 进行中，历史通过不替代最新结果 |
| JXCQ 开发验证 | 隔离目录、主机身份、文件哈希、测试原始日志 | 已有六组验证，非完整安装验收 |
| 完整包安装和回退 | 主程序、Guard、SafetyAgent、协议/共享组件的一致身份；安装、移除、恢复入口记录 | 待完成 |
| 停滞恢复 | 真实动作、新鲜反馈、旧实例退出、匹配续测、真实提交 | 软件与硬件证据尚未闭环 |
| 现场切换授权 | 用户明确确认本次版本、范围和试验窗口 | 尚未取得 |

不能将主程序压缩包当作独立 Guard 完整交付；不能用测试报告、旧版本报告或脏源码候选标记冒充正式验收。构建入口与模式门禁见[完整安装包交付入口核对](2026-09-09_完整安装包交付入口核对.md)。

## A. 切换窗口之前

1. 本地完成构建、依赖校验、版本检查、故障注入和回归。冻结一个候选身份，列清未验收项目；现场不即时修改候选文件。
2. JXCQ 先验证该候选的完整安装/回退流程。使用独立目录及明确的测试账户/入口，确认不会与既有试验实例争用资源；测试自动动作仅可针对隔离测试实例。
3. 获得相应现场准备授权后，核实 wj-epb 主机、实际运行路径、版本、命令行、工作目录、数据目录、运行账户、Guard/旧监督组件及自动启动入口。记录配置哈希、当前试验身份和已耐久提交水位，不输出凭据。
4. 保存桌面快捷方式原文件及 TargetPath、Arguments、WorkingDirectory、IconLocation；分别检查现场用户桌面和公共桌面，避免遗漏同名入口。保存相关服务/任务的原始配置和启停状态。
5. 新版放入独立版本目录；旧版目录、配置和入口备份保持完整。只传输哈希有变化的文件，落盘后核对完整清单。不可覆盖运行中的二进制、配置或数据库。
6. 提前检查磁盘空间、必需依赖和包完整性。数据备份采用已支持的一致性方式，不把运行中的数据库文件复制视为可靠备份。大量历史日志留在现场，优先回传故障时间段、索引及必要证据；不得为提速删除原始数据。

## B. 用户确认后的受控切换

按以下顺序记录开始/结束时间、操作者、候选哈希及每个门禁结果；任一门禁不满足即停止后续步骤。

1. 确认现场操作者、试验允许中断窗口、设备安全状态及回退版本。确认不同时运行两套监督恢复控制者。
2. 通过受支持的停机流程停止旧试验并抑制其自动重启；实际断能、卸压并确认新鲜反馈安全。不得用强杀代替设备安全确认。
3. 等待本轮数据收口、耐久写入和旧进程/后台任务退出。记录最终提交水位；若仍有未终结硬件动作或数据任务，不允许新版抢占资源。
4. 按已在 JXCQ 验证的安装事务切换完整组件及配置。现场配置须经兼容校验，不用仓库默认值覆盖校准参数。安装自动恢复模式必须与真实批准的验收模式一致，不绕过发布门禁。
5. 从将交付给现场人员的桌面入口启动，核实实际进程路径、版本、参数、工作目录及监督组件身份。仅看到“3.0”图标或窗口标题不算验证。
6. 检查试验身份、通道启用状态、校准和已有数据连续性，再按获准范围开始自学习/正式试验。未通过硬件验收的自动动作不能擅自启用。

## C. 现场测试矩阵

| 场景 | 通过条件 | 必须保留 |
| --- | --- | --- |
| 冷启动/续接 | 启动入口正确，无双实例，试验身份和提交水位正确 | 路径、版本、启动记录、水位 |
| 正常自学习 | 完成规定学习与封存，无无进展阻塞，不误触发恢复 | 阶段进展、封存结果、耗时 |
| 正式运行 | 实际采集、控制与持久化持续提交，数据不重复、不丢失 | 原始数据及提交序号 |
| 正常等待 | 冷却、保压、学习等有合法状态和期限时不误判停滞 | 等待原因、期限、进展 |
| 受控停滞 | 在明确批准且安全的故障注入下识别停滞；断能卸压→新鲜安全反馈→旧实例终结→正确续测→真实提交 | 同一事务完整时间线、全部影响范围、原始反馈 |
| 不安全/失新反馈 | 不能重新送电；明确记录未确认原因，允许人工安全处置 | 反馈年龄、阈值、拒绝原因 |
| 恢复中人工停止 | 撤销旧恢复权限，迟到结果不改写新状态、不再启机 | 控制权代次与进程/任务记录 |
| 重复失败 | 不无限重启、不重复计圈、不丢数据；策略与报告一致 | 尝试记录、提交水位、终态 |

不得通过制造危险物理状态来测试拒绝门禁；现场故障注入须另行明确批准。记录每项实测耗时，再据此评价“及时恢复”，不把单元测试耗时当作现场恢复时延。

## D. 立即停止测试和回退

出现安全反馈不可确认、数据连续性缺口、错误试验身份、重复监督实例、错误入口或持续无进展时，停止进一步自动测试并保存证据。

1. 先安全停机并确认电流/压力；无法确认时保持禁止启动，交现场人工处置，不直接拉起旧版。
2. 确认新版及其自动启动/恢复任务不会再次拉起，所有在途硬件动作已终结。保存新版日志、试验数据、提交水位和故障事务；不删除新版本产生的数据。
3. 校验旧版是否兼容新版写入的数据/检查点。兼容性未知时禁止直接打开；保留原数据，按已验证的备份/迁移方案和用户决定恢复，不能盲目覆盖旧备份造成已完成试验丢失。
4. 恢复旧版整套组件、原配置和原监督状态；恢复原快捷方式文件及四项属性，处理本次新增入口时只操作已记录的精确目标。不能仅替换 EXE 或改图标。
5. 由恢复后的桌面入口实际启动，核实真实进程路径/版本/工作目录、Guard 身份及数据水位。确认旧版实际续跑并产生业务提交后，才记录回退成功。

“回退后桌面仍是新版”的具体原因尚须现场快捷方式和安装记录证明；可能的入口残留不能当作已确认根因。上述入口备份和实际启动验收用于避免同类遗漏。

源码已确认旧安装器存在按名称删除旧入口且无原链接备份的机制。本次已补完整链接备份和目标归属检查，范围与剩余事务缺口见[快捷方式回退补强记录](2026-09-09_桌面快捷方式回退缺口与备份补强.md)。该补强尚未在现场执行，不能替代本节的整套回退验收。

## E. 结果报告与证据

新增授权例外：对于确认完全卡死且无法协作断能的旧主程序，允许先精确终止旧实例，再独立断能、卸压，取得动作后的新鲜电流和压力安全证据后续测。这不是一般回退或正常等待时的终止许可，也不代表现在批准现场部署。实现及测试边界见[完全卡死主程序兜底](2026-09-09_RecoveryGuard完全卡死主程序兜底.md)。现场验收应增加停止撤销、独立输出失败、反馈陈旧/不安全、重启后无业务提交等反例，均不得被判定为恢复成功。

每次执行建立唯一记录，列出主机、时间、授权、源码提交、包哈希、安装目录、配置哈希、组件身份、切换中断时长、测试范围、每项结果和原始证据路径。软件通过、硬件通过、未测、失败必须分列。

首轮回传以小型结果摘要和必要故障片段为主；完整数据在现场保留并建立索引，后续按需分批取回。不能因回传未完成阻塞已安全稳定运行，也不能以提速为理由缺失安全与数据证据。

当前实现审查见[恢复入口统一门禁审查](2026-09-09_RecoveryGuard恢复入口统一门禁审查.md)，JXCQ 开发验证见[增量验证记录](2026-09-09_JXCQ恢复策略增量验证记录.md)。这些文档均不等同于现场验收通过。
