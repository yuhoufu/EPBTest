# V4.1 独立协作停止接入与验证

基线 `29f8c88`。本轮补齐此前运行时文档中“主程序未接入 CooperativeStop 请求”的代码入口，仍不是完整现场安装包验收。

## 生产路径

监控初始化完成后，如果通过独立安装/恢复入口绑定了当前项目，创建每秒轮询的后台观察器。观察器读取持久恢复事务，核对当前控制进程身份及 RunId/RunEpoch，只对当前 CooperativeStop 请求调用一次原有 `EpbManager.StopAllAsync`，来源为 SystemFault，不将故障接管变成人工停止。

该观察器不占用 UI 或轻量状态发布线程。请求执行期间不重入；监控窗关闭后停止后续轮询。已经进入停止的工作不会因关闭窗体被伪装成已取消，若其卡死仍由外部执行器按期限清理旧进程。

主程序只有取得 LogicalQuiescenceConfirmed 才写入协作完成回执。持久写入重新核验精确控制者、请求、代际、RunId、RunEpoch、当前阶段及期限。相同有效回执幂等；迟到、外来、旧批次或阶段推进后的回执拒绝。旧回执可留作诊断，但不同请求不能复用。

执行器收到当前有效回执可以提前进入 PowerOff；没有回执仍按原定最多 25 秒期限接管。协作回执不表示独立硬件安全确认，不签发启动票据，也不解除 SafetyCleanupPending。后续独立电源 OFF、精确旧进程清理、DO/AO/压力安全步骤全部保留。
