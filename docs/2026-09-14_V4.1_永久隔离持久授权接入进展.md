# V4.1 永久隔离持久授权接入进展

基线 `8da8179`。本轮接入永久隔离的写入方向，尚未完成全部通道资格生命周期，不能发布现场候选包。

## 代码发现

控制器原有永久报警路径持久修改项目 TestConfig.xml，再通过非关键 UI 观察者更新界面，但没有同步独立运行意图的 PermanentChannels。独立重启目标因此可能与项目永久报警事实不一致。此外，独立配置摘要仍包含报警锁存和连续超周期计数；这些运行状态变化可能阻止健康通道通过重启时的配置身份校验。这是代码路径确认，不能据此代替现场事故日志证明每次停机均由它导致。

## 本轮修改

- 控制器在原有持久禁用事务中、写入项目 XML 之前，同步调用独立资格写入器。传入当前 RunChainIdentity、整组通道、故障代码和关联事务。此调用不通过 UI 事件，沿用既有故障持久化路径；仍需故障注入验证调用耗时和并发行为。
- 独立状态存储按精确控制者和 RunId/RunEpoch 核验，原子加入整组 PermanentChannels，递增意图修订并记录审计。重复整组隔离幂等。已完成恢复事务更新绑定修订；未完成事务的票据被撤销，仍须完成必要安全清理。
- 人工新批次从配置导入已锁存永久报警，并与持久隔离并集；普通重新开始不能清除隔离。
- 独立配置摘要升级为 `IndependentEligibilityV1`。仅将 Enabled、永久报警锁存/描述字段、连续超周期计数/时间作为受其他机制管理的运行字段剔除；通道身份、目标次数、安全参数继续参与摘要。原恢复检查点摘要保持原行为。
- 旧 `IndependentSelectionV1` 注册不能直接沿用，需要重新生成注册和摘要。本轮没有迁移现场注册。

持久资格写入失败会使既有永久禁用持久事务返回失败并保留诊断，不伪报成功。不能宣称在任意磁盘失效下永久事实已经保存。
