# V4 隐藏 MDI 监控窗收尾后未释放修复

## 已证实原因

真实主窗、监控窗和原控制器的隔离模拟试验在停止并完成落盘后没有退出。`Codex/mts-1a17c620/stdout.log` 持续记录 `Lifecycle=Stopping`、`Reentry=3`、`Shutdown=RanToCompletion`、`MonitorDisposed=False`。UI 定时器仍执行，所以该证据不支持“UI 线程卡死”或“Watchdog 关闭任务尚未完成”。

`AcceptOperatorClose()` 为了快速关闭可见界面调用 `Hide()`。对于 WinForms MDI 子窗体，隐藏会销毁窗口句柄，但不释放 Form 对象。原最终收尾路径要求 `IsHandleCreated` 才调用 `BeginInvoke(Close)`，因此隐藏的 MDI 子窗体永远跳过最终关闭。

在本机使用普通 WinForms 父子窗单独复现：Shown 时 Handle=True/Disposed=False；Hide 后 Handle=False/Disposed=False；直接 Close 后 Handle=False/Disposed=True。无需连接任何现场设备即可复现。

这解释本轮真实监控窗模拟用例的退出失败；没有证据将其直接等同于 WJ-EPB 历史 DEV 采样中断的原因。

## 修改

- 原停止、安全授权、落盘与资源收尾仍须完成；只有既有关闭回执允许退出，才进入最终关闭。
- 有窗口句柄时保持异步投递关闭；没有句柄时在原 UI 上下文直接完成授权后的关闭，释放隐藏的 MDI 子窗体。
- 无句柄的 `Form.Close()` 直接 Dispose，不会触发 FormClosed；因此授权关闭入口在释放完成后补充 Closed 生命周期。
- 集成测试以 Disposed 作为子窗真正释放的证据，随后模拟关闭主窗；不再依赖隐藏窗可能不触发的 FormClosed。

没有新增强杀、固定等待、安全旁路或现场部署。本轮修复不改变故障检测门限和恢复目标集合。
