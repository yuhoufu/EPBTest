# V4.1 近零电流独立重试与持久隔离接入

## 源码确认的问题

`EpbManager.ResolveChannelFaultRecoveryPolicy` 将 `OpenCircuitOrOutputFault` 固定归为本批次禁用；启动定位的硬件确认分支也使用本批次禁用。它们不是持久隔离，普通重启会重新检查该通道。既有基础设施切换窗口重分类只能覆盖已识别的恢复窗口，不能证明窗口之外的低电流一定来自卡钳或线束。

此次改动不将输出命令受理、DAQ 有效及软件供电许可解释为物理供电电压已经正常。现场低电流的物理根因仍未确认，NI 驱动故障也未因此证明或修复。

## 已实现的处理

在绑定独立恢复安装的主程序中，正式报警后台工作项和启动定位失败入口均接入独立持久记录：

1. 首次不充分证据的近零故障保存通道、首发运行批次和独立事务代际。通道本批次停止，但仍在独立恢复的有效目标内，由既有停滞／启动期限触发接管。
2. 同一批次重复消息、原进程在接管阶段的迟到消息，不算新的重启失败。
3. 独立事务代际已推进，且替代进程提交了新的运行批次后再次发生同通道近零故障，原子加入持久永久隔离集合并撤销旧恢复凭证。其他通道不会被加入隔离集合。
4. 普通开始保留历史。明确人工解除隔离的既有事务才删除该通道的近零重试记录，并继续保持暂停，不能仅解除隔离就自行续测。
5. 若独立替代批次通过了真实数据库推进验证，则结案本次非永久故障的待重试记录。以后新发生的故障按新事件处理；仅启动成功不能结案，永久隔离不能由验证自动清除。

正式报警的记录运行在既有报警后台任务内、安全停止请求之后、报警灯和快照等待之前。启动定位使用后台任务写入，避免把持久写入加到采集回调中。

独立记录先提交，再沿用项目永久报警 XML 持久化入口；XML 后续写入失败不会撤销独立侧已经保存的禁止恢复状态。没有独立安装绑定的原入口保持原策略。
