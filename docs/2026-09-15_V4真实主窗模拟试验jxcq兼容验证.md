# V4 真实主窗模拟试验 jxcq 兼容验证

## 范围

在 jxcq 的真实交互会话运行 `Main_Frm`、`FrmEpbMainMonitor`、原 EpbManager、采集回调与 EpbDiskWriter；仅设备工厂使用测试模型。目标为 4、7 通道各完成五圈自学习和三个正式周期，再通过原停止与关闭入口正常退出。

本次验证覆盖 `97b1b8e` 的生产关闭修复。测试使用本地已通过的 `mts-62e38fad` 二进制组合；它包含单次 Disposed 订阅修复，不包含之后新增的 MDI 空闲快捷测试命令。不是现场安装包，也不将测试宿主等同于正式 EXE 全入口。

测试模型根据原控制输出产生采样，原控制器计算周期并写盘。没有向数据库直接插入“成功圈”。独立 SafetyAgent 测试替身只拒绝执行，不访问硬件，不返回安全成功回执。本次未验证 SYSTEM 服务强制接管、硬件安全工作进程或跨进程续测。

## 环境与隔离

- 主机 `MT-20251206JXCQ`，远端 PowerShell `5.1.19041.7725`。
- 交互会话 1；独立测试任务 `EPB-Isolated-Monitor-real1` 使用交互用户最高权限启动。
- 隔离根目录 `D:\mts-jxcq-real1`，新建项目 `D:\mts-jxcq-real1\D\P`。不复用现场计数或数据。
- 传输归档 `monitor-real1.zip`，41,787,206 字节，SHA-256 `641BDDB588BC77539356549707AE33F7010F2CB53F4DA185EDD7BAA74163D15C`。远端在展开前重新计算并核对摘要。
- 测试子进程上限 250 秒、Private Bytes 上限 1 GiB；诊断宿主上限 310 秒、Private Bytes 上限 256 MiB，调用方独立检查物理可用和提交余量。
- 使用 DCOM/CIM，无 WinRM 会话。脚本、哈希、所有权、资源与结果证据保存在主仓库 `Codex/v41-jxcq`。

## 执行记录

最初两个诊断宿主在读取所有权握手文件时退出，第二次捕获明确的 IOException：文件正被占用。它们没有创建测试项目或启动控制器。第三版将读取限定为八秒内重试，保留原 PID 与启动时间核验；不是略过所有权校验。

第三版启动的真实测试控制器为 PID 7552、启动 UTC ticks `639250490496099210`，会话 1。实际试验、正常停止和窗口释放完成；包装脚本未保留原进程句柄，PowerShell 5.1 返回的 ExitCode 为 null，因此整轮按失败保留。包装脚本清理了旧测试子进程 23004；不能将它记为全部自行退出。

第二轮保持测试二进制不变，仅修正包装脚本：Start-Process 后立即持有 Process.Handle，等待退出后读取真实退出码，null 仍明确判失败。对应行为也在本机 Windows PowerShell 5.1 的独立短进程用例确认返回 0。

## 最终结果：正常试验与退出通过

第二轮根目录 `D:\mts-jxcq-real2`，专属任务 `EPB-Isolated-Monitor-real2`。测试主进程 PID **17248**，启动 UTC ticks `639250497383150174`；包装进程 PID **17332**，启动 UTC ticks `639250497373564620`。北京时间 **2026-09-15 14:17:50** 完成，结果：

- 4、7 通道各五个已完成学习圈及三个正式周期；正式周期为 1、2、3，没有其他通道记录。
- 六条正式记录均为 completed，mechanical_completed=1、采样数非零、结束时间存在；六个波形文件均存在且摘要已核对。
- 主程序测试宿主返回退出码 0，stderr 为空；主窗、监控窗正常关闭。
- SafetyAgent 拒绝执行替身未被调用；未伪造安全阶段成功。
- 第二轮没有强制清理子进程，`childCleanup=[]`。测试主进程 Private Bytes 峰值 **134,561,792 字节**。

独立采集器在试验结束后另建短时诊断连接，确认两个项目内程序均不存在、专属任务不存在，才复制稳定数据库和指定六个正式波形文件。回传数据共 **1,425,614 字节**，没有采集全部原始滑动数据。

证据位于主仓库 `Codex/v41-jxcq/monitor-real2-evidence/`：

- `worker-result.json`：真实退出码、测试异常、峰值内存、子进程清理。
- `controller-owner.json`、`worker-owner.json`：实际 PID、启动时间、交互会话。
- `collection.json`：任务不存在、项目进程数为 0、逐文件大小和 SHA-256。
- `D/P/index.db` 及 `D/P/HistoricalSnapshots/`：回传的只读核验输入。
- `database-verification.json`：本地独立核验，包含数据库行和六个波形摘要；验证器同时要求远端退出码为 0，不能仅凭 stdout 的 PASS 放行。

回传 ZIP 的 SHA-256 为 `C4658E3C9459F29C7213B095DAE6FA6FAACF31C9F09C37CB76CE26AD1909B31B`，传输后重新计算一致。第二轮数据库核验脚本退出码 0；第一轮仍因退出码缺失被验证器拒绝，没有改写为通过。

## 资源与会话收尾

六次诊断宿主（两次启动前失败、两次测试、两次采集）的 `*.resources.json` 均记录 `processExited=true`、`winrmSessionsCreated=0`。最后复核可用物理内存 **8,357,642,240 字节**，提交用量 **13,988,274,176 字节**，提交上限 **19,494,666,240 字节**。没有残留本任务控制程序或任务计划。第二轮业务用例是正常停止后退出，不是自恢复成功证明。

## 剩余验收

独立执行服务接管、精确终止旧会话、消费一次性凭证、真实主窗从已提交计数续测及完整故障矩阵仍须串联。此正常试验用例不能代替这些验收。真实硬件安全执行仍应单列台架验证；本轮没有连接或打断 WJ-EPB。
