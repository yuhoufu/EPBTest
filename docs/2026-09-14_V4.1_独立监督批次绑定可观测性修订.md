# V4.1 独立监督批次绑定可观测性

## 问题与修改

原 executor-observation.json 只有安装 ID、时间和文字 Detail；即使持久状态已绑定新进程，外部状态检查也无法明确识别服务观察的 RunId/RunEpoch、精确进程身份或恢复事务。不能据此解释“服务活着但试验是否仍停滞”。

现在服务发布 schemaVersion=2 观察：StateRevision、RunId/RunEpoch、ControllerPid/StartUtcTicks/SessionToken、BindingState、TransactionId/Phase、LastTransactionVerified。所有字段来自同一次有效持久状态读取，Detail 限 512 字符。新 DTO 独立于 Windows 服务宿主，供实际跨进程测试复用。

管理脚本 Status 有界读取至多 16 KiB 的观察文件，仅当安装身份匹配、版本为 2、时间年龄 0～15 秒、服务 Running 且观察 StateRevision 与当前持久状态一致时报告新鲜绑定。过期、缺失、旧协议或状态已变化均为 STALE_OR_MISSING；原始批次/事务字段仍明确冠以 Observed。

LastTransactionVerified/HistoricalTransactionVerified 只是历史事务结果，不宣称当前控制动作还在继续。CurrentBusinessRecovery 保持 UNVERIFIED，要求另查动作、计数及正式提交。观察失效不撤销授权、不触发人工停止、不阻断独立接管；本次没有新增依赖旧 Watchdog/UI 安全回执的恢复门槛。
