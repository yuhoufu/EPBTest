# LastKnownGood 晋升证据边界复核

状态：已按既有 V2.14.2 决策澄清，不作为软件缺陷补写行政门禁。本文不是晋升批准，不授权 wj-epb 部署或改变试验条件。

## 已核实的现状

- `Tools/Install-MTTFTest-Unattended.ps1` 为命令行兼容保留 `SoakEvidencePath`，晋升分支不读取它。当前晋升强制检查程序文件和包身份，不把现场流程字段当作机器安全许可。
- `docs/02_Issues/2026-09-02_V2.14.2.0_取消发布审批门禁与正式包简化部署说明.md` 记录了现场使用方已确认的决策：24/72/168 小时记录由操作人员管理，可记录但不阻断显式 LKG 晋升；文件哈希、组件版本、槽身份和设备安全门禁继续强制。
- 旧文档 `02_Issues/2026-09-01_V2.14.0.0_无人值守自恢复架构彻底修复实施与验证.md` 给出 168 小时 PASS 后晋升的示例。这不构成当前实现已经支持对应证据的证明。
- `Tests/AdaptiveControlTests/I0049RecoveryTests.cs` 的 `RunSoak` 生成 `soak-status.json`：要求 21600 秒，即 6 小时，循环运行软件回归；固定发布 `hardwareTestPerformed=false`。
- `Tools/Read-I0049SoakStatus.ps1` 仅以允许原子替换的共享方式读取该 JSON，并没有批准晋升、核验包哈希或核验现场业务数据。

## 不得混用的证据

| 证据 | 可证明 | 不可证明 |
| --- | --- | --- |
| 包身份/文件清单校验 | 所校验时点的文件与清单一致 | 现场学习、正式提交、自恢复通过 |
| I0049 六小时 PASSED | 对应软件循环达到自身通过条件 | 168 小时现场试验或硬件恢复验收 |
| JXCQ 隔离策略回归 | 对应软件策略及注入场景 | wj-epb 的真实硬件行为 |
| 人工提供的证据路径 | 指定了一个文件 | 文件可信、属于当前包或满足晋升条件 |

## 运维侧仍需完成的证据链路

1. 明确当前版本的晋升证据生产入口和契约。不能把旧示例的时长或新设 `passed=true` 字段直接当成已实现验收。
2. 证据需绑定实际候选包身份、主机、项目和观察期间；不能仅凭版本字符串匹配。
3. 按经确认的现场验收要求记录学习完成、连续真实业务提交及恢复注入结果；软件模拟必须单独标记，不能代替硬件验证。
4. 如未来决定恢复机器强制的现场证据门禁，必须先形成新的明确需求并定义可信生产者、签名/权限、身份绑定和跨阶段恢复契约；不得仅凭旧示例或任意 JSON 字段恢复旧规则。
5. 当前应在运维验收记录中封存所使用证据及摘要，使后续能够追查依据；软件继续对包与槽身份 fail-closed。

本复核不宣称 168 小时或硬件验证已经完成，只确认“未读取 SoakEvidencePath”符合已有产品决策，不应在本轮擅自改变。I0050 液压恢复状态发布一致性仍为独立事项。
