- **整改版本**：`V2.13.0.40`

本次故障是两个问题的叠加：

1. EPB7 的 `0.082 A` 近零电流证据仍指向该通道的卡钳、线束、接插件或驱动输出支路开路，单凭封存数据不能进一步断言一定是卡钳本体。

## 3. 近零电流整改

### 3.1 判定证据

启动定位不再用 `ForwardPositioningFault` 覆盖真实故障。仅当以下证据同时满足时，规范化根因才判定为 `OpenCircuitOrOutputFault`，故障归类为 `HardwareConfirmed`：

- 正转命令已被接受；
- DAQ 样本新鲜；
- 程控电源许可有效；
- 当前不处于 DAQ 恢复、电源切换或供电恢复窗口；
- 电流连续约 `200 ms` 不高于 `0.10 A`。

`StartupPositioningResult` 已增加命令、DAQ、供电、基础设施切换、实测电流、阈值和持续时间证据。首发故障快照以结构化 JSON 保留，后续错误不能把原始近零电流证据覆盖掉。

### 3.2 隔离语义

- 新增 `FaultRecoveryPolicy.CurrentRunDisableChannel`。
- 确认近零电流后，通道锁存 `AlarmStopped`、立即关闭该通道输出并从本次启动集合移除。
- 该故障不进入 `SoftwareSelfHealing`，也不执行机械重试。
- 不写入 `PermanentAlarmLatched`，不修改项目永久启用配置。
- 当前进程内禁止再次启动该通道；新进程按项目原始配置重新检测。
- 正式循环中的 `OpenCircuitOrOutputFault` 使用相同的当前运行隔离策略；过流、高平台等既有永久故障策略保持不变。

### 3.3 报警

报警包含通道、实测电流、阈值、确认时间、可能原因和处置。示例：

> EPB7 上电后连续约200ms电流≤0.10A（实测0.082A），疑似卡钳/线束/驱动支路开路；本次运行已隔离，下次启动重新检测。

DAQ 陈旧、供电许可缺失或基础设施正在恢复时，不生成硬件确认报警，继续按软件瞬态处理，避免把系统切换窗口误报为卡钳故障。

## 4. 全场景有界退出整改

### 4.1 单一关闭事务

- 首次关闭请求建立唯一 `_watchdogCloseTask`，重复点击、人工停止、启动取消、学习中关闭和 Watchdog 接管均加入同一事务。
- 批量启动取消不再提前拆除 Watchdog 会话，只发布运行停止事实。
- 已失败或已完成的关闭事务不会被重复点击替换成第二个事务。
- 界面显示实际阶段和剩余时间，不再以“可重试关闭”引导用户建立竞争事务。

### 4.2 最终安全事实与拆除顺序

- `WatchdogClosingTombstone` 新记录升级为 schema 3，仍兼容读取 schema 1/2。
- Controller 进度只记录阶段和版本，不能推测或伪造压力、持久化、连续性、逻辑静默等安全事实。
- 最终 `StopSafetyResult` 一次性写入电机、电源、压力、持久化、连续性和逻辑静默的真实结果，并设置 `FinalSafetyResultCommitted`。
- 最终结果耐久提交成功前，禁止关闭 Pipeline、Engine 和 Journal；提交成功后才恢复同一个保留关闭事务并完成拆除。
- `CanRestartInProcess` 继续使用严格安全条件，应用退出授权与进程内重启资格完全分离。

正常路径顺序为：`StopAll -> 最终证据耐久提交 -> 资源释放 -> Watchdog终态 -> 传输拆除 -> 窗口关闭`。

### 4.3 30 秒硬截止

- 首次关闭请求耐久保存应用退出意图，绑定 `SessionId/Generation/Lease`、停止事务、主进程 PID、进程启动时间、请求时间和 `T0+30s` 截止时间。
- 主程序线程池退出监督器与独立 Watchdog Host 同时守护截止时间，避免 UI、厂商 SDK 或异步收口卡死后无人推进。
- `T0+25s` 开始生成有界诊断，诊断最长受限且不能推迟截止。
- `T0+30s` 主程序仍存在时，主程序先执行自终止；Watchdog 仅在 PID 与启动时间双重匹配后兜底结束精确进程。
- PID 或启动时间不匹配时禁止结束进程，避免误杀复用 PID 的其他程序。
- 强制截止记录为 `ForcedDeadlineExit`，保留所有未确认的安全/数据事实，且不得触发自动重启。
- 下次启动会检查未确认的强制退出回执，向操作员明确提示上次异常退出。

无条件 30 秒截止是本版本确认的产品策略：即使断能或落盘结果仍未确认，也会结束主进程。风险不会被隐藏，而是写入耐久回执并在下次启动提示。
