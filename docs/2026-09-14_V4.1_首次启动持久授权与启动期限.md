# V4.1 首次启动持久授权与启动期限

承接 `29995a0`。本轮在修复工作树完成代码与本地回归，没有连接或部署 WJ-EPB、jxcq。

## 行为与代码接入

新增主程序人工入口参数 `--independent-installation <受保护注册文件>`。它与一次性恢复入口互斥，只绑定安装身份及进程执行撤权门，不自动开始试验；存在有效运行授权、活动恢复或安全清理义务时拒绝用该入口抢占，要求走原恢复凭证。

在监控界面人工开始路径，进入原 `StartBatchSynchronizedWithResultAsync` 前异步执行持久授权：

- 核对项目路径、数据库身份、软件身份与配置摘要。
- 生成新 RunId、递增 RunEpoch，以新 RunId 建立 RootRunId。
- 保存当次选择的通道、周期、启动预算和人工开始审计，保留既有永久隔离。
- 保存成功后才撤销旧人工停止界面凭证并进入原启动预检及控制流程。保存失败不通过这条入口上电，也不因等待磁盘而同步阻塞 UI 线程。
- 当前批次仍有有效运行目标时，存储层拒绝重复 Arm，不覆盖原批次和期限；人工停止后明确重新开始可建立新批次。
- 尚未创建批次的安装入口执行停止时，不伪造空 RunId 的停止事务。

原有未配置独立安装入口的软件启动方式保持原路径；**安装脚本和快捷方式尚需接通新入口，不能据此认为现有现场程序已经使用了新授权。**

## 持久启动期限

项目聚合状态升级为 schema 2，新增必需字段 `RunStartedUtcTicks`、`StartupDeadlineUtcTicks`、`RootRunId`。旧 schema 1 或缺字段不会猜测补齐；安装维护流程仍需处理旧状态，不允许直接覆盖迁移。

人工启动预算为：安装注册的启动定位预算 + 当次学习圈数乘周期 + 两个周期余量。定位预算默认 300 秒，可在安装注册中配置，校验范围为大于零且不超过 300 秒；总预算继续受运行意图上限校验。它是独立监督预算，不放宽主控制器现有硬件超时或安全门限。

Arm 和恢复新批次提交时，在同一个原子状态更新中记录开始时间和期限。读取校验要求期限与本批次预算一致；重新打开状态或服务进程重启不会延长它。恢复提交保留 RootRunId，不再把每一代父批次误当作根批次。

独立服务已移除上一轮 `InitialLearningIntegrationPending` 的检测禁用分支：有效存活批次可以积累只读数据库观察；启动期限内不因学习期间尚无正式记录发起停滞重启，期限后按停滞阈值及连续确认判断。服务重新启动仍需重新取得连续观察证据，因此到期不等于无条件立刻杀进程；数据库不可读也不伪造停滞。

## 发布前仍需完成

1. 人工取消勾选、部分暂停与通道完成必须持续同步持久意图；当前首次开始及整批停止接入不能替代这些事件。
2. 当前既有配置哈希保留 `Enabled`、`TotalCount`，而安装注册配置摘要是固定的。合法人工修改通道或目标后，需要完成配置身份与运行意图的受控更新，不能删掉安全配置校验来绕过，也不能让旧恢复集合重新启用人工停用通道。
3. 新协作停止阶段尚需主程序回执接入，原 Watchdog/旧侧车启动权和独立执行器仍需统一交接。
4. 临近目标、学习期间已完成通道的排除，液压期限、近零电流重试/隔离、完整跨进程注入、jxcq 安装修复卸载回滚仍需完成。
5. 安装注册、快捷方式、版本来源、标签和完整 7-Zip 包尚未交付。真实硬件安全仍需独立列出台架验收。

本轮为生产集成进展，不是“所有现场故障已彻底解决”的结论。
