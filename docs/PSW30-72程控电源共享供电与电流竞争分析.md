# PSW 30-72 程控电源共享供电与电流竞争分析

## 1. 文档目的

本文用于分析 EPB 耐久台架中“1台程控电源并联控制3个 EPB 工位”的共享供电风险，并为现场核验、控制整改和台架验收提供依据。

本文结论边界如下：

- **已确认：** 台架由4台程控电源控制12个 EPB，每台对应3个通道；`V1.2_1` 的批量启动相位未采用现场 XML 中的 `800 ms` 配置。
- **高可信关联：** 电源3所带 EPB8、EPB9 出现约20 A的平坦支路电流和，符合共享电源总限流造成支路电流竞争的机理。
- **尚未确认：** 事件发生时电源的实际 `ISET`、输出电压、输出总电流及 CV/CC 状态。因此不能将“20 A限流”写成现场既定事实，也不能据此单独认定卡钳机械损坏根因。

相关问题调查见：[EPB卡钳堵转未重复报警及齿轮损坏问题](02_Issues/EPB卡钳堵转未重复报警及齿轮损坏问题-20260728.md)。

## 2. 设备能力与证据等级

### 2.1 PSW 30-72 官方能力

根据 GW Instek 官方资料，PSW 30-72 是单输出、多量程可编程开关直流电源：

| 项目 | 官方规格/行为 | 本台架含义 |
|---|---|---|
| 输出电压 | 0～30 V | 仓库中出现的 `Voltage=50` 不可能作为该型号的直接有效输出设定 |
| 输出电流 | 0～72 A | 72 A是设备额定上限，不代表现场实际限流值 |
| 额定功率 | 720 W | 可用电压、电流组合仍受720 W功率包络约束 |
| 输出形式 | 单输出 | 同组3个 EPB 共享同一输出端和总电流能力 |
| 调节模式 | CV/CC，支持优先模式 | 负载总需求超过设定电流时可能从恒压转入恒流并降低输出电压 |
| 通信接口 | LAN、USB及模拟控制 | 可用于读取身份、设定、回读和工作状态并纳入试验留档 |

官方资料：

- [GW Instek PSW Series 产品页](https://www.gwinstek.com/en-US/products/detail/PSW-Series)
- [GW Instek PSW Series User Manual](https://www.gwinstek.com/en-global/products/downloadSeriesDownNew/6636/1330)
- [GW Instek PSW Series Programming Manual](https://www.gwinstek.com/en-IN/products/downloadSeriesDownNew/6634/1340)

PSW 在恒压模式下维持输出电压；当负载要求的总电流超过设定值时，电源可转入恒流模式，维持总输出电流并使实际输出电压低于设定电压。这里的“总电流”是电源输出端看到的合计负载电流，不是每个并联支路的独立限流。

### 2.2 额定能力、配置线索与现场事实

| 信息 | 当前值 | 证据等级 | 使用限制 |
|---|---:|---|---|
| PSW 30-72额定能力 | 30 V、72 A、720 W | 官方规格/已确认 | 不能替代实际设定值 |
| 仓库 `MaxCurrent` | 20 A | 配置线索 | 未取得事件时电源回读，不能写成现场事实 |
| 仓库 `Voltage` | 50 V | 冲突配置 | 超出PSW 30-72范围，可能是遗留配置、代理协议或型号不一致 |
| 现场实际 `ISET` | 未知 | 待验证 | 必须从四台电源逐台读取并留证 |
| 现场实际 `VSET` | 未知 | 待验证 | 不能由仓库 `Voltage=50` 推断 |
| 事件时 CV/CC 状态 | 未记录 | 待验证 | 支路电流和不能替代电源状态 |
| 事件时总输出电流/电压 | 未记录 | 待验证 | 需与各支路电流和DO同步采集 |

如果现场电压处于常见的12～14 V区间，则20 A对应约240～280 W，低于720 W额定功率；在这一条件下，若 `ISET=20 A`，首先起约束作用的是配置电流限制，而不是电源720 W额定功率。但由于现场设定尚未读取，该判断仅用于解释机理。

## 3. 台架共享供电架构

本地台架说明 `epb的控制和数据采集逻辑：.ini` 明确记录：12个 EPB 由4台程控电源控制，每台电源供3个通道；同一电源组内应错峰启动，避免同时出现最大电流。现场 `Config\TestConfig.xml` 的分组为：

| 电源组 | EPB 通道 | 项目 `10364-009` 启用通道 | 配置错峰 |
|---|---|---|---:|
| 电源1 | EPB1、EPB2、EPB3 | 无 | 800 ms |
| 电源2 | EPB4、EPB5、EPB6 | 无 | 800 ms |
| 电源3 | EPB7、EPB8、EPB9 | EPB8、EPB9 | 800 ms |
| 电源4 | EPB10、EPB11、EPB12 | EPB10、EPB12 | 800 ms |

本次事件虽然只启用4个通道，但电源3和电源4均存在两个活动支路，并非每台电源仅带一个负载。

## 4. 启动调度与配置偏差

### 4.1 V1.2_1 实际相位

现场 XML 为每个电源组配置 `StaggerMs=800`，但 Git 标签 `1.2_1` 的 `Controller/EpbManager.BatchStart.cs` 使用固定值：

```text
StaggerDeltaMs = 350
phase = IndexInPowerGroup(channel) × StaggerDeltaMs
```

`IndexInPowerGroup(channel)=(channel-1)%3`，因此实际相位为：

| 电源组 | 通道相位 | 本次活动通道间隔 |
|---|---|---:|
| 电源3 | EPB7=0、EPB8=350、EPB9=700 ms | EPB8→EPB9：350 ms |
| 电源4 | EPB10=0、EPB11=350、EPB12=700 ms | EPB10→EPB12：700 ms |

CSV 主要脉冲起点显示 EPB8→EPB9约错开320～355 ms、EPB10→EPB12约错开680～715 ms，与硬编码相位相符，而不是按每个已启用通道重新计算800 ms间隔。

### 4.2 固定错峰不是安全屏障

错峰只改变启动时刻，无法保证前一支路已经离开高电流阶段。夹紧时间会随卡钳行程、温度、电压、机械负载和故障状态变化；本次代表性高电流窗口已经达到2.746 s和4.422 s。因此：

- 350 ms明显不能避免多个高电流阶段重叠；
- 即使800 ms配置真正生效，也不能覆盖数秒级异常高电流阶段；
- 安全控制应采用同组高电流阶段互斥，或使用经过最坏工况验证的容量约束，而不是只依赖固定延时。

## 5. 电流竞争机理

### 5.1 并联支路的总限流

三个 EPB 并联到单输出电源时：

```text
Iout = IEPB-A + IEPB-B + IEPB-C
```

若总需求超过电源设定电流：

```text
Idemand,total > ISET
```

电源可能进入恒流状态，使：

```text
Iout ≈ ISET
Vout < VSET
```

电源不会保证每个 EPB 获得相同电流。各支路的电流分配受电机反电势、绕组阻抗、线束与触点压降、机械负载及瞬时位置影响。某一支路需求变化还会影响同组其他支路。

### 5.2 对 EPB 断电判据的影响

现场夹紧基准为15 A，安全裕量2 A，提前断电判据约为13 A。如果共享电源进入总限流，可能出现：

1. 多个支路同时处于高负载；
2. 电源输出电压下降，总电流受限；
3. 每个支路均保持明显高于空载的电流；
4. 单通道却无法稳定达到13 A；
5. 软件继续等待，直至正向3秒超时；
6. 重启后再次重复，形成累计热和机械冲击风险。

若现场 `ISET` 最终确认是20 A，则仅作容量说明：

| 并发支路数 | 按每支路13 A计算的需求 | 与20 A比较 |
|---:|---:|---|
| 1 | 13 A | 理论上有7 A余量 |
| 2 | 26 A | 缺少6 A，无法保证两支路同时达到判据 |
| 3 | 39 A | 缺少19 A，无法保证三支路同时达到判据 |

实际工程容量还必须包含峰值、线损、测量误差和安全裕量，并受720 W、线束、继电器、连接器和卡钳允许电流约束。不能仅为达到软件阈值而盲目提高限流值。

## 6. 现场同步波形证据

### 6.1 统计方法

对 2026-07-27 同一批次的通道 CSV 进行只读分析：

- EPB8：`Latest\EPB8\20260727_143533`
- EPB9、EPB10、EPB12：各通道的 `20260727_143534`
- 以 CSV 内部时间戳为准，按1 ms分桶；
- 每个通道取桶内绝对电流最大值；
- 仅在同一时间桶同时存在数据时计算支路电流和。

该方法适合识别支路峰值重叠，但不能替代电源输出端的校准电流测量。通道采样时钟偏差、传感器标定及分桶方法都可能影响毫秒级峰值和。

### 6.2 电源3：EPB8+EPB9

| 指标 | 结果 |
|---|---:|
| 共同有效1 ms时间桶 | 34,376 |
| 两通道同时≥5 A | 4,068桶 |
| 支路电流和≥18 A | 3,689桶 |
| 最大支路电流和 | 21.146 A |
| 最大值时支路构成 | EPB8约11.809 A + EPB9约9.337 A |
| 约20 A平坦区间 | 14:33:32.255～14:33:32.291 |
| 平坦区间范围 | 19.970～19.973 A，约37 ms |

约20 A的短时平坦支路电流和，与“电源总电流设定约20 A并进入恒流”的行为高度一致。该证据的置信度为**高可信关联**而非“已确认”，原因是事件时没有同步记录电源 `ISET`、总输出电流、输出电压或 CC 状态。

### 6.3 电源4：EPB10+EPB12

| 指标 | 结果 |
|---|---:|
| 共同有效1 ms时间桶 | 17,713 |
| 两通道同时≥5 A | 15桶 |
| 最大支路电流和 | 16.294 A |
| 约20 A平坦区间 | 未观察到 |

已检查窗口没有发现与电源3同等强度的约20 A削顶证据。该结果不证明电源4从未限流，只说明当前选定数据窗口不足以支持这一判断。

## 7. 控制与追溯风险

### 7.1 电源连接与状态留档不足

当前项目代码仅发现一个逻辑 `AsyncTcpClient` 电源客户端，并只读取 `Power1ServerAdr`。这可能表示软件连接的是中间代理服务，也可能表示四台现场电源并未在本项目中分别监控。现有证据不足以二选一，现场必须确认实际链路。

当前日志未见以下信息的逐电源留档：

- `*IDN?` 返回的型号和序列号；
- 电压、电流和功率设定值；
- 实际输出电压、总电流；
- CV/CC状态、输出开关和保护状态；
- 电源组与EPB通道的实际接线对应。

缺少这些数据时，无法把支路电流竞争与电源工作模式形成完整因果闭环。

### 7.2 配置与协议疑点

| 疑点 | 本地证据 | 风险 | 现场动作 |
|---|---|---|---|
| `Voltage=50` | `MTTfTest\App.config`及历史配置 | 超出PSW 30-72的30 V范围 | 确认配置是否遗留、是否由代理换算、实际型号是否一致 |
| `MaxCurrent=20` | 同一配置 | 可能是限流线索，但真实性受冲突配置影响 | 从每台电源读取实际设定并拍照留档 |
| 电源2与电源4 IP重复 | `开发相关\04_程控电源\2025-6-11 程控电源IP 142804.md` | 可能是文档笔误或实际网络冲突 | 逐台断开/识别并修正资产表 |
| 本地限流命令与官方标准SCPI写法不同 | `Main_Frm.cs`与官方编程手册 | 可能经过代理转换，也可能命令未作用于目标设备 | 保存原始收发报文并查询设定回读 |

只有“命令发送成功”而无设定回读、状态回读和物理测量时，不能证明电源已按期望工作。

## 8. 设计与整改原则

### 8.1 供电容量

每个电源组的基本容量条件为：

```text
ISET ≥ Σ(允许同时运行支路的实测需求电流) + 工程裕量
```

同时还必须满足：

```text
Vout × Iout ≤ 720 W
```

并检查电源线、保险、继电器、连接器、端子和卡钳自身的允许电流。新限流值应基于单通道峰值、双/三通道并发实测及最坏温度和机械负载确定，本文不直接给出固定设定值。

### 8.2 调度与保护

- 在容量未经验证前，同一电源组内只允许一个通道处于夹紧或释放高电流阶段。
- 组内互斥应以实际阶段结束、实际断电或安全超时为释放条件，不以350 ms或800 ms固定延时作为唯一条件。
- 电源进入异常 CC、输出电压显著跌落或任一支路超时时，应停止共享该电源的全部通道。
- 电源组映射、身份及设定值未知或回读不一致时，批量试验不得启动。
- 每个支路应有与线束和负载匹配的独立过流/短路保护；总电源限流不能替代支路保护。
- 支路电流继续由独立传感器采集，电源总电流用于交叉核对和识别竞争。

### 8.3 数据与报警

每次试验启动前保存：

- 四台电源型号、序列号、IP和通道分组；
- `VSET/ISET`、功率与保护设定、CV/CC优先模式；
- 设定回读、实际输出回读和输出开关状态；
- 软件版本、配置文件哈希和测试人员。

运行中同步记录电源输出电压、总电流、CV/CC状态、各支路电流、DO命令和继电器反馈。进入限流、输出电压跌落或通信中断均应形成明确事件，并与 UI、蜂鸣器、日志及快照联动。

## 10. 验收标准

以下条件全部满足后，共享供电整改方可验收：

1. 四台电源的型号、序列号、IP、通道组和接线均已核验并留档。
2. 软件逐台记录真实 `VSET/ISET`、输出电压、总电流及 CV/CC 状态，不再依赖未回读的配置值。
3. 单、双、三通道试验均能通过同步数据还原电源总电流、支路电流与DO/继电器的完整时序。
4. 不允许任何通道因共享电流竞争保持高电流直到3秒超时。
5. 进入异常恒流、输出电压跌落、通信中断或任一通道超时时，共享该电源的通道全部安全断电。
6. 组级故障时 UI、蜂鸣器、日志、数据库状态及CSV/BIN快照完整联动。
7. 实际调度策略与配置一致；若使用串行控制，高电流阶段不存在重叠。
8. 每组完成至少100圈回归，圈状态与文件证据一致，无无法解释的 `running`、伪 `alarm` 或圈号错配。

## 11. 数据质量与未决项

| 未决项 | 当前影响 | 关闭证据 |
|---|---|---|
| 现场 `ISET/VSET` 未知 | 无法确认约20 A平台是否由电源限流产生 | 四台电源原始查询响应、面板照片和同步回读 |
| 无 CV/CC状态记录 | 无法确认事件时工作模式 | 时间同步的状态日志 |
| 支路电流和不等于电源校准总电流 | 毫秒级峰值和可能有标定/对齐误差 | 电源回读及独立钳形表/分流器交叉测量 |
| 目录时间与CSV内部时间不一致 | 易错误定位事件发生时刻 | 统一使用采样时间并记录导出时间 |
| 文件名圈号与内部 `Cycle` 不一致 | 易把不同圈次错误关联 | 修复落盘命名并进行一致性检查 |
| 电源2、电源4 IP重复记录 | 无法可靠追溯设备身份 | 现场逐台识别后的资产表 |
| `Voltage=50` 与型号冲突 | 仓库配置真实性存疑 | 明确代理协议、有效配置源和实际设备型号 |

在这些未决项关闭前，结论措辞应保持为：

> 共享电源组内峰值重叠与支路电流竞争是持续高电流平台和夹紧超时的高可信促成因素；现场实际限流状态及其与卡钳齿轮损坏之间的最终因果关系仍待电源侧同步数据和机械拆检验证。
