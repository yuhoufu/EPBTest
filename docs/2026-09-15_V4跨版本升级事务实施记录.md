# V4 跨版本升级事务实施记录

## 当前实现范围

文件安装器增加 `Get-IndependentUpgradePlan`，输入必须是分别经安装包路径/摘要验证得到的旧、新文件计划及原安装记录。函数只生成计划，尚未开放 Upgrade 执行入口，不修改任何文件或试验状态。

旧包必须与原安装记录同构建；新旧计划必须指向同一规范安装目录，新版本必须严格高于旧版本。相同版本应走 Repair；低版本回滚必须使用专门的回滚流程，不能冒充 Upgrade。

计划分为：新程序组件、旧包有而新包没有的待退出组件、应保留的原配置及非组件文件。沿用程序组件扩展名范围，配置目录全部排除；不把新包默认配置直接覆盖现场配置。旧组件列表保留其原摘要，供后续事务核验归属和恢复。

## 已验证

`Test-UpgradePlan.ps1` 在 Windows PowerShell 5.1 x86 下 6/6、exit 0：

- 正常升级正确识别替换、新增、退出组件；旧配置及数据库进入保留集合。
- 同版、降级、非法版本拒绝。
- 其他安装目录拒绝。
- 原安装记录与旧包摘要不一致时拒绝。

日志位于主仓库 `Codex/v41-upgrade-plan-test.log`。此为计划函数测试，没有执行升级；未访问 jxcq 或 WJ-EPB。

## 尚未实施或验收

### 文件替换与旧组件退出事务进展

`Invoke-IndependentFileRepair` 已支持预检生成的旧组件退出列表：替换前核验旧摘要、路径归属、重复目标及文件预算；退出组件移动到事务备份，成功后保留备份。后续只读检查失败时，在同一文件锁内逆序恢复旧组件和被替换文件，并移除本次新增文件。只读检查回调不得承担注册信息写入；注册元数据仍需要独立的协调事务。

本地 Windows PowerShell 5.1 x86 验证：

- `Test-UpgradeFileTransaction.ps1`：5/5，exit 0。覆盖成功退出及备份、退出后检查失败、退出文件被占用、旧摘要改变、反斜杠配置路径拒绝；失败后核验原始字节、新文件移除和锁释放。
- `Test-IndependentFileRepair.ps1`：原有 7/7，exit 0，替换及并发/未完成事务拒绝行为保持通过。
- 日志：主仓库 `Codex/v41-upgrade-files-test-r3.log`、`Codex/v41-file-repair-upgrade-regression.log`。

保留初次未通过证据：首次脚本被本机执行策略拦截，未执行测试；第二次故障注入回调受到 PowerShell 动态作用域中的同名变量影响，回滚本身完成，但未到达预期的注入位置。测试改为捕获独立闭包后，明确确认“新文件已替换、旧文件已退出”再注入失败，5 项全部通过。本次未连接 jxcq 或 WJ-EPB，不作为跨版本完整升级或断电恢复验收。
