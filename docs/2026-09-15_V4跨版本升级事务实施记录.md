# V4 跨版本升级事务实施记录

## 当前实现范围

文件安装器增加 `Get-IndependentUpgradePlan`，输入必须是分别经安装包路径/摘要验证得到的旧、新文件计划及原安装记录。函数只生成计划，尚未开放 Upgrade 执行入口，不修改任何文件或试验状态。

旧包必须与原安装记录同构建；新旧计划必须指向同一规范安装目录，新版本必须严格高于旧版本。相同版本应走 Repair；低版本回滚必须使用专门的回滚流程，不能冒充 Upgrade。

计划分为：新程序组件、旧包有而新包没有的待退出组件、应保留的原配置及非组件文件。沿用程序组件扩展名范围，配置目录全部排除；不把新包默认配置直接覆盖现场配置。旧组件列表保留其原摘要，供后续事务核验归属和恢复。

## 已验证

`Test-UpgradePlan.ps1` 在 Windows PowerShell 5.1 x86 下 6/6、exit 0：

- 正常升级正确识别替换、新增、退出组件；旧配置及数据库进入保留集合。
- 同版、降级、非法版本拒绝。
- 其他安装目录拒绝。
- 原安装记录与旧包摘要不一致时拒绝。

日志位于主仓库 `Codex/v41-upgrade-plan-test.log`。此为计划函数测试，没有执行升级；未访问 jxcq 或 WJ-EPB。

## 中断文件事务恢复入口

增加 `Restore-IndependentFileTransaction` 及安装器 `RecoverFiles -TransactionId <32位事务ID>` 模式。入口使用原包和安装记录校验、可信维护注册、主控制进程退出检查、独立服务停止及执行器租约，保持维护状态，不启动试验、不自动修复服务注册。此模式只恢复明确指定的文件事务，不按目录猜测要恢复哪个事务。

恢复前整体检查日志大小、条目数量、组件范围、重复路径、重解析点、文件预算、原始摘要和备份摘要；只接受 Prepared、RollbackFailed、RolledBack。已提交 Replaced 不作为中断事务自动回滚。备份通过复制恢复且保留原副本，重复恢复可识别已恢复文件；新增文件只有摘要符合本次载荷才允许删除。全部完成后原子写入 RolledBack，保留恢复前日志。

`Test-InterruptedFileReplay.ps1` 在本地 Windows PowerShell 5.1 x86 下 3/3、exit 0：原文件及退出组件恢复、新增组件移除、重复恢复幂等、备份保留；目标被修改或备份被破坏时，整体预检拒绝且不恢复其他文件。日志：主仓库 `Codex/v41-file-replay-entry-test.log`。

验证限制：本次通过真实文件事务生成载荷，再构造“文件已替换但成功日志尚未提交”的中断状态；未强杀安装器进程，未在 jxcq 执行 RecoverFiles 管理员入口。因此只证明文件重放函数在上述状态下的行为，不证明完整升级断电恢复、注册元数据回滚或远程入口生命周期已经验收。注册信息迁移与文件事务协调仍待完成。

### 实际文件事务子进程强制中断验证

随后增加并执行 `Test-FileTransactionProcessCrash.ps1`，本地 Windows PowerShell 5.1 x86、exit 0。测试在独立子进程调用生产文件事务函数，确认主组件已经替换、新组件已新增、旧组件已退出后，由父进程核对 PID 和启动时间并强制终止该子进程。未修改日志阶段，实际读取到 Prepared，然后调用生产恢复函数，验证原主组件和退出组件字节恢复、新增组件移除、最终日志 RolledBack。

父进程具有 25 秒就绪期限和 256 MiB 子进程私有内存上限；子进程等待至多 45 秒，父进程异常时自行进入失败回滚。finally 只清理本次创建的精确子进程。测试后另行按 PID/启动时间复核，该测试进程已退出。

证据目录：主仓库 `Codex/v41-tests/file-crash-635eadac10424a598cd1910f926a7e04`，包含创建身份、子进程输出、原始事务备份和 `result.json`；总日志 `Codex/v41-file-transaction-process-crash.log`。

本项补足实际文件事务进程死亡后的持久恢复证据。范围仍为文件事务函数，不是顶层安装入口、整机断电、SYSTEM 服务迁移或注册元数据协调验收；未连接 jxcq 或 WJ-EPB。

## 注册摘要迁移准备

增加 `Get-IndependentUpgradeRegistration` 纯准备函数。读取并校验原注册及持久状态，要求维护模式、安全收尾完成、无活动恢复事务、无未撤销启动凭证且无未人工停止的 Armed 意图。原有意图通过 `RequireBoundIntent` 核对项目、数据库身份、程序路径和配置摘要。

候选必须保留主程序和 SafetyAgent 的原注册路径，分别存在唯一且摘要有效的组件。深复制原注册后只更新两个可执行文件摘要，重新通过协议校验；不写注册文件、不改运行意图、不重建隔离或通道选择、不授予启动许可。路径变化的迁移不由这个函数猜测处理。

本地 PS5.1 x86 的 `Test-UpgradeRegistration.ps1` 3/3、exit 0，使用已构建协议和注册夹具，验证摘要更新、其余全部字段及原对象保持不变、配置副本无共享引用、非维护模式拒绝、原路径缺失拒绝。日志：`Codex/v41-upgrade-registration-test-r2.log`。尚未覆盖已有停止/暂停/永久隔离意图的完整迁移，也未接通文件与注册的统一提交。

首轮失败已保留 `Codex/v41-upgrade-registration-test.log`：实现误用了 PowerShell 自动变量 `$Matches`，正则匹配覆盖组件列表，导致候选摘要为空并被协议校验拒绝；改名 `$components` 后通过。此为本轮开发中发现的问题，无注册写入、无现场影响，不能归因于 JSON 复制。

## 程序文件与安装元数据联合事务

文件事务增加独立的 `MetadataFiles` 参数，仅允许替换既有 `IndependentState/registration.json` 和 `installed-files.json`，不能写入运行意图、试验配置或数据库。带元数据的事务使用 schemaVersion 2，原有纯程序组件事务继续使用版本 1；恢复读取两种版本，并仅对版本 2 的明确元数据条目开放上述两个固定路径。

程序组件、注册摘要和安装清单在同一文件锁、同一 Prepared 日志和同一失败回滚边界内执行。源文件全部暂存后才开始替换，后续安装清单失败会逆序恢复已经写入的注册文件和程序文件。按原事务进行中断恢复时同样恢复这些元数据。程序组件路径也统一正反斜杠后验证，配置目录不能通过反斜杠形式进入组件替换范围。

本地 Windows PowerShell 5.1 x86 验证：

- `Test-CoordinatedUpgradeFiles.ps1` 3/3、exit 0：三类文件替换成功后构造 Prepared 状态并恢复；锁住最后的清单文件时，证明已替换程序及注册随后均回滚；持久状态路径拒绝且无部分修改。
- 原文件修复 7/7、组件退出 5/5、中断重放 3/3 及实际子进程强制中断恢复均 exit 0。
- 日志在主仓库 `Codex/v41-coordinated-upgrade-test.log` 和 `Codex/v41-coordinated-Test-*.log`，各测试使用独立目录，测试子进程已在各自 finally 内清理。

验收边界：本组元数据内容使用隔离测试字节验证事务，不代表真实注册迁移、服务/任务升级已运行。注册候选生成与该事务仍需在顶层 Upgrade 入口连接，失败后的顶层维护注册加载、旧包清单选择和 jxcq 全流程仍待验收。文件日志提交也不等于整个安装升级提交；顶层流程不得提前宣告升级完成。

## 安装器 Upgrade 入口接通进展

`Install-IndependentRecoveryBundle.ps1` 增加 `ValidateUpgrade`、`Upgrade` 和 `PreviousBundleDirectory` 参数。新包由 `BundleDirectory` 指定，旧包必须通过原安装记录匹配及文件摘要校验，升级执行另核验新旧组件版本。旧包检查发生在进入维护及停止服务之前。

Upgrade 沿用已有维护、主控制进程退出、独立服务身份和停止、执行器租约、旧会话进程退出检查。随后生成保留项目身份的新注册及新安装清单，调用联合文件事务；提交前通过新注册的严格文件摘要验证，并再次确认持久状态与事务开始时完全相同。失败进入文件及元数据回滚，保留维护状态。所有准备文件和结果位于安装目录受保护的 `Upgrade/<事务ID>/`。

**当前仅接通到 FilesCommitted，完整升级未完成。** 返回结果明确标记 `finalizationRequired=true`，不调用 Enable，不启动试验。服务、交互任务和快捷方式收尾及其失败补偿仍待实现；不能把该模式正常返回解释为可交付升级已通过。外层一键入口也尚未增加升级路由。

本地回归：UpgradePlan 6/6、UpgradeRegistration 3/3、CoordinatedUpgradeFiles 3/3、原一键包验证测试均 exit 0。日志 `Codex/v41-upgrade-entry-Test-*.log`。这些验证覆盖解析和已接入函数，但**尚未实际调用管理员 Upgrade 完整入口**；需要下一阶段 jxcq 隔离安装夹具验证。文件日志和顶层结果之间的进程中断、混合注册/清单恢复，以及原版本包选择仍需补齐验证。

## 服务、任务及快捷方式收尾接通

后续实现已将 Upgrade 的 FilesCommitted 之后接入 `Complete-IndependentUpgrade`：原子记录 Registering，调用管理脚本 Repair（验证或补齐本安装服务、任务和绑定）；原子记录 UpdatingShortcut，创建当前实际程序版本快捷方式，再精确移除同安装身份的旧版本快捷方式；最后记录 Completed。全程保持维护，不启用续测。上节的“只接通 FilesCommitted”是前一提交状态，当前代码已继续接通收尾，但完整管理员入口仍未验收。

失败原子记录 FinalizationFailed，保留版本、安装身份及文件事务，不以泛化 Failed 覆盖。增加 `FinalizeUpgrade -TransactionId <Upgrade目录ID>`，要求新包与已安装清单匹配，沿用维护与进程检查、执行器租约、逐个程序组件摘要和可信注册校验后重试收尾。身份不匹配在执行任何收尾步骤前拒绝。

此处采用可重试维护状态：收尾失败后程序文件可能已是新版，不能宣称已自动降回旧版。完整降级回滚、断电处于文件与元数据混合阶段的顶层恢复，以及清单成功但收尾结果缺失的恢复仍待完善。

本地 PS5.1 x86：`Test-UpgradeFinalization.ps1` 3/3、exit 0，覆盖阶段先落盘、快捷方式步骤注入失败不报成功、重试按序完成、外来安装身份不执行；实际隔离目录快捷方式创建、目标校验、幂等、外来文件保留、删除及非法版本回归通过。日志 `Codex/v41-upgrade-finalization-test.log`、`Codex/v41-upgrade-shortcut-regression.log`。阶段测试使用回调模拟服务/任务操作；不能当作 jxcq SYSTEM 服务和交互任务实测。此次未连接任何远端主机。
