# 整组恢复授权范围调用审查

## 结论

当前源码仍存在“恢复登记范围与执行范围可能不同”的缺口，不能据已有软件测试通过宣布整组恢复完成。本记录是静态调用链证据，不是现场故障复现、硬件验收或修复完成证明。

`ExecuteAffectedGroupResetAsync` 先校验 requestedChannels 的恢复状态和代次，再从 `_timers`、`_runners`、`_hydraulicParticipants` 增补同液压组成员。新增成员捕获执行许可，但该许可不等同于已登记的恢复合同。后续清场、状态发布使用扩大后的 channels。

## 修复必须同时解决的边界

1. 区分物理安全影响范围与可续测范围。暂停、人工停止、禁用的成员不得因为共享资源被恢复重新加入；共享输出受影响仍必须纳入安全分析。
2. 整组范围必须与真实恢复合同绑定，不能仅为后来加入的成员捕获执行许可就认为完成授权。
3. 解决组成员在登记后变化的准入协调，而非删掉执行扩展后忽略同组旧对象。
4. 硬期限升级须明确原 incident 与新组恢复的交接。释放液压 ownership lease 不代表原恢复任务及其所有在途动作已经终止；不得未经分析将所有调用机械改为再登记一个 incident。
5. 新旧任务终态提交、退出和异常清理不得覆盖接替任务的状态。正常等待和停止/维护撤权仍优先。
6. 最终顺序仍是实际断能、卸压，取得动作后的新鲜电流与压力安全证据，再续测，以真实业务提交确认恢复成功。

`TryBeginRecoveryIncident` 在 `_recoveryAdmissionGate` 内登记合同；`RecoveryIncidentCoordinator.ScopeKey` 包含 run、epoch、ownerKind、targetPhase、resourceScope，不包含源 correlation。不能据此推断不同 ownerKind 的组任务自动完成交接或互斥，需要结合生产状态发布、任务登记和执行栅栏验证。

## 下一轮必要验证

- 在登记与执行之间新增同组运行成员：合同、断能对象、安全反馈对象和续测集合保持符合上述边界。
- 液压、电源、报警三类硬期限升级：旧任务晚到回调、终态清理不污染新任务。
- 重复故障和共享组并发升级：只有一个有权重新上能的执行者。
- 人工停止、暂停、维护及 Stop→Start 新代次发生在交接各阶段：撤权有效，旧任务不得续测。
- 新鲜反馈缺失、不安全、任一输出失败或在途硬件动作未结束：不得误报恢复完成，保留后续安全恢复路径。

本轮只新增审查记录，没有改变运行代码，没有启动新的测试或远程部署。此前测试数字不能作为本缺口已修复的证据。

## 后续实现：旧任务退出前保留登记

后续继续实现时确认 `RecoveryIncidentCoordinator.Complete` 原先在终态验证成功后立即取消登记、释放 lease；调用该方法的 worker 可能仍在执行后续 await 或 finally。因此即使投影已是终态，也不能据此授权重叠的新恢复任务。

已修改协调器：终态提交成功后保留范围与任务 lease；由生产 worker 包装层在任务体及异常路径退出后的 finally 中清理登记。清理有独立原子门禁，避免外部完成回调与退出清理并发重复释放。此处退出指实际被 await 的任务体返回，不声称该任务体未等待的硬件叶子任务也已退出；后者仍须原有硬件动作登记门禁。

## 接替状态身份的补充证据

继续阅读 `EpbManager.PublishChannelRuntimeState`，确认已有 Recovering 状态在收到显式 owner 更新时会调用 `RecoveryOwnershipPolicy.MatchesExplicitOwner`；不匹配则记录 `RecoveryOwnerIdentityMismatch` 并返回。直接硬期限调用整组执行体时，原液压/电源 incident 尚未完成，而整组执行体以 `AffectedGroupRecovery`、传入 correlationId 作为 owner 发布状态。因此不能通过该状态发布完成从原 owner 到整组 owner 的交接；方法返回也没有向执行体提供“已接管”的成功回执。

另需区分合同 `IncidentId` 与 `OwnerId`：协调器默认生成新 IncidentId；整组包装首发状态使用 contract.IncidentId，但其执行体接收的是 ownerId，并将该值同时用作 correlationId 和 ownerId。活动圈上限包装同样需要核对这两个身份。不能用二者在某些入口恰好相同来证明所有入口的合同覆盖正确。

后续整组交接必须显式携带冻结合同身份，并在原任务退出、后继合同登记完成后才执行后继状态发布与动作。这条证据不授权放宽已有 owner 冲突门禁，也不证明当前整组恢复已可完成。
