# V4.1 安装文件归属与修复预检

## 本次实现

文件安装器此前只保存安装结果，没有逐文件的原安装归属记录。仅用当前包覆盖既有目录，不能证明它与原安装是同一构建，也可能覆盖现场配置。

本次在受保护的新安装目录中、复制第一个载荷前保存 `installed-files.json`，记录协议版本、程序版本、规范化安装目录、每个实际复制文件的相对路径和 SHA-256。安装失败保留记录，供维护定位，不猜测或递归删除其他文件。

新增 `ValidateRepair` 只读入口：验证安装路径所有者/重解析点、记录文件大小上限 4 MiB、包与原安装版本及目录一致、文件数量一致、无重复文件、每个路径及摘要与原安装完全一致。相同版本号而构建内容不同也拒绝。

预检输出仅包含 EXE、DLL、PDB、PowerShell 脚本和 EXE.config；`Current/Config/` 中所有文件、数据库、其他未知类型均不作为修复覆盖对象。包摘要检查及大小上限沿用现有安装器。预检不写入安装目录、不修改运行意图、不停止服务，也不代表此刻可以覆盖运行中的组件。

## 检查命令

```powershell
.\Tools\Install-IndependentRecoveryBundle.ps1 -Mode ValidateRepair `
    -BundleDirectory '完整包路径' -InstallRoot '既有安装目录'
```

旧安装没有该记录时会报错，不能凭现有 EXE 版本号猜测其文件归属。后续完整升级/迁移必须明确处理这种情况。

## 验证与范围

Windows PowerShell 5.1 x86 下 `Test-IndependentRepairFiles.ps1` 7/7：有效记录、版本不匹配、目录不匹配、摘要不匹配、重复文件、缺失文件及未知路径。有效案例包含配置目录内 DLL 和数据库，均未进入修复候选。

包文件验证 8/8，通过；顶层包验证/验收脚本 exit 0。证据位于主仓库 `Codex/v41-repair-files-test.log`、`v41-repair-bundlefiles.log`、`v41-repair-topbundle.log`。
