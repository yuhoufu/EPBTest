## 4. A 阶段：旧版运行期间完成所有准备

### A1. 只读基线

使用 `Tools/Read-WjEpbFieldStatus.ps1` 采集身份和业务快照；至少两次相隔 15 秒。核对主机、账户、Main 完整路径/版本/摘要/PID/启动时间、Session/Run、人工意图、通道状态、采样/控制和真实 SQLite 提交。读取错误或合法冷却/学习阶段分别记录。

旧版 V1 健康端点 Unsupported 不算异常。新版必须用匹配端点加业务证据判断。旧版数据库以 `epb_cycles` 为准；新版依实际 writer 和迁移后的表语义核实，不套用旧版 receipt 统计口径。

### A2. 包预置与环境预检

1. 在 D 盘创建当次唯一部署目录，命名含日期、候选提交和轮次；包和证据目录分开。
2. 只传本次确定的归档，核对双端 SHA256；完整解压后定位实际顶层目录，运行根入口 `ValidatePackage`。
3. 核对 .NET 4.8、实际 NI x86 运行时、电源/液压配置、用户交互会话、服务及任务入口；不在生产运行期间探测或占用设备资源。
4. 检查安装卷空间。当前 Main 安装器要求“来源文件总大小三倍 + 1 GiB”，按实际解压大小计算并留运行余量，不能按 34 MB 压缩包估算。
5. 若需整理空间，先明确无活动引用、路径归属及可恢复方式；不得临时删除 Current、DataStore、项目数据或事故证据。准备不足则不进入停机。
6. 核对既有安装迁移测试涵盖正常关闭后检查点更新时间、UTF-8 中文读取及本轮版本组合。运行产生的最终回执只能停机后验证，不提前伪造。

本地/JXCQ 已通过的同包验证不重复全跑；若修改任何组件或安装脚本，应生成新身份候选，重新完成受影响验证，旧包报告不能继承为新包通过。

## 5. B 阶段：最短必要停机与新版接替

进入条件：A 阶段全部有记录、新的部署确认及窗口已登记、现场当前状态仍适用、回退可执行。

1. **锁定当次身份。** 重新读取 PID/启动 ticks、Session/Run 和通道基线；当次操作脚本绑定新身份，不复用旧轮次 UI 脚本或旧任务。
2. **正常停止。** 使用已验证界面入口停止试验；确认本次人工停止、输出断能、液压释放、持久化收口和资源释放。停止回执与本次事务匹配；不拿历史人工安全确认代替。
3. **正常退出。** 用正常关闭入口退出，确认 Main 实际退出。若卡住，先保留失败证据并核实安全事务，不能按进程名批量结束。仍在处理安全接管的组件不得被中断。
4. **冻结最终变化。** 记录最后成功圈、机械圈、在途圈及最终提交，刷新配置/检查点备份。完成现场最终增量并确认归档成功、基链有效；网络回传随后进行。如果以后要将压缩也移出窗口，必须先实现并验证独立冻结快照流程，当前不能直接假设脚本支持。
5. **安装匹配 Base。** 使用最终包 Base 的受控观察安装入口，按安装事务协调维护、Supervisor 与代理；保存安装输出、迁移结果和新组件摘要。保留最新 DataStore 与项目数据。缺少真实报告时不调用根自动安装入口假装已经启用自动恢复。
6. **首次启动并人工开始。** 通过实际支持的交互会话监督入口启动；查询实际消费结果、新进程及桌面证据。使用正常界面打开原项目并开始试验，形成新的人工运行授权，禁止回放旧许可。
7. **开始学习后回传。** 将已冻结增量归档与必要部署证据回传本地，保持现场原件。发现传输与采集争用时降低传输负载。回传失败记为待补，不反过来停止已正常运行的新版。

异常说明：WinRM 超时、MainWindowHandle=0 或一次 UI 空结果均不能独立证明启动失败。必须先核查新 PID/启动时间、监督消费记录和交互桌面；JSON 数组先赋值再枚举，使用已验证 `Read-FieldUiEvidence.ps1`。不得据此立即重复启动或回退。

## 7. D 阶段：RecoveryGuard 分阶段现场测试

### D1. 观察模式

记录独立安装路径、组件清单、模式和两个任务的实际状态。验证合法学习、正式运行、冷却/保压时不误派发恢复；读取稳定快照、授权、事务和监督时效。只观察通过不等于自动恢复通过。

### D2. 受控 RecoverExited

候选 `Invoke-MTTFTest-RecoveryGuardCommissioning.ps1` 提供 Plan / Execute，默认 10 分钟、最多 15 分钟。须匹配已安装 Main 和 Guard、已有 Run 意图、InstallationId/AuthorizationId/IntentVersion，常驻执行任务必须 Disabled。

Plan 不能预先绑定旧版或未来未知运行。Execute 在动作前以 CreateNew 消费单次计划；结果不确定时先核对 `execution-claimed`、执行进程和输出，不重用计划。

特别限制：Healthy 会返回 `StopWorker=true` 并结束；有效期不是持续等候异常的观察承诺。历史 B 轮 Healthy/ActionDispatched=false 只证明健康时不误恢复。若要验证异常退出，必须在计划仍有效、意图仍允许且具备真实安全条件的异常场景执行。若健康计划已消费，则在适用时重新制订新计划；不得伪造异常或人工 Run 意图。

优先记录自然发生的异常。主动退出/组件故障试验需另行授权并经安全设计；正常人工停止必须阻止恢复，不能拿人工停止后强行续测来做正向样例。若现场未出现可验证异常，则 exitedRecovery 留未验收。

正向通过要求：可信旧实例退出和安全交接、同一有效授权的合法续接、唯一新实例、必要学习完成、所有可续测通道真实正式与持久化提交推进、数据对账成立。窗口出现、许可 Approved、执行器退出码 0 均不单独算成功。

### D3. RecoverStalled 及独立安全边界

当前受控入口只开放 RecoverExited，不能修改计划字段或复制 settings 越级测试 RecoverStalled。停滞模式需要另一个已验证且获准的测试安排；没有可用路径时该项保持未验收。

活动 Main 占用硬件且无法证明独立断能时，预期结果是 Blocked。人工面板按钮不能当作无人值守自动断能装置。现场核对按钮断能范围、保持、反馈及复位行为；未验证反馈时不承诺 Guard 能感知按钮。复位不得自动恢复人工停止的授权。

| oldState | 停止/完成/过期旧授权不恢复；旧备份不能提供新恢复权限 |

| businessRecovery | 各参与通道按阶段完成实际业务与保存验证，隔离故障通道不冒充完成 |
| exitedRecovery | 本次新组件真实异常退出后的完整恢复闭环 |

### D5. 常驻自动模式正式启用

报告必须绑定实际 Main build-identity、Guard EXE、共享核心 DLL、Guard 基包 identity 四项 SHA256，目标机器/台架正确，各项真实附件存在且哈希一致。生产报告 testOnly=false、passed=true、physicalHardwareSafetyVerified=true 只能据实签署。

先 Validate，再正式安装相应模式。注意：当前根 `Install-AutomaticRecoveryBundle.ps1` 在 Install/Repair 中也调用 Main 安装器，因此不能把晋级当成在线无停机操作。默认安排第二个短窗口；若希望只晋级独立 Guard，必须先验证受支持安装路径、事务互斥和回退，不在现场临时绕开入口。

正式安装后核对模式、执行任务启用状态、组件和报告身份；按入口要求建立新的人工授权，继续业务验证。只在报告批准时选择 RecoverStalled。整体未通过时保持准确的候选状态，不能为提速省掉报告。

## 8. 异常处理及完整回退

| 情况 | 动作 |
| --- | --- |
| 预检/包校验失败 | 不停旧版，修正准备问题 |
| 停止安全或保存未闭合 | 中止换包，保留安全组件和证据，通知现场；不强杀越过 |
| 安装前拒绝且旧文件未变 | 核对维护及任务实际状态，按支持入口恢复旧版，记录真实影响 |
| 新版学习/持久化真实失败 | 有界取证，正常安全收口；满足条件后执行预备回退 |
| 启动响应超时 | 查实际进程、凭据消费和桌面，不直接重复启动/回退 |
| 只有网络回传失败 | 现场保留归档，续传指定文件；不把它当业务故障 |
| 新数据兼容性或计数不明 | 保持安全停止，保全数据并查明；禁止用旧数据库覆盖 |

回退步骤：

1. 保留当次新版日志、运行身份、最后提交及停止事务；完成断能、卸压、保存、正常退出。
2. 协调 Guard、Supervisor、Agent 和任务至无竞争状态；只处理经路径/PID/启动时间核实的精确残留，保留安全接管者。
3. 使用预置匹配旧程序恢复软件。保留最新 Current\DataStore、项目数据、目标、计数和配置；新版新增文件亦保留。共享许可与预算不能从旧备份整体回放。
4. 恢复旧版服务和任务定义；不将新版自动任务和旧组件混用。核对所有组件摘要，文件占用先查归属，不临时强制覆盖 DLL。
5. **恢复旧版快捷方式。** 用已验证旧入口重建正确版本名称和参数；备份归档明确的新链接，消除用户桌面、公共桌面和开始菜单中的错误入口。不能只改 V3 名称而保留 `--launch-main`。
6. 用计划内首次启动验证旧入口，重新打开原项目开始测试；允许必要学习，至少两次相隔 15 秒的业务/提交对账确认旧版继续推进。
7. 更新只读监控绑定；移除本轮明确的临时任务，保留证据。记录停止到开始学习、全通道正式运行的实际时长及不必要等待原因。

## 10. I0050 第二步和完成标准

按用户指定顺序，I0050 液压恢复状态一致性独立作为第二步。先确定性复现液压登记到 incident/生命周期/心跳发布的中间态，覆盖取消、失败、后继代次与真实孤儿恢复；不得仅放宽 Watchdog 判据。Guard 恢复成功不能作为 I0050 根因修复证明。

第二步如改动组件，应生成新候选身份、完成相应控制/磁盘/电源与 Guard 回归及 JXCQ 验证，评估重新现场验收范围；不可复用旧组件报告冒充新版本通过。

本目标完成须有：匹配的正式完整包、实现与回归证据、wj-epb 真实业务和所选自动恢复模式验收、数据对账、现场操作/回退/快捷方式闭环、真实限制及第二步状态文档。任一必要现场项缺失时整体保持未完成。
