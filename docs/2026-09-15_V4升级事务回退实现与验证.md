# V4 升级事务回退实现与验证

增加独立安装器及外层一键脚本的 RollbackUpgrade 模式，包生成器增加“回退版本.cmd”。该入口使用本次新版包执行，要求原构建完整包和 Upgrade 目录的明确事务ID。不同于 RecoverFiles：普通中断恢复仍不能撤销已提交的 Replaced 文件事务，只有完成升级身份与原包校验的版本回退入口传递 AllowCommitted。

## 校验与执行

入口保留管理员、可信安装目录及注册、安全维护、主程序退出、精确服务身份、执行器租约、会话辅助进程退出检查。当前安装记录须匹配新包或原包，允许文件已回退但收尾失败后的重试；其他版本拒绝。

读取受保护升级结果，核验安装ID、起止版本、允许阶段、事务路径归属；原安装清单从事务内备份读取并核验摘要。每个旧组件必须存在于事务中，原字节摘要必须匹配原包；新增或替换组件必须匹配新包目标和摘要。备份摘要和当前目标实际状态由文件恢复函数再次核验。超出两个已验证包的组件拒绝。

先持久记录 RollingBack，再恢复文件和注册，严格校验恢复后的注册及原组件摘要。随后核验/修复服务与任务，创建实际旧版本快捷方式并精确删除被替换的新版本快捷方式。成功写 RolledBack，失败保留 RollbackFailed 和原因。全程保持维护；运行意图、计数、配置及数据库不作为回退载荷，不自动启用监督或开始试验。

快捷方式替换允许高版本回到低版本，但两版必须不同，且现有快捷方式目标、工作目录和安装ID必须吻合；不会按名称批量删除其他安装快捷方式。

## 已验证

- 本地 Windows PowerShell 5.1 x86：Test-CommittedUpgradeRollback.ps1 5/5、exit 0，覆盖明确回退权限、原包身份和完整性拒绝、已提交文件回退、原清单恢复、新增文件移除以及重复执行。
- 原中断恢复 Test-InterruptedFileReplay.ps1 3/3、exit 0。
- 日志：主仓库 Codex/v41-committed-rollback-test-r2.log、Codex/v41-rollback-replay-regression.log。

这些是文件及计划函数测试，不是管理员顶层 RollbackUpgrade、SYSTEM 服务/任务或 UAC 实测。此前 jxcq 的完整旧包安装→4.1.0.0 升级已通过，但本次新增回退入口尚需重新打包后执行完整逆向测试、故障注入和重复回退；不能宣告整体回滚已验收。本次未连接远端或部署现场，保留既有测试包。
