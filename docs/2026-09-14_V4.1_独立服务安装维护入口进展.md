# V4.1 独立服务安装维护入口进展

基线 `d6fd7fc`。本轮新增安装维护入口，不代表完整安装包已经可交付。

## 已实现

`Tools/Manage-IndependentRecovery.ps1` 提供 Install、Status、Enable、Maintenance、Uninstall。它要求管理员、已经准备好的受保护安装注册文件及独立执行器路径；加载协议程序集前检查本地文件及祖先 ACL/所有者/重解析点，随后使用生产协议校验注册和组件配置哈希。

每个安装 ID 对应 `MTTFTestIndependent-<InstallationId>` SYSTEM 服务及 `\MTTFTest\Independent-<InstallationId>` 交互启动任务。任务无自动触发器，只接收一次性票据参数，使用指定用户的交互令牌、最高权限、IgnoreNew、不强杀和无限执行期限。既有任务使用运行时同一完整定义验证器检查，不以同名代表归属正确；服务核验精确命令行和 SYSTEM 身份。

安装先进入维护，注册对象后保持维护。Enable 在维护模式下启动服务，服务进入 Running 后才解除维护；这不是试验恢复成功判据。卸载前再次检查旧控制程序已退出，持久进入维护，等待本服务停止后删除其任务和服务，保留数据库、持久意图及诊断。安装失败只回退本次创建的对象，不清理其他项目。

协议增加原子 `SetInstallationMaintenance`：运行授权仍 Armed（包括暂停）、未终结恢复事务或 SafetyCleanupPending 均拒绝维护变更。人工停止后可以进入维护；解除维护不会重新 Armed，也不清除人工停止。脚本额外要求旧控制进程退出，不能将“收到人工停止命令”当作硬件停止完成。

## 仍需完成

该脚本尚未在 jxcq 实际注册服务或任务。完整包仍需生成受保护注册、统一配置摘要/源身份、创建首次人工启动快捷方式、撤销原恢复启动权并处理安全迁移；安装修复、损坏对象诊断、卸载后确认及回滚贯通仍待验证。

现阶段不能直接把此脚本或构建目录当作现场完整安装包。jxcq 完整 SYSTEM 接管、交互新进程、正确恢复目标及三正式周期落盘验收仍未完成；真实硬件安全执行还需台架验收。本轮没有连接或干预 WJ-EPB。
