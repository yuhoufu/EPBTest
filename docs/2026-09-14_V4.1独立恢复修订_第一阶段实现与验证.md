# V4.1 独立恢复修订：第一阶段实现与验证记录

状态：开发中，未完成完整候选交付，禁止将本记录理解为“独立SYSTEM恢复已经可用”。当前现场版本、包及运行进程未改变。

## 基线

事故文档与处置记录已提交为 3bfb0f0。它明确标注V4.0.0.3仍有恢复断链。目标版本4.1.0.0在当前本地及已获取引用的版本历史检查中未发现使用；尚未升级程序集版本、创建候选tag或生成部署包。

## 已实现

1. 主程序独立状态发布不再同步执行停止准备方法的同步前缀：准备任务通过Task.Run启动。它避免撤销/DO同步调用直接占住发布循环，但不是完整的外部进程超时接管。
2. 生产停止请求入口允许前一Pipe事务全部安全delivery终止后接收后续独立请求；前一事务未退休时暂缓新请求，不污染整条入口。同事务身份冲突仍保留拒绝，退休请求重放不能重复执行。退休记录限制256项；到达容量后不再退休，应由后续外部恢复阶段明确处理，不能宣称无限次请求均已覆盖。
3. 新增V2运行意图、持久恢复事务及带代际的阶段机：人工未勾选/暂停/永久隔离/完成通道排除；修订号防旧写入恢复旧选择；25秒协作期限；每30分钟最多3次、间隔60秒；阶段不可跳过；验证阶段要求替代进程身份。
4. 新增独立安全阶段执行核心：终止旧控制者前仅确认电源OFF；终止后重新确认电源OFF、DO、AO和压力。所有部分失败返回未确认，不伪造原SafetyAgent握手。

其中第3、4项目前是已测试核心，**尚未接入SYSTEM宿主、持久意图生产写入和交互启动任务**。原FallbackGuard仍走旧链，不能以这些单测证明现场已能独立接管。
