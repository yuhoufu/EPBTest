# V4.1 安装绑定与旧恢复启动互斥

## 已确认的竞态

旧 Watchdog、SessionAgent 和主程序旧跨进程恢复入口原先分别检查安装绑定，再调用 `Process.Start`。检查与实际创建之间没有和安装程序共用的原子边界，可能在检查后由安装程序写入新绑定，而旧启动者仍继续创建进程。

## 修订

- 安装绑定、最终旧恢复进程创建和主程序启动时读取绑定，共用以规范化完整 EXE 路径计算的全局命名互斥锁，等待上限 5 秒。
- 最终创建持锁重新验证绑定。有效独立绑定或损坏绑定都不能回退旧恢复启动。
- 安装持锁再次核对目标 EXE 路径是否仍有活进程；同名而路径不同的进程不作为目标。检查结果无法确认时拒绝安装，不结束进程。候选同名进程超过 128 个拒绝继续。
- 锁只包围最终本地创建。Watchdog 等待 SessionAgent 的跨进程请求不持该锁，避免两边等待同一互斥锁。
- 主程序手动启动的绑定读取也进入同一互斥区，避免在安装写入前读取旧的“未绑定”状态后继续初始化。

此修订没有终止旧 Watchdog、旧 SafetyAgent，也没有实现其硬件句柄的完整交接。它修复的是安装与启动的竞态，不代表完整接管与续测验收已经通过。

## 验证

本轮初始 Debug x86 构建退出码 0；独立 worker 17/17、状态 156/156，实际退出码 0。日志位于仓库根 `Codex/v41-binding-race-build.log`、`v41-binding-race-process.log`。

新增测试覆盖目标主程序仍存活时拒绝绑定、同名其他路径不误阻塞、安装互斥期间启动等待，以及等待后重新读取绑定。测试只使用本地隔离目录；不操作现场进程。

最终 Debug x86 构建退出码 0；最终独立 worker 17/17、状态 156/156、启动绑定测试 18/18，实际退出码均为 0，日志前缀分别为 `Codex/v41-binding-race-final-build.log`、`v41-binding-race-final-process.log`、`v41-binding-race-bootstrap.log`。

旧启动互斥修改后完整 AdaptiveControl 833/833、Fallback 75/75、磁盘 58/58、电源 19/19，实际退出码均为 0，日志为 `Codex/v41-binding-race-adaptive-full.log`、`v41-binding-race-fallback.log`、`v41-binding-race-disk.log`、`v41-binding-race-power.log`。全量之后补充的主程序启动读取互斥由最终构建及启动绑定测试覆盖，不把先前全量结果写成最后一次补充后的全量结果。

jxcq 的 SYSTEM／交互身份组合及完整安装、修复、卸载需要重新验收；本轮没有连接 WJ-EPB。
