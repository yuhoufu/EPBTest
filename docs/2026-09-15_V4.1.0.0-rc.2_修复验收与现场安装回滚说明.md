# V4.1.0.0-rc.2 修复验收与现场安装回滚说明

## 交付边界

程序和组件版本为 **4.1.0.0**，候选通过 **v4.1.0.0-rc.2** 标签、源码提交与包 SHA-256 区分。原 rc.1 包和标签保留。最终归档目录为主仓库 `Codex/delivery-v4.1.0.0-rc.2`；以包内 `automatic-bundle.json`、`Base/build-identity.json` 和包旁 `.sha256.txt` 核对实际身份，不能只看快捷方式名称。

本轮已在 jxcq 隔离项目验证恢复控制链和安装生命周期，**未部署 WJ-EPB，未验证真实硬件安全执行或长期无人耐久**。候选的 `fieldDeploymentApproved=false` 是有意保留的状态。安装成功、服务运行、主程序存在均不能代替续测验收。

## 监督程序的职责

| 程序/任务 | 作用 |
|---|---|
| `MTTFTest.FallbackGuard.exe`，服务 `MTTFTestIndependent-<安装ID>` | SYSTEM 独立数据库观察与恢复事务执行；没有持久运行意图则等待。 |
| `\MTTFTest\Independent-<安装ID>` | 专属交互用户的最高权限启动任务；仅接受有效的一次性恢复启动凭证。 |
| `MTTFTestSupervisor` | 原会话监督服务，SYSTEM；承载和核验主程序创建的会话看门狗。 |
| `MTTFTestSessionAgent` 登录任务 | 在实际交互登录会话中运行 SessionAgent。 |
| 当前会话 Watchdog、安全工作进程 | 只属于具体项目/批次，按 PID、启动时间和会话身份约束。 |

旧主程序登录自启任务不作为第二个恢复启动者。安装器只接管本安装路径所属的注册；若提示其他安装归属，先查原安装位置，不能通过批量删除同名任务/进程绕过。

## 安装前确认

1. 本轮不自动更新 WJ-EPB。实际换版时先记录当前项目路径、勾选通道、人工暂停/永久隔离、计数和旧安装路径，保存旧完整包。
2. 人工停止试验，确认控制输出和装置状态安全，等待停止收尾并退出。不要在仍运行时覆盖 DLL；不要用安装命令绕过安全联锁。
3. 将候选 `.7z` 完整解压到本机，保留 `Base`、`FallbackGuard`、`Tools` 和所有一键入口结构。校验归档 SHA，再执行包检查。
4. 使用目标交互账户确认 SID。普通登录账户 PowerShell 可执行：

```powershell
[Security.Principal.WindowsIdentity]::GetCurrent().User.Value
```

SYSTEM 会话中该值是 SYSTEM，不能当成交互账户 SID。远程安装应明确传入实际登录试验账户的 SID。

## 新安装

在**候选包目录**打开管理员 Windows PowerShell。以下变量按现场实际值填写；不要照抄项目路径到其他台架。

```powershell
$installRoot = 'C:\Program Files (x86)\MTTFTest_4.1.0.0_rc2'
$projectPath = 'D:\EPB\_Data\10243-028'
$operatorSid = '实际交互账户SID'
.\Install-AutomaticRecoveryBundle.ps1 -Mode ValidatePackage
.\Install-AutomaticRecoveryBundle.ps1 -Mode Install -InstallRoot $installRoot -ProjectDirectory $projectPath -InteractiveUserSid $operatorSid
.\Install-AutomaticRecoveryBundle.ps1 -Mode Status -InstallRoot $installRoot
```

安装目录必须尚不存在，父目录必须受保护。安装注册后台，不主动开始试验。启动程序后人工核对项目和有效通道，再执行原安全预检、自学习和开始流程。快捷方式文件版本应显示 V4.1.0.0，候选 rc 身份看安装清单及标签。

## 从旧版升级或替换

**数字版本更高且有原完整包**时，在新包目录执行：

```powershell
$oldBundle = 'D:\保存的旧版完整解压包'
.\Install-AutomaticRecoveryBundle.ps1 -Mode ValidateUpgrade -InstallRoot $installRoot -PreviousBundleDirectory $oldBundle
.\Install-AutomaticRecoveryBundle.ps1 -Mode Upgrade -InstallRoot $installRoot -PreviousBundleDirectory $oldBundle
```

升级成功仍处于维护停止，不自动续测。检查状态后，通过“恢复后台服务”或以下命令显式启用，然后人工打开程序并核对试验：

```powershell
.\Install-AutomaticRecoveryBundle.ps1 -Mode Restore -InstallRoot $installRoot
```

**4.1.0.0-rc.1 与 rc.2 数字版本相同**，不能冒充数字版本升级，也不能用修复入口覆盖不同构建。先使用新包中的兼容卸载入口核验并移除原独立架构安装，再选一个全新的受保护安装目录安装 rc.2：

```powershell
.\Tools\Install-IndependentRecoveryBundle.ps1 -Mode Uninstall -BundleDirectory $oldBundle -InstallRoot $oldInstallRoot
```

上述兼容入口仅用于有独立架构清单、注册与原文件记录的包；V2/V3 旧架构须使用其原包卸载流程，不能猜测迁移。卸载保留配置、数据和诊断，原目录仍可能存在；不要递归清空现场目录。新安装直接指向原项目数据库，不重置计数。

## 修复、回滚、卸载

修复必须用**同构建完整包**，用于组件损坏或服务/任务缺失：

```powershell
.\Install-AutomaticRecoveryBundle.ps1 -Mode Repair -InstallRoot $installRoot
.\Install-AutomaticRecoveryBundle.ps1 -Mode Status -InstallRoot $installRoot
# 完成检查后显式启用后台；这不代表已经开始试验。
.\Install-AutomaticRecoveryBundle.ps1 -Mode Restore -InstallRoot $installRoot
```

数字版本升级后回滚，在本次新包目录使用升级记录 `Upgrade\<32位事务ID>\result.json` 的 ID 和原包：

```powershell
.\Install-AutomaticRecoveryBundle.ps1 -Mode RollbackUpgrade -InstallRoot $installRoot -PreviousBundleDirectory $oldBundle -TransactionId '实际升级事务ID'
```

回滚恢复原程序、注册和快捷方式，保持维护停止。`FinalizeUpgrade` 用于最终注册失败的重试；`RecoverFiles` 使用 `Repair` 文件事务 ID，不能代替数字版本回滚，也不能猜测事务 ID。

卸载当前构建用该构建包的“一键卸载”或：

```powershell
.\Install-AutomaticRecoveryBundle.ps1 -Mode Uninstall -InstallRoot $installRoot
```

回滚后旧构建需要新管理入口兼容清理时，使用上面的 `Tools\Install-IndependentRecoveryBundle.ps1 -Mode Uninstall -BundleDirectory $oldBundle`。所有入口均核验本安装归属，保留项目数据，不以进程名称全局强杀。

## 恢复验收及异常处理

正常运行每 5 秒只读观察；正式停滞阈值 `max(90秒,6×周期)`，连续三次确认；自学习使用其配置预算。每项目每 30 分钟最多三次整体重启，失败间隔至少 60 秒。达到预算或安全不能确认必须明确记录未恢复原因，不能无休止重启。

一次恢复验收必须同时满足：唯一替代控制进程、恢复目标正确、旧授权失效、新监督绑定、装置动作恢复、机械计数推进、至少三个新正式周期落盘。手工取消勾选、人工暂停、整批停止、已完成或永久隔离的通道不得被重启重新加入。

数据库不可读与无推进不同；先看独立事务、阶段期限、具体安全阻塞项和有界采证结果。真实电流/压力、NI 设备句柄释放和重新打开、DO/AO 的物理输出必须单列台架验收。当前结果不能证明所有 Dev 回调中断已经消除，也不能以几小时无故障宣称长期稳定性已经证明。
