## 3. 根因结论

第 28 圈属于软件误报警，不是程控电源故障，也不能据此判定卡钳真实堵转。

- 项目 `TestConfig.xml` 仍保存旧值 `ForwardProgressConfirmMs=200`、`ForwardProgressDeadlineMs=3000`，覆盖了源码原有的 `1000ms / 5000ms` 安全默认值。报警中的 `window=220ms` 与该旧配置吻合。
- EPB10 第 28 圈的 2kHz 原始电流峰值为 `15.301A`，其中约 `11.5ms` 高于 15A；10ms 快速控制通道恰好漏过这段短峰，随后只观察到约 14.6A 的低斜率平台。
- 原算法只用 10ms 控制样本做正向进展判定，因而把“已经达到夹紧目标后的平台”错误判为 `ForwardCurrentRiseStalled`。
- 程控电源遥测共检查 16640 条记录，未发现断连、CC、限流、保护或通信错误，不支持供电故障结论。
- 4 条峰值软预警全部发生在学习阶段；正式阶段 177 个完整圈的峰值误差全部在 ±0.8A 内。软预警不会停止试验，影响耐久运行的是第 28 圈错误进入了硬停路径。

## 4. 参数归属整改

以下参数自本次整改起属于程序安全策略，只从 `MTTfTest.exe.config` 的 `appSettings` 加载。切换项目不再改变这些值，旧项目 XML 中的同名字段仅兼容读取、运行时明确忽略，项目保存时也不再写回。

| EXE 配置键 | 生效默认值 | 含义 |
|---|---:|---|
| `EpbForwardProgressConfirmMs` | 1000ms | 低于合格下限时，正向低斜率硬故障确认 |
| `EpbForwardMinimumRiseSlopeAperMs` | 0.001A/ms | 正向最低进展斜率 |
| `EpbForwardProgressDeadlineMs` | 5000ms | 正向负载上升进展期限 |
| `EpbForwardNearTargetConfirmMs` | 200ms | 近目标平台确认 |
| `EpbForwardAcceptableUndershootA` | 0.8A | 目标允许欠量，15A 对应 14.2A 合格下限 |
| `EpbReverseProgressConfirmMs` | 200ms | 反向进展确认 |
| `EpbReverseMinimumDecaySlopeAperMs` | 0.001A/ms | 反向最低衰减斜率 |
| `EpbReverseProgressDeadlineMs` | 2500ms | 反向进展期限 |
| `EpbOffCurrentClearThresholdA` | 0.1A | 断电清零电流阈值 |
| `EpbOffCurrentClearTimeoutMs` | 1000ms | 断电清零超时 |

启动时对安全参数执行下限校验：正向确认不小于 1000ms、正向期限不小于 5000ms、反向确认不小于 200ms、反向期限不小于 2500ms、清零超时不小于 1000ms。缺失或非法值采用编译安全默认值并记录警告。

每次启动试验均会在项目 `Config` 目录生成 `EpbProgramSafetyEffective.xml`，记录策略版本、生效值、来源和捕获时间；该文件只用于审计，不参与下次加载。

项目配置继续保留与工况直接相关的内容，例如目标电流、保持时间、反向释放限值、启用通道、错峰和试验次数。

## 5. 正向判定矩阵

控流目标保持 15A，合格下限采用 `15-0.8=14.2A`，斜率阈值仍保持 `0.001A/ms`，不通过降低斜率阈值掩盖真实堵转。

| 优先级 | 证据 | 处理 | 圈结果 |
|---:|---|---|---|
| 1 | 预测值或 10ms 控制电流达到 15A | 立即断电 | 正常成功 |
| 2 | 2kHz 全数据峰值达到 15A | 下一次快速回调立即断电，并继续执行峰值超调检查 | 正常成功，断电原因 `FullRateTarget` |
| 3 | 低斜率持续 200ms，且有效峰值/平台不低于 14.2A | 安全断电，继续保持和反向释放 | `SuccessWithWarning`，原因 `NearTargetPlateau` |
| 4 | 电流低于 14.2A 且低斜率连续 1000ms | 立即断电并报警 | 硬故障 `ForwardCurrentRiseStalled` |

近目标完成和全数据达标都不会取消峰值捕获。断电后仍执行超调上限、连续超调、断电清零、报警快照等既有逻辑。开路、异常电流下降、DAQ 断流、9 秒绝对正向上电、反向失速、过流、程控电源保护和断电未清零继续作为硬保护。

圈结果及日志现在分别记录：

- 断电原因；
- 2kHz 全数据峰值；
- 10ms 控制通道峰值；
- 目标电流和峰值误差；
- 安全策略版本。

## 7. 台架发布步骤

1. 先执行 200 圈复测，确认无软件误报警、无旧项目参数回流，并核对全数据峰值与控制峰值字段。
2. 再执行 1000 圈先导试验，检查 `NearTargetPlateau` 是否集中在单个卡钳或连续恶化。
3. 前两阶段通过后进入 10 万圈正式耐久。

学习阶段零散峰值软预警允许继续试验。正式阶段若近目标预警连续出现或集中在同一卡钳，应检查卡钳机械状态、线束压降和采样链路；不得自动放宽斜率、过流、开路、DAQ 断流或绝对上电等硬保护。
