# EPB4、EPB5、EPB11、EPB12 启动时序确认

## 1. 问题说明

现场同时启用了 EPB4、EPB5、EPB11、EPB12。根据实时电流曲线观察，卡钳的上电顺序表现为：

```text
EPB4 → EPB5 与 EPB11 → EPB12
```

而不是预期的：

```text
EPB4 与 EPB11 → EPB5 与 EPB12
```

本文结合当前程序代码及配置确认实际启动规则。

## 2. 确认结论

当前程序的设计时序就是：

```text
公共电机锚点
   0 ms：EPB4
 800 ms：EPB5、EPB11
1600 ms：EPB12
```

因此，现场曲线呈现的 `4 → 5&11 → 12` 与当前程序实现一致，并非曲线显示错误。

程序不会因为本次只选择了部分卡钳，就重新压缩各电源组内部的启动序号。每个卡钳使用其在 XML 电源组成员列表中的固定物理位置计算启动相位；未选择的卡钳仍然保留对应的空时序位置。

## 3. 当前电源组配置

配置文件：`MTTfTest/Config/TestConfig.xml`

当前四个电源组的错峰时间均为 `800 ms`。与本次选择有关的配置为：

```xml
<Group>
  <Id>2</Id>
  <StaggerMs>800</StaggerMs>
  <Members>4,5,6</Members>
</Group>

<Group>
  <Id>4</Id>
  <StaggerMs>800</StaggerMs>
  <Members>10,11,12</Members>
</Group>
```

按成员列表中的固定位置计算，本次四个卡钳的分配如下：

| 卡钳 | 电源组 | XML 成员列表 | 固定批次序号 | 启动相位 |
|---|---:|---|---:|---:|
| EPB4 | 2 | 4、5、6 | 0 | 0 ms |
| EPB5 | 2 | 4、5、6 | 1 | 800 ms |
| EPB11 | 4 | 10、11、12 | 1 | 800 ms |
| EPB12 | 4 | 10、11、12 | 2 | 1600 ms |

其中 EPB10 虽然没有启用，但其固定的第一个位置不会被 EPB11 补位。因此 EPB11 仍处于 `800 ms` 相位，而不是 `0 ms` 相位。

## 4. 代码依据

### 4.1 固定批次位置不会因稀疏选择而压缩

文件：`Controller/ElectricalStaggerPlan.cs`

`ChannelStaggerAssignment.BatchOrdinal` 的代码注释明确说明：批次序号来自 XML `Group/Members` 中的物理位置，不随稀疏选择、故障隔离或恢复重入而压缩。

错峰计划生成时，程序先对原始成员列表执行带索引的枚举：

```csharp
group.Members
    .Select((channel, batchOrdinal) => new { channel, batchOrdinal })
    .Where(item => selectedSet.Contains(item.channel))
```

这里是在过滤已选通道之前取得 `batchOrdinal`，所以未选择成员的位置仍被保留。

单通道相位的计算公式为：

```csharp
PhaseMs = checked(batchOrdinal * staggerMs);
```

### 4.2 正式运行按照公共锚点加固定相位启动

文件：`Controller/EpbManager.BatchStart.cs`

正式阶段获得双液压组共同的电机锚点后，各通道的计划启动时间按照以下方式计算：

```csharp
var plannedStartUtc = globalSlot.MotorAnchorUtc.Value
    .AddMilliseconds(phase);
```

因此不同电源组中具有相同固定批次序号的卡钳会同时启动。本次 EPB5 和 EPB11 都处于固定序号 1，所以二者都在公共锚点后 `800 ms` 启动。

学习阶段也使用同一份固定错峰计划，因此学习、资格检查和正式运行阶段的电气相位规则保持一致。

## 5. 为什么不是 EPB4 与 EPB11 同时启动

若按“本次每个电源组实际选择的通道重新排序”，分组将会是：

```text
电源组2：[EPB4, EPB5]   → 0 ms、800 ms
电源组4：[EPB11, EPB12] → 0 ms、800 ms
```

这样才能得到：

```text
0 ms：EPB4、EPB11
800 ms：EPB5、EPB12
```

但当前代码明确采用固定物理位置策略，而不是上述动态压缩策略。所以 EPB11 不会因 EPB10 未选择而从 `800 ms` 前移到 `0 ms`，EPB12也不会从 `1600 ms` 前移到 `800 ms`。

## 6. 当前策略的设计含义

固定物理位置策略可以保证同一卡钳在以下场景中的相位保持不变：

- 部分通道未启用；
- 某个通道发生故障并被隔离；
- 通道经过无人值守恢复后重新加入；
- 不同批次选择了不同的卡钳组合。

其代价是：当一个电源组只选择了后部成员时，前面会保留空相位，不能自动形成“各电源组第一台同时、第二台同时”的紧凑启动队列。

## 7. 是否需要修改

如果业务要求明确为“各电源组本次选中的第一台同时启动、第二台同时启动”，则需要把错峰规则由固定物理序号改为本次已选成员的压缩序号。

该修改不应只调整一处延时计算，还需要同步评估：

- 学习阶段和正式阶段是否继续使用同一份计划；
- 故障隔离后剩余通道是否允许改变相位；
- 恢复重入时是否保持启动前相位，还是按当前存活成员重新排位；
- 相位变化是否影响液压公共槽、周期对齐及事故证据解释；
- 运行日志中的 `batch`、`phase` 字段是否仍能稳定追踪同一卡钳。

在未修改程序前，应以当前固定相位规则作为现场曲线判读依据。
