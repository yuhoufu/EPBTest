# EPB 常温疲劳测试软件程序打包方案

本文档用于指导当前 `EPBTest` 解决方案后续建立 Windows 安装包工程和一键构建流程。打包对象仅为 EPB 常温疲劳测试主程序，不在本文档对应的首版安装包中包含调试工具、通信测试工具和自动化测试程序。

## 1. 项目与发布基线

### 1.1 主程序

- 解决方案：`TfTest.sln`
- 主项目：`MTTfTest/MTTfTest.csproj`
- 发布入口：`MTTFTest.exe`
- 产品显示名：`EPB常温疲劳测试软件`
- 发布者：`上海好耐电子科技有限公司`
- 当前基准版本：`2.6.0`
- 版本来源：`MTTfTest/Properties/AssemblyInfo.cs` 中的 `AssemblyInformationalVersion`

### 1.2 技术环境

- Windows 10/11
- Visual Studio 2022 或 Visual Studio Build Tools 2022
- C# 9
- WinForms
- .NET Framework 4.8
- NuGet `packages.config` 依赖管理
- 安装包工具：Inno Setup 6
- 构建脚本：PowerShell 7，同时兼容 Windows PowerShell 5.1

### 1.3 架构约束

安装包和绿色版固定发布为 **x86**，不得使用 AnyCPU 或 x64。实施打包工程前，应将主项目的 `Release` 配置统一为 x86，并确认相关项目引用使用同一架构。

采用 x86 的原因如下：

- `Controller` 的现有构建目标为 x86；
- NI-DAQmx 引用声明为 x86；
- SQLite 依赖包含 x86 原生库 `x86/SQLite.Interop.dll`；
- 当前主项目的 Debug 和 Release 存在 x86/AnyCPU 混用，直接按 AnyCPU 发布存在原生库加载失败风险。

构建脚本必须在收集文件前验证生成的 `MTTFTest.exe` 为 x86。如果检测到 AnyCPU 或 x64，应立即终止构建并给出明确错误。

## 2. 交付目录规划

后续实施时，在仓库根目录新增以下结构：

```text
installer/
├─ EPBTest.iss
├─ Includes/
└─ Assets/

scripts/
├─ Build.ps1
├─ Publish.ps1
└─ BuildInstaller.ps1

publish/
└─ EPBTest-x86/

artifacts/
```

目录职责：

- `installer/`：Inno Setup 工程、公共宏、图标和安装界面资源；
- `scripts/`：编译、文件收集和安装包生成脚本；
- `publish/EPBTest-x86/`：经过筛选的临时发布目录，不提交 Git；
- `artifacts/`：最终安装包、绿色版 ZIP 和 SHA256 校验文件，不提交 Git。

## 3. 安装与运行目录

### 3.1 首版默认目录

首版安装目录使用：

```text
{commonappdata}\Horizon\EPBTest
```

即通常对应：

```text
C:\ProgramData\Horizon\EPBTest
```

开始菜单和桌面快捷方式直接指向该目录中的 `MTTFTest.exe`，并将“起始位置”设置为安装目录。

不应将首版安装到 `{autopf}`。当前程序大量使用 `Environment.CurrentDirectory`、`Application.StartupPath` 和 `AppDomain.CurrentDomain.BaseDirectory` 访问 `Config`，并会修改配置、创建试验项目、SQLite 数据库、日志和 `.dat` 缓存。安装到只读的 Program Files 可能导致普通用户启动后写入失败。

安装器必须为 `Users` 组授予安装目录的“读取、执行、创建、修改”权限，管理员保留完全控制权限。不要向 `Everyone` 授予完全控制权限。

### 3.2 首次安装目录

首次安装至少创建：

```text
Config\
DataStore\
log\
Backup\
```

其中：

- `Config` 存放软件默认配置和现场调整后的配置；
- `DataStore` 存放试验项目、项目配置、`index.db` 和滑动缓存；
- `log` 存放运行、警告和错误日志；
- `Backup` 存放安装器执行覆盖升级前生成的配置备份。

### 3.3 后续迁移方向

若未来需要符合标准的“程序与数据分离”结构，可将程序安装到 `{autopf32}\Horizon\EPBTest`，将现场数据保存在 `{commonappdata}\Horizon\EPBTest`。执行该迁移前必须先改造业务代码，集中管理配置与数据根目录，不能只修改安装脚本。

## 4. 发布文件清单

### 4.1 必须包含

发布内容以一次干净的 `Release|x86` 构建输出为基础，至少包含：

- `MTTFTest.exe` 和 `MTTFTest.exe.config`；
- 项目程序集：`Config.dll`、`Controller.dll`、`DataOperation.dll`、`IO.NI.dll`、`Timing.dll`、`ZlgCanComm.dll`、`PowerSupply.Core.dll` 和实际构建产生的其他项目 DLL；
- DevExpress 24.2 运行时 DLL，仅收集主程序实际引用和运行所需的程序集；
- `SunnyUI.dll`、`SunnyUI.Common.dll`、`ZedGraph.dll`；
- `System.Data.SQLite.dll` 及 `x86/SQLite.Interop.dll`；
- `System.Buffers.dll`、`System.Memory.dll`、`System.Numerics.Vectors.dll`、`System.Runtime.CompilerServices.Unsafe.dll` 等实际复制到输出目录的 NuGet 运行时依赖；
- `AsyncTcpClient.dll` 及其他硬件通信依赖；
- `Config/AIConfig.xml`、`AlarmConfig.xml`、`AOConfig.xml`、`DOConfig.xml`、`PowerSupplyConfig.xml`、`TestConfig.xml`、`UIConfig.xml`；
- 程序运行所需的 CAN DBC 文件，例如代码引用的 `Config/CAN_V4_3_0.dbc`；
- `License-LGPL.txt` 以及第三方组件许可要求必须随程序分发的文本；
- 经确认实际使用的中文资源程序集。

发布脚本不得只维护一份容易过期的 DLL 手写名单。应先从干净构建输出收集文件，再通过允许和排除规则筛选，并对上述关键文件做显式存在性验证。

### 4.2 必须排除

默认排除：

- `*.pdb`，只有指定 `-IncludePdb` 时才保留；
- 第三方 API 文档 `*.xml`；
- `*.vshost.*`、`*.manifest`、构建日志和临时文件；
- `DataStore` 中的任何历史试验项目；
- `EPB*_sliding.dat` 及其他运行产生的 `.dat` 文件；
- `index.db`、历史 SQLite 数据库和数据库日志；
- `log`、`Logs`、`运行日志` 等运行日志目录；
- 开发现场生成的 CSV、错误日志和运行日志；
- 未使用的卫星语言资源目录；
- 测试程序集、测试夹具和调试工具输出。

发布脚本应把 `DataStore` 作为空目录创建，禁止从 `MTTfTest/bin/Release/DataStore` 复制任何内容。特别是现有构建目录中的大型 `EPB*_sliding.dat` 文件绝不能进入安装包或绿色版。

### 4.3 不属于首版安装包

以下程序不包含在主安装包中：

- `PowerSupplyDebugger`；
- `ClientOfEMB1` 和 `ClientOfEMB2`；
- `AdaptiveControlTests`、`EpbDiskWriterTests`、`PowerSupplyDebugger.Tests`；
- 开发相关目录中的串口、CAN、程控电源和 NI 调试工具。

## 5. 前置环境与硬件依赖

### 5.1 .NET Framework 4.8

安装器必须检测 .NET Framework 4.8 Release 注册表值。缺失时：

- 显示中文提示，说明主程序无法运行；
- 支持通过参数指定离线安装程序路径；
- 离线安装失败或用户取消时不得继续安装主程序；
- 安装完成需要重启时，应正确提示或返回对应静默安装退出码。

### 5.2 NI-DAQmx

安装器必须检测与当前程序架构和程序集版本兼容的 NI-DAQmx Runtime/驱动。首版不把 NI 安装程序嵌入主安装包，而是：

- 缺失时给出中文提示和内部安装说明；
- 支持通过安装器参数传入外部离线安装程序；
- 将“仅安装软件、不连接采集设备”作为可选继续路径；
- 在发布说明中记录开发验证使用的 NI-DAQmx 版本和测试硬件型号。

NI .NET 程序集随主程序分发与 NI 驱动安装不是同一件事。即使发布目录包含 `NationalInstruments.Common.dll` 和 `NationalInstruments.DAQmx.dll`，目标机仍需安装匹配的硬件驱动。

### 5.3 周立功 CAN 驱动

程序使用 `ZlgCanComm`。安装器应预留周立功 CAN 设备驱动检测接口，驱动缺失时给出中文安装说明，但不在首版主安装包中内嵌驱动。

### 5.4 DevExpress 许可

打包前必须由项目负责人确认 DevExpress 24.2 的运行时再分发许可，并仅分发运行必需的 DevExpress DLL。不得把设计时组件、调试符号或完整开发环境程序集无差别打入安装包。

## 6. 安装包行为

Inno Setup 工程应满足以下要求：

1. 安装范围为所有用户，需要管理员权限。
2. 创建开始菜单快捷方式。
3. 提供可选桌面快捷方式，默认不勾选。
4. 在 Windows“已安装的应用”中显示产品名称、版本、发布者、图标和卸载入口。
5. 安装前检测 `MTTFTest.exe` 是否正在运行；提示用户关闭，并允许安装器在确认后关闭进程。
6. 使用稳定且唯一的 `AppId`，后续版本不得更换，以支持覆盖升级。
7. 安装完成页提供“启动 EPB常温疲劳测试软件”选项，静默模式下不自动启动。
8. 支持 `/SILENT`、`/VERYSILENT`、`/SUPPRESSMSGBOXES` 和 `/NORESTART` 等 Inno Setup 标准参数。
9. 支持静默卸载，并保证默认不删除用户数据。
10. 安装失败必须回滚本次写入的程序文件，不得破坏升级前的配置备份。

安装包输出名称：

```text
EPBTest_Setup_{Version}_x86.exe
```

绿色版输出名称：

```text
EPBTest_Portable_{Version}_x86.zip
```

## 7. 配置、升级与卸载策略

### 7.1 首次安装

- 将经过版本控制的默认配置复制到 `Config`；
- 创建空的 `DataStore` 和 `log`；
- 不附带任何现场历史数据；
- 安装结束前验证主程序、配置、DBC 和 SQLite x86 原生库存在。

### 7.2 覆盖升级

升级前必须：

1. 确认主程序已退出；
2. 将现有 `Config` 完整复制到带日期和旧版本号的 `Backup` 子目录；
3. 对程序文件执行覆盖更新；
4. 对配置文件采用“保留现场配置优先”策略；
5. 新增配置文件可补充，已存在配置不得被默认模板直接覆盖；
6. 如配置格式必须升级，应由明确的迁移逻辑处理，并在迁移失败时恢复备份。

升级时必须保留：

- `Config` 中现场修改的配置和标定值；
- `DataStore` 中所有项目目录；
- `index.db` 及其他 SQLite 数据库；
- 所有 `.dat`、CSV 和历史测试数据；
- `log` 中的日志；
- `Backup` 中既有备份。

### 7.3 卸载

默认卸载只删除由安装器安装的程序文件、快捷方式和卸载注册信息，保留 `Config`、`DataStore`、`log` 和 `Backup`。

交互式卸载结束时可询问：

> 是否同时删除现场配置、标定数据、试验数据库、日志和全部历史测试数据？此操作不可恢复。

只有用户明确确认后才能删除数据目录。静默卸载默认必须保留数据；如确需自动清理，应使用单独且含义明确的参数，例如 `/PURGEUSERDATA=1`，并在发布说明中突出风险。

## 8. 一键构建脚本

统一入口：

```powershell
.\scripts\BuildInstaller.ps1 `
    -Configuration Release `
    -Platform x86 `
    -Version 2.6.0
```

可选参数建议：

```powershell
-IncludePdb
-SkipInstaller
-SkipPortable
-MsBuildPath <path>
-IsccPath <path>
-DotNet48OfflineInstaller <path>
```

脚本应按以下顺序执行：

1. 解析仓库根目录，所有路径都基于脚本位置计算，不依赖当前工作目录。
2. 校验版本号格式，并与 `AssemblyInformationalVersion` 比较；不一致时默认报错，除非实施时定义了明确的版本注入机制。
3. 使用 `vswhere.exe` 探测 Visual Studio 2022/MSBuild，同时允许参数覆盖。
4. 探测 Inno Setup 6 的 `ISCC.exe`，同时允许参数覆盖。
5. 检查 NuGet 或 MSBuild restore 能力并恢复 `packages.config` 依赖。
6. 清理并重新创建 `publish/EPBTest-x86` 和本次构建对应的 `artifacts` 临时内容。
7. 以 `Release|x86` 编译主项目及其项目依赖；不得把整个解决方案中的测试和调试工具作为发布目标。
8. 验证构建产物存在、主程序架构为 x86、关键 DLL 版本和 SQLite x86 原生库正确。
9. 收集发布文件并应用包含/排除规则。
10. 明确创建空的 `DataStore`、`log` 和 `Backup`，不从构建目录复制运行数据。
11. 执行发布清单校验；发现关键文件缺失、禁止文件存在或意外超大文件时立即失败。
12. 将版本、源目录、输出目录、产品名和发布者传递给 Inno Setup。
13. 生成安装包。
14. 从同一份已校验发布目录生成绿色版 ZIP。
15. 为安装包和 ZIP 分别生成 SHA256 校验文件。
16. 输出产物路径、大小、SHA256、版本和构建时间摘要。

任一环节失败时必须立即停止，返回非零退出代码，并输出包含失败步骤、文件路径和建议处理方式的中文错误信息。脚本必须正确处理包含空格和中文的路径，不得写死开发电脑上的 Visual Studio、NI 或 Inno Setup 绝对路径。

## 9. 发布清单校验

构建脚本在生成安装包前执行强制校验。

### 9.1 必须存在

```text
MTTFTest.exe
MTTFTest.exe.config
Config\AIConfig.xml
Config\AlarmConfig.xml
Config\AOConfig.xml
Config\DOConfig.xml
Config\PowerSupplyConfig.xml
Config\TestConfig.xml
Config\UIConfig.xml
Config\CAN_V4_3_0.dbc
System.Data.SQLite.dll
x86\SQLite.Interop.dll
```

项目依赖 DLL 和硬件通信 DLL 也必须根据实际引用结果逐一验证。

### 9.2 禁止存在

```text
*.pdb                  # 未指定 -IncludePdb 时
*.vshost.*
DataStore\*            # 允许目录存在，但必须为空
log\*                  # 允许目录存在，但必须为空
*.db
*.dat
*.csv
RunLog_*.txt
WarnLog_*.txt
ErrorLog_*.txt
```

应额外设置单文件体积告警阈值，例如 50 MB。除已登记的合法运行时文件外，发现超过阈值的文件应终止发布，防止误收集现场数据。

## 10. 安装与发布验收

### 10.1 构建验收

- 在未预先设置当前目录的 PowerShell 中也能执行统一入口；
- PowerShell 7 和 Windows PowerShell 5.1 均能运行；
- 路径包含中文和空格时仍能成功；
- 缺少 MSBuild、ISCC、依赖包或关键发布文件时返回非零退出码；
- 最终产物名称、程序集版本、安装器版本一致；
- 安装包和绿色版来自同一份已校验的发布目录；
- SHA256 文件内容与产物一致；
- 产物不包含历史项目、数据库、日志和大型滑动缓存。

### 10.2 安装验收

在一台未安装本软件的 Windows 10/11 测试机上验证：

1. 正常安装、开始菜单快捷方式和可选桌面快捷方式；
2. “已安装的应用”信息完整；
3. 普通用户能够启动程序并读写 `Config`；
4. 首次创建试验项目、`DataStore`、数据库和日志成功；
5. SQLite 能加载 `x86/SQLite.Interop.dll`，无 `BadImageFormatException` 或 DLL 找不到错误；
6. 安装 .NET Framework 4.8 后程序可以启动；
7. NI-DAQmx 缺失时安装器提示清晰，程序部署状态可识别；
8. NI-DAQmx 和周立功驱动正确安装后，采集设备和 CAN 设备连接成功；
9. 程控电源和其他硬件通信基本功能正常；
10. 程序运行时再次安装会提示关闭程序；
11. `/SILENT` 和 `/VERYSILENT` 安装行为符合预期。

### 10.3 升级与卸载验收

- 使用包含自定义配置和历史数据的旧版本执行覆盖升级；
- 升级前配置备份成功；
- 现场配置、标定值、项目数据库、日志和 `.dat` 文件不丢失；
- 新版本程序文件正确覆盖，版本显示为目标版本；
- 默认卸载后用户数据仍存在；
- 重新安装后可继续识别保留的数据；
- 只有明确选择清理数据时才删除整个数据目录；
- 静默卸载默认保留数据。

### 10.4 绿色版验收

- ZIP 解压到普通用户可写目录后可直接启动；
- ZIP 内 `DataStore` 和 `log` 为空；
- 配置、DBC、SQLite x86 原生库和运行依赖齐全；
- 在只读目录启动时，应在发布说明中明确提示当前版本不支持该用法；
- 绿色版与安装版使用相同版本号并通过 SHA256 校验。

## 11. 发布资料

实施安装工程时应同时新增 `README-Installer.md`，至少说明：

- 开发机所需工具和版本；
- 一键构建命令及参数；
- .NET Framework、NI-DAQmx 和周立功驱动准备方式；
- 安装、静默安装、升级和卸载命令；
- 用户数据保留与清理规则；
- 发布清单、测试记录和 SHA256 校验方式；
- DevExpress 和其他第三方组件的再分发合规要求；
- 已知限制：首版程序和可写数据位于同一 ProgramData 目录。

每次正式发布至少保留安装包、绿色版、SHA256 文件、构建日志、发布清单和验收记录，并由发布人员记录版本、Git 提交号、构建机器和日期。
