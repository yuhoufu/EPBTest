# Dev1 队列报警修复实施与验证

## 1. 结论

本次修改消除了 DAQ 后台处理线程同步写磁盘/SQLite 的耦合点，并为每台 DAQ 增加独立持久化队列、设备级安全暂停和 10 秒自动恢复闭环。持久化过载时，仅暂停故障设备对应卡钳；当前圈安全断电、释压并封为 `canceled`，不计入成功圈数。恢复后从下一完整圈继续。

原有液压封圈屏障和资格后相位窗口修改均保留，未修改事件复盘报告及产品版本号。

## 2. 架构变化

数据链路调整为：

1. DAQ 回调只完成快速控制样本发布和原始批次轻量入队。
2. `ProcessLoop` 完成工程转换、因果滤波、安全快照、峰值和 `DaqDiskBatch` 构造。
3. `DiskBatchReady` 将池化批次转交给 `DaqPersistenceCoordinator`；旧 `OnDiskBatch` 仅作为弃用兼容接口保留。
4. 协调器维护 Dev1/Dev2 两个独立有界队列，由一个公平轮询工作线程串行访问共享 SQLite 连接。
5. `DiskWriterRecorderAdapter` 通过 `IBatchedEpbCycleRecorder` 执行设备内多通道事务写入；每通道每批只更新一次 `sample_count/end_time`。
6. 环形文件使用连续数组批量写；跨文件尾部时最多拆为两段。

池化缓冲区所有权只转移一次，并在成功、失败、拒绝、旧 generation 丢弃和关闭流程中归还。

## 3. 周期一致性

- `BeginCycle` 保存准确 UTC 开始时间，早于开始边界的积压样本被过滤。
- 完成、取消、报警快照和历史证据均先固定结束时间，再等待 DAQ 发布序列及持久化序列到达封圈水位。
- `SealCycleWindow` 拦截晚于结束时间的样本，跨边界批次按时间窗截取。
- 最终样本数在封圈屏障完成后从记录器重新读取，不使用异步队列消费前的旧计数。
- `canceled`、`failed`、`alarm` 不进入正常成功圈计数；定时器只按成功圈达到目标后结束。
- 暂停时调度基准按实际暂停时长平移，恢复后不追赶暂停期间错过的触发点。

## 4. 安全暂停与恢复

触发 `DaqPersistenceLag` 或 `BackgroundQueueFull` 后：

- 高优先级关闭对应 DAQ 设备映射的 EPB 输出；
- 取消当前圈的临时令牌、冻结圈结束时间、释放液压租约；
- 通道进入 `Paused`，Runner、试验会话及成功圈计数保留；
- 暂停截止时间后的批次不再落入正式圈；
- `BackgroundQueueFull` 重建对应 DAQ，并将协调器切换到新 generation，旧代次批次不得倒灌；
- Dev1/Dev2 分别维护恢复上下文和关联号，不对另一设备的通道执行停机。

恢复必须同时满足：队列深度不高于恢复水位、最老批次不超过恢复年龄、无在途/未解决写盘异常、连续新鲜后台批次达标、DAQ 连续回调新鲜且 generation 一致。通过电源/DAQ 准备检查后恢复液压参与资格及定时器，从下一完整圈继续。

SQLite/I/O 异常按 `25/50/100/250 ms` 退避重试。10 秒未恢复、真正达到硬容量或不可恢复写盘错误升级为设备级锁存故障。升级时仅最小通道号作为主报警，其余通道显示同关联号的“联锁停机”。`ControlQueueFull`、`DaqCallbackStale` 仍立即锁存，不进入持久化自动恢复。

DAQ 恢复期间由取消令牌引起的液压故障归类为 `CascadeCanceledByDaqFault` 诊断，不生成压力不足/泄漏二次报警。

## 5. 配置

| 配置项 | 默认值 | 说明 |
|---|---:|---|
| `DaqProcessingQueueCapacity` | 64 | 原 DAQ 工程处理队列，保持不变 |
| `DaqPersistenceQueueCapacity` | 256 | 每设备持久化硬容量 |
| `DaqPersistencePauseDepth` | 128 | 安全暂停深度 |
| `DaqPersistenceResumeDepth` | 32 | 自动恢复深度 |
| `DaqPersistencePauseAgeMs` | 1000 | 最老批次暂停阈值 |
| `DaqPersistenceResumeAgeMs` | 100 | 自动恢复年龄阈值 |
| `DaqPersistenceRecoveryTimeoutMs` | 10000 | 超时升级锁存故障 |
| `DaqPersistenceRequiredFreshBatches` | 10 | 连续新鲜回调/批次数 |

## 6. 故障码与 UI 语义

| 故障码 | 语义 | 行为 |
|---|---|---|
| `DaqPersistenceLag` | 持久化积压 | 设备级安全暂停，可自动恢复 |
| `BackgroundQueueFull` | 后台/持久化队列达到硬上限 | 安全停机；处理队列满时重建 generation，真正硬满时升级 |
| `DaqPersistenceRecoveryTimeout` | 10 秒未恢复 | 设备级锁存报警 |
| `ControlQueueFull` | 控制数据不可信 | 立即锁存 |
| `DaqCallbackStale` | DAQ 主动断流/回调陈旧 | 立即锁存 |

暂停和恢复通过 `DaqPersistenceStateChanged` 统一显示 `Lagging/Paused/Recovering/Recovered/Failed`，暂停阶段不触发蜂鸣器。

## 7. 诊断与导出

每个设备事件创建唯一目录：

`IncidentSnapshots/<yyyyMMdd_HHmmss_fff>-<Device>-<CorrelationId>`

目录至少包含：

- `incident.json`：故障码、generation、队列水位、影响通道、恢复参数及最终结果；
- `daq_timing.csv`：Callback、Processing、Persistence、Lag、HardFault 及转换、滤波、峰值、批次构造、投递、UI 通知等阶段耗时；
- `daq_runtime.csv`：显式 `Runtime` 行，包含 GC、托管内存和线程池余量；
- 可获取时附加当前圈和最近圈 CSV/BIN 证据。

Latest 导出使用唯一毫秒时间戳和序号目录，先在唯一暂存目录完整写入并校验，再以目录重命名原子发布。同目标导出串行化；内容一致视为幂等成功，不一致的旧文件保留为 `.conflict.*` 证据。

## 8. 自动化验证

2026-08-04 本地验证结果：

- Debug x86、Release x86 全量构建：通过（Release 保留仓库既有 73 条警告，0 错误）。
- `AdaptiveControlTests`：`134/134` 通过（基线 132，新增持久化低水位恢复、硬容量真实故障码）。
- `EpbDiskWriterTests`：`20/20` 通过（基线 17，新增批量时间窗/重启、多通道事务、Latest 并发原子导出）。

Debug/Release 两套测试结果一致。现场 2 小时/1000 圈闸门属于台架验证，不以单元测试结果替代。

## 9. 现场检查步骤

1. 使用 6 路、2 kHz、20 点/批、15 秒周期运行至少 2 小时或 1000 圈。
2. 确认 `BackgroundQueueFull=0`、导出失败为 0、正式圈无静默丢批。
3. 从 `daq_timing.csv` 统计处理队列年龄：P99 `<50 ms`、最大值 `<100 ms`。
4. 分别注入 0.5 秒、1 秒、SQLite busy 和 10 秒持续写盘故障。
5. 确认短时故障只暂停对应设备，另一设备继续；当前圈为 `canceled` 且成功计数不增加。
6. 确认健康后 10 秒内自动恢复；持续故障只产生一个主报警及同关联号联锁状态。
7. 检查 IncidentSnapshot 文件完整，无半套 Latest、`.tmp` 残留或“文件已存在”错误。
8. 故障恢复后继续运行，确认托管内存回到预热基线 ±10%，队列和内存不持续上升。

## 10. 回滚

代码回滚应以本次变更集为单位，同时回滚 `DaqDiskBatch/DiskBatchReady`、持久化协调器、批量记录接口和恢复状态机，不能只删除配置项或单独恢复同步写盘。回滚前先停止试验、确认电机输出关闭及液压安全释放，并保留 IncidentSnapshots、Latest 冲突证据和项目日志用于追溯。

配置回滚无需修改项目 XML；新增 App.config 项缺失时程序会使用本文默认值。禁止通过增大 `DaqProcessingQueueCapacity` 规避慢消费。
