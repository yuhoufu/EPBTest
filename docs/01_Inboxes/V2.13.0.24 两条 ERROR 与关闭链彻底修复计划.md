# V2.13.0.24 两条 ERROR 与关闭链彻底修复计划

## 总结

根因已经确认：

- Watchdog ERROR：首次管道连接失败属于正常的“先连接、再拉起 Sidecar”流程，但共享 `TaskCompletionSource` 的异常无人等待，GC 后触发 `TaskScheduler.UnobservedTaskException`。
- AO ERROR：`EpbManager.ReleaseHardwareForRestart()` 已执行 AO 归零和释放，`FormClosed` 又对同一 AO 执行 `ResetAll()`，在 Writer 已清空后产生“冷启动安全基线写零失败”误报。
- 人工停止后关闭还存在重复调用 `StopAllAsync`、重复释放硬件和停止授权状态未随新一轮启动清除的问题。

目标版本确定为 **V2.13.0.24**，修复真实生命周期缺陷，不通过过滤或降级日志掩盖问题。

## 核心修改

### Watchdog 连接异常

- 在 `ConnectReservation` 内增加统一失败发布方法：
  - 向共享完成任务发布原始异常。
  - 立即显式观察该任务异常，避免无并发等待者时进入未观察异常队列。
  - Owner 继续抛出原异常；并发 Joiner 仍收到相同异常。
- `PipeUnavailable` 仍作为首次连接的预期分支，继续执行 Sidecar 拉起和 Attach。
- Sidecar 拉起失败、Attach 失败、协议失败及 Fail-Closed 仍保留真实 ERROR，不改变安全策略。

### AO 生命周期

- 为 `AoController` 增加线程安全的生命周期锁和一次性 `_disposed` 状态。
- 所有写入、归零和释放操作与 `Dispose()` 串行化，避免写入与释放竞态。
- `Dispose()` 幂等；多次调用不再重复释放 NI Task。
- Dispose 后的写入或归零直接拒绝，并最多记录一次准确的生命周期 WARN，不再产生“冷启动安全基线失败”ERROR。
- Dispose 前真实的 AO 写零失败仍必须记录 ERROR，保持安全诊断能力。

### 人工停止与窗体关闭

- 将 `EpbManager.ReleaseHardwareForRestart()` 改为同步、等待式的一次性释放：
  - 并发调用只能有一个执行者。
  - 后续调用等待首次释放完成后返回。
  - DAQ、AO、DO、电源、后台任务和监控资源均只释放一次。
- 在监控窗体内建立统一的硬件释放入口，由 `FormClosing` 和 `FormClosed` 共用：
  - `_epb` 已创建时，由 `EpbManager` 持有并释放硬件。
  - 初始化中途失败、尚未创建 `_epb` 时，才执行直接 DO 断能、AO 归零和采集器释放兜底。
  - `FormClosed` 不再直接重复调用 AO/DO。
- 人工停止完成后保存一份带 RunId、CorrelationId 的停止结果快照：
  - 结果满足现有关闭准入条件、当前批次已结束且期间没有新启动时，关闭窗口直接复用结果，不再启动第二个 StopAll。
  - 结果不完整、超时、仍有批次或无法确认属于当前运行时，继续执行现有 `ApplicationClosing` 安全停机。
  - 每次新的启动请求在任何硬件重新使能前清除旧停止凭证和 `_operatorStopRequested`，防止上一轮人工停止错误授权下一轮退出。
- 不改变现有压力证据不足时的现场退出策略，只消除重复事务和过期授权。

## 测试与验收

- Watchdog 回归：
  - 单 Owner、零 Joiner：首次 PipeUnavailable 后成功拉起并连接，强制 GC 后不得出现未观察异常。
  - 1/64 并发调用者：仍只拉起一次，所有调用者共享相同成功或失败结果。
  - Sidecar 拉起失败、Attach 失败、取消和 Fail-Closed 行为保持原样。
  - 运行 `--watchdog-transport-hardening`、`--watchdog-client-real50` 和严格 Host V4 测试。
- 停机与硬件释放回归：
  - 人工停止成功后关闭：物理 StopAll 一次、硬件释放一次、AO 归零一次。
  - 未人工停止直接关闭：执行一次 ApplicationClosing StopAll 和一次释放。
  - 新一轮启动后关闭：不得复用上一轮人工停止结果。
  - FormClosing/FormClosed 重入或并发：资源释放次数仍为一。
  - `_epb` 初始化失败：直接硬件兜底执行一次。
  - AO Dispose 后误调用不得产生冷启动写零 ERROR；真实写零失败仍产生 ERROR。
  - 运行 `--stop-production-seam`、Watchdog WinForms UI 测试及完整 AdaptiveControlTests。
- 现场验收：
  - V2.13.0.24 冷启动、运行、人工停止、关闭至少重复 5 次。
  - 连续运行不少于 2 小时。
  - ERROR 日志中不得再出现 `TaskScheduler.UnobservedTaskException` 或关闭阶段的 `AO 冷启动安全基线写零失败`。
  - 日志必须能证明 Watchdog 首次连接恢复成功、停止事务唯一、AO/DO/DAQ 释放唯一且最终安全状态成立。
