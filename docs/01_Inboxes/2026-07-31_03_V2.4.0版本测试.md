# V2.4.0.0 自学习误报警与数据落盘整改报告

## 1. 技术结论

- 2026-07-31 现场记录中有 **5 个非空遥测批次，对应 5 次学习启动失败**。原项目 `index.db` 完整性检查为 `ok`，但 `epb_cycles=0`，根因是学习阶段没有建立 Recorder 圈边界，不是 SQLite 损坏。
- 程控电源 5 个有效遥测文件共 **1,033 行**，最大输出电流 `23.663A`、最大功率 `283.885W`；`CC`、限压、限流、限功率、保护跳闸和 `Error` 均为 0。现有证据不支持“程控电源限流/保护导致失败”。
- EPB8、EPB10 已多次达到约 `14.3~15.0A` 的夹紧区间；旧逻辑在断电后只等待 `100ms` 并读取一次电流，读到 `1.878~3.189A` 后误触发电源组联锁。该判据已改为 `20ms` 周期轮询、最多 `1000ms`。
- EPB9/EPB11 的 `ForwardCurrentRiseStalled` 原确认窗口仅 `203~219ms`，对暂时平台过于敏感；正向失速确认已改为连续 `1000ms`，首次无稳定模型的负载上升期限已改为 `5000ms`。
- `DaqSampleStale>100ms` 出现在首发报警约 5 秒后的反向阶段。报警流程已移除 Runner，但学习协程仍继续保持/反向，因而不再收到采样；这是控制收尾级联故障，不是独立 DAQ 硬件故障。
- EPB11 两次出现 `OpenCircuitOrOutputFault I=0.027A`，该值远低于有效驱动电流，仍按真实硬件故障处理，不通过放宽开路阈值掩盖。

## 3. 现场故障诊断

### 3.1 首次完全释放后的 3 秒期限偏短

第一批中：

- EPB8：`elapsed=3006ms`，`I=1.813A`
- EPB10：`elapsed=3007ms`，`I=1.368A`
- EPB9：`elapsed=3013ms`，`I=0.121A`

三路都在旧 `ForwardProgressDeadlineMs=3000` 边界附近结束。首次学习前卡钳经过完整预释放，空行程长于已有模型场景是合理的，因此无稳定模型时放宽到 `5000ms`；正向绝对上电 `9s` 保护仍保留。

### 3.2 200ms 失速确认会把暂时平台当成堵转

后续批次 EPB9/EPB11 的失速窗口仅 `203~219ms`，窗口中位电流约 `2.706~10.907A`，斜率为负或低于阈值。整改后先识别低斜率候选段，再要求候选连续满 `1000ms`，最后用完整 1 秒窗口复核；恢复上升会立即清除候选计时。

### 3.3 断电后单点读取不能代表电流未清零

旧流程是“断电命令成功 → 固定等待 100ms → 单次读流 → 超限联锁”。现场在正常夹紧断电后仍读到 `1.878~3.189A`，说明 100ms 处于衰减尾部。整改后保持 DO 关闭，以 20ms 周期轮询；任一点降至 `OffCurrentClearThresholdA` 即通过，只有 1 秒窗口耗尽才调用一次组级联锁。

### 3.4 DAQ 断流是报警后的派生故障

首发硬故障触发后，报警停机路径会从采样链移除 Runner；旧学习任务使用的只有批次令牌，没有与通道停机令牌联动，因此仍可能执行保持并进入反向。反向等待器收不到新样本后触发 `DaqSampleStale>100ms`。

整改后：

1. 学习开始前为每个通道创建独立停止令牌。
2. 通道令牌与批次令牌、学习阶段故障令牌链接。
3. Runner 报警回调在线程内同步取消学习阶段和故障通道令牌。
4. 首个学习硬故障会取消其余学习任务；已报警通道不会继续保持或反向。
5. `DaqSampleStale>100ms` 本身仍保留为硬保护。

### 3.5 EPB11 仍需硬件排查

EPB11 两次开路电流均约 `0.027A`。程控电源遥测没有保护或通信异常，因此优先检查：

1. 卡钳电机及插接件；
2. 线束导通与接触电阻；
3. DO 正反向输出及继电器；
4. 通道电流采样映射。

## 4. 已实施代码整改

### 4.1 安全时序默认值

默认值、XML 发布配置和设置界面回退值已统一：

```text
ForwardProgressConfirmMs = 1000
ForwardProgressDeadlineMs = 5000
OffCurrentClearTimeoutMs = 1000
```

反向失速确认仍为 `200ms`；正向 `9s`、反向 `5s` 绝对上电时限、过流、开路和 DAQ 断流保护均未放宽。

### 4.2 学习阶段停止与故障传播

- 学习阶段每路使用独立停止 CTS，并与批次/学习故障 CTS 关联。
- 报警回调同步取消学习，后台报警输出和文件导出不再延迟控制停机。
- 非报警异常会封存当前学习圈并取消学习阶段；同批其它活动学习圈封为 `learning_canceled`。
- 正式阶段开始时仍会更新通道停止 CTS，不改变正式运行的既有控制路径。

### 4.3 学习圈 Recorder 与文件结构

`IEpbCycleRecorder` 新增：

- `BeginLearningCycle(...)`：在 SQLite 中原子分配 `-1、-2、...` 的负数内部圈号；
- `SealAndExportCycle(...)`：支持 `learning_completed`、`learning_canceled`、`learning_failed`；
- 原 `SealAndExportAlarmCycle(...)` 保留，并委托通用封存实现。

学习文件结构：

```text
{StoreDir}\{TestName}\LearningCycles\
  {RunId}\EPB08\Learning_0001\
    EPB8_Cycle_-000001.csv
    EPB8_Cycle_-000001.bin
```

硬故障仍写入 `AlarmSnapshots`，并保留断电后尾部、控制时序和报警元数据。Recorder 单通道锁负责原子领取封存权；报警后台与学习收尾并发时只有一方能够封圈，另一方不会重复导出或改写状态。

负圈号不会进入以下正式口径：

- `GetMaxCycleNumber`；
- 正式成功 `RunCount`；
- 最近正式 10 圈导出；
- 正式圈归档/保留清理。

环形写指针恢复改为按 SQLite 最新插入记录恢复，确保负学习圈在重启后不会造成写位置回退。旧版停用的 DAQ 原始定时落盘链路未重新启用。
