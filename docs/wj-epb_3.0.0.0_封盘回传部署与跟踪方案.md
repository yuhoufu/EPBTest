## 2. 开始后的顺序

1. **只读预检。** 通过Get-WjEpbSession核对真实主机、mt会话、版本、程序路径、PID/启动时间、监督服务和任务。核实实际运行项目、数据目录、逐通道目标/已完成/剩余、落盘提交、当前步骤、磁盘空间。查明既有远程自动恢复调度，切换期间协调暂停并记录原状态，避免其恢复已人工停止的旧试验。预检发现项目或身份不符时先解释，不能直接安装。
2. **准备回退材料。** 备份现场实际2.14.2.11完整程序、配置、服务/任务定义及监督记录，登记原路径。以现场旧版支持的启动和配置入口具体化恢复命令，不照搬JXCQ的2.17.3.0命令。传入新版包至现场D:\debug下独立目录，核对安装包摘要和内部清单，仅暂存不安装。根据数据量、备份链和吞吐估算停机时间。
3. **正常停止并封盘。** 使用旧版正常停止/保存入口，等待本次保存完成，记录最终逐通道落盘基线；确认断能、卸压、资源释放后退出。无法取得可信安全证据时需现场人员确认本次状态；历史人工确认不能复用。保存失败或安全条件不满足时不强杀、不切换。
4. **封装并回传。** 此时才形成停机一致备份。先核对现场EPB-IncrementalBackup_new.ps1的参数、输出与成功判据，再对实际项目执行封装至D:\EPB_Data\Backups，工作目录D:\EPB_BackupWork。若为增量包，登记并补齐本机缺少的基础包及依赖链，不只回传最后一个增量。封装成功立即通过既有共享回传至本机D:\EPB_Data\Backups；限定本次归档及所需依赖文件，保存工具退出码和传输结果。沿用章程追加约定，不额外开展全量回传摘要/解压扫描；仍核对文件存在、大小和传输报告，不能把仅生成远端包视为已回传。传输失败先重试或报告，不进入安装。不执行旧文档的删除日志命令，现场原数据与日志保留。
5. **部署新版。** 回传完成后，协调旧监督组件进入维护状态，核对无在途安全接管、旧新硬件占用不重叠。管理员运行完整包一键安装入口，部署Main及Guard，保留现场配置；首装失败按步骤日志处理，不能将Main成功而Guard失败算整体成功。校验3.0.0.0版本、组件身份、服务、任务、快捷方式，以及Guard仅观察/执行禁用。
6. **原项目续测验收。** 经Supervisor从mt交互会话启动主窗口，加载核实后的原项目，先对账再通过正常入口开始/恢复。人工维护停止不能被自动恢复覆盖，本次续测属于明确的新启动操作。逐通道核对目标、完成、剩余和检查点，不清零、不复制旧许可。允许有依据的重新学习阶段。至少两次有效持久化提交，并覆盖合法控制步骤推进，采样、控制及保存均有证据才判为续测成功；窗口出现不算成功。
7. **开始观察。** 对账通过记录T0，安排T0起24小时跟踪。初次恢复在当前任务内连续跟踪至确认，之后沿用章程最新约定每30分钟只读巡检；正常静默，仅异常、恢复结果或监控不可用时通知。实际创建调度并确认首检后才宣布监控已启用。

## 3. 跟踪边界

巡检记录版本与进程身份、重复实例、监督状态、Guard决策、逐通道业务推进、实际保存提交、错误和磁盘空间。按现场配置填写合法等待、采样、保存和恢复预算；单次圈数未变或文件时间变化均不足以判定业务状态。

保留现有Supervisor受支持的恢复机制；本次不开放Guard自动执行、不注入故障。章程第7节远程介入授权明确限于旧2.14.2.11，不能自动扩展为新版远程强制恢复。新版发生异常时取证、观察Supervisor处理并通知；无本次可信安全证据时不强杀或反复重启。人工停止和急停优先，永久故障通道按受支持隔离逻辑处理。

24小时结束汇总实际检查次数、缺测区间、自然异常和恢复对账；未自然发生的故障场景保留未验收，不自动无限延长。断线或调度失败明确报告监控不可用。

## 4. 回退条件与方式

安装失败、项目不兼容、计数差无法解释、保存失败或安全条件不满足时停止继续变更并保留证据。先完成受支持的安全收口，再按预检记录恢复现场实际2.14.2.11程序、匹配配置、服务与任务。

新版生成的数据及恢复记录独立保留，不把旧数据覆盖回原项目，不回放旧恢复许可。若旧版不能安全读取新版已产生的状态，则保持安全停止，提交数据差异，不擅自降计数续测。回退后同样验证身份、安全及业务进度；不能仅凭旧窗口出现宣布恢复。
