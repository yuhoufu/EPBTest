# V4 独立恢复真实主窗联调阻塞与修订

本记录针对 jxcq 隔离项目和模拟硬件。WJ-EPB 当前试验未被本轮测试干预。程序版本仍为 4.1.0.0；原 rc.1 安装包和标签保持不变。本记录不代表新版候选已通过交付验收。

## 已证实问题

### 配置摘要错误包含机械运行计数

EPB-M4 测试从已有数据库及配置续测：通道 4、7 各有三个正式记录，机械计数各为 8（含学习动作）。默认模板初始化使默认配置的机械计数变为 0，项目配置仍保留 8。稳定配置摘要原先排除了 RunCount 等运行字段，却遗漏 MechanicalCycleCount，导致合法恢复被配置身份校验拒绝。

修订排除该运行字段；不修改 XML、数据库或机械计数，不排除目标次数及安全配置。捕获的初始化前、默认初始化后及项目配置，经修订后的真实摘要方法计算均为 `26A21F2115C940A8F440F0529848E38E0F67FC6F1AE289F654014F3440EFDA85`。新增回归验证摘要一致且源文件未被改写。注册配置摘要需要由新版本重新生成，不可复用旧候选凭证。

该修订独立提交为 `d999432`。Debug x86 构建及 AdaptiveControl 863/863 通过；证据位于仓库根目录 Codex 下 `v41-mechanical-identity-*`。

### 独立恢复未建立新 Watchdog 会话

EPB-M5 的 SYSTEM 执行器完成模拟安全阶段并拉起真实主窗，进入 Verifying，但未达到正式续测。主窗显示恢复预检后停留空闲，最终测试超时。

源码链路确认：独立入口调用 ResumeFromIndependentRecoveryAsync，再进入无人恢复批次入口；该入口要求 Watchdog exact Attached。旧恢复入口提前执行 AttachRecoverySessionAsync，而独立入口未建立任何会话。独立执行器的一次性凭证不能代替该握手。

本轮修订由独立入口为新进程建立新 Watchdog 会话，配置当前项目 Journal 路径，握手前后复核持久授权；仍保留批次入口的 Attached、UI Ready、安全及恢复授权检查。此修改的端到端效果以正在进行的 EPB-M6 验证为准，不能仅凭构建通过宣布修复完成。

EPB-M6 新证据：15:21:27.302 主程序记录 `IndependentRecoveryWatchdogAttachFailed`，具体为 Journal 初始化失败。会话引导文件已生成，但未进入正式试验。CreateContext 原 catch 丢弃了异常；后续修订把底层异常写入返回诊断，继续定位，不放宽 Journal 门禁。会话修订后的本地 AdaptiveControl 仍为 863/863，但不支持宣称端到端修复完成。

### 合法路径空格被错误当作恢复证明缺失

EPB-M7 增强诊断确认 `PristineReadBackMismatch`；对原会话调用生产 FileStore.Load，返回 `BootstrapProofMissing`。证明文件实际存在。源码 `DurableRelaunchAuthorityV4Validator.HasProof` 对 BootstrapProofPath 和 BootstrapPrimaryPath 调用了禁止空白的 HasToken，因测试安装在 `C:\Program Files\EPB-M7` 而拒绝有效证明。这解释了此前无空格目录的普通主窗测试通过，而本轮受保护安装目录失败。

修订为已有 HasPathToken 路径规则；证明标记、SHA-256、重启预算以及 FileStore 对真实证明的路径/内容绑定继续保留。BootstrapAndCapability 回归使用 `Program Files/试验项目` 子目录，验证创建、重新打开、故障权威写入以及拒绝二次覆盖。Debug x86 构建成功，恢复权威/回执测试 42/42。证据：`Codex/v41-journal-space-build.log`、`Codex/v41-journal-space-receipt.log`。

主窗现在暴露内部启动失败结果供测试读取；夹具在首次失败时立即输出有界错误证据，外部监督据此收尾，避免继续等待 300 秒。M7 已确认服务和任务移除、项目进程为零。EPB-M8 正在验证上述组合修订的端到端效果；未达到最终续测标准前不生成通过声明。

M8 结果补充：已越过 Journal 初始化，随后收到 `SupervisorLaunchRejected:SupervisorRequestRejected:SupervisorExecutablePathMismatch`。原 Supervisor 的固定控制管道连接到了另一个安装路径的服务，按生产身份校验正确拒绝当前隔离目录的 Watchdog。下一步需补齐隔离测试的 Supervisor/SessionAgent 安装与启动生命周期；不得删除此路径核验以取得通过。M8 未开始正式续测。

### Supervisor 混淆项目目录与 Journal 目录

M9 在确认 jxcq 无主程序/试验侧车后，保存原服务配置并临时切换到同一候选目录，验证结束恢复原服务路径和 Running 状态。没有覆盖原安装文件；既有登录代理保留。对应受限脚本为 `Codex/v41-jxcq/monitor-supervisor-switch.ps1`，该脚本仅接受 EPB-M9 路径，切换前拒绝活动控制进程，恢复时核验原记录及现有路径。

M9 越过执行文件身份检查，随后报 `IndependentSessionLaunchNotAdmitted`。SupervisorLaunchRecord.ProjectDirectory 实际来自 `--journal-directory`，值为项目下 WatchdogSessions；StartFromRecord 将它直接传入要求真实项目目录的 RequireCurrentSessionHost，和注册的项目目录不相等。

修订在独立会话入口明确从 WatchdogSessions 解析项目目录，再执行原有项目、进程和持久事务核验；非独立安装保留旧流程。回归覆盖合法日志目录、拒绝任意目录及拒绝其他项目。此修订尚待构建和端到端验收，不能算作已经验证关闭。

M9 清理已确认：隔离执行器服务和启动任务删除、隔离项目进程为零；原 Supervisor 已恢复至 `C:\Program Files (x86)\MTTFTest\Current\MTTFTest.Watchdog.exe` 并运行。磁盘写入回归 58/58 通过，完整 AdaptiveControl 回归仍在执行。

## 清理与验证边界

M3、M4、M5 未通过正常卸载收尾：安全清理未确认或旧控制进程仍在，安装管理器拒绝卸载。测试外部监督精确终止隔离项目进程后，按安装 ID、路径核对并删除其服务和任务；未伪造安全成功回执。M5 最终确认服务不存在、启动任务已移除、项目进程为零。对应脚本、所有权及资源证据在 `Codex/v41-jxcq`，未使用 WinRM 会话。

真实电源、DO/AO、压力与继电器安全尚需台架验证。模拟成功不能替代该项。历史 DEV 秒级未回调的底层物理/驱动原因仍未由本轮证据证明。

最终交付仍要求唯一替代进程、正确目标通道、实际控制动作、机械计数推进、至少三个新增正式记录以及监督重新绑定；EPB-M5 的进程存活和 Verifying 不满足这一标准。
