# V4.1 打包架构切换

`New-AutomaticRecoveryBundle.ps1` 默认生成 schemaVersion=2、V4-Independent-SystemExecutor 清单；恢复策略标记为 RequiresDurableRunIntent。独立程序不再默认为仅观察，仍需主程序明确开始建立授权，不能由安装器擅自开始试验。

只有显式 `-LegacyRecovery` 才生成原 schemaVersion=1 清单及旧 PersistentFallback 工具、额外观察入口和旧说明。原有一键包核心入口名称保留；7-Zip `.7z`、LZMA2、`-mx=9`、压缩后校验与 SHA-256 流程保持不变，已有输出目录仍拒绝覆盖。

`RecoveryGuard-Acceptance.ps1` 在包完整性校验后，从有界读取的实际清单获取架构，避免新包仍被固定报告为旧架构。硬件动作、计数落盘、耐久及主动硬件恢复仍为 NOT_VERIFIED，不因包结构正确而变成通过。

## 本地验证

- PowerShell 5.1 x86 执行 `Test-BundleArchitecture.ps1`：从生产脚本提取清单表达式，验证独立默认/旧版兼容两种模式，**2/2**，无压缩包生成。日志：主仓库 `Codex/v41-bundle-architecture-tests.log`。
- `Test-TopBundle.ps1` 使用不可执行占位组件的完整清单，实际运行顶层 ValidatePackage 和 RecoveryGuard-Acceptance，退出码 0；架构为 V4-Independent-SystemExecutor，动作、落盘、耐久均为 NOT_VERIFIED。日志：`Codex/v41-topbundle-acceptance-tests.log`。

这两项没有执行完整 Release 打包，不能据此声称已交付安装包。测试清单的 4.1.0.0 只是夹具版本，不是已完成版本迭代或 tag。
