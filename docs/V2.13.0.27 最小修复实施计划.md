# V2.13.0.27 最小修复实施计划

- 保留 DAQ 阈值、`StartBlocked` 执行围栏、Watchdog 失效安全和重启预算。

## Implementation Changes

### 1. DAQ 重复阶段推进

- 为 `AdvanceDaqRecoveryStage` 增加仅调用方显式启用的“同阶段已提交”模式。
- 只允许 `DoOffConfirmed` 在 Controller gate、已发布进度和当前 `DaqRecoveryTransaction` 三者均为同一阶段时幂等成功，不重复发布或增加版本。
- 正常恢复和自维护两处调用启用该模式；跳级、回退、跨代次、SafeIdle 和 Terminal 仍严格拒绝。

### 2. 液压 ForceRelease 后旧租约收口

- 恢复自愈调用 `ForceReleaseAsync` 时生成并传递精确 reason。
- 增加内部 `TryRetireForceReleasedScope`：只接受同液压组、代次已退出、lease 已完成且异常精确匹配本次 `HydraulicForceRelease` 的旧 scope。
- 调用前继续要求 DO OFF；`ForceReleaseAsync` 返回即代表物理释放和安全压力确认完成。
- 仅在恢复代次进入前及 scope 替换两处使用；其他取消、压力失败、活动 lease 或代次不匹配继续抛出并 fail closed。

### 3. 保留恢复 worker 真实错误

- `RecoveryIncidentCoordinator` 的 worker 异常不再调用 `CompleteAfterTerminal(null)`。
- 发布 `RecoveryWorkerFailed:<BaseExceptionType>`，详情携带异常信息和 incident/run/epoch/resource 身份。
- 仍然提交安全终态并释放 owner，不允许失败通道复活。

### 4. 硬件安全等待不再触发进程风暴

- `WatchdogHostStopMonitor.EvaluateTick` 增加内部可选参数 `hardwareSafeIdle`。
- 只有经验证的当前恢复进程、心跳小于 5 秒、phase 为 `SafeIdleHardwareUnavailable`、`HardwareUnavailable=true`、输出数为 0、fingerprint/探测信息完整、且无人工停止或会话撤权时才成立。
- 该状态只抑制“非活动 StopAll 的粘滞终态”再次杀进程；进程死亡、心跳超时、重新带电、活动 StopAll、身份异常或人工停止仍立即接管。

### 5. 冻结恢复通道意图

- Watchdog 会话增加可选字段：冻结标志、排序去重后的 `FrozenExcludedChannels`、来源 PID/start ticks、RunId/RunEpoch。
- 首次接管只允许从已验证的初始主进程心跳计算：人工禁用 + 已完成 + 永久报警通道；空集合也必须以冻结标志区分。
- 在首个 launch intent 前同步持久化；持久化失败则阻断重启。
- 后续恢复子进程即使把 1–12 全报为 disabled，也只能使用冻结集合。
- Sidecar 重启时恢复该集合；若已处于恢复代次但冻结证据缺失或非法，则 fail closed。
- 保持 Watchdog Journal schema 4 和现有 wire protocol，不新增耐久授权协议字段；每代使用的冻结集合继续进入现有 durable `LaunchArguments`。

### 6. 诊断显示

- UI 中 `NextProbeUtc` 先转本地时间，并明确显示为本地时间。
- 硬件预检失败详情补充 `StageError`、`LastStage`、`Outcome`，同时保留各子系统错误。
- 本轮不生成 PackageManifest；实施文档明确正式现场包仍须从干净提交运行发布脚本生成。

## Test Plan

- DAQ：自动确认后再次确认只成功一次；跳级、回退、其他 epoch 仍拒绝。
- 液压：匹配本次 ForceRelease 的旧 scope 可退役并建立新 Recovery；不匹配异常、活动 lease 和压力失败不得被吞。
- Recovery：同步异常、异步异常和空 Task 均发布真实 reason，禁止再出现 `RecoveryTerminalPublisherMissing`。
- Watchdog：安全硬件等待不派发重启；进程死亡、心跳超时、带电、人工停止及活动 StopAll 仍派发一次。
- 通道冻结：初始集合持久化、空集合、子进程全禁用污染、Sidecar 重载、非法/缺失冻结证据 fail closed 全覆盖。
- 完整验证顺序：
  1. 还原 PowerSupplyDebugger `win-x64` 资产并构建 Debug x86。
  2. 运行 AdaptiveControlTests、EpbDiskWriterTests 和 17 项 PowerSupplyDebugger.Tests。
  3. 还原 PowerSupplyDebugger `win-x86` Release 资产并构建 Release Any CPU。
  4. 核对主程序与三个 Watchdog 程序集均为 `2.13.0.27`。
  5. 执行 `git diff --check`，要求 0 error、无新增编译警告类型。
- 实施文档保留现场门槛：暂停/继续 100 次、DAQ 陈旧注入、PSU 无 `*IDN?` 响应、恢复进程真实崩溃接管，以及 24 小时长稳。
