# V4.1 生产恢复原子交接协议

状态：协议与文件存储已实现并完成本地回归；SYSTEM 宿主、主程序启动入口和安装程序仍需接入。本文不表示完整恢复交付完成。前序 jxcq 结果对应旧提交，不能用作本轮新增协议的远端验收。

## 为什么调整第一阶段的存储方式

第一阶段分别保存运行意图和恢复事务。若替代进程消费凭证后，更新运行意图和事务的两个写入之间发生崩溃，就可能留下新旧 RunId 混合状态。仅增加两个文件各自的修订号不能保证整个交接原子完成。

新增 `Watchdog.Protocol/IndependentProjectState.cs`，生产交接使用 `independent-project-state.json` 单一聚合文件保存：

- 维护模式、状态总修订号及安全清理待办。
- 当前运行意图及其修订号。
- 恢复事务、阶段、请求、代际和替代进程身份。
- 当前控制进程的 PID、启动时间、可执行文件、Windows 会话及独立会话标识。
- 一次性启动凭证、摘要、期限、目标交互会话及消费者身份。
- 最近 32 条操作来源、通道选择前后值、运行身份和原因审计。

每次修改都在同一跨进程互斥锁内重新读取状态，核对总修订号，再以原子文件替换提交整个聚合状态。不能用上一次读取的副本覆盖新的人工操作。互斥锁允许 SYSTEM、Administrators 和创建者访问；生产目录和配置仍必须由安装程序施加 ACL，JSON 和互斥锁本身不能替代文件权限边界。

## 交接规则

1. `ArmManualRun` 创建新批次；维护中、安全清理未完成或恢复事务未结束时拒绝新批次。普通重新开始保留永久隔离。
2. `BeginRecovery` 将恢复事务和 `SafetyCleanupPending=true` 一次性提交。
3. 人工停止、暂停或取消勾选递增意图修订号并撤销已有凭证。**不能同时清除安全清理待办**；已经开始的安全清理仍须由宿主完成。
4. `IssueLaunchTicket` 只允许在 `LaunchPending`、安全清理完成、授权仍一致且未处于维护模式时调用。凭证绑定目标交互会话，Session 0 不能作为主程序恢复启动目标。
5. `ConsumeLaunchTicket` 同时保存消费记录和替代 PID/启动时间。摘要、期限、会话、路径、当前修订号不一致时拒绝；同一个凭证最多消费一次。
6. `CommitReplacementRun` 在同一次提交中更新意图 RunId/RunEpoch、事务 RunId/RunEpoch、意图修订号和当前控制进程绑定。消费后人工停止，或者已经超过阶段期限，均不得提交新运行批次。
7. 凭证消费者崩溃，不重新开放已经消费的凭证。宿主必须按原事务的明确阶段处理失败与重试，不得凭进程消失重新发放旧许可。

反序列化显式要求安全清理、维护、停止、暂停和凭证撤销等字段存在，并检查布尔类型，防止缺失字段被默认为“允许”。审计限制条数及字符串长度，避免中文长原因使 64 KiB 状态文件上限阻止后续人工停止。

证据位于仓库根 `Codex/`：

- `v41-state-tests.log`：原有工作进程 5 项、原子状态 22 项。

测试中的安全阶段推进为模拟，不执行硬件动作，不证明独立硬件安全确认已完成。

## 后续接入约束

- SYSTEM 宿主和主程序必须使用本聚合状态作为生产交接源，不能并行使用第一阶段两个文件作为另一份有效授权。
- 宿主从受保护安装配置确定项目、数据库、程序摘要及交互任务，不接受用户可写文件提供的任意 SYSTEM 命令。
- 对人工撤权的事务，宿主仍要处理未完成安全清理，但不能继续消费或生成旧启动许可。
- 实际 PID、启动时间、可执行路径和交互会话必须在操作系统中复核；协议字段并不是进程真实性证明。
- 旧 Watchdog 与新执行器必须共享执行权约束。主程序运行前和旧控制者上电前的撤权检查尚须接入，不能仅依赖 UI 心跳。
- 需要在 jxcq 的交互会话中重跑凭证竞争和整链测试；主程序凭证拒绝 Session 0，不能把 SYSTEM 测试进程冒充交互主程序。
- 接通后仍须完成三个正式周期落盘验收、服务与任务安装/修复/卸载/回滚、统一版本和完整 7z 安装包；真实硬件确认另列台架验收。

## 后续实现：撤权后的安全清理与独立硬件入口

`CompleteSafetyStage` 已加入聚合状态存储。它按请求、执行者、代际和阶段接收完成回执，不再因为人工撤权就丢弃正在进行的安全清理。协作停止失败或超时可转到独立断电阶段；电源、进程清理或输出/压力阶段失败及迟到回执进入 `NeedsAttention`，保留清理待办。安全清理全部完成后，若授权已变化，则终止为 `Cancelled`，不生成启动凭证。

SafetyAgent 新增实际命令入口：`--independent-stage <命令文件绝对路径>`。该入口：

- 只接受 SYSTEM 身份；不会把旧 SafetyAgent 握手伪装成新独立授权。
- 验证命令文件、配置文件及目录祖先的所有者、写入权限和重解析点，拒绝非受信任所有者、可被非受信任主体改写的路径和远程路径。
- 只接受 AIConfig.xml、AOConfig.xml、DOConfig.xml、PowerSupplyConfig.xml 四项封存配置清单，逐项校验 SHA-256；沿用现有硬件库和运行安全参数验证。
- 回执记录命令摘要、阶段随机值、请求、代际、阶段、工作进程 PID/启动时间及完成时间。接收方必须使用 `MatchesCurrent` 校验，不凭 `Confirmed=true` 单独放行。
- 该入口本身不能中断已卡死的驱动调用；生产宿主仍必须使用已实现的 Job 工作进程外部期限，并在接收阶段完成前确认工作进程已结束。

新增本地验证：`v41-worker-solution-build.log` 为 Debug x86 构建；`v41-cleanup-tests.log` 为工作进程 5/5、聚合状态与安全回执 33/33；`v41-worker-access-test.json` 记录非 SYSTEM 实际执行独立硬件入口返回 77。回归包含协作期限升级、撤权后完成清理但不续测、迟到安全回执、错误工作进程/启动时间/命令摘要/阶段随机值以及配置路径穿越拒绝。

上述测试未调用真实硬件。SYSTEM 服务调度、注册配置、主程序启动消费与旧执行权撤销仍未接通，本轮没有进行 jxcq 或 WJ-EPB 的远端操作，也未新增安装包或版本标签。

### 原子状态调度层

后续新增 `IndependentProjectRecoveryPump`，使用原子聚合状态调用有界操作端。安全阶段优先处理原事务清理责任，协作期限到达时撤销工作进程并升级；启动和验证阶段在每次调度时复核维护模式、人工停止/暂停、授权修订号和运行身份。启动端返回成功并不足以推进，必须存在已持久消费的凭证及匹配的替代进程身份；验证前还必须完成新控制进程绑定。

操作接口 `IIndependentProjectRuntimeOperations.CancelStageWorkers` 明确要求回收 Native Job 所属进程，不能仅取消托管 Task。操作调用与状态提交之间若发生人工操作，状态修订号比较交换会拒绝旧提交；宿主须重新读取状态，不能覆盖新操作。

本地 `v41-pump-build.log` 构建通过，`v41-pump-tests.log` 记录工作进程 5/5、状态与调度回归 38/38。新调度回归使用模拟操作端覆盖协作超时、清理中撤权、未持久消费启动结果拒绝、未提交新运行批次不能验证及完整绑定后完成状态。它没有证明真实动作和数据库推进；Windows 服务宿主、生产操作端和主程序入口仍待接入，目标安装包仍未完成。

### 独立安全工作进程操作端

新增 `IndependentSafetyWorkerOperation`，把 SYSTEM 身份检查、可执行文件摘要校验、受保护命令读取、Native Job 启动、外部期限及安全回执校验连接起来。只在工作进程成功退出、Job 清理完成且回执匹配时返回阶段成功。没有回执、退出失败、命令/进程身份不一致、时钟倒退或期限到达均返回失败并回收工作进程。

`IndependentBoundedWorker` 在正常阶段结束时查询 Job 活动进程数，最多等待 1 秒确认清空，未确认则抛出清理失败；不以父进程退出单独证明派生进程已退出。异常销毁仍通过关闭 Job 句柄触发内核清理，不报告业务恢复成功。

本地 `v41-operation-tests-build.log` 构建通过，`v41-operation-tests.log` 为工作进程 5/5、状态与权限回归 39/39，包括实际非 SYSTEM 调用操作端拒绝。此轮未在 SYSTEM 下执行真实安全动作，仍需服务宿主集成和 jxcq 对应验证；未部署现场或生成安装包。
