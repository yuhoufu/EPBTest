# V4 独立凭证到真实主窗续测测试入口

## 本轮改变

正常主窗模拟试验已在 jxcq 通过，但此前独立服务整链使用的是直接生成数据库记录的测试控制器。两者尚未合并，不能据此声称独立服务已经恢复真实主窗的试验。

本轮让 Main_Frm 的正常监控创建与独立恢复创建共用实例级 CreateMonitor。正式构造函数继续使用原硬件实现；只有测试程序集能传入内部设备工厂。恢复入口仍传递原 ParentRunId 作为受保护学习根，不改变凭证消费、配置身份、启动安全预检或试验计数规则。

## 测试入口

以下命令仅存在于 AdaptiveControlTests.exe，不加入正式程序命令行或安装包配置。所有入口都要求同目录的 `REAL-MONITOR-SIMULATION-ONLY.txt` 内容为 `SIMULATED_NO_HARDWARE`。

- `--prepare-independent-monitor <交互用户SID>`：从已经存在的隔离项目 `D/P` 导出生产注册信息，绑定测试 EXE 和测试安全工作进程，保存只读数据库基线。要求整条目录链满足生产受保护文件规则。此步不武装运行意图。
- `--arm-independent-monitor`：必须由注册交互用户执行，以本进程真实 PID、启动时间和会话创建 4、7 通道运行意图，保留数据库计数，随后退出。用于让生产执行服务独立检测退出并恢复；这不是“卡住的真实控制进程已被强制终止”的测试。
- 生产交互启动参数 `--independent-registration <路径> --independent-ticket <nonce>`：调用原 Parse、ConsumeAndBind，随后由真实 Main_Frm.OnShown 创建监控并调用原恢复入口。测试定时器只观察圈完成事件，不点击开始、不直接写试验数据库。

新进程必须在各目标产生三个新的正式完成事件后，再观察到生产独立执行器将同一进程绑定的事务置为 Verified，才通过原停止按钮结束，并正常关闭窗口。成功状态另存 `real-monitor-verified.json`；最终成功保存 `real-monitor-result.json`。按 PID 分开的 stdout、stderr 和错误文件保留诊断。用例有 300 秒业务上限和 315 秒 UI 线程退出上限，外部测试所有者还必须设置进程期限及精确清理。

安全工作进程为既有 IndependentRecovery.ProcessTests 的模拟工厂。真实电源、DO、AO、压力安全仍不能由该用例证明；生产 SafetyAgent 没有新增模拟开关。

- 三个新增入口在无模拟标记的目录中均明确拒绝，未初始化硬件、未创建恢复授权：`v41-fixture-arm-rejection-final.log`、`v41-fixture-prepare-rejection-final.log`、`v41-fixture-ticket-rejection-final.log`。
- 主窗新工厂创建带受保护学习根的真实 MDI 监控窗，初始化和关闭通过：`Codex/mts-6d6dfa50`，退出码 0。测试额外确认原学习根 GUID 未丢失。主进程 16848 不存在、子进程数 0。

**新的有效凭证正向续测用例尚未执行。** 后续需在 jxcq 新建受保护隔离目录，导入已完成三个正式周期的模拟项目，安装生产 SYSTEM 执行服务和最高权限交互任务，先准备再武装，并核对新进程至少推进到第六个正式周期、原有记录不变、Verified 状态及监督绑定。之后还需接入活进程卡住、部分停滞、并发停止等故障矩阵。

前一轮 jxcq 正常试验通过的事实不扩展到这些新增入口。本轮未连接 WJ-EPB，未改既有 rc.1 包或标签，也未宣称完整候选交付完成。
