# V4.1 一键关键证据采集入口实现与验证

## 变更

独立架构的一键包 `Evidence` 原先直接报“尚未实现”。现在转入 `Tools/Export-IndependentRecoveryEvidence.ps1`，包生成器包含该脚本，顶层包校验要求该脚本在摘要清单中。一键入口为读取受保护注册/状态申请管理员运行，并传递安装根及证据目录；不调用旧恢复架构的采证程序。

保存内容：

- 注册身份、当前组件状态、独立项目状态（含运行意图、接管审计和事务）、观察文件。
- 当前恢复事务的验证基线及最多 16 个匹配的安全命令/回执；最多枚举 64 个候选文件，截断明确记录。
- 12 个通道的机械完成标记计数和最近正式记录摘要，包括当前已排除通道，便于核对选择状态。查询这些通道不授予运行权限。
- 读取工作进程的 PID/启动时间、各文件 SHA-256、缺失/失败项与范围说明。

这是**关键恢复证据**，不是完整数据库备份、全部波形封盘、故障转储或跨文件原子快照。状态和数据库分别在读取时刻获得，不可解释为完全同时。`businessRecovery` 固定为 `NOT_VERIFIED`。

## 资源及写入边界

读取数据库沿用生产只读查询，新增可选 `--output` 文件入口；原标准输出接口保持原样。输出采用 CreateNew，拒绝覆盖；数据库查询由独立 native Job 工作进程承载，外部期限 3 秒，内存上限 256 MiB，Dispose 负责回收工作进程。

脚本逐文件读取最多 64 Ki 字符；保存状态等文件总预算 2 MiB，数据库摘要另限 64 Ki 字符。20 秒检查是脚本阶段间的软期限，不声称能中断管理器内部阻塞调用；远程执行仍必须由调用方独立实施整个诊断任务的硬期限。本次 jxcq 调用方预算 45 秒、控制任务 40 秒、控制器等待 28 秒。

输出须为新的本机目录，不能位于项目、状态或安装组件目录之内，不能通过重解析点跳入这些位置。既有输出拒绝覆盖。数据库读取失败或缺少观察文件会记录为缺失项；其他采集错误保留已有证据并报告失败，不宣称“完整采证成功”。不修改试验计数、授权、状态、项目数据或运行进程。

## 使用

生成完整候选包后，可双击包中的 `一键故障采证.cmd`；默认输出到包的 `Evidence/UTC时间`。也可以在管理员 PowerShell 中指定目录：

```powershell
.\Install-AutomaticRecoveryBundle.ps1 -Mode Evidence `
  -InstallRoot 'C:\Program Files (x86)\MTTFTest' `
  -EvidenceDirectory 'D:\EPB-Evidence\本次唯一目录名'
```

安装目录仅为示例，应使用实际安装路径。本轮未生成最终候选包，因此此说明不是已交付安装包的路径承诺。
