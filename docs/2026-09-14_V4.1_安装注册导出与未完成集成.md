# V4.1 安装注册配置导出

## 本次解决的缺口

现有一键包入口仍调用原安装流程。独立执行器需要项目、数据库、主程序、硬件配置及交互用户的注册身份，但此前没有从实际主程序配置生成这些字段的生产入口。让 PowerShell 重新实现配置摘要算法会造成与主程序判断不一致。

增加主程序参数 `--export-independent-registration-draft`，必须依次提供五个值：项目目录、目标状态目录、交互用户 SID、安装 ID（32 位无连字符 GUID）、输出文件路径。参数必须完整且不能混用其他启动参数。

该入口位于首启配置、恢复入口和 WinForms 启动之前。它读取指定项目现有的 `Config/TestConfig.xml`、`index.db` 文件身份和实际运行配置，调用主程序既有 `ComputeIndependentConfigurationHash`，导出 `IndependentExecutorRegistration` 草稿。输出包含实际二进制和四个硬件 XML 的 SHA-256、液压安全阈值、DAQ 配置及数据库创建时间。读取前后校验项目配置及摘要没有变化；草稿采用临时文件后不覆盖移动，已有输出或并发占用均失败。

不创建数据库或运行状态，不修正、重置计数，不写入安装绑定，不注册任务或服务，不访问硬件，也不自动续测。液压阈值直接取项目配置，经现有安全协议验证；导出器不新增放宽阈值。

## 草稿与正式注册的区别

草稿中的 `ConfigDirectory` 仍指向当前运行配置目录。安装程序必须在维护状态下封存配置、复核摘要、保护目录 ACL，并将正式注册指向受保护的配置副本；必须通过 `LoadTrusted` 后才允许服务使用。导出成功不意味着配置目录权限合格、数据库可读、旧进程已退出或项目可以安全启动。

导出只读取数据库文件身份，不做 SQL 校验或推进判断。数据库有效性与正式业务记录验收由后续安装验证及恢复执行器完成，不能根据文件存在判定数据库健康。

主程序仍保留 requireAdministrator 清单。正式安装程序应先完成提权，再启动该导出入口并检查退出码；不会为导出降低程序权限要求。正常导出返回 0，参数、输入、配置校验或输出失败返回 1，并向标准错误输出原因，安装调用方应捕获该输出。

## 后续接入：受保护配置封存

新增 `IndependentExecutorRegistration.SealDraft`。草稿文件及目标状态目录必须先通过受信所有者、ACL 和无重解析点校验。四个硬件配置文件按草稿摘要复制到唯一 `safety-config-<GUID>` 子目录，每文件上限 4 MiB，以 16 KiB 缓冲流式复制并 Flush(true)。复制后验证摘要和权限；正式注册指向该副本，通过既有 LoadTrusted 对程序、SafetyAgent、配置及注册文件完整校验后，采用不覆盖移动发布。

已有注册文件拒绝覆盖。失败配置副本保留为诊断，不注册服务、不写入安装绑定、不改变运行意图。该操作只解决配置封存，旧协议退出、维护和服务启用仍由后续安装流程负责。未把原始草稿或文件存在当作数据库健康、硬件安全或续测成功。

安装管理脚本增加 `-Mode Seal -DraftPath <草稿> -RegistrationPath <正式注册> -ExecutorPath <受保护执行器>`，在进入任务计划或服务逻辑之前完成封存并返回。一键包生成脚本纳入 `Manage-IndependentRecovery.ps1`，使该入口随包交付；旧一键安装入口的自动串联仍未完成，不改变其架构标记冒充集成完成。

## 后续接入：Prepare 安装准备流程

## 后续修订：独立恢复入口不得进入首启安装

审查任务拉起入口发现：Program.Main 在独立恢复 Parse/ConsumeAndBind 之前调用 FirstRunBootstrap.PrepareOrExit，但 HasRecoveryArguments 只识别旧 `--watchdog-*` / `--recovery-*` 参数。独立任务使用 `--independent-registration ... --independent-ticket ...`，原先会被当作普通启动。在正式包尚无 configured 标记、或从包目录运行且找到已安装程序时，可能转入首次安装、交互配置或已安装版本跳转，而非验证本次独立恢复凭证。

这是源码可证实的入口分流缺陷，不能据此断言它就是此前 WJ-EPB 全通道停机的原因；现场是否进入该分支尚须对应日志。修订只补充三个已定义独立入口参数的识别：`--independent-registration`、`--independent-ticket`、`--independent-installation`。它们跳过首启安装分支，继续由已有 Parse 和 ConsumeAndBind 校验路径、账户、维护状态、执行文件摘要及一次性凭证；不放宽任何恢复授权。普通无参数启动仍保留原首启流程。

新增十项断言：三个参数分别被识别，分别在正式包目录和已安装目录缺少配置标记时继续协议路径；普通无参数启动不被归类为恢复。测试故意只给参数名、不附值，证明缺失参数不能误转入安装；后续参数拒绝由原独立协议处理，测试不把“继续协议路径”当作获准续测。
