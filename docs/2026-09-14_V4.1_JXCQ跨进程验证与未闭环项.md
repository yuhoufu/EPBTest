## 2. 本轮代码修改

### 2.1 可终止的独立工作进程

新增 `Watchdog.Protocol/IndependentBoundedWorker.cs`：

1. 使用挂起方式创建子进程，先加入 Windows Job 对象，再恢复执行，避免子进程在归属登记前派生逃逸进程。
2. 工作进程在独立进程中执行；调用者轮询期限，超时终止本 Job 的进程树。
3. Job 采用关闭句柄时终止全部成员的策略。执行器进程异常退出后，由 Windows 回收 Job 句柄并终止工作进程，不依赖执行器的 `finally`。
4. 配置单进程及整个 Job 内存上限，默认 256 MiB，最多 8 个进程；不按进程名称批量终止。
5. 零退出码、非零退出码、运行中和超时分别返回。工作进程正常退出也清理它残留的子进程。

新增独立 x86 测试项目 `Tests/IndependentRecovery.ProcessTests`，已加入解决方案；它不引用主程序、控制器或 NI 硬件库。相同测试也加入 AdaptiveControl 完整回归。

**该组件目前是执行器所需的已验证基础设施，尚未接入生产 SYSTEM 服务或硬件阶段调用。** 不能把模拟挂死退出测试写成真实 NI 驱动卡死恢复验收。

### 2.2 持久事务的并发边界

`IndependentRecoveryJournal.Tick` 在同一事务锁中重新读取持久运行意图和恢复事务，再执行一次非阻塞阶段推进。旧内存副本不能代表当前授权。

增加按修订号、执行者、代际和请求 ID 的比较交换。迟到工作进程回执不能覆盖较新事务；回执不能改变阶段、目标通道、运行身份、期限或重试历史，已绑定的替代进程身份不能被覆盖。阶段推进仍必须走阶段机。

新增回归覆盖迟到回执、伪跳过安全阶段和持久人工撤权。**SYSTEM 存储 ACL、生产权限交接和启动前复核仍未完成接入。**

### 2.3 数据库观察证据失效

生产 `DatabaseStallMonitor` 补齐以下边界：

- 收到明确停止标志后清空旧停滞基线；重新观察时从新基线计时，不把停止期间算成故障等待。
- 通道集合或周期变化后清空旧恢复验证基线，避免用旧集合的成功记录证明新集合恢复。
- 校验通道范围、重复通道及周期范围。
- FallbackGuard 生成及收缩数据库观察目标时补充排除永久故障通道。

测试中的停止标志验证的是数据库观察器输入契约，**不表示人工暂停、取消勾选等全部 UI 事件已经接入新的持久协议**。状态到持久意图的生产绑定仍是未闭环项。
