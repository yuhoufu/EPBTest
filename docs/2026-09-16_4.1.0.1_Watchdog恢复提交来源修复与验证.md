## 原因与影响

独立执行器恢复入口创建自己的新 Watchdog 会话，没有旧 Watchdog AttachRecoverySession 的恢复许可，但公共续测方法原本无条件发送旧 RecoveryBatchCommitted、抬高心跳提交代次并写旧 marker。现场许可 None/Generation=0，因此接收端拒绝，接受代次保持零，后续心跳不断重试。40987 是累计拒绝次数，不是故障或进程重启次数。

原始 RecoveryStage 为空不是该拒绝的原因：Formal/RunActive 解析为 FormalBatchStarted。两层 RunId/RunEpoch 不同也不能单独证明许可身份错误，因为 None 分支先退出。既有数据库两次查询三路各推进一圈，说明当时业务继续运行；不据此保证未来故障恢复一定成功。

## 实现

1. 公共续测入口必传 `RecoveryStartupSource`，三个调用点分别传 LegacyWatchdog、IndependentExecutor、SoftwareCheckpoint。只有 LegacyWatchdog 调用旧协议提交闭包，因而独立恢复不产生旧代次、消息或 marker。共享安全预检、通道选择、剩余机械计数与 `ConfirmRecoveryBatchStarted` 保留。
2. 接收端只有在旧许可为未使用的 None（代次及提交代次零，无 PermitId/Nonce）且可核验安装注册、项目路径、独立事务/已消费票据、替代控制进程 PID/启动时间及精确侧车会话注册时，才记录 `NotApplicableIndependentRecovery`。新观察还必须与当前已记录心跳的运行身份及提交代次一致。安装或状态不可读、证据缺失、普通 None 均不视为成功。
3. 终态去重包含 SessionId、PID、进程启动时间、RunId、RunEpoch 和提交代次，最多保留 32 项并随 journal 持久化/重载。旧消息命中已证明的精确键可终止重复处理；任何实际旧恢复许可仍先经过原许可路径，后续代次和不同运行不被旧键吞掉。未更新 `LastRecoveryBatchCommitGeneration`，未将许可改成 Committed，未重置失败预算/熔断。
4. rc.2 的带身份、空 Stage marker 可与精确心跳关联，随后得到同一终态。原 marker 保留为证据，重读时命中终态；不全局删除或移动文件，避免并发写入下一代 marker 时误删除。无身份的 format1 marker 保持未证明，不擅自终结。
5. 提交诊断写独立的 `RecoveryCommitDisposition` / `RecoveryCommitDiagnostic`，不再把 Deferred 写入当前业务 State/LastReason。拒绝日志带许可状态、解析阶段和原因；启动日志带真实恢复来源。独立来源证明的文件/哈希读取尝试按单宿主至少间隔五秒限频。

这些终态仅表示旧协议不适用，不是试验恢复成功。独立事务仍由执行器验证实际机械完成和至少三个正式数据库记录；没有在启动返回时提前 Verified。暂停/停止后仍可观察已发生的独立来源，但不恢复票据授权、不重新上电或启动通道。
