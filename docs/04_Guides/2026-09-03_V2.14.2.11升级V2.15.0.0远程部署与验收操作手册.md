### 7.2 使用 PowerShell Remoting 复制

## 10. 步骤五：迁移现场运行配置

V2.15.0.0 的运行配置权威目录是：

```text
C:\ProgramData\MTTFTest\Config
```

安装脚本遵循以下规则：

1. ProgramData 中已存在的配置不覆盖；
2. ProgramData 不存在时，优先读取旧安装槽 `Current\Config`；
3. 仍不存在时才使用正式包中的默认配置。

如果 V2.14.2.11 从 `D:\debug` 等便携目录运行，安装脚本不会自动把该目录识别为旧 `Current`。因此必须人工核对以下 8 个现场配置：

- `AIConfig.xml`
- `AlarmConfig.xml`
- `AOConfig.xml`
- `DOConfig.xml`
- `PowerSupplyConfig.xml`
- `TestConfig.xml`
- `UnattendedAlarmConfig.xml`
- `UIConfig.xml`

先比较旧现场配置、现有 ProgramData 配置和新包默认配置。确认旧配置确实是现场当前有效配置后，只补齐 ProgramData 中缺失的文件，不要无条件覆盖已有文件：

```powershell
$oldConfig = Join-Path $oldProgramDirectory 'Config'
$runtimeConfig = 'C:\ProgramData\MTTFTest\Config'
$configNames = @(
    'AIConfig.xml','AlarmConfig.xml','AOConfig.xml','DOConfig.xml',
    'PowerSupplyConfig.xml','TestConfig.xml','UnattendedAlarmConfig.xml','UIConfig.xml'
)

New-Item -ItemType Directory -Path $runtimeConfig -Force | Out-Null
foreach ($name in $configNames) {
    $source = Join-Path $oldConfig $name
    $target = Join-Path $runtimeConfig $name
    if (-not (Test-Path $target) -and (Test-Path $source)) {
        Copy-Item -LiteralPath $source -Destination $target
    }
}

Get-ChildItem $runtimeConfig -File |
    Where-Object { $_.Name -in $configNames } |
    Get-FileHash -Algorithm SHA256 |
    Format-Table Path, Hash -AutoSize
```

DAQ 通道、AO/DO、液压、电源和报警参数必须由熟悉现场设备的人员复核。不能只根据文件名相同就认为配置兼容。

### 12.1 schema 5 安全证明拒绝安装时

如果看到以下含义的错误，属于安全门禁正常工作：

```text
schema 5 会话缺少 MotorOff/PressureSafe/PersistenceDrained 三项安全证明；
保持 SafeIdleAlarmed，拒绝安装新授权。
```

此时必须：

1. 保持设备断能；
2. 保存安装日志和原检查点；
3. 回到旧版安全退出流程，确认三项证明为何未形成；
4. 由研发人员分析检查点和硬件证据；
5. 证据闭环后重新执行安装。

禁止编辑 JSON 把字段改成 `true`，禁止删除检查点来绕过门禁，禁止手工复制新 EXE 覆盖旧程序。

### 12.2 检查点损坏时

## 13. 步骤八：安装后静态验收

### 13.1 校验安装目录

安装会在 `Current` 中新增 `MTTFTest.FirstRun.configured`，所以安装后的目录不能直接作为未安装正式包运行递归校验，否则该运行态标记会被正确识别为清单外文件。应先再次校验远程暂存正式包，再以其中已经验证过的 `build-identity.json` 为清单，逐文件比对安装槽：

```powershell
$operatorPackage = 'C:\MTTFTest-Deploy\V2.15.0.0-QUICKDEPLOY-R20'
$package = Join-Path $operatorPackage 'Package'
$current = 'C:\Program Files (x86)\MTTFTest\Current'

& "$package\Deployment\Verify-Release.ps1" -ReleaseDirectory $package
if (-not $?) { throw '暂存正式包校验失败。' }

$identity = Get-Content -Raw "$package\build-identity.json" | ConvertFrom-Json
$failures = @()
foreach ($file in @($identity.files)) {
    $relative = [string]$file.name
    $target = Join-Path $current $relative
    if (-not (Test-Path -LiteralPath $target -PathType Leaf)) {
        $failures += "MISSING $relative"
        continue
    }
    $actual = (Get-FileHash -Algorithm SHA256 -LiteralPath $target).Hash.ToLowerInvariant()
    if ($actual -ne ([string]$file.sha256).ToLowerInvariant()) {
        $failures += "HASH_MISMATCH $relative"
    }
}
if ($failures.Count -ne 0) {
    $failures | ForEach-Object { Write-Error $_ }
    throw '安装槽与正式包清单不一致。'
}

$allowedFiles = @($identity.files | ForEach-Object { [string]$_.name }) + @(
    'build-identity.json',
    'SHA256SUMS.txt',
    'MTTFTest.FirstRun.configured'
)
$unexpectedFiles = @(Get-ChildItem -LiteralPath $current -Recurse -File | ForEach-Object {
    $_.FullName.Substring($current.Length).TrimStart('\')
} | Where-Object { $_ -notin $allowedFiles })
if ($unexpectedFiles.Count -ne 0) {
    $unexpectedFiles | ForEach-Object { Write-Error "UNEXPECTED $_" }
    throw '首次启动前发现清单外文件。'
}

$mainHash = (Get-FileHash -Algorithm SHA256 "$current\MTTFTest.exe").Hash.ToLowerInvariant()
if ($mainHash -ne 'dc858fc10633975f39237ed8fc5a20c4b8b12fedcd2a05b33aa050c61ae78db3') {
    throw "主程序 SHA-256 错误：$mainHash"
}
'INSTALLED_MANIFEST_PASS'
```

必须看到暂存正式包 `verified: true` 和 `INSTALLED_MANIFEST_PASS`。首次启动前，`Current` 相对正式包允许新增的运行态文件只有 `MTTFTest.FirstRun.configured`；若发现其他未知文件，先分析来源再启动。

### 15.3 无负载安全验证

在不连接负载或确保输出不会造成危险的条件下进行：

1. 打开程序但不开始正式试验；

- 始终只有一个主进程和一个有效 permit。

## 17. 失败处理和停止线

出现以下任一情况，立即停止试验并保持 `SafeIdleAlarmed`：

- 正式包校验失败；
- 任一组件不是 2.15.0.0；
- schema 5 安全证明缺失或损坏；
- 配置来源无法确认；
- Supervisor 不是 LocalSystem 或没有运行；
- 主程序不是通过 capability 启动；
- 存在多个主进程或多个有效 permit；
- MotorOff、压力安全或落盘无法证明；
- DAQ 数据陈旧仍参与控制；
- 自动恢复绕过 receipt/哈希/revision 校验；
- 首圈出现重复恢复事务、重复 StopAll 或数据不完整。

失败后应收集：

- 安装 transcript；
- `last-deployment-result.json`；
- `C:\ProgramData\MTTFTest` 完整副本；
- 当前用户 `%LOCALAPPDATA%\MTTFTest` 完整副本；
- 项目 `Recovery`、`WatchdogSessions*` 和 UpgradeEvidence；
- Windows Application/System 事件日志；
- 服务、任务、进程、PID、SessionId、CreationDate 和可执行路径；
- 新旧配置及 SHA-256；
- dump、ETW 和 SafetyAgent 结果。

安装脚本保留的 `.retired-*` 是旧安装槽审计证据，不是自动回退按钮。`PromoteLastKnownGood` 模式也不是把 `.retired-*` 恢复成 `Current` 的回滚命令。禁止直接把 V2.14 文件覆盖回 `Current`。需要降级时，必须先保持物理断能，由研发制定单独的受控降级方案，并重新处理 schema、服务、任务和授权状态。

## 18. PowerShell Remoting 的使用边界

可以使用以下入口进入远程会话：

```powershell
Enter-PSSession -ComputerName mt-20251206jxcq -Credential (Get-Credential)
```

适合远程执行：

- 复制正式包；
- 校验正式包；
- 查询版本、服务、任务、进程和日志；
- 创建备份；
- 在确认是管理员、确认是实际运行账号且有人观察硬件时执行安装。

- 判断物理电机是否真正断能；

- 操作和观察 WinForms UI；
- 首次真实硬件强杀验证；
- 无现场观察条件下的正式首圈。

安装任务使用 `Interactive` 登录类型。即使 WinRM 中安装成功，也必须在实际桌面会话中确认 SessionAgent、AutoStart 和 UI 启动链路。
