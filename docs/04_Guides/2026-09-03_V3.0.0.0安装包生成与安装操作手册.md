## 1. 最简单的打包方法

在仓库根目录打开 PowerShell，执行：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass `
    -File .\Tools\Build-V3Installer.ps1
```

脚本会自动完成：

1. 检查 Git 工作区必须干净；
2. 检查统一版本必须为 `3.0.0.0`；
3. 自动寻找 Visual Studio 2022 MSBuild 和 7-Zip；
4. 执行严格 Release 构建；
5. 执行 Adaptive、写盘、电源、Recovery Kernel、EngineHost 集成和部署契约测试；
6. 生成带 `build-identity.json`、PDB 和递归 SHA-256 的内层不可变包；
7. 生成与 V2.15 相同格式的快捷安装外层；
8. 执行 `7z t` 和压缩包 SHA-256 复核；
9. 写入可回传的 `.result.json`。

默认输出：

```text
artifacts\releases\V3.0.0.0-<commit>-<time>-FIELD-VALIDATION\
artifacts\deploy\V3.0.0.0_现场验证包_<commit>_QUICKDEPLOY_R23\
artifacts\deploy\V3.0.0.0_现场验证包_<commit>_QUICKDEPLOY_R23.7z
artifacts\deploy\V3.0.0.0_现场验证包_<commit>_QUICKDEPLOY_R23.7z.sha256
artifacts\deploy\V3.0.0.0_现场验证包_<commit>_QUICKDEPLOY_R23.7z.result.json
```

指定工具或输出路径：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass `
    -File .\Tools\Build-V3Installer.ps1 `
    -MsBuild 'C:\Program Files\Microsoft Visual Studio\2022\Professional\MSBuild\Current\Bin\MSBuild.exe' `
    -SevenZip 'C:\Program Files\7-Zip\7z.exe' `
    -ReleaseRoot 'D:\MTTFTest-Packages\releases' `
    -OutputRoot 'D:\MTTFTest-Packages\deploy'
```

├─ 快捷部署包-SHA256.txt
├─ 现场验证候选包-未正式放行.txt

## 3. 默认为什么生成“现场验证候选包”

V3 已通过软件构建和自动化测试，但安装态 LocalSystem 全事务强杀矩阵、真实 NI/CAN/电源/液压验证以及 168 小时长稳尚未全部完成。因此默认包：

- 可以在有人观察硬件、能够立即人工断能的条件下受控安装；
- 可以用于 I0026 组合故障复现、真实硬件验证和长稳验证；
- `releaseStatus` 为 `FIELD_VALIDATION_CANDIDATE`；
- `deploymentApproved` 为 `false`；
- 不能作为正式量产或正式无人值守放行包归档。

## 4. 正式包门禁

只有安装态强杀矩阵、真实硬件矩阵和 168 小时长稳均通过后，才可准备正式批准证据，例如：

```json
{
  "schemaVersion": 1,
  "installedCrashMatrixPassed": true,
  "hardwareMatrixPassed": true,
  "soak168HoursPassed": true,
  "approvedBy": "负责人姓名",
  "approvedUtc": "2026-09-10T08:00:00Z"
}
```

然后执行：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass `
    -File .\Tools\Build-V3Installer.ps1 `
    -FormalRelease `
    -FormalApprovalEvidencePath 'D:\MTTFTest-Evidence\V3-formal-approval.json'
```

正式包名称为：

```text
V3.0.0.0_操作员包_<commit>_QUICKDEPLOY_R23.7z
```

不得为了得到“正式包”而伪造批准证据或手工修改 `build-identity.json`。修改身份后递归哈希会失效。

## 5. 工控机安装

### 5.1 安装前

1. 将 `.7z`、`.7z.sha256` 和 `.7z.result.json` 一起复制到工控机本地磁盘；
2. 按 `.sha256` 核对压缩包；
3. 完整解压，不要在压缩包预览窗口或网络共享中运行；
4. 使用以后长期运行试验的 Windows 生产账号登录；
5. 在旧程序中执行停止试验；
6. 确认所有 DO、AO、电源和液压处于安全状态；
7. 确认数据落盘结束并备份现场配置、ProgramData 和事故封存；
8. 不要手工清理 `%LOCALAPPDATA%\MTTFTest` 或 `%ProgramData%\MTTFTest`。

### 5.2 执行安装

1. 双击解压目录第一层的 `一键安装正式版.cmd`；
2. Windows 管理员权限提示出现后选择“是”；
3. 等待九个安装阶段全部完成；
4. 安装失败时不要反复强行重试，先保存窗口信息和部署日志。

默认安装目录：

```text
C:\Program Files (x86)\MTTFTest\Current
```

安装器同时创建：

- LocalSystem 服务：`MTTFTestSupervisor`
- 登录代理任务：`MTTFTestSessionAgent`
- 登录自启动任务：`MTTFTestAutoStart`
- 桌面快捷方式：`MT EPB 试验系统 V3.0`
- 同 V3 代际基线：`LastKnownGood`

### 5.3 安装后

1. 运行 `检查运行状态.cmd`；
2. 核对 Supervisor 服务、SessionAgent 任务和 AutoStart 任务存在；
3. 核对只有一个 EngineHost 和一个 UI；
4. 使用桌面快捷方式或 `启动试验.cmd`，不要直接双击 `MTTFTest.exe`；
5. 首次只做全断能 SafeIdle、无源预检和单通道低风险验证；
6. 再执行 I0026 的 DAQ 陈旧、电源查询超时和 EngineHost 替换组合回归；
7. 候选包现场验证期间必须有人值守并具备人工急停条件。

部署结果位于：

```text
C:\ProgramData\MTTFTest\DeploymentLogs\last-deployment-result.json
```

## 6. 更新、修复与卸载

- 更新：停止试验并断能后，完整解压新包，运行新包的 `一键安装正式版.cmd`；
- 修复：运行同一包的 `一键修复.cmd`；
- 状态检查：运行 `检查运行状态.cmd`；
- 卸载：安全停止后运行 `一键卸载.cmd`，输入 `Y` 或 `A` 确认。

不要把新文件直接覆盖到正在运行的 `Current`。卸载会移除程序、服务、任务和快捷方式，但保留 `C:\ProgramData\MTTFTest` 中的配置、日志和事故证据。

## 7. 常见失败

| 现象 | 处理 |
|---|---|
| 工作区不干净 | 先提交源码；安装包必须精确绑定一个 Git commit |
| 找不到 MSBuild | 使用 `-MsBuild` 指定 VS 2022 MSBuild.exe |
| 找不到 7-Zip | 安装 7-Zip 或使用 `-SevenZip` 指定 |
| 自动化测试失败 | 不生成包；先修复失败，不允许跳过 |
| 旧 schema 安全证明不完整 | 保持断能并封存证据，不要删除检查点绕过 |
| 包哈希不匹配 | 丢弃该压缩包并重新生成/传输 |
| Current/LKG 代际不兼容 | 由安装器重新建立 V3 LKG，不得放入 V2.15 包 |
| 安装后直接双击 EXE 被拒绝 | 使用桌面快捷方式或 `启动试验.cmd` |
