# V4.1.0.6 与 V4.1.0.7 版本差异说明

文档日期：2026-09-21。适用项目：EPBTest / MTTFTest。

本文依据两个版本的实际源码差异、最终构建与验收记录编写。现场状态采用北京时间 **2026-09-21 07:59 的检查结果**，不代表此后持续实时监控。文中的“默认约 1 秒”指对应既有有效等待配置；已有更长配置时，以实际配置及下述计算规则为准。

## 1. 核心结论

**V4.1.0.7 的生产行为改动只有两处：保压期间遇到陈旧压力样本，以及断电电流确认期间遇到不新鲜的电流样本，允许等待新鲜采样的窗口由原默认约 1 秒延长到至少 3 秒。**

这次改动用于减少短时采样过期导致的提前失败。250 ms 带电采样失新保护、100 ms 压力新鲜度要求，以及真实低压、真实电流未清零的原保护时间均保留。新版本没有新增一套自动恢复系统，也没有修改动作流程或圈数统计规则。

需要区分三件事：

1. **样本是否新鲜**：旧数据仍按原标准判为过期，不会因为窗口变长而被当作有效数据。
2. **可以等待多久**：仅两个指定分支允许多等一段时间，期间可能被其他独立保护提前终止。
3. **能否自动续测**：仍由既有断电、故障处理、机械状态确认和重新准入逻辑决定。3 秒窗口不保证保住当前圈，也不保证所有故障都自动恢复。

截至上述检查时间，`wj-epb` 仍运行 **V4.1.0.6**。V4.1.0.7 已完成软件构建与 jxcq 环境验收，尚未部署到 `wj-epb`，也未完成实机带负载耐久验收。因此，现场此前的长时间稳定运行不能归因于 V4.1.0.7 的改动。

## 4. “新鲜度”与“等待时间”的区别

### 4.1 压力样本年龄

压力 `AgeMs` 使用单调时钟计算。样本保存的时间来自相应采集回调入口的单调时钟记录；读取压力时，用当前单调时钟减去该记录得到年龄。它不等于日志时间与当前墙上时间的简单相减。

压力分类按以下顺序进行：无样本、无效数值、过期、压力低于下限。压力样本年龄超过配置上限时，即使显示压力很高，也不能当作新鲜合格压力。

本次 **`PressureSampleMaxAgeMs = 100 ms` 不变**。调整的是已经发现异常以后允许确认、等待的时长。

### 4.2 DAQ 新鲜度与电流确认

DAQ 新鲜度快照分别记录回调、控制入队、控制处理完成等时间。用于相关电流确认路径的 `IsFresh` 取决于 DAQ 新鲜度判断；其控制处理年龄来自最后完成控制处理的单调时钟记录，相关默认界限为 250 ms。

因此，“压力样本年龄”“DAQ 回调间隔”“控制处理年龄”“断电确认已经等待多久”不是同一个指标。不能把日志里的任意一个间隔直接与 3 秒比较，就判断新版本是否应该继续。

### 4.3 两个 3 秒的起点不同

| 分支 | 计时起点 | 正常恢复条件 |
|---|---|---|
| 保压异常确认 | 本轮持续异常第一次被监测到时 | 压力重新新鲜、数值有效且达到保压下限，清除异常计时 |
| 断电电流确认 | 进入本次断电电流轮询时 | 电流样本新鲜、数值有限且绝对值不超过清零阈值，立即成功返回 |

两个计时都不是“最后一个有效样本之后统一再等 3 秒”。轮询和线程调度会带来偏差，3 秒属于软件判断窗口，不是硬实时精确截止保证。

## 5. 压力过期处理的详细变化

对应代码：`Controller/HydraulicGroupCoordinator.cs`，`MonitorQualifiedPressureAsync`。

### 5.1 原版与新版算法

原版所有保压异常共用原确认时间；该有效确认时间最低为 1000 ms。新版仅在当前失败原因是 `StaleSample` 时采用以下规则：

```text
首次发现压力异常：记录原有异常起点 lowSince

若当前原因是 StaleSample：
    本次适用确认时间 = max(3000 ms, 原确认时间)
否则：
    本次适用确认时间 = 原确认时间

持续异常时间达到本次适用确认时间：进入原故障处理
压力完全恢复合格：清除 lowSince
```

监测约每 10 ms 检查一次；释放已开始时退出此保压监测。原有压力下限计算不变，仍根据压力阈值及允许保压下降量计算。

### 5.2 3 秒不是从“确认断电”开始

**这处压力监测没有新增“确认电机已断电后才能开始 3 秒等待”的门禁。** 它仍从首次异常起算，独立的带电采样失新保护继续负责快速切断相关输出。

因此，不应把本版本描述为“所有通道确认断电后，压力才统一等待 3 秒”，也不能理解为允许在无有效采样的情况下持续带电 3 秒。

### 5.3 异常类型切换不会重新计时

`lowSince` 在持续异常期间保留，只有完全恢复合格才清除。例如：

- 前 2 秒为压力过期，随后收到新鲜但真实低压的样本。
- 此时重新使用原约 1 秒低压确认时间。
- 因为持续异常已经超过 1 秒，可以立即进入低压故障处理，不会再额外给 1 秒。

反过来，异常转为过期时也是沿用原异常起点，不是重新获得完整的 3 秒。

### 5.4 为什么日志中的年龄可能约为 3.1 秒

假设最后一份压力样本之后完全没有更新，压力年龄先超过 100 ms 才被判为过期，再从首次发现异常开始累计确认时间。在其他保护均未先触发的前提下：

| 版本 | 理想化时间关系 |
|---|---|
| V4.1.0.6 | 约 100 ms 新鲜度窗口 + 1000 ms 确认，即年龄约 1100 ms |
| V4.1.0.7 | 约 100 ms 新鲜度窗口 + 3000 ms 确认，即年龄约 3100 ms |

这是说明计时关系的例子，实际还受初次发现时间、轮询和调度影响。**3100 ms 不是本次日志统计得到的历史最大过期值，也不是新增配置项。**

### 5.5 持续失败的分类保持不变

压力过期、无样本、无效值继续按原系统故障路径处理。新鲜真实低压仍按原确认时间使当前液压代次失败；连续确认的液压代次失败可按原规则升级为硬件确认故障。这里的连续 3 个代次，不是连续读取 3 次，更不表示允许不安全状态继续完成 3 圈。

## 6. 断电电流确认的详细变化

对应代码：`Controller/EpbCycleRunner.Adaptive.cs`，`PollOffCurrentUntilClearAsync`。

### 6.1 成功条件不变

每次轮询首先判断：

```text
样本新鲜
且电流不是 NaN / Infinity
且 abs(电流) <= 原清零阈值
```

只有三项同时满足才返回成功。恢复合格后立即返回，不要求一定等满 3 秒。成功检查在该次轮询的超时检查之前执行，因此不能把窗口理解成严格精确的硬截止边界。

### 6.2 新版只对不新鲜的分支延长等待

```text
原轮询超时 = boundedTimeoutMs

如果 sample.IsFresh：
    本次适用超时 = 原轮询超时
否则：
    本次适用超时 = max(3000 ms, 原轮询超时)

从本次轮询入口累计的时间达到适用超时：返回确认失败
```

原配置通常为 1000 ms，常用轮询间隔为 20 ms。等待继续使用原取消令牌，取消后不会强制继续等满 3 秒。

例如，先过期 2 秒，再恢复为新鲜高电流：此时仍不符合清零条件，并立即重新适用原 1 秒超时。由于轮询已经持续 2 秒，可直接失败，不重新计时。

### 6.3 超时不等于所有调用场景都永久停机

该方法返回确认结果，由调用方执行既有处理。终端断电确认路径原来就存在电源侧冗余断电证明：在 DO OFF 路径成功等前提下，连接正常的电源遥测需要数值有限、年龄不超过 1000 ms，且电流绝对值不超过 0.5 A。

这个冗余路径 **V4.1.0.6 已有**，不是 V4.1.0.7 新增；其中 `OutputEnabled` 被记录，但不能把“它必须为 false”写成该辅助判据。无法取得合格证明时，仍可能进入原电源组紧急断电与告警。其他调用场景保留各自的处理，不能把某一个调用方的降级策略推广到全部路径。

## 7. 没有修改的保护与恢复逻辑

| 项目 | 两版本保持的规则 | 与 3 秒改动的关系 |
|---|---|---|
| 带电控制阶段采样失新 | 相关快速保护默认 250 ms | 可以先断电并中止当前圈，不等待 3 秒 |
| 压力新鲜度 | 100 ms | 旧压力仍然无效 |
| 控制队列延迟 | 50 ms 警告、带电场景 100 ms 硬故障策略 | 独立判断，可能更早触发 |
| DAQ 存活监测 | Warn 250 ms、Suspect 1500 ms、Trip 5000 ms | 未整体放宽 |
| DAQ Trip 连续确认 | 达到条件后连续 3 次检查 | 不是 3 × 5 秒；常用检查周期约 20 ms |
| 采样配置 | 2000 Hz、每通道每批 20 点，约 10 ms 一批 | 未降低采样负载或频率 |
| 建压达标 | 新鲜有效压力、目标条件及稳定性要求 | 过期高压力不能证明建压成功 |
| 释压达标 | 新鲜有效样本及安全压力稳定窗口；常用安全压力 5 bar、稳定 100 ms、超时 5000 ms | 过期零压力不能证明释压完成 |
| 新鲜度安全围栏重新准入 | 在已建立该围栏的路径，回调/入队/处理年龄合格并持续 500 ms，还需相关机械和电源条件 | 并非每个断电分支都必然执行同一围栏 |
| 完整 DAQ 恢复 | 使用原新鲜度、同代次新批次推进及连续性验证；典型要求 10 个新有效批次 | 不是重复读取同一缓存 10 次 |
| 电源恢复后的稳定准入 | 存在待恢复电源通道时，适用原默认 5000 ms 稳定观察及其他条件 | 不是所有恢复都固定等 5 秒 |
| 圈数、持久化与自动恢复路由 | 原动作、作废、计数、落盘及恢复规则 | 本次未修改 |

DAQ 存活监测会结合设备是否有带电通道、是否处于失新后的升级观察等状态。未带电设备记录的较大间隔，不能直接等同于带电控制故障；快速断电后保留的升级观察也可能继续跟踪设备。

**不要求两个数采卡钳同时工作，相关保护才生效。** 单个设备有相关带电通道就可能进入相应监测条件。双设备同时工作的负载影响需要实测，不能仅凭现场未停机就认定“因为两个数采没有同时工作”。本次版本差异没有证明此前所有停机的统一根因。

## 8. 典型场景举例

下表只比较发生变化的指定分支。假设对应原配置为 1 秒，且没有其他保护先触发；“恢复”均指收到该分支所需的真正合格新鲜数据。

| 场景 | V4.1.0.6 | V4.1.0.7 |
|---|---|---|
| 异常等待开始后约 0.8 秒恢复 | 可在原窗口内通过 | 同样可通过，无需等满 3 秒 |
| 压力持续过期约 2.2 秒后恢复合格 | 此保压分支通常已达到原失败窗口 | 此分支可避免原 1 秒处的提前失败 |
| 断电电流确认开始后约 2.2 秒才收到新鲜低电流 | 此轮询通常已超时 | 此轮询可通过 |
| 压力持续过期超过新窗口 | 按原较短窗口失败 | 仍失败，只是指定分支等待更久 |
| 陈旧样本始终显示 0 A | 不能证明清零 | 仍不能证明清零，不能提前成功 |
| 新鲜电流一直高于清零阈值 | 按原约 1 秒处理 | 同样按原约 1 秒处理 |
| 压力先过期 2 秒，再变成新鲜低压 | 原路径通常已处理失败 | 转回原低压确认规则，可能立即失败 |
| 带电采样失新已触发快速断电 | 当前圈按原规则处理 | 仍按原规则处理；3 秒不撤销已经触发的保护 |

这些例子说明新版能减少哪一类提前失败，不代表“2.2 秒以内的所有现场故障都能自动续测”。自动恢复可能作废当前圈，并需满足既有重新准入条件。
