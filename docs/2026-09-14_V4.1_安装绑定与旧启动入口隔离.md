# V4.1 安装绑定与旧启动入口隔离

基线 `f959d84`。本轮补上安装后普通启动绕过独立绑定的入口，尚未宣称旧监督交接全部完成。

## 实现

安装在主程序旁生成 `<主程序.exe>.independent.json`，记录安装 ID 与受保护注册路径。写入要求项目维护中、没有活动授权或清理事务，并按主程序路径的全局互斥锁串行执行；已有其他安装绑定时拒绝覆盖。

解析绑定时校验文件及祖先的权限/所有者、注册文件及已登记组件哈希、主程序路径、安装 ID 和状态目录，并复核绑定文件未在校验期间变化。绑定损坏不回退为无监督普通启动。

主程序普通启动自动读取绑定并走独立安装入口；携带旧 `--watchdog-recover` / `--epb-recover` 参数的已绑定进程拒绝启动，显式独立注册参数也不能指向另一个安装。未部署绑定的现有程序维持原入口。

旧 Watchdog 的 GuardedProcessLauncher 在消耗许可前、SessionAgent 在写消费记录前，以及主程序旧跨进程启动边界增加同一检查：已绑定主程序返回 `IndependentExecutorOwnsProcessRelaunch`。同进程恢复策略未修改。独立执行器仍按持久意图及停滞/进程退出证据决定恢复，不允许一个无批次归属的旧请求重启当前健康试验。

安装脚本在服务和任务注册后写入绑定。卸载服务保留绑定及维护状态，避免残存旧启动器立即恢复旧协议；完整卸载/迁移流程仍需处理程序文件和旧组件，不能把这一入口单独当作最终卸载包。
