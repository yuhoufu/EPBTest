# V4.1 组件文件替换与失败回滚验证

本次实现 `Invoke-IndependentFileRepair` 文件事务函数：先暂存全部候选文件并校验 SHA-256，再逐个原子替换，保留原文件副本；发生异常时倒序恢复原文件，并移除本次新补入的文件。事务日志、暂存载荷及副本位于安装目录 `Repair/<事务ID>/`，不递归删除项目文件。

此函数尚未开放为直接执行的安装器模式。生产调用前必须取得安装维护权及执行器租约、确认本安装进程已退出。损坏组件下的可信维护引导和这一调用入口尚待接通；不能据此宣称完整修复或升级回滚已完成。

## 行为与边界

- 目标必须在指定安装根内，拒绝重复目标、重解析点及配置目录，限定程序组件扩展名。
- 单文件上限 256 MiB、总载荷 2 GiB、最多 10,000 个组件。暂存摘要必须匹配修复预检结果。
- 替换前再次校验旧文件摘要，防止悄悄覆盖预检后变化的文件。逐文件替换后校验新摘要。
- 回滚前校验旧副本摘要；删除本次新增文件前核对其新摘要。失败不能删除归属已变化的文件。
- 日志区分 `Prepared`、`Replaced`、`RolledBack`、`RollbackFailed`。即使回滚成功，当前修复调用仍报告失败，不能当作修复完成。
- 测试发现 PowerShell 5.1 会将 `File.Replace` 的空备份参数转换为空路径，现改用明确的上版日志备份路径。
- 当前仅验证可捕获异常的回滚；操作系统崩溃、断电、回滚本身受阻及下次启动恢复未完成验收。保留日志不等于已经实现崩溃续接。

## 实际文件测试

新增 `Test-IndependentFileRepair.ps1`，不替换任何在用程序。四个隔离场景通过：

1. 正常替换两个既有文件并补入一个缺失文件，逐个摘要一致。
2. 最后一个 DLL 持有禁止写入/删除的真实文件句柄，前面的替换成功后发生共享冲突；回滚恢复两个既有文件的原始内容，并移除新文件。测试检查失败新载荷确实存在，证明不是仅在暂存阶段就提前失败。
3. 最后一个源文件摘要错误，拒绝替换，原目录保持。
4. 配置目录内 DLL 被排除，原目录保持。

本地 Windows PowerShell 5.1 x86：4/4、exit 0，证据主仓库 `Codex/v41-file-repair-test.log`。修复归属预检 7/7；顶层包验证及验收脚本 exit 0，证据 `Codex/v41-file-repair-topbundle.log`。

## 剩余工作

### 后续补充：并发与未收尾事务保护

文件替换函数现持有安装根 `file-repair.lock` 的独占句柄直至 finally，拒绝另一个文件修复同时进入。开始新事务前有界检查最多 256 个历史事务，每个日志不超过 4 MiB；日志缺失、协议不符或阶段不是 `Replaced`/`RolledBack` 时停止，不覆盖尚未确认的半替换状态。拒绝后释放本次持有的锁。该保护不取代独立执行器租约，也不等于崩溃自动回滚已经实现。

新增真实文件锁竞争、`Prepared` 中断记录、日志缺失三项，合计 7/7，本地 PS5.1 x86 exit 0，证据 `Codex/v41-repair-lock-test.log`。jxcq 相同测试于 23:32:15 通过，PS 5.1.19041.7725，结果 `Codex/v41-jxcq/filerepair2-result.json`。诊断宿主 PID 11048 按 PID/启动时间归属监督并确认退出，无 WinRM 会话；结束物理可用 9,678,475,264 字节、提交量 10,934,374,400 字节、提交上限 19,494,666,240 字节，资源证据 `filerepair2-r1.ps1.resources.json`。未操作 WJ-EPB。
