## 2. 整改结果摘要

当前代码已经完成以下整改：

1. 批量调度不再使用硬编码 `350 ms` 和固定模3分组。
2. 错峰计划由运行时加载的 `ElectricalGroups/Group` 配置生成。
3. 同组相位按“本次已选通道”升序重新编号。
4. 不同电源组首通道可以并行启动。
5. 预释放、学习、正式循环和单通道入口均使用统一的错峰计划逻辑。
6. 预释放会一次性创建全部任务，后一相位不等待前一任务结束。
7. 同组硬故障只停止故障通道，不新增组级停机和电源组锁存。
8. 新运行继续复位通道报警锁存，同次运行重复报警仍去重。
9. 当前报警圈仍必须同时具备CSV和BIN文件才能写为 `alarm`，否则写为 `failed`。
10. Runner中的DO调用已收口到统一辅助方法，并记录结构化时间线。
11. 报警快照已增加错峰计划、DO时间线和报警元数据。
12. 未实现任何PSW程控电源通信、设定、回读或CV/CC监控。

## 4. 不可变错峰计划

### 4.1 新增模型

代码新增以下内部类型：

- `ChannelStaggerAssignment`
- `ElectricalStaggerPlan`
- `ElectricalStaggerPlanException`
- `ElectricalStaggerPlanner`
- `ElectricalStaggerExecutor`
- `ChannelFaultIsolationPolicy`

这些类型为 `internal`，没有扩大公共API。测试项目继续通过已有 `InternalsVisibleTo("AdaptiveControlTests")` 访问纯逻辑类型。

每个通道的计划项包含：

| 字段 | 含义 |
|---|---|
| `Channel` | EPB通道号 |
| `ElectricalGroupId` | XML配置的电气组ID |
| `SelectedIndexInGroup` | 本次已选同组通道中的升序序号 |
| `StaggerMs` | 该电气组配置的错峰步长 |
| `PhaseMs` | `SelectedIndexInGroup × StaggerMs` |

计划在运行开始时复制为不可变快照。运行过程中修改配置对象或XML，不会改变当前运行的计划。

### 4.2 已实现的配置校验

启动前一次性检查并汇总以下问题：

- 至少选择一个通道；
- 已选通道必须位于1～12；
- 试验周期必须大于0；
- 电气组ID必须为正数且唯一；
- 每个电气组必须配置成员；
- 成员通道必须位于1～12；
- 同一组内不得重复配置通道；
- 一个通道不得同时属于多个电气组；
- 每个已选通道必须属于一个电气组；
- `StaggerMs` 必须大于0；
- 最大计划相位必须小于运行周期；
- 相位乘法溢出时拒绝启动。

校验失败时抛出 `ElectricalStaggerPlanException`，错误消息同时列出已发现的问题，不再把漏配通道当作独立组，也不使用固定模3规则兜底。

### 4.3 相位结果

以 `StaggerMs=800` 为例，当前算法产生：

| 已选通道 | 实际计划 |
|---|---|
| EPB8 | EPB8=`0 ms` |
| EPB8、EPB9 | EPB8=`0 ms`，EPB9=`800 ms` |
| EPB7、EPB8、EPB9 | EPB7=`0 ms`，EPB8=`800 ms`，EPB9=`1600 ms` |
| EPB10、EPB12 | EPB10=`0 ms`，EPB12=`800 ms` |
| EPB8、EPB9、EPB10、EPB12 | EPB8/EPB10=`0 ms`，EPB9/EPB12=`800 ms` |

单独选择EPB9或EPB12时，相位为0，不再因为其物理工位位置产生额外等待。

## 5. 四条运行路径的落地行为

### 5.1 批量启动

`StartBatchSynchronizedAsync` 当前按以下顺序执行：

1. 对已选通道去重并升序排列；
2. 在任何预释放或Runner任务启动前生成计划；
3. 为批次生成唯一 `RunId`；
4. 保存计划和通道运行上下文；
5. 输出各电气组、序号和相位摘要日志；
6. 对全部已选通道调用 `ChannelAlarmStopLatch.BeginRun`；
7. 把同一个计划实例传给预释放、学习和正式阶段。

压力组仍只负责液压锚点，电气组只负责相位，两种分组没有合并。

### 5.2 预释放

预释放已由“逐波等待完成”改为：

- 一次性创建全部通道任务；
- 每个任务独立等待 `anchorUtc + PhaseMs`；
- 到达计划相位后立即进入该通道的 `PreReleaseAsync`；
- 不等待前一相位通道完成；
- 不同电源组的0相位任务可同时执行；
- 全部等待和Runner任务使用同一个取消令牌。

因此，错峰只控制开始相位，不构成同组互斥。

### 5.3 学习阶段

学习阶段保留原有液压锚点和超期滚动逻辑，只把相位来源替换为当前计划：

```text
计划时刻 = 本圈液压锚点 + ElectricalStaggerPlan.PhaseMs
```

实际启动时记录：

- `RunId`；
- 通道和电气组；
- 学习圈号；
- 计划相位；
- `PlannedUtc`；
- `ActualUtc`；
- `DeviationMs`。

### 5.4 正式循环

正式阶段按计划相位计算首个触发时刻，并继续使用现有 `HighPrecisionTimer` 和 `AlignToWallClock` 超期策略。

已实现：

- 后续循环保持固定墙钟相位；
- 已过期相位滚动到未来周期；
- 不进行追赶式连续补发；
- 一个通道持续时间延长不会动态顺延其他通道；
- 每圈记录计划时刻、实际时刻和偏差。

### 5.5 单通道运行

`StartChannelAsync(channel)` 会为单个通道调用同一个Planner。由于本次同组已选集合只有一个通道：

```text
SelectedIndexInGroup = 0
PhaseMs = 0
```

单通道的学习、正式循环及DO证据均关联独立 `RunId`。

## 6. 兼容性处理

为了不破坏已有调用代码：

- 原公共方法  
  `PreReleaseBatchStaggeredAsync(int[] channels, int? keepMs, int deltaMs, CancellationToken token)`  
  的签名被保留；
- 原公共属性 `StaggerDeltaMs` 被保留并标记为废弃兼容入口。

行为变化如下：

- 外部传入的 `deltaMs` 不再参与安全调度；
- 调用兼容方法时会记录警告；
- 实际错峰只读取 `ElectricalGroups/Group/StaggerMs`；
- `StaggerDeltaMs` 仅保存兼容值，不被批量调度路径读取；
- 不再保留硬编码 `350 ms` 默认安全措施。

## 7. 通道故障和报警保护

### 7.1 故障隔离

`ChannelFaultIsolationPolicy` 当前只返回故障通道本身。

以EPB8报警为例：

- EPB8执行高优先级断电；
- EPB8计时器、Runner和液压参与状态被清理；
- EPB9及其他同组通道不进入停止列表；
- 不取消同组其他通道的计时器；
- 不新增电源组故障锁存；
- 同组正常通道继续保持原计划相位。

### 7.2 报警锁存

现有通道级 `ChannelAlarmStopLatch` 继续生效：

- 单通道新运行调用 `BeginRun(channel)`；
- 批量新运行对每个已选通道调用 `BeginRun`；
- 同次运行首次报警获得处理权；
- 同次运行重复报警去重；
- 下一次运行可以再次触发首次报警。

### 7.3 报警圈状态

数据库状态规则没有放宽：

```text
当前报警圈CSV存在，并且当前报警圈BIN存在
    → alarm
否则
    → failed
```

新增的JSON或DO时间线属于辅助证据。即使辅助文件写入失败，也不改变CSV/BIN对 `alarm/failed` 的决定。

## 8. DO命令追踪

### 8.1 统一入口

Runner新增四个辅助方法：

- `CommandForward`
- `CommandReverse`
- `CommandOff`
- `CommandOffHighPriority`

正式编译的三个Runner源文件中的直接DO调用均已改走这些方法。Manager中的自然完成、人工停止和报警快速停机也写入同一时间线。

报警快速停机使用 `CommandEpbOffHighPriority`；普通人工停止和自然完成保持普通断电语义。

### 8.2 事件内容

每条DO事件记录：

| 字段 | 内容 |
|---|---|
| `Utc` | 命令调用UTC |
| `MonotonicTicks` | `Stopwatch.GetTimestamp()` |
| `MonotonicElapsedMs` | 相对进程基准的单调时间 |
| `RunId` | 批次或单通道运行ID |
| `CycleNumber` | 当前圈号 |
| `ElectricalGroupId` | 电气组ID |
| `Channel` | EPB通道 |
| `PlannedPhaseMs` | 计划相位 |
| `ElectricalPhaseDueUtc` | 当前电气阶段计划时刻 |
| `ElectricalPhaseStartDeviationMs` | 实际命令时刻相对计划时刻的偏差 |
| `Stage` | 调用该命令的Runner阶段/方法 |
| `Command` | Forward、Reverse、Off或OffHighPriority |
| `DoCommandResult` | `DoController` 方法返回值 |
| `BranchCurrentA` | 命令调用前读取的支路电流 |

追踪或日志自身发生异常时会被吞掉，不改变原始DO方法的返回或异常语义。

### 8.3 缓冲边界

DO时间线使用线程安全的有界内存缓冲：

- 最多保留10,000条；
- 最长保留最近60秒；
- 超限时从最旧事件开始淘汰；
- 报警导出后，其他仍运行通道可继续记录事件。

### 8.4 物理证据边界

所有日志和快照均明确：

```text
PhysicalOffStatus = NotMeasured
```

`DoCommandResult=true` 只代表软件DO方法返回成功，不代表：

- 继电器触点已经断开；
- 负载端已经物理断电；
- 线束电流已经降为0；
- 程控电源已经退出恒流状态。

物理断电仍需外部DI、示波器或逻辑分析仪验证。

## 9. 报警快照增强

报警目录 `AlarmSnapshots/<时间>-EPBxx` 现在额外生成：

```text
alarm-metadata.json
electrical-stagger-plan.json
do-control-timeline.csv
```

### 9.1 `alarm-metadata.json`

包含：

- 实际报警UTC；
- `RunId`；
- 报警通道和圈号；
- 报警原因；
- 电气组、选中序号、`StaggerMs`和相位；
- 同组已选通道及其计划；
- 报警通道最近一次正向、反向和断电命令；
- 对应DO返回值和支路电流；
- 当前圈CSV/BIN完整性；
- `physicalOffStatus="NotMeasured"`。

### 9.2 `electrical-stagger-plan.json`

保存运行开始时生成的计划快照，包括：

- `RunId`；
- 计划创建UTC；
- 运行周期；
- 本次所有已选通道的组号、序号、错峰步长和相位。

导出时不会重新读取XML。

### 9.3 `do-control-timeline.csv`

时间线：

- 使用 `InvariantCulture`；
- 按UTC及单调时钟排序；
- 包含命令、返回值、支路电流、阶段计划时刻和偏差；
- 包含本运行最近60秒内仍在缓冲区的事件；
- 明确物理状态为 `NotMeasured`。

三个辅助文件分别采用best-effort写入。单个辅助文件失败不会阻止其他文件尝试写入，也不会阻塞已先执行的高优先级断电。
