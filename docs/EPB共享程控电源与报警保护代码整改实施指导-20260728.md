## 2. Codex 最终交付目标

Codex 必须把现有“按通道独立控制、按固定时间错峰”的模式改造成以下闭环：

```text
配置加载与强校验
    ↓
四台电源逐台身份/设定/状态回读
    ↓
批量启动安全门禁
    ↓
同电源组高电流阶段互斥
    ↓
正向/反向上电 + 电源/支路同步监控
    ↓
正常断电并确认，或发生异常后组级断电
    ↓
报警、UI、蜂鸣器、数据库、CSV/BIN及电源遥测证据闭环
```

完成后应具备以下能力：

1. 同一电源组内默认只允许一个通道处于正向、反向或预释放上电阶段。
2. 不同电源组仍可并行，不把12通道全部串行化。
3. XML 中的电源组映射和错峰参数进入实际控制路径，不再使用硬编码 `350 ms` 作为安全措施。
4. 四台电源分别连接、识别和回读；未确认的 `20 A` 和冲突的 `50 V` 不得自动下发。
5. 电源断连、状态过期、持续 CC、输出电压异常或任一同组通道硬故障时，立即执行组级安全停机。
6. 新运行复位通道和电源组故障锁存；同一次运行内重复事件去重，但不能抑制下一次运行的报警。
7. 报警圈只有在当前圈 CSV/BIN 完整时写为 `alarm`，否则写为 `failed`。
8. 软件日志和报警快照能够还原电源组、支路电流、DO命令及断电结果的时序。

## 4. 不可破坏的安全约束

以下约束优先级高于性能、圈数和界面体验：

1. **断电优先：** 所有异常和取消路径必须先执行 `SetEpbOffHighPriority`，再记录日志、导出快照或等待网络。
2. **未知即禁止：** 电源身份、设定、状态、通道映射或输出反馈未知时，不允许启动对应电源组。
3. **同组互斥：** 首个现场发布版本固定 `MaxConcurrentHighCurrent=1`，不得通过配置放大。
4. **不同组可并行：** 互斥锁按 `ElectricalGroup.Id` 建立，禁止使用全局单锁。
5. **租约覆盖实际上电：** 租约在DO上电前获得，断电命令发出且反馈确认后才能释放；保持阶段已经断电，不占用租约。
6. **所有路径一致：** 正式循环、学习、预释放、单通道、批量、自适应和Legacy路径都必须经过同一安全包装器。
7. **释放必须幂等：** 正常、异常、超时、取消和重复回调均不得导致重复释放或 `SemaphoreFullException`。
8. **故障按运行去重：** 同一批次同一电源组只触发一次组级停机；新批次必须复位。
9. **状态不得伪造：** 没有电源回读时写 `Unknown/Stale`，不得沿用上一次状态或推断为CV。
10. **文件证据优先：** 快照不完整时数据库写 `failed`，不得为满足统计写成 `alarm`。
11. **不猜现场参数：** `ISET/VSET`、最低允许电压、线束上限和持久化阈值必须由现场核验后显式配置。
12. **禁止UI线程阻塞：** 移除电源控制路径中的 `Thread.Sleep`；网络等待不得阻塞 WinForms UI。

### 5.2 Controller 公共接口

在 `Controller/PowerSupply` 下新增以下接口和模型；命名可以按仓库风格微调，但职责和输入输出不得改变：

```csharp
public enum EpbPoweredStage
{
    PreRelease,
    ForwardClamp,
    ReverseRelease
}

public interface IPowerGroupCoordinator
{
    Task<PowerGroupLease> AcquireAsync(
        int channel,
        EpbPoweredStage stage,
        CancellationToken token);

    int GetGroupId(int channel);
    IReadOnlyList<int> GetGroupChannels(int groupId);
    void BeginBatch(Guid batchId, IEnumerable<int> channels);
    bool TryLatchGroupFault(int groupId, string reason);
    void EndBatch(Guid batchId);
}

public sealed class PowerGroupLease : IDisposable
{
    public int GroupId { get; }
    public int Channel { get; }
    public EpbPoweredStage Stage { get; }
    public void MarkOutputOffConfirmed();
    public void Dispose();
}

public interface IPowerSupplyStateProvider
{
    PowerSupplySnapshot GetLatest(int powerSupplyId);
    bool IsReadyForRun(int powerSupplyId, out string reason);

}

public interface IEpbOutputFeedback
{
    Task<bool> ConfirmOffAsync(
        int channel,
        int timeoutMs,
        CancellationToken token);
}
```

`PowerSupplySnapshot` 至少包含：

- `PowerSupplyId`、`Identity`、`TimestampUtc`、单调时钟时间戳；
- `VSet`、`ISet`、`VOut`、`IOut`；
- `RegulationMode`：`CV`、`CC`、`Unknown`；
- `OutputEnabled`、`Connected`、`ProtectionActive`；
- `RawStatus` 和最近一次通信异常摘要。

`PowerSupplyFault` 至少包含：

- `PowerSupplyId`、`GroupId`、故障代码、原因；
- 首次发生时间、最新遥测；
- 当前批次ID和当时活动通道。

### 5.3 电源通信接口

具体 TCP/SCPI 实现放在 `MTTfTest/PowerSupply`，通过接口交给 Controller：

```csharp
public interface IPowerSupplyGateway
{
    Task ConnectAsync(CancellationToken token);
    Task<PowerSupplyIdentity> QueryIdentityAsync(CancellationToken token);
    Task<PowerSupplySetpoints> QuerySetpointsAsync(CancellationToken token);
    Task<PowerSupplySnapshot> QuerySnapshotAsync(CancellationToken token);
    Task ApplySetpointsAsync(PowerSupplySetpoints value, CancellationToken token);
    Task OutputOffAsync(CancellationToken token);

```

实现要求：

- 每台电源一个串行命令队列，同一连接上只允许一个未完成查询；
- 请求必须有超时、响应终止符、数值解析和原始报文日志；
- 写设定后立即查询回读，允许误差来自显式配置，不得硬编码猜测；
- `*IDN?` 型号与 `ExpectedModel` 不匹配时进入 `Faulted`；
- SCPI 指令必须逐项对照 PSW Programming Manual；现有 `CURR:LIM`、`FUNC VOLT` 等命令在完成协议确认前不得沿用为生产实现；
- 如果现场实际通过代理服务通信，新增 `ExistingTcpProxyGateway`，并要求代理支持身份、设定和状态回读；无法回读的代理模式不得通过批量启动门禁。

## 6. 配置模型与校验

### 6.1 保留并扩展电气组

扩展 `Config/ConfigLoader.cs` 中 `ElectricalGroup`：

| 字段 | 类型 | 规则 |
|---|---|---|
| `Id` | `int` | 正数且唯一，同时作为 `PowerSupplyId` |
| `Members` | `List<int>` | 通道1～12；启用通道必须且只能属于一组 |
| `StaggerMs` | `int` | ≥0，仅用于负载平滑，不作为安全屏障 |
| `MaxConcurrentHighCurrent` | `int` | 首个现场版本只能为1 |
| `AcquireTimeoutMs` | `int` | 必填且>0；超时触发组级故障，不允许静默跳过 |
| `OffConfirmTimeoutMs` | `int` | 必填且>0；断电反馈超时触发组级故障 |

加载旧配置时可以把 `MaxConcurrentHighCurrent` 内存默认值设为1，但必须记录“配置已迁移”的警告；保存配置时写入新字段。

### 6.2 新增电源资产配置

在 `TestConfig.xml` 增加 `PowerSupplies`。每个 `PowerSupply` 必须包含：

- `Id`，与 `ElectricalGroup.Id` 一一对应；
- `Enabled`；
- `Protocol`：只允许 `GwInstekPswScpi` 或 `ExistingTcpProxy`；
- `Host`、`Port`，同一协议下端点不得重复；代理确需复用时必须有唯一 `DeviceAddress`；
- `ExpectedModel`，本台架为 `PSW 30-72`；
- `ExpectedVoltageV`、`ExpectedCurrentLimitA`；
- `BenchMaxCurrentA`，来自线束、继电器和连接器能力确认；
- `MinimumSafeOutputVoltageV`；
- `SetpointToleranceV/A`；
- `TelemetryPollMs`、`TelemetryStaleMs`；
- `CcPersistMs`、`VoltageDropPersistMs`；
- `CommandTimeoutMs`。

现场值未知的数值字段不设默认值。`Enabled=true` 且字段缺失时，配置加载可以完成，但安全预检必须失败并列出缺失项。

### 6.3 强校验规则

新增 `PowerSupplyConfigValidator`，一次返回全部错误，不只返回第一条：

1. 启用的 EPB 通道必须且只能属于一个电气组。
2. 每个启用电气组必须有一台启用电源。
3. 电源ID、组ID、端点和代理设备地址按协议规则唯一。
4. PSW 30-72要求 `0 < ExpectedVoltageV ≤ 30`、`0 < ExpectedCurrentLimitA ≤ 72`。
5. `ExpectedVoltageV × ExpectedCurrentLimitA ≤ 720 W`。
6. `ExpectedCurrentLimitA ≤ BenchMaxCurrentA`。
7. 所有时间、容差和安全阈值为正，且状态过期时间大于采样周期。
8. `MaxConcurrentHighCurrent` 在首个生产版本必须等于1。
9. 批量启动前，配置映射、设备身份、设定回读和输出状态必须全部一致。

仓库当前 `App.config` 中的 `Voltage=50`、`MaxCurrent=20` 只能作为迁移线索。Codex 不得把它们自动复制到新配置；旧入口应标记废弃，并在启用新监督器后停止参与电源初始化。

## 7. 核心控制改造

### 7.1 建立唯一通道—电源组映射

新增不可变 `ElectricalGroupMap`：

- 构造时完成重复通道、越界通道和空组校验；
- 提供 `GetGroupId(channel)`、`GetMembers(groupId)`；
- 提供 `GetConfiguredPhaseMs(channel)`，统一替代当前多个 `IndexInPowerGroup` 实现；
- `EpbManager.StartChannelAsync`、批量学习和正式批量启动必须使用同一个实例。

删除 `EpbManager.BatchStart.cs` 中安全意义上的 `StaggerDeltaMs=350`。如果为兼容界面暂时保留属性，必须标记 `[Obsolete]`，且不得再参与相位计算。

### 7.2 实现组级高电流租约

`PowerGroupCoordinator` 为每个电气组持有独立 `SemaphoreSlim(1,1)`，并维护：

- 当前租约通道和阶段；
- 获取、上电、断电命令、断电确认、释放的单调时钟时间；
- 当前批次ID；
- 组级故障锁存；
- 等待队列和取消状态。

行为规则：

1. `AcquireAsync` 前先检查配置、批次和电源 `Ready` 状态。
2. 等待超过 `AcquireTimeoutMs` 时，返回硬故障并触发组级停机。
3. 获得租约后再次检查电源状态，避免等待期间状态变化。
4. `PowerGroupLease.Dispose()` 只有在 `MarkOutputOffConfirmed()` 后才正常释放。
5. 未确认断电就释放时必须触发故障，不能让下一支路上电。
6. 取消等待不占用信号量；持有租约时取消仍必须先高优先级断电。
7. 不同组的信号量相互独立。

### 7.3 收口所有上电入口

在 `EpbCycleRunner` partial 类中新增唯一包装器，例如：

```csharp
private async Task<T> ExecutePoweredStageAsync<T>(
    EpbPoweredStage stage,
    Action energize,
    Func<CancellationToken, Task<T>> body,
    CancellationToken token)
```

包装器必须按以下顺序执行：

1. 从 `IPowerGroupCoordinator` 获取租约；
2. 记录即将上电的组、通道、阶段和电源快照；
3. 调用 `energize`；
4. 执行阶段主体和现有自适应监控；
5. 在 `finally` 中无条件调用 `SetEpbOffHighPriority`；
6. 等待 `IEpbOutputFeedback.ConfirmOffAsync`；
7. 记录断电结果并调用 `MarkOutputOffConfirmed`；
8. 释放租约；
9. 断电命令或反馈失败时触发组级故障，不允许下一等待通道获得租约。

Codex 必须通过搜索确认下列文件不再存在包装器之外的普通上电调用：

- `Controller/EpbCycleRunner.cs`
- `Controller/EpbCycleRunner.Adaptive.cs`
- `Controller/EpbCycleRunner.Advance.Sync.cs`

允许保留的直接DO调用仅限：

- 包装器内部的上电和断电；
- `EpbManager` 的紧急组级断电；
- 明确标注的初始化全断电路径。

保持阶段不持有租约。预释放、学习、Legacy和自适应路径都必须接入，不能只改 `RunOneAdaptiveAsync`。

### 7.4 批量启动门禁

在 `StartBatchSynchronizedAsync` 和UI批量启动按钮进入控制器前，执行同一套 `BatchSafetyPreflight`：

1. 校验选中通道和组映射；
2. 确认每个涉及电源均为 `Ready`；
3. 对照身份、设定回读和配置；
4. 确认输出反馈采集在线；
5. 确认无遗留通道/组级报警锁存；
6. 生成唯一 `BatchId` 并调用通道、组级 `BeginRun/BeginBatch`；
7. 将预检结果保存为 `batch-preflight-<BatchId>.json`；
8. 任一失败时不执行预释放和任何DO上电，并向UI显示全部失败原因。

单通道启动也必须进行该通道所属电源的预检，不能绕开门禁。

### 7.5 组级故障停机

在 `EpbManager` 增加：

```csharp
private void StopPowerGroupOnFault(
    int groupId,
    string faultCode,
    string reason,
    PowerSupplySnapshot snapshot)
```

顺序固定为：

1. 通过组级锁存取得本批次首次停机权；
2. 对该组所有通道立即执行 `SetEpbOffHighPriority`；
3. 取消该组活动 Runner、定时器、学习和等待租约；
4. 尝试调用电源 `OutputOffAsync`，但不得等待网络后才执行DO断电；
5. 仅对当时存在活动圈的通道触发 `PowerGroupFault` 报警和快照；
6. 当前圈有完整 CSV/BIN 时写 `alarm`，否则写 `failed`；
7. 导出组级故障元数据和故障前后的电源遥测；
8. 通知 UI、报警灯和蜂鸣器；
9. 该组保持锁定，必须由新运行预检复位，不允许自动恢复。

组级故障至少包括：

- `PowerSupplyDisconnected`
- `PowerSupplyStatusStale`
- `IdentityMismatch`
- `SetpointMismatch`
- `UnexpectedConstantCurrent`
- `OutputVoltageLow`
- `PowerSupplyProtection`
- `PowerGroupAcquireTimeout`
- `OutputOffNotConfirmed`
- 同组任一通道的 `ClampTimeout`、绝对上电超时或硬件过流

## 8. 电源监督、遥测与证据

### 8.1 四电源监督器

新增 `PowerSupplySupervisor`，由 `Main_Frm` 创建并注入 `EpbManager`：

- 从新配置创建4个独立 gateway；
- 应用启动时只连接和查询，不自动下发旧 `App.config` 的电压/电流；
- 提供逐台 `Disconnected → Connecting → Verifying → Ready → Faulted` 状态机；
- 每台电源独立重连，但运行中断连立即触发组级停机；
- 只有操作员完成配置确认后，才允许执行“写设定并回读”；
- 退出程序时先全通道DO断电，再尝试关闭电源输出和连接。

旧 `powerClient[1]`、`ClsGlobal.PowerServerAdr[1]` 和同步 `InitPower` 在新监督器稳定后移除。迁移期间不得同时由新旧实现向同一电源发送命令。

### 8.2 运行判据

具体阈值来自必填配置。实现统一的持久化判定，禁止单点抖动触发：

- `TelemetryStaleMs` 内无新状态：组级故障；
- 通道上电期间持续 CC 达到 `CcPersistMs`，且支路未达到正常结束判据：组级故障；
- 输出电压低于 `MinimumSafeOutputVoltageV` 达到 `VoltageDropPersistMs`：组级故障；
- 保护寄存器置位或输出意外关闭：组级故障；
- 遥测处于 `Unknown` 时不允许新租约，上电期间转为 `Unknown` 则停机。

运行判据使用单调时钟计算持续时间，UTC只用于日志展示。

### 8.3 电源遥测文件

在 `DataOperation` 新增 `PowerSupplyTelemetryWriter`，每批次保存：

```text
PowerSupplies/
  <BatchId>/
    batch-preflight-<BatchId>.json
    PS01-telemetry.csv
    PS02-telemetry.csv
    PS03-telemetry.csv
    PS04-telemetry.csv
    power-events.jsonl
```

遥测 CSV 至少包含：

```text
TimestampUtc,MonotonicTicks,BatchId,PowerSupplyId,GroupId,
VSet,ISet,VOut,IOut,Mode,OutputEnabled,Connected,ProtectionActive,
ActiveChannels,ActiveStages,RawStatus
```

落盘要求：

- 使用 `InvariantCulture`；
- 时间精确到毫秒，保留实际采样间隔；
- JSONL每条事件独立可解析；
- 批量写入并定期flush，不在控制回调中同步大量IO；
- 进程异常退出后已写记录仍可读取；
- 报警快照复制故障前至少5秒和故障后至少2秒遥测，若进程无法取得后段则明确标记缺失；
- 不把各支路电流求和伪装成 `IOut`；可另存 `BranchCurrentSumA` 并注明来源。

## 9. UI 与操作流程

在 `FrmEpbMainMonitor` 增加只读电源状态区，每台显示：

- 电源ID、型号/序列号、IP；
- `VSET/ISET` 与 `VOUT/IOUT`；
- CV/CC、输出、连接和保护状态；
- 所属EPB通道；
- 最后更新时间和当前故障。

操作规则：

1. 未全部通过预检时，批量启动按钮保持禁用，并显示具体原因。
2. 任何组级故障将对应组标红，显示共同故障ID。
3. UI只能发出请求，不能自行覆盖 Controller 的安全门禁。
4. “清除故障”不等于直接复位锁存；必须重新完成预检并开始新批次。
5. 不提供绕过组内互斥的隐藏开关。
6. 当前四台实际设定未确认前，界面只允许查看和核验，不允许一键写入仓库旧值。

## 10. 实施顺序

Codex 必须按以下阶段提交；每阶段均保持可编译、测试通过，不允许一次性重写：

### 阶段A：配置与纯逻辑基础

- 新增配置模型、加载/保存和 `PowerSupplyConfigValidator`。
- 新增 `ElectricalGroupMap`、`PowerGroupCoordinator`、租约和组级锁存。
- 增加无硬件测试。
- 暂不连接真实电源，不改变现场输出。

### 阶段B：上电入口收口

- 向 `EpbCycleRunner` 注入协调器和输出反馈接口。
- 将所有正向、反向和预释放上电改走唯一包装器。
- 批量和单通道路径统一映射；移除350 ms安全依赖。
- 使用假DO验证取消、异常和并发时序。

### 阶段C：电源协议与监督器

- 先用假TCP服务器完成请求—响应、超时、乱序和断连测试。
- 对照官方编程手册实现 `GwInstekPswScpiGateway`。
- 在现场只读连接中完成 `*IDN?`、设定和状态查询。
- 在未获得人工确认前不实现自动写入现场设定。

### 阶段D：组级故障、落盘和UI

- 接入电源状态判据、组级停机和报警联动。
- 增加遥测文件和报警快照元数据。
- 增加四电源UI状态及批量启动门禁。
- 验证旧报警锁存和文件证据逻辑未回退。

### 阶段E：现场灰度

- 先不接样件验证全断电和反馈。
- 再按单通道、同组双通道、同组三通道、四组并行顺序扩大。
- 完成故障注入和每组100圈回归后，才允许耐久试验。

## 13. 现场验收

自动化测试通过后，按下列顺序执行现场验证：

1. 四台电源逐台核验型号、序列号、IP、组映射和接线。
2. 输出关闭状态完成只读查询；保存原始SCPI请求和响应。
3. 断开负载验证DO全断电、继电器反馈和组级故障。
4. 单通道运行，建立正常电源V/I和支路电流基线。
5. 同组双通道故意同时发起，确认第二通道等待租约且没有DO上电。
6. 同组三通道重复验证；不得依赖350 ms或800 ms避免重叠。
7. 注入电源断连、状态过期、CC持续、低压、DAQ断流和卡钳堵转。
8. 验证故障发生后同组全部实际断电，其他组按策略安全运行或停止。
9. 核对UI、蜂鸣器、日志、数据库、CSV/BIN、电源遥测和快照。
10. 每组单独100圈，再执行四组并行100圈。

必须量化记录：

- 最后有效遥测到故障识别的时间；
- 故障识别到DO断电命令的时间；
- DO断电命令到继电器/负载实际断电的时间；
- 同组租约交接间隔；
- CC/低压持续时间；
- 报警文件生成耗时和缺失率；
- 每个通道成功、报警、失败、取消圈数及文件一致率。

## 14. 完成定义

代码整改只有同时满足以下条件才算完成：

- [ ] 4台电源均有独立、可追溯的身份、设定和状态；
- [ ] `Voltage=50`和未确认的`MaxCurrent=20`不再自动参与PSW初始化；
- [ ] 同组所有上电入口都受唯一租约控制；
- [ ] 不同电源组可并行；
- [ ] 配置800 ms能进入实际相位计算，但不承担安全保证；
- [ ] 任一组级故障均先DO断电，再做网络和落盘操作；
- [ ] 断电反馈失败会锁死该组并报警；
- [ ] 通道和组级锁存均按新运行复位；
- [ ] 电源遥测、支路波形、DO和报警文件可按时间关联；
- [ ] `alarm`状态具有当前圈CSV/BIN证据；
- [ ] 所有新增及既有自动化测试通过；
- [ ] 单/双/三通道故障注入和每组100圈现场验收通过；
- [ ] 代码、配置示例、操作说明和验收报告均使用带日期的文档文件名。

## 15. Codex 执行纪律

执行本指导书时，Codex 必须遵守：

1. 开始前读取本指导书、两份来源文档和当前 `git status`。
2. 保留用户已有未提交修改，不覆盖无关文件。

## 16. 范围边界

本指导书授权的代码整改范围包括配置、控制器、电源通信适配、遥测落盘、UI状态和自动化测试。以下事项不由代码自动决定：

- 现场最终 `VSET/ISET`；
- 线束、保险、继电器和连接器允许电流；
- PSW 的CV/CC优先模式；
- 卡钳齿轮损坏的最终机械责任归因；
- 没有物理断电反馈时是否允许继续生产耐久试验。

这些参数和结论必须由设备、电气、试验及样件责任方共同确认，并以带日期的现场验收文档留档。
