# EPBTest 正式发布包生成与部署操作说明

## 1. 目的

本文说明如何从当前仓库生成可部署的完整正式候选包，使程序启动后能够通过发布包身份校验，窗口标题不再出现：

```text
[非受控包:PackageManifestMissing]
```

正式包必须由 `Tools\Build-Release.ps1` 生成。不得把 `MTTfTest\bin\Release` 当作现场包，也不得只复制或替换 `MTTFTest.exe`。

## 2. 正式包包含的身份文件

正式包根目录必须包含：

- `build-identity.json`：版本、Git 提交、构建时间、配置摘要、测试结果和放行状态；
- `SHA256SUMS.txt`：发布包内全部受管文件的 SHA-256 校验值；
- `MTTFTest.exe`、看门狗程序、DLL、资源和完整 `Config` 目录。

程序启动时会验证身份、文件集合及不可变文件哈希。缺少身份文件、混用不同构建的 DLL 或手工替换 EXE，都会在标题中显示“非受控包”。

## 3. 生成前准备

在开发机确认已安装：

1. Git；
2. Visual Studio 及 MSBuild；
3. .NET SDK（用于部分自动测试）；
4. Python 3 和项目现场门禁测试所需依赖；
5. 项目所需的 NuGet/本地依赖与 NI 相关编译环境。

仓库默认使用的 MSBuild 路径为：

```text
D:\Microsoft Visual Studio\18\Professional\MSBuild\Current\Bin\MSBuild.exe
```

如果本机路径不同，可在执行脚本时通过 `-MsBuild` 指定实际路径。

## 4. 正式生成步骤

### 4.1 打开 PowerShell 并进入仓库

```powershell
Set-Location 'D:\Github\wanxiang\EPBTest'
```

### 4.2 确认程序版本

检查 `MTTfTest\MTTfTest.csproj` 中的 `ApplicationVersion`，确认它是准备发布的版本号。

```powershell
Select-String -Path '.\MTTfTest\MTTfTest.csproj' -Pattern 'ApplicationVersion'
```

版本变更必须先经过正常代码审查并提交，不能在打包后修改程序集版本。

### 4.3 确认 Git 工作区干净

```powershell
git status --short
git rev-parse HEAD
git branch --show-current
```

正式打包要求 `git status --short` 没有任何输出。若存在修改，应先确认修改内容并正常提交：

```powershell
git diff
git diff --cached
```

不要为了通过门禁而删除不明确的文件，也不要使用 `-AllowDirtyCandidate` 生成生产包。该参数生成的包会被标记为：

```text
DIRTY_CANDIDATE_NOT_FOR_PRODUCTION
```

这种包只能用于研发验证，不能部署现场。

### 4.4 执行正式打包

使用默认设置：

```powershell
powershell -ExecutionPolicy Bypass -File '.\Tools\Build-Release.ps1'
```

脚本默认执行 600 秒持久化浸泡测试，并依次完成：

1. NuGet/项目依赖还原；
2. 清空并重建 `MTTfTest\bin\Release` 暂存目录；
3. Release 全量编译；
4. `AdaptiveControlTests`；
5. `EpbDiskWriterTests`；
6. 600 秒持久化浸泡测试；
7. `PowerSupplyDebugger.Tests`；
8. Python 现场门禁测试；
9. 生成身份和 SHA-256 清单；
10. 将产物复制到独立、不可覆盖的版本目录；
11. 对独立包进行最终校验。

打包耗时会明显超过 10 分钟，应等待脚本自然结束，不要在构建或测试过程中修改、切换或提交源码。

如果 MSBuild 不在默认位置：

```powershell
powershell -ExecutionPolicy Bypass -File '.\Tools\Build-Release.ps1' `
  -MsBuild 'C:\实际路径\MSBuild.exe'
```

如需把包输出到指定目录：

```powershell
powershell -ExecutionPolicy Bypass -File '.\Tools\Build-Release.ps1' `
  -PackageRoot 'D:\EPB-Releases'
```

不指定 `-PackageRoot` 时，默认输出到：

```text
D:\Github\wanxiang\EPBTest\artifacts\releases\
```

包目录名称类似：

```text
V2.13.0.23-0123456789ab-20260825_153000
```

其中包含版本号、Git 提交前 12 位和 UTC 打包时间。

### 4.5 判断生成成功

脚本最后必须出现类似输出：

```text
Release 正式候选包已生成并独立校验：<完整包路径>
ScratchOutput=... PackageOutput=... Commit=... Branch=... Dirty=False ...
```

只要脚本抛出错误或中途退出，就不能使用暂存目录或半成品部署。

## 5. 独立复核正式包

将下面的包路径替换成脚本输出的 `PackageOutput`：

```powershell
$package = 'D:\Github\wanxiang\EPBTest\artifacts\releases\V2.13.0.23-提交号-时间'

powershell -ExecutionPolicy Bypass -File '.\Tools\Verify-Release.ps1' `
  -ReleaseDirectory $package `
  -RequireDeploymentApproved
```

校验成功会输出 JSON，关键字段应为：

```json
{
  "verified": true,
  "releaseStatus": "FORMAL_RELEASE_CANDIDATE",
  "deploymentApproved": true,
  "gitDirty": false,
  "verification": "PASS"
}
```

还应直接检查身份文件：

```powershell
Get-Content (Join-Path $package 'build-identity.json') -Raw
Get-FileHash (Join-Path $package 'MTTFTest.exe') -Algorithm SHA256
Get-FileHash (Join-Path $package 'build-identity.json') -Algorithm SHA256
Get-FileHash (Join-Path $package 'SHA256SUMS.txt') -Algorithm SHA256
```

建议把以下信息记录到交付单：

- 包目录名称；
- `productVersion`；
- 完整 `gitCommit`；
- `buildUtc`；
- `configSha256`；
- `MTTFTest.exe` SHA-256；
- `build-identity.json` SHA-256；
- `SHA256SUMS.txt` SHA-256。

## 6. 现场部署

1. 停止当前试验并正常退出主程序和看门狗；
2. 保留当前现场程序目录作为可回退备份；
3. 把正式包**整个目录**复制到新的独立版本目录；
4. 不要覆盖旧版本目录，不要只复制 EXE 或个别 DLL；
5. 从新目录中的 `MTTFTest.exe` 启动；
6. 核对窗口标题中的产品名称、版本和 PID；
7. 确认标题中不再出现 `[非受控包:...]`；
8. 查看启动日志中的“启动构建身份”，确认：

```text
PackageVerified=True
PackageCode=Verified
```

正式运行前还应进行配置核对、DAQ/DO/电源预检和必要的现场点检。

## 7. 配置文件注意事项

程序允许通过产品界面调整 `Config` 目录中既有 XML 的参数内容，但配置文件集合必须保持完整。不得随意新增、删除或重命名以下文件：

```text
AIConfig.xml
AlarmConfig.xml
AOConfig.xml
DOConfig.xml
PowerSupplyConfig.xml
TestConfig.xml
UIConfig.xml
```

建议在部署前先对原始正式包执行 `Verify-Release.ps1`，再进行现场参数配置。配置调整后应另行备份并记录项目配置身份，不要修改 EXE、DLL、资源文件、`build-identity.json` 或 `SHA256SUMS.txt`。

## 8. 常见失败与处理

### 8.1 `源码树不是干净状态`

原因：存在未提交修改或未跟踪文件。

处理：执行 `git status --short`，审查并提交应发布的内容；不应使用 `-AllowDirtyCandidate` 绕过生产门禁。

### 8.2 `MSBuild 不存在`

原因：默认 MSBuild 路径与本机安装位置不同。

处理：查找实际路径并通过 `-MsBuild` 指定：

```powershell
$vswhere = Join-Path ${env:ProgramFiles(x86)} 'Microsoft Visual Studio\Installer\vswhere.exe'
& $vswhere -latest -requires Microsoft.Component.MSBuild -find 'MSBuild\**\Bin\MSBuild.exe'
```

### 8.3 回归测试或浸泡测试失败

原因：正式发布门禁未全部通过。

处理：保留完整控制台输出并修复具体问题；不得从 `bin\Release` 或 `.staging-*` 目录取文件部署。

### 8.4 启动后显示 `PackageManifestMissing`

原因：运行目录缺少 `build-identity.json` 或 `SHA256SUMS.txt`。

处理：确认启动的是独立正式包目录，并重新复制完整目录。

### 8.5 启动后显示 `PackageFileHashMismatch`

原因：EXE、DLL 或其他不可变程序文件在打包后被替换或损坏。

处理：停止使用该目录，从已校验的原始正式包重新完整复制。不要单独替换文件。

### 8.6 启动后显示 `PackageFileSetMismatch` 或 `UnexpectedPackageFile`

原因：包内文件缺失、多出，或把其他版本文件混入当前目录。

处理：新建空目录并重新复制完整正式包，不要在旧程序目录上覆盖升级。

### 8.7 标题仍显示非受控包，但版本号正确

版本号只来自程序集属性，不能证明整个目录属于同一次构建。应以 `build-identity.json`、`SHA256SUMS.txt` 和 `Verify-Release.ps1` 的结果为准。

## 9. 禁止事项

- 禁止部署 `MTTfTest\bin\Debug`；
- 禁止部署 `MTTfTest\bin\Release`；
- 禁止使用 DIRTY 候选作为生产包；
- 禁止只替换 `MTTFTest.exe`；
- 禁止把不同版本的 DLL 混入同一目录；
- 禁止修改正式包中的身份文件和校验清单；
- 禁止在原版本目录上直接覆盖升级；
- 禁止在打包过程中修改或切换源码。

## 10. 一组可直接执行的标准命令

```powershell
Set-Location 'D:\Github\wanxiang\EPBTest'

git status --short
git rev-parse HEAD
git branch --show-current

# git status --short 必须无输出，之后再执行正式打包。
powershell -ExecutionPolicy Bypass -File '.\Tools\Build-Release.ps1'

# 从上一条命令最后输出中复制 PackageOutput，并在此复核。
$package = '请替换为实际 PackageOutput'
powershell -ExecutionPolicy Bypass -File '.\Tools\Verify-Release.ps1' `
  -ReleaseDirectory $package `
  -RequireDeploymentApproved
```

只有最后的独立验证通过，并且包内身份满足 `FORMAL_RELEASE_CANDIDATE`、`deploymentApproved=true`、`gitDirty=false`，该目录才是可交付的完整正式候选包。
