# V4.1 SYSTEM 服务生产入口与剩余集成

承接 `708de61`，修复工作树 `Codex/independent-fallback-v4-work`。

## 本轮实际完成

在 `MTTFTest.FallbackGuard.exe` 新增 `--independent-service --registration <受保护注册文件>` 入口。对应服务名为 `MTTFTestIndependent-<InstallationId>`。新增的 `IndependentExecutorService` 使用 Windows `ServiceBase`，`IndependentExecutorRuntime` 实际组合现有安全执行器、恢复推进器、启动工作进程和只读数据库观察器。

**尚未注册或安装这一服务，未交付现场候选包，也未证明完整 SYSTEM 实机执行。** 本轮没有连接 WJ-EPB 或 jxcq。

## 已连接的生产代码路径

- 启动时要求 SYSTEM、受保护安装注册和配置哈希，获取项目独占执行租约；失败不报告服务成功运行。
- 服务以独立线程推进当前持久恢复事务；主进程不存在时可基于有效持久运行意图发起接管。
- 安全阶段调用 `IndependentProjectSafetyRunner`，由有界子进程执行原有电源关闭、精确进程终止、输出和压力确认。没有在服务线程内调用 NI 原生控制。
- 旧控制进程清理后、发出启动凭证前读取并保存数据库验收基线。基线按 RequestId 文件命名，并核对代际、数据库身份和完整目标集合；服务重新打开该事务时读取同一基线，不能在已签发凭证后补建缺失基线。
- 调度 `IndependentLaunchWorkerOperation`；凭证写入与阶段推进分开轮询，后续从新状态修订号继续，避免拿旧修订号提交启动成功。
- 替代进程已绑定后，检查精确 PID/启动时间/路径/Windows 会话，再以五秒间隔只读验证各目标的机械完成和至少三个正式采样完成记录。
- 数据库读取由现有有界子进程执行。读取失败或超时会打断连续停滞确认，不伪造“无推进”；启动和验证期限仍由持久事务决定。
- 停止服务时停止循环、释放本实例工作进程和租约，等待上限 15 秒；不能确认退出时报告错误。人工撤权和失败替代进程继续沿用上一轮持久清理义务，不能依赖工作进程退出替代硬件确认。
- `executor-observation.json` 每五秒发布有界诊断文本。它不是运行许可，也不能用其存在或更新时间证明试验恢复。

## 明确没有补齐的集成

1. **首次人工启动、重新开始及学习阶段尚未发布完整持久阶段和期限。** 为避免将正常学习误判为停滞，目前存活进程的数据库停滞检测只对本独立事务已验证的当前批次开启；其他批次明确显示 `InitialLearningIntegrationPending`。这不是最终交付行为，必须继续接通后才能发布。尚无正式记录的情况也不能冒充“正常运行”。
2. `CooperativeStop` 的持久阶段已经作为停止请求存在，但主程序尚未接入该新请求及回执；运行时最多等待其既有 25 秒期限，随后推进独立安全阶段。不能将这一等待写成主程序已协作停止。
3. 原 Watchdog 的启动权、旧侧车清理和独立服务尚未完成统一事务交接。服务观察新 Controller 绑定，不等于已验证全部原监督组件重新绑定。
4. 人工选择/暂停、永久隔离、近零电流一次重试及液压队列期限仍需完整集成。
5. 安装/修复/卸载/回滚脚本尚未注册新服务和交互任务；维护模式和旧协议迁移没有完成。因此不得将本轮构建目录当作现场一键安装包。
6. 完整 SYSTEM 接管、计划任务拉起交互主程序、模拟动作与三周期落盘的贯通测试尚未运行；真实硬件安全执行仍须台架确认。
