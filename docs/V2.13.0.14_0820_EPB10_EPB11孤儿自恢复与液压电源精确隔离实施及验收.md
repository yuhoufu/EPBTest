## 2. 根因与修复对照

| 问题 | V2.13.0.13根因 | V2.13.0.14处理 |
|---|---|---|
| EPB10/11进入自恢复 | 电源组4的高优先级OFF调用超出100ms软件确认期限，10/11按共享电气组安全断电 | 保留该安全范围；软件超时不等同于卡钳损坏 |
| EPB10/11不能恢复 | 电源组3与4同映射液压2；同优先级使用`>=`互相抢占，旧任务把取消误记为“更高层已接管” | 只有严格更高优先级可抢占；同优先级不同owner严格排队 |
| 孤儿Recovering无终点 | 恢复任务无通道登记；任务退出后无owner、无补建；Watchdog只看DAQ | 任务按全部通道登记；500ms扫描全部恢复域；无覆盖1秒即组清场 |
| 60秒期限失效 | 期限属于原任务，任务取消/移除后一起消失 | 连续Recovering起点独立保存；单调时钟60秒期限不被重试、文本刷新或系统校时重置 |
| 软件故障无限重试 | 电源/液压循环仅靠60秒任务令牌，无3次真实尝试终态 | 第3次失败或60秒到期执行受影响组Stop→Start等价清场 |
| 液压2牵连液压1 | 组恢复失败后走全批StopAll/StartBlocked | 硬件确认只隔离故障事件内当前启用成员；不撤销健康独立组运行授权 |
| 故障组重启后仍勾选 | 外部设备硬件故障统一按可恢复处理 | 液压/电源`HardwareConfirmed`执行项目级`Enabled=false`并同步UI取消勾选 |
| 硬件隔离与旧恢复并发 | 软件自恢复只检查Run/Timer/Runner，硬件确认到达后旧任务仍可能执行一次重新使能 | 硬件锁存或报警停机立即终止同组旧恢复；隔离后禁止再次使能 |
| 报警不确定 | 启动阶段提前返回绕过`Alarm.SetAlarmAsync`，串口仅记录打开或最终失败 | 硬件确认统一请求报警；记录映射、请求、响应、失败、次数和耗时 |
| 暂停/停止像卡死 | UI主要等待完成后才给结论，命令受理缺少贯穿身份 | 点击立即显示已受理并记录CommandId；停止过程每秒显示阶段及Watchdog倒计时 |

## 3. 恢复状态机不变量

### 3.1 Recovering准入与存活

任一启用通道处于`Recovering`时，必须满足：

```text
同一RunId/RunEpoch
AND 连续恢复起点存在
AND （DAQ恢复上下文存在
     OR 启动调用栈明确拥有
     OR 受影响通道恢复任务存在 AND 组owner/恢复域标记存在）
AND 硬期限 = 首次连续进入Recovering + 60秒
```

恢复理由变化、重试、owner排队或状态重复发布都不创建新的60秒窗口。

### 3.2 收敛终态

每条恢复路径只能到达以下结果之一：

```text
恢复成功
  -> 机械释放和数据边界确认
  -> 从未来完整公共槽重入
  -> Running/Paused/Completed

连续3次失败或60秒到期
  -> 受影响液压组Stop→Start等价清场
  -> 成功后重新加入
  -> 失败则SystemRecoveryCircuitOpen/ExternalRecoveryRequired
  -> 独立Watchdog接管

硬件确认
  -> 故障组成员OFF + AlarmStopped
  -> 报警与证据
  -> 当前项目Enabled=false
  -> 健康独立组保持运行
```

不允许“任务已结束但通道仍Recovering”、无期限owner、无接管确认的取消出口，或依赖人工强杀才能重新开始。

## 4. 故障范围矩阵

| 证据 | 分类 | 停机/恢复范围 | 声光 | 持久禁用 | 健康通道 |
|---|---|---|---|---|---|
| 单次低压、陈旧压力、液压屏障异常 | SystemFault/SoftwareTransient | 当前液压组暂时断能并自恢复 | 否 | 否 | 其它液压组继续 |
| 连续3代新鲜液压低压 | HardwareConfirmed | 故障事件内当前启用成员；本项目为9/10/11 | 是 | 9/10/11 | 4/5继续 |
| PSU通信/调度瞬态 | SystemFault/SoftwareTransient | 当前电气组恢复；同液压owner排队 | 否 | 否 | 其它电气组继续 |
| PSU4新鲜保护/硬件失败确认 | HardwareConfirmed | 电气组4事件成员10/11 | 是 | 10/11 | EPB9、4/5继续 |
| DAQ软件链故障 | SystemFault/SoftwareTransient | 对应DAQ组安全截止与恢复 | 按既有确认策略 | 否 | 独立DAQ/组继续 |
| 无任务或owner的Recovering | Software invariant | 1秒内受影响液压组自动清场 | 否 | 否 | 无关组继续 |

`HardwareConfirmed`只来自已有的新鲜、连续或独立硬件证据门；owner冲突、线程取消、串口/DAQ延迟不能增加硬件确认次数。

## 5. Watchdog与机械进展

主程序向Sidecar提供：

- 全部`RecoveringChannels`和`OrphanRecoveryChannels`；
- 最早连续恢复起点与60秒硬期限；
- 预期恢复通道、仍带电通道和待关闭电源组；
- 每通道Timer、Runner、Energized状态；
- 每通道机械完成次数和最后机械完成时刻；
- 连续软件作废次数、DO命令序号和峰值截止水位。

孤儿非DAQ恢复映射为结构化`OrphanPaused`接管信号，复用现有Sidecar五秒接管策略。DO刷新、峰值刷新和UI状态刷新不能冒充机械进展。

## 6. 声光报警审计

启动时记录：

```text
AlarmMappingLoaded Channel=9 Device=... Line=...
AlarmMappingLoaded Output=Buzzer Device=... Line=...
```

动作时记录：

```text
AlarmOutputRequested Channel=9 Device=... Line=... State=On
AlarmOutputAcked Channel=9 Device=... Line=... State=On Attempt=1 LatencyMs=... Confirmation=SerialResponse
AlarmOutputFailed Channel=9 Device=... Line=... State=On Attempts=... LatencyMs=... Error=...
```

`Acked`表示串口从站按当前配置返回，不代表具备独立物理触点读回。现场仍需对EPB9、EPB10、EPB11和蜂鸣器逐点观察，验证配置中的Device/Line与实际灯号一致。

## 9. 现场验收步骤

1. 使用软件故障注入让电源组3、4同时请求液压2 owner，确认日志显示排队，无同优先级取消；EPB9/10/11均在60秒内恢复或进入明确终态。
2. 人工终止某个电源恢复任务，确认1秒左右出现`RecoveryInvariantViolation`，随后自动组清场，不需点击停止或强杀。
3. 注入液压2单次低压后恢复：9/10/11自恢复，4/5次数持续增加，无硬件声光、无取消勾选。
4. 注入液压2连续3代新鲜低压：9/10/11断电、声光请求、项目勾选取消；4/5保持运行并继续增加机械次数。
5. 注入PSU4确认保护：仅10/11取消勾选并报警，EPB9保持运行。
6. 分别点击暂停、继续、停止：点击后立即看到已受理文字和CommandId；停止期间可见阶段与接管倒计时。
7. 逐点测试9/10/11指示灯和蜂鸣器，对照`AlarmMappingLoaded`与`AlarmOutputAcked`核对实际输出。
8. 重启软件并重新加载项目：已确认故障成员仍为未勾选；健康组仍保持已启用。
9. 连续运行72小时并组合注入DAQ延迟、owner竞争、液压短失压和串口失败，确认无孤儿状态、无无关组停机、无人工强杀需求。

## 10. 发布判定

自动化测试用于证明状态机、并发和范围策略；现场液压泄漏、卡钳物理隔离及声光Device/Line只能由实机验收确认。满足第9节实机验收后，方可用`V2.13.0.14`替换事故版本。
