## 2. 本阶段目标

将现有批量控制中的硬编码 `350 ms` 和固定模3分组，改造成由 `TestConfig.xml` 中 `ElectricalGroups` 驱动的固定相位错峰：

```text
加载并校验 ElectricalGroups
        ↓
按“本次选中通道”生成不可变错峰计划
        ↓
预释放、学习、正式循环和单通道入口共用该计划
        ↓
同组按 0/Δ/2Δ 启动，不同组并行
        ↓
每通道独立运行、独立硬保护、独立报警停机
        ↓
记录计划相位、实际DO命令和报警证据
```

最终行为必须满足：

1. 同一电源组不是串行队列，也不使用互斥锁；各通道按固定相位启动。
2. 不同电源组相互独立，每组第一个已选通道均可在相同锚点启动。
3. 相位按本次已选通道重新编号，不按物理工位固定保留空相位。
4. 前一通道仍在高电流阶段时，后一通道到达计划相位后照常启动，不动态顺延。
5. 同组任一通道硬故障只停止故障通道，不停止同组其他通道。
6. 新运行复位通道报警锁存；同一次运行的重复报警继续去重。
7. 当前报警圈CSV/BIN完整时写 `alarm`，否则写 `failed`。
8. 日志和报警快照能还原计划相位、实际上电/断电命令及方法返回结果。

## 3. 明确不实施的内容

本阶段不实施以下内容：

- 不建立同组 `SemaphoreSlim`、租约或 `MaxConcurrentHighCurrent=1`；
- 不把同组通道强制串行；
- 不检测前一通道是否已退出高电流阶段后再启动下一通道；
- 不连接或控制4台程控电源；
- 不发送PSW SCPI命令；
- 不查询电源身份、`VSET/ISET`、`VOUT/IOUT`或CV/CC状态；
- 不新增电源断连、状态过期、持续CC或输出低压判据；
- 不新增电源组故障锁存和组级停机；
- 不修改 `MTTfTest/Main_Frm.cs` 中现有电源相关遗留代码；
- 不把DO方法返回值表述为继电器触点或负载物理断电确认。

PSW 30-72及约20 A平台分析仅作为风险背景。固定错峰只能降低上电峰值同时出现的概率，不能保证高电流阶段绝不重叠，也不能证明或排除程控电源限流。

## 5. 错峰计划模型

### 5.1 建议新增类型

在 `Controller` 中新增纯逻辑类型，避免依赖NI、WinForms或真实计时器：

```csharp
public sealed class ChannelStaggerAssignment
{
    public int Channel { get; }
    public int ElectricalGroupId { get; }
    public int SelectedIndexInGroup { get; }
    public int StaggerMs { get; }
    public int PhaseMs { get; }
}

public sealed class ElectricalStaggerPlan
{
    public int PeriodMs { get; }
    public DateTime CreatedUtc { get; }
    public IReadOnlyDictionary<int, ChannelStaggerAssignment> Assignments { get; }

    public ChannelStaggerAssignment Get(int channel);
}

public static class ElectricalStaggerPlanner
{
    public static ElectricalStaggerPlan Build(
        IEnumerable<int> selectedChannels,
        IEnumerable<ElectricalGroup> configuredGroups,
        int periodMs);
}
```

类型可以是 `internal`；如果现有测试项目需要直接调用，可通过 `InternalsVisibleTo` 或保持最小 `public` 可见性。不得把设备通信、DO控制或运行状态放入计划类型。

### 5.2 计划生成算法

`Build` 固定按以下顺序执行：

1. 对已选通道去重并升序排列。
2. 校验已选通道范围为1～12。
3. 校验电气组ID为正且唯一。
4. 校验配置成员范围为1～12。
5. 校验同一通道没有出现在多个电气组。
6. 校验每个已选通道恰好属于一个电气组。
7. 对每个涉及的电气组，取“已选通道与组成员的交集”并按通道号升序排列。
8. 将交集中的通道重新编号为 `0..n-1`。
9. 计算 `PhaseMs = SelectedIndexInGroup × StaggerMs`。
10. 校验 `StaggerMs > 0`，并校验该组最大 `PhaseMs < periodMs`。
11. 复制所有结果，生成运行期间不可变的计划快照。

验证失败时一次返回全部问题，UI/调用方应显示具体组号和通道号；不得自动把未分组通道当成独立组，也不得继续使用模3规则兜底。

### 5.3 明确相位示例

现场配置：

```xml
<ElectricalGroups>
  <Group>
    <Id>3</Id>
    <Members>7,8,9</Members>
    <StaggerMs>800</StaggerMs>
  </Group>
  <Group>
    <Id>4</Id>
    <Members>10,11,12</Members>
    <StaggerMs>800</StaggerMs>
  </Group>
</ElectricalGroups>
```

不同选择下的计划：

| 已选通道 | 计划相位 |
|---|---|
| EPB8 | EPB8=`0 ms` |
| EPB8、EPB9 | EPB8=`0 ms`，EPB9=`800 ms` |
| EPB7、EPB8、EPB9 | EPB7=`0 ms`，EPB8=`800 ms`，EPB9=`1600 ms` |
| EPB10、EPB12 | EPB10=`0 ms`，EPB12=`800 ms` |
| EPB8、EPB9、EPB10、EPB12 | EPB8/EPB10=`0 ms`，EPB9/EPB12=`800 ms` |

EPB8、EPB9只被选中时，不使用物理位置对应的800/1600 ms；首个已选通道重新从0开始。

## 6. 各运行路径接入方式

### 6.1 批量入口

`StartBatchSynchronizedAsync` 在任何预释放、学习或正式计时器创建之前：

1. 规范化选中通道；
2. 调用 `ElectricalStaggerPlanner.Build`；
3. 记录计划摘要；
4. 为每个通道调用 `_alarmStopLatch.BeginRun`；
5. 将同一个 `ElectricalStaggerPlan` 传入预释放、学习和正式阶段。

当前批次启动后不重新读取组配置。运行期间修改XML只影响下一次启动。

建议签名调整：

```csharp
private Task PreReleaseBatchStaggeredAsync(
    int[] channels,
    int? keepMs,
    ElectricalStaggerPlan plan,
    CancellationToken token);

private Task RunLearningPhaseAsync(
    Dictionary<int, List<int>> pressureGroups,
    Dictionary<int, DateTime> t0OfPressureGroup,
    int learnCycles,
    ElectricalStaggerPlan plan,
    CancellationToken token);

private void StartFormalPhaseTimers(
    Dictionary<int, List<int>> pressureGroups,
    Dictionary<int, DateTime> t0OfPressureGroup,
    ElectricalStaggerPlan plan,
    CancellationToken token);
```

电气组只决定相位；现有压力组仍决定液压锚点。两类分组不得合并。

### 6.2 预释放

当前代码按相位桶顺序执行，并等待整桶完成。必须改为：

```csharp
var anchorUtc = DateTime.UtcNow.AddMilliseconds(500);

var tasks = channels.Select(async channel =>
{
    var phaseMs = plan.Get(channel).PhaseMs;
    await DelayUntilAsync(anchorUtc.AddMilliseconds(phaseMs), token);
    await GetRunner(channel).PreReleaseAsync(keepMs, token);
});

await Task.WhenAll(tasks);
```

要求：

- 所有通道任务一次性创建；
- 不等待前一相位的 `PreReleaseAsync` 完成；
- 不同电气组相位0的通道可同时执行；
- 相位800 ms的通道即使相位0通道仍在运行，也按时启动；
- 取消时所有等待和Runner任务均收到同一token。

### 6.3 学习阶段

保留现有压力组锚点和 `RollForwardToFuture` 逻辑，只替换相位来源：

```csharp
var phase = plan.Get(channel).PhaseMs;
var at = cycleAnchorUtc.AddMilliseconds(phase);
```

不得再调用 `IndexInPowerGroup` 或读取 `StaggerDeltaMs`。

学习阶段每圈仍允许同组高电流阶段重叠；自适应通道继续使用现有电流状态机和硬保护。

### 6.4 正式阶段

`StartFormalPhaseTimers` 使用计划相位计算每个通道的初始延时：

```csharp
var phase = plan.Get(channel).PhaseMs;
var firstDueUtc = groupAnchorUtc.AddMilliseconds(phase);
```

要求：

- 后续每圈保持 `anchor + k×PeriodMs + PhaseMs`；
- 相位过期时滚动到未来周期，不进行追赶式连续上电；
- 不因某通道上一圈持续时间延长而动态改变其他通道相位；
- 继续采用现有高精计时器和超期策略，不另建第二套周期调度器。

### 6.5 单通道启动

`StartChannelAsync(channel)` 也使用 `ElectricalStaggerPlanner.Build(new[]{channel}, ...)`。

由于组内已选集合只有一个通道，其 `SelectedIndexInGroup=0`、`PhaseMs=0`。删除当前按完整组物理位置计算首启延迟的逻辑，避免单独启动EPB8、EPB9或EPB12时额外等待。

## 7. 通道故障与报警锁存

### 7.1 停机范围

故障范围保持通道级：

- EPB8硬故障只调用EPB8的高优先级断电和停止流程；
- EPB9及同组其他通道继续按原计划运行；
- 不取消同组计时器；
- 不新增电源组锁存；
- 不因同组通道继续运行而复位故障通道；
- 故障通道只能通过一次新的通道运行重新进入。

### 7.2 锁存规则

保留现有 `ChannelAlarmStopLatch`：

1. 单通道新运行调用 `BeginRun(channel)`；
2. 批量新运行在启动阶段对全部已选通道调用 `BeginRun`；
3. 本次运行首次报警通过 `TryRequestStop` 获得处理权；
4. 本次运行重复报警去重；
5. 下一次运行再次 `BeginRun` 后，首次报警必须能够重新触发。

不得恢复 `_alarmStopRequested` 永久残留的旧行为，也不得引入组级锁存替代通道锁存。

### 7.3 数据库状态

报警圈状态继续执行：

```text
当前报警圈CSV存在 && 当前报警圈BIN存在
    → alarm
否则
    → failed
```

报警圈、失败圈和取消圈不增加成功圈数。不得因增加调度或时间线文件而放松当前CSV/BIN证据要求。

## 8. DO控制时间线

### 8.1 统一DO辅助方法

为了覆盖 `EpbCycleRunner.cs`、`EpbCycleRunner.Adaptive.cs` 和
`EpbCycleRunner.Advance.Sync.cs` 中分散的DO调用，在Runner partial类内增加：

```csharp
private bool CommandForward(string stage);
private bool CommandReverse(string stage);
private bool CommandOff(string stage);
private bool CommandOffHighPriority(string stage);
```

每个方法固定执行：

1. 读取UTC和 `Stopwatch.GetTimestamp()`；
2. 读取当前通道电流；
3. 调用对应 `DoController` 方法；
4. 记录返回值；
5. 向控制时间线写入结构化事件；
6. 返回原始DO方法结果，不改变现有控制语义。

所有正式Runner路径的 `SetEpbForward/Reverse/Off/OffHighPriority` 均改走辅助方法。`EpbManager` 中独立的紧急停机入口可以直接调用DO，但也必须向同一时间线追加事件。

### 8.2 时间线事件

建议新增：

```csharp
public enum EpbDoCommandKind
{
    Forward,
    Reverse,
    Off,
    OffHighPriority
}

public sealed class EpbControlTraceEvent
{
    public DateTime TimestampUtc { get; set; }
    public long MonotonicTicks { get; set; }
    public Guid BatchId { get; set; }
    public int Channel { get; set; }
    public int ElectricalGroupId { get; set; }
    public int CycleNumber { get; set; }
    public int PlannedPhaseMs { get; set; }
    public string Stage { get; set; }
    public EpbDoCommandKind Command { get; set; }
    public bool CommandSucceeded { get; set; }
    public double CurrentAtCommandA { get; set; }
}
```

运行中使用有界环形缓冲，避免耐久试验无限占用内存。至少保留最近60秒或最近10,000条事件；报警导出完成后仍继续记录后续运行通道。

### 8.3 证据边界

`CommandSucceeded=true` 只表示 `DoController` 方法返回成功：

- 不能写成继电器触点已断开；
- 不能写成负载已经物理断电；
- 命令时刻电流只能作为辅助证据；
- 物理断电必须由外部DI、示波器或逻辑分析仪确认。

日志和快照字段统一使用 `DoCommandResult`，禁止使用 `PhysicalOffConfirmed`。

## 9. 报警快照增强

在现有 `AlarmSnapshots/<时间>-EPBxx` 中增加：

```text
alarm-metadata.json
electrical-stagger-plan.json
do-control-timeline.csv
```

### 9.1 `alarm-metadata.json`

至少包含：

- 报警通道、圈号、原因和UTC；
- 批次ID；
- 电气组ID及同组已选通道；
- `StaggerMs`和各通道计划相位；
- 报警前最后一次正向、反向和断电命令；
- 对应DO返回值；
- 明确字段 `PhysicalOffStatus="NotMeasured"`，表示本阶段没有物理触点反馈。

### 9.2 `electrical-stagger-plan.json`

保存批次启动时的不可变计划，不在导出时重新读取XML。这样即使运行中配置文件被修改，也能还原当时实际使用的相位。

### 9.3 `do-control-timeline.csv`

导出报警前至少10秒至报警时刻的：

- 报警通道；
- 与报警通道同电气组的本批次通道；
- 必要时其他正在运行通道的同期命令事件。

CSV使用 `InvariantCulture`，时间精确到毫秒，并同时保存单调时钟ticks。

新增元数据或时间线导出失败时：

- 不阻塞高优先级断电；
- 记录快照增强文件失败原因；
- 当前圈 `alarm/failed` 仍只由原有CSV/BIN证据决定。

## 10. 日志要求

批次开始时记录：

```text
EPB错峰计划 Batch=<id> Period=15000ms
Group3 Stagger=800ms: EPB8(index=0,phase=0), EPB9(index=1,phase=800)
Group4 Stagger=800ms: EPB10(index=0,phase=0), EPB12(index=1,phase=800)
```

每个阶段记录：

- 计划时刻；
- 实际开始时刻；
- 计划相位；
- 实际偏差；
- 通道、圈号、阶段和电气组；
- DO命令及返回值。

报警时记录：

- 报警通道和原因；
- 本通道最近一次DO命令；
- 同组计划和同组通道当前运行状态；
- 明确说明“只停止故障通道”；
- 快照CSV/BIN及增强文件是否成功。

不得在2 ms采样循环中逐点写日志。DO事件、阶段边界和报警事件才写结构化日志。

## 11. Codex实施顺序

### 阶段A：纯逻辑计划

1. 新增 `ElectricalStaggerPlan`、Assignment和Planner。
2. 完成配置校验和计划单元测试。

### 阶段B：四条路径统一接入

## 14. 现场验收

### 14.1 无负载时序检查

使用逻辑分析仪或示波器观察DO，配置 `StaggerMs=800`：

- 选EPB8、EPB9：两路正向启动间隔约800 ms；
- 选EPB10、EPB12：两路正向启动间隔约800 ms；
- 同时选择四通道：EPB8与EPB10接近同时，EPB9与EPB12约晚800 ms；
- 允许前一路尚未结束时后一路启动；
- 单独选择EPB9或EPB12时不得额外等待。

### 14.2 通道故障隔离

注入EPB8堵转：

- EPB8触发高优先级断电、报警、UI提示和快照；
- EPB9不被停止，继续按其周期和相位运行；
- EPB8的当前圈按CSV/BIN证据写 `alarm` 或 `failed`；
- 新运行EPB8后能够再次报警。

### 14.3 100圈验证

使用现场项目组合EPB8、EPB9、EPB10、EPB12连续运行100圈：

- EPB8/EPB10相位约0 ms；
- EPB9/EPB12相位约800 ms；
- 每圈相位偏差可追溯；
- 不发生追赶式连续上电；
- 圈号连续且各状态与文件证据一致；
- 日志、计划JSON、DO时间线和报警快照可相互对齐。

本阶段验收不发送任何程控电源命令，也不以PSW状态作为通过条件。

Codex实施代码时必须：

2. 保留用户已有未提交修改，不覆盖无关文件。

4. 不修改历史现场数据库、CSV、BIN或报警快照。

8. 不放松现有通道硬保护和报警文件证据要求。
9. 不在DAQ高频采样回调中同步写日志或文件。

## 17. 结论边界

本方案确定的是软件错峰调度和通道级保护行为：

- `StaggerMs`控制的是开始相位，不是高电流阶段互斥；
- 阶段重叠是当前效率取舍下允许的行为；
- 软件不感知程控电源真实CV/CC状态；
- DO返回成功不等于负载物理断电；
- 若现场仍出现约20 A平台，需要通过独立电源测量和DO物理时序继续调查，不能仅靠本次代码整改关闭机械根因。
