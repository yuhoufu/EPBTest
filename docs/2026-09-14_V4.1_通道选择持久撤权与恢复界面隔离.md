# V4.1 通道选择持久撤权与恢复界面隔离

基线：`6fabf02`，修复工作树 `Codex/independent-fallback-v4-work`。本记录属于开发中验证，不是完整候选包验收。

## 行为和实现

人工改变通道选择时，先按当前控制进程身份、RunId、RunEpoch 写入持久运行意图，再保存界面配置。取消勾选立即排除恢复目标；重新勾选保持该批次通道暂停，必须明确重新开始才能恢复运行。重复相同选择幂等，其他进程或旧批次不能借此更新授权。保存期间阻止新的整批启动，持久化失败恢复原勾选并明确报错。

审查发现，无人值守恢复准备直接赋值复选框，会经过同一人工选择事件。现改用现有带 `_channelSelectionUiGuard` 的更新入口，使检查点恢复不产生人工选择审计或撤销正在使用的恢复许可。该修订没有增加硬件启动入口。

独立配置摘要使用 `IndependentSelectionV1`，只将 EpbRecords 中 Enabled 从配置摘要中分离，选择仍由持久运行意图管控；目标次数、通道身份和安全参数继续参与摘要。旧恢复检查点仍使用原配置摘要。新的安装注册必须生成匹配摘要，不猜测迁移旧注册。
